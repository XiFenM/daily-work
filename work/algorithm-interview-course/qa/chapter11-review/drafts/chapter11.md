# 第 11 章 课程结语

## 本章解决什么问题

第十一章没有再引入新的数据结构、题目或算法，而是回答一个更接近长期学习的问题：

> 学完这门课以后，怎样把已经接触的知识转化为可持续、可迁移的算法面试能力？

唯一课次 11-01 给出四个直接落点：[course_direct | 11-01:ev-001–ev-004]

1. **基础**：算法面试主要考察基础，难题也常在基础问题上继续增加条件；
2. **练习**：使用 LeetCode 持续训练算法；
3. **深挖**：不能停在 OJ 的 `Accepted`，还要继续追问设计、实现和优化；
4. **归类**：对问题分类与基本思考模式形成清晰认识。

从章节编辑角度，可以把这四点组织成整门课程的最终闭环：[editorial_inference | 基于 11-01:ev-001–ev-004 与第 1–10 章正式综述]

```text
基础知识
→ 问题分类与识别信号
→ 算法设计
→ 可靠实现
→ Accepted 作为一次反馈
→ 复杂度、边界与替代方案优化
→ 沉淀为可迁移模式
→ 回到下一轮基础补强
```

`Accepted` 在这个闭环里是中间节点，不是终点。

## 一、基础：课程结束不等于基础结束

11-01 明确提醒：课程例题多为中等及以下难度，但大多数算法面试主要考察基础；难题往往也是在基础问题上继续添加条件。[course_direct | 11-01:ev-001]

这段话不是“只做简单题”的许可。它强调的是投入顺序：[editorial_inference | 基于 11-01:ev-001]

1. 先能识别和解释基础结构与思想；
2. 再能把它们可靠实现；
3. 再观察多个基础机制如何在额外条件下组合；
4. 遇到难题时回到基础状态、约束和选择，而不是只记成“难题模板”。

## 二、分类：把知识变成可调用索引

讲师希望学习者在课程结束时，对算法问题的分类和基本思考模式形成清晰认识。[course_direct | 11-01:ev-004]

分类至少有三层用途：[editorial_inference | 基于 11-01:ev-004]

### 1. 缩小候选空间

看到问题目标、输入结构和数据规模后，先判断可能涉及哪一类基础工具，避免从所有算法中盲目搜索。

### 2. 暴露关键差异

同属一个类别的题，可能因为以下条件而需要不同方案：

- 输入是否有序；
- 值是否允许重复、负数或复用；
- 是否要求原地、稳定或恢复具体解；
- 区间端点是否允许相接；
- 状态能否只依赖前一层；
- 局部选择能否被证明安全。

[editorial_inference | 前十章共性边界]

### 3. 促进迁移而非背诵

真正的分类记录应写“为什么属于这一类”和“什么条件会让它不再属于这一类”。只记录题名与模板，不足以形成讲师所说的基本思考模式。[editorial_inference | 基于 11-01:ev-004]

## 三、设计、实现与优化：一道题的三层掌握

11-01 明确要求：做题不能只追求在线 OJ 上的 `Accepted`，而要继续思考算法如何设计、具体如何实现、实现之后是否还能优化。[course_direct | 11-01:ev-003]

### 设计层

回答“为什么是这个方案”：

- 哪些约束给出线索；
- 直接基线如何覆盖候选；
- 状态、窗口、递归契约或贪心选择怎样定义；
- 正确性依赖哪些前提；
- 主要瓶颈是什么。

[editorial_inference | 基于第 1、2、7–10 章方法]

### 实现层

回答“抽象怎样落成代码”：

- 变量与数据结构是否对应设计语义；
- 初始化、边界、循环/递归终止和返回值是否一致；
- 输入是否被修改，额外空间从哪里产生；
- 关键 token 与遍历顺序是否准确；
- 代表性与极端测试是否覆盖主要风险。

[editorial_inference | 基于第 3–10 章代码 QA]

### 优化层

回答“能否更好，以及代价是什么”：

- 复杂度的主导项在哪里；
- 哪些重复工作可以被预处理、缓存或查找结构消除；
- 是否可以压缩状态，或证明只保留一个候选；
- 优化是否改变空间、可读性、输入契约和证明负担；
- 新方案的适用条件是否比原方案更窄。

[editorial_inference | 基于第 2、4、9、10 章]

三层缺一不可：设计无法实现只是想法；实现无法解释容易退化为模板；优化脱离瓶颈和前提则可能只是在增加复杂度。[editorial_inference]

## 四、超越 `Accepted`

### `Accepted` 提供什么

在 OJ 语境中，它表示当前提交通过了平台设置的判定，是实现获得的一次外部反馈。[course_direct + editorial_inference | 11-01:ev-003]

### `Accepted` 不自动提供什么

| 不自动保证的内容 | 还需要怎样检查 |
| --- | --- |
| 设计是最合适的 | 比较基线、替代方案和题目约束 |
| 正确性解释完整 | 写出状态语义、转移理由、不变量或交换步骤 |
| 复杂度口径准确 | 定义变量，拆分各阶段成本 |
| 边界已经理解 | 自己设计最小、极端和冲突用例 |
| 代码适合面试表达 | 检查命名、结构、输入修改和关键 token |
| 能迁移到变体 | 改变条件，定位原方案失效点 |

[editorial_inference | 基于 11-01:ev-003 与前十章 QA]

### 一次完整练习的退出条件

可以把“做完一道题”定义为至少能回答：[editorial_inference]

1. 我为什么识别出这个方向？
2. 我能从基线推到当前设计吗？
3. 我能不看答案解释并实现关键部分吗？
4. 我能说清正确性和复杂度的证据边界吗？
5. 我知道当前方法在哪些条件下失效吗？
6. 我能把经验归入一个可迁移模式吗？

这比“提交状态为绿色”更接近本章所强调的长期能力。

## 常见错误

1. **轻视基础题。** 把题目名称常见或难度不高误解为无需深入实现和解释。[course_direct + editorial_inference | 11-01:ev-001]
2. **只按题量衡量准备。** 结语没有给出刷题数量目标，而是把重点放在设计、实现、优化和分类认知。[course_direct | 11-01:ev-003, ev-004]
3. **把分类变成套模板。** 没有核对约束和状态语义就复制代码，无法形成可迁移思考模式。[editorial_inference]
4. **把 `Accepted` 当正确性证明。** 平台测试反馈不等于形式化证明，也不保证已经理解所有边界。[editorial_inference | 11-01:ev-003]
5. **优化没有对象。** 只说“还能优化”，却说不清瓶颈、成本和新方案的前提。[editorial_inference]
6. **把录制时期的平台评价当实时事实。** 本章没有联网核验 LeetCode 当前功能或题库。[course_direct + editorial_inference | 11-01:ev-002]
7. **把维护承诺写成已完成更新。** 视频只表达课程会持续维护。[course_direct | 11-01:ev-004]
8. **为结语补算法内容。** 本章没有代码、复杂度、公式或题解，不能从前十章复制进来。[editorial_inference | normalized 结构边界]
9. **把首尾呼应写成显式回指。** 第一章回环是编辑归纳，不是 11-01 说出了课次编号。[editorial_inference]

## 课后实践方案

下面是一套单轮循环模板。具体周期与题量均应按个人情况决定；整个流程是编辑建议，不是课程要求：[editorial_inference]

### 第一步：选一个基础类别

从复杂度、数组、查找表、链表、栈队列、树、回溯、动态规划或贪心中选择一个薄弱主题。

### 第二步：做少量代表题

选择能够暴露该类别关键状态与边界的题，而不是只追求数量。

### 第三步：每题完成三层记录

- 设计：线索、基线、状态/选择、正确性理由；
- 实现：关键变量、边界、测试、输入契约；
- 优化：瓶颈、替代方案、复杂度与代价。

### 第四步：做一个变体

主动改变一个条件，检查原分类、状态或实现是否仍成立。

### 第五步：回到基础地图

把错误归类为基础不清、识别失败、设计缺口、实现错误、复杂度误判或证明不足，并决定下一轮补强点。

这套循环把 11-01 的四条直接建议转成可执行记录，但不能反向声称讲师规定了周期、题量或表格格式。[course_direct + editorial_inference | 11-01:ev-001–ev-004]
