# 2-2 对数据规模有一个概念

## 一句话定位

本节通过 C++ 累加循环的基准运行时间实测，建立了“1 秒时间限制下不同复杂度算法所能处理的数据规模 $n$”的量化直觉，并讲解了辅助空间与递归调用栈对空间复杂度的影响。

## 学习目标

- 掌握家用计算机上 $10^8$ 次简单基础操作约耗时 0.4–1 秒的性能基准（`03:43`）。
- 能够根据 1 秒时间限制，推算 $O(n)$、$O(n \log n)$、$O(n^2)$ 等算法可处理的极限与保守数据规模（`04:26`）。
- 能够运用基准耗时解释为什么 $O(n^2)$ 排序算法处理 $10^5$ 规模数据会导致程序假死（`06:12`）。
- 理解空间复杂度的概念，区分 $O(1)$、$O(n)$、$O(n^2)$ 的辅助内存占用（`08:42`）。
- 理解递归调用的栈空间开销，并能根据递归最大深度计算递归算法的空间复杂度（`09:51`）。

## 详细笔记

### 1. 为什么要对数据规模建立概念 (`00:00`)

讲师指出，许多初学者在编写算法时缺乏对数据规模 $n$ 的直觉，经常出现“对 $10^5$ 级别的数据运行选择排序，导致计算机界面假死/卡死”的情况（`00:24`）。建立对数据规模与算法运行时间对应关系的直觉，是算法设计与面试应答的关键基础。

### 2. C++ 运行时间实测与基准数据 (`01:00`)

讲师编写并运行了一段 C++ 代码，测试 $O(n)$ 梯度的循环累加耗时（`01:01`）：

- **代码设计**：外层循环 $x$ 从 1 到 9，数据规模 $n = 10^x$。内层进行 $n$ 次 `sum += i` 的加法操作。
- **计时方式**：使用 `<ctime>` 头文件中的 `clock()` 获取时钟周期数，相减后除以全局常量 `CLOCKS_PER_SEC` 并转为 `double` 类型，得到以秒（s）为单位的精确时间（`01:53`）。
- **实测结果记录**（`02:55`）：
  - $10^1 \sim 10^2$：约 $2 \times 10^{-6}$ s（规模太小，CPU 计时不够敏感）；
  - $10^3$：$5 \times 10^{-6}$ s；
  - $10^4$：$4 \times 10^{-5}$ s；
  - $10^5$：$0.000403$ s；
  - $10^6$：$0.004016$ s；
  - $10^7$：$0.041024$ s；
  - $10^8$：$0.414551$ s（**核心基准：约 0.41 秒**）；
  - $10^9$：$4.12745$ s（约 4.13 秒）。

**讲师总结**：数据规模每扩大 10 倍，运行时间也基本扩大 10 倍，验证了算法的确为 $O(n)$ 级别。在当前家用计算机配置下，$10^8$ 次简单指令操作（加法/变量读写）耗时约为 0.4–1 秒（`03:43`）。

### 3. 1秒时间限制下的数据规模经验法则 (`04:26`)

以“在 1 秒（1s）内解决问题”为常见算法限制，讲师总结了不同复杂度算法可处理的数据规模（画面直接可见 `04:28`）：

1. **$O(n^2)$ 算法**：
   - 理论极限：可处理约 $10^4$ 级别数据（$(10^4)^2 = 10^8$ 次操作，耗时约 0.4s）；
   - 保守估计：建议用于 $10^3$ 级别数据（`05:58`）。
2. **$O(n \log n)$ 算法**：
   - 理论极限：可处理约 $10^7$ 级别数据（$\log_2(10^7) \approx 23$，$10^7 \times 23 \approx 2.3 \times 10^8$ 次操作，耗时约 1s）；
   - 保守估计：建议用于 $10^6$ 级别数据（`06:08`）。
3. **$O(n)$ 算法**：
   - 理论极限：可处理约 $10^8$ 级别数据（`04:54`）；
   - 保守估计：建议用于 $10^7$ 级别数据（`06:03`）。
4. **高阶/低阶补充**（讲师口头补充 `08:06`）：
   - $O(n^3)$ 算法：可处理 $n \le 100$ 级别数据（$100^3 = 10^6 \ll 10^8$）；
   - **保守折扣原因**：实际算法（如归并排序）每一步常数项可能较庞大（含多次比较、赋值、临时数组开辟），不能简单等同于 1 次基础加法，因此保守估计时通常除以 2 或除以 10（`05:46`）。

### 4. 解释选择排序假死与面试应用 (`06:12`)

- **假死原因推算**：选择排序是 $O(n^2)$ 算法。对 $n=10^5$ 数据，需执行 $(10^5)^2 = 10^{10}$ 次比较与交换。按 $10^8$ 次简单加法需 0.4 秒计算，$10^{10}$ 次简单加法至少需 $0.4 \times 100 = 40$ 秒（`06:48`）。再加上比较与元素交换的复杂常数，实际耗时远超 40 秒。由于程序为单线程串行执行，吃满 CPU 单核资源，导致系统界面失去响应（假死）（`07:08`）。
- **面试倒推策略**：面试官给出数据规模 $n$ 后，可直接确定解法复杂度的上限（`07:23`）：
  - 若 $n = 10^8$，通常必须设计 $O(n)$ 或更低复杂度的算法，并且仍要留意常数项与内存访问成本；
  - 若 $n = 10^3$，设计 $O(n^2)$ 算法完全可行；
  - 若 $n \le 100$，甚至可以考虑 $O(n^3)$ 算法。

### 5. 空间复杂度与递归开销 (`08:42`)

- **空间复杂度定义**：与时间复杂度分析方式一致，衡量算法运行所需开辟的**辅助空间**随数据规模 $n$ 的增长关系（`08:54`）。
  - 开辟 $n$ 长度辅助一维数组：$O(n)$ 空间；
  - 开辟 $n \times n$ 辅助二维数组：$O(n^2)$ 空间；
  - 仅开辟常数个临时变量（如原地排序算法）：$O(1)$ 空间（`09:21`）。
- **递归调用的栈空间代价**（`09:51`）：递归调用会消耗系统栈空间。
  - 循环累加 `sum1`（`10:18`）：开辟 `ret` 和 `i` 两个变量，空间复杂度为 $O(1)$。
  - 递归累加 `sum2`（`10:44`）：递归语义为计算 $0 \sim n$ 的和，递归深度为 $n$。系统栈需同时装载 $n$ 个函数调用栈帧，空间复杂度升为 $O(n)$。
  - **核心规律**：递归算法的空间复杂度至少等于其**最大递归深度**（`11:13`）。

## 问题与解法

本节非算法题讲解，讲师通过两个 C++ 代码示例进行概念演示与论证。

### 代码示例 1：时间复杂度基准测试代码

```cpp
// 画面直接可见 (01:01–02:52)
#include <iostream>
#include <cmath>
#include <ctime>

using namespace std;

int main() {
    for (int x = 1; x <= 9; x++) {
        int n = pow(10, x);
        clock_t startTime = clock();
        int sum = 0;
        for (int i = 0; i < n; i++)
            sum += i;
        clock_t endTime = clock();
        cout << "10^" << x << " : " << double(endTime - startTime) / CLOCKS_PER_SEC << " s" << endl;
    }
    return 0;
}
```

### 代码示例 2：迭代求和与递归求和的空间复杂度对比

```cpp
// 画面直接可见 (10:18–10:44)

// 迭代实现：空间复杂度 O(1)
int sum1(int n) {
    assert(n >= 0);
    int ret = 0;
    for (int i = 0; i <= n; i++)
        ret += i;
    return ret;
}

// 递归实现：空间复杂度 O(n)
int sum2(int n) {
    assert(n >= 0);
    if (n == 0)
        return 0;
    return n + sum2(n - 1);
}
```

## 正确性与不变量

- **迭代求和 `sum1` 不变量**：在第 $i$ 次循环开始前，`ret` 保存 $[0, i-1]$ 所有整数之和。循环终止条件为 $i = n + 1$，此时 `ret` 正确存储 $[0, n]$ 之和。
- **递归求和 `sum2` 正确性**：递归基为 $n = 0$，直接返回 $0$。对于 $n > 0$，假设 `sum2(n - 1)` 能正确计算 $[0, n - 1]$ 之和，则 $n + sum2(n - 1)$ 覆盖所有 $[0, n]$ 整数，归纳成立。
- **分析者补充说明**：讲师重点在于说明 `sum2` 在递归入栈过程中产生 $n$ 层栈帧，因而空间复杂度为 $O(n)$，而非强调证明算法本身的数学正确性。

| ------------------------------- | ------------- | ------------- | ------------------------------------------------------------------- |

## 面试视角

- **面试前应先澄清的问题**：拿到题目后，优先问清输入数据规模 $n$ 的取值范围，以及是否有严格的时间限制（默认通常为 1 秒在线评测）。
- **推荐的口头表达顺序**：
  1. 根据面试官给出的数据规模 $n$，在心中用基准法则倒推目标复杂度阶（如 $n = 10^5 \implies$ 不能用 $O(n^2)$，必须设计 $O(n \log n)$ 或 $O(n)$ 算法）；
  2. 向面试官说明：“因为数据规模到了 $10^5$，如果用 $O(n^2)$ 暴力解法会超时，因此我打算采用 $O(n \log n)$ 的解法……”；
  3. 讨论空间开销时，主动说明递归深度所带来的栈空间消耗。
- **面试官可能追问**：
  - 如果把递归解法改写为迭代解法，空间复杂度会有什么变化？（例如由 $O(n)$ 降为 $O(1)$）。
  - 如果离线预处理允许运行 5 分钟或 1 小时，算法复杂度限制该如何调整？（讲师口头点到，预处理场景可容忍更高复杂度 `08:25`）。

## 易错点与边界测试

| 风险                        | 为什么容易错                                                   | 最小测试或反例                                                                                       |
| --------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 忽略递归的系统栈开销        | 以为没有用 `new`/`malloc` 开辟数组，空间复杂度就是 $O(1)$      | 深度为 $n$ 的单路递归 `sum2(n)`，栈空间消耗为 $O(n)$，当 $n$ 过大时会导致栈溢出（Stack Overflow）。  |
| 忽视常数项与复杂操作        | 误以为 $10^8$ 规模下任何 $O(n)$ 算法都只需 0.4 秒              | 若循环内部包含复杂的内存分配、IO 或多次嵌套调用，常数项增大，实际耗时会超出 1 秒，因此需作保守折扣。 |
| 对 $10^5$ 规模使用 $O(n^2)$ | 忽视 $10^5$ 平方后达到 $10^{10}$ 操作量，远超 CPU 1 秒处理极限 | 对 $10^5$ 长度的随机数组运行选择排序，观察到程序长时间未响应。                                       |

### 记忆卡

- **问题**：1秒内解决问题，不同复杂度算法的保守数据规模是多少？
  - **简答**：$O(n^2) \sim 10^3$；$O(n \log n) \sim 10^6$；$O(n) \sim 10^7$。
- **问题**：CPU 在 1 秒内大约能处理多少次简单指令？
  - **简答**：约 $10^8$ 次（实测 $10^8$ 次加法约耗时 0.41s）。
- **问题**：递归调用的空间复杂度计算规则是什么？
  - **简答**：至少等于系统栈所达到的**最大递归深度**。
