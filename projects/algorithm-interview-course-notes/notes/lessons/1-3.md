# 1-3 如何准备算法面试

## 一句话定位

本节系统梳理了算法面试准备的误区与正确范畴，明确指出无需死磕《算法导论》或追求 ACM 竞赛难度，并推荐了以 LeetCode 为主的 OJ 练习平台与“原理学习与实践做题保持平衡”的备考策略。

## 学习目标

1. 识别并避开算法面试准备中的三大常见误区（死磕理论大部头、过早陷入高级数据结构实现细节、盲目追求竞赛难度）。
2. 明确算法面试的真实准备范畴（基础排序、基础数据结构实现与应用、基本算法思想）。
3. 通过 Intel、乐视、阿里、百度等名企真题，理解算法面试对基础知识点的考查方式。
4. 区分竞赛型 OJ 与面试型 OJ，掌握首选 LeetCode 并以 HackerRank 为辅的平台使用策略。
5. 树立“学习原理与实践做题保持平衡”的复习观念，避免无脑机械刷题。

## 详细笔记

### 1. 算法面试准备的三大误区 (`00:39`)

- **误区 1：远不需要啃完一本《算法导论》** (`00:46`)
  - 《算法导论》是经典巨著，但侧重于严格的理论推导与数学证明。
  - **讲师演示举例** (`01:28`)：讲师展示了《算法导论》中关于“随机化快速排序平均时间复杂度为 $O(n \log n)$”的复杂数学期望推导过程。
  - **讲师观点**：面试官通常不强调也不要求现场推导这些理论证明，面试官自己往往也未完全掌握。面试只需熟记 $O(n \log n)$ 的结论并能实现代码即可。
  - **学习建议** (`03:49`)：**切忌完美主义**。不要试图一次性完美掌握所有知识，应学会抓大放下，先掌握主干和结论，有感性认识和实践后再回看理论推导。
- **误区 2：高级数据结构与复杂算法考查概率极低** (`03:55`)
  - 红黑树、B-Tree、斐波那契堆、计算几何、数论、FFT（快速傅里叶变换）等，在通用算法面试中被提及的概率很低(`04:09`)。
  - 除非涉及特定专业领域（如信号处理用到 FFT），否则在第一轮复习准备中无需涉及这些高级结构的具体代码实现(`04:55`)。
- **误区 3：远不需要达到信息学竞赛（ACM）的水准** (`05:01`)
  - 很多同学容易将算法面试与 ACM/ICPC 等竞赛混淆。算法面试的难度和覆盖面与竞赛有很大差异，未参加过竞赛完全不影响准备算法面试。

### 2. 算法面试的真实准备范畴 (`05:47`)

讲师强调：**不要轻视基础算法和数据结构，而去盲目关注偏难怪或“脑筋急转弯”式题目** (`05:51`)。实际面试绝大多数题目围绕以下基础范畴：

1.  **各种排序算法**：特点、原理与对比 (`06:27`)。
2.  **基础数据结构与算法的实现**：如堆、二叉树、图的底层实现 (`06:31`)。
3.  **基础数据结构的使用**：链表、栈、队列、哈希表、图、Trie（字典树）、并查集等 (`06:39`)。
4.  **基础算法**：深度优先搜索（DFS）、广度优先搜索（BFS）、二分查找、递归等 (`06:51`)。
5.  **基本算法思想**：递归、分治、回溯搜索、贪心、动态规划（DP）等 (`06:59`)。

> **讲师课程体系分工说明** (`07:34`)：
> 讲师在慕课网的另一门课程《算法与数据结构》重点讲解上述第 1、2 项（各种排序与堆/二叉树/图的底层实现）；而本门课程（《算法面试视频课程》）重点讲解第 3、4、5 项（如何使用数据结构和算法思想去解决具体的面试问题）。

### 3. 名企笔试/面试基础题真题示例 (`07:59`)

讲师展示了 4 家名企的真实题目，证明大厂非常注重基础：

- **Intel 题** (`07:59`)：给定初始序列 `1 8 6 2 5 4 7 3` 建最小堆，求建堆完毕后对应二叉树的中序遍历序列。（考查：最小堆构建逻辑 + 二叉树中序遍历）
- **乐视题** (`08:22`)：20 个元素的有序数组（下标从 1 开始）做二分查找，求查找 `A[2]` 时比较序列的下标。（考查：二分查找的具体执行步骤）
- **阿里巴巴题** (`08:39`)：序列 `(5, 11, 7, 2, 3, 17)` 用堆排序建立的初始堆形态。（考查：堆排序中的建堆过程）
- **百度题** (`08:54`)：图采用邻接表存储时，求最小生成树的 Prim 算法时间复杂度。（考查：图的存储结构 + Prim 算法复杂度）

### 4. 在线判题系统（OJ）的选择 (`10:34`)

- **落实在代码上**：学习算法不能停留在看书和阅读，必须通过代码实践并验证正确性 (`11:16`)。
- **不推荐的平台** (`11:41`)：Codeforces（俄）、TopCoder（美）、CodeChef（印）。这些平台偏向程序设计竞赛，题目偏难偏怪，不适合面试准备。
- **首推平台：LeetCode** (`12:25`)
  - 定位："Online Portal for IT Interview"，专为 IT 面试设计。
  - 特点：题目源于真实面试题，付费会员可查看企业标签与出题频次。本课程绝大多数例题选自 LeetCode。
- **辅助平台：HackerRank** (`13:35`)
  - 定位："Revolutionizing Tech Recruiting"。
  - 特点：知识点分类极细（如同点技能树），非常适合专项弱项突破。
  - 缺点：部分题目偏难且不完全是真实面试题，建议作为辅助平台 (`14:51`)。

### 5. 学习与做题的平衡心法 (`16:06`)

- **拒绝盲目刷题/机械刷题** (`16:28`)：单纯追求 Accept 数量，只关注题目做对与否，而忽视背后的算法思想，效果极差。
- **掌握平衡** (`16:14`)：
  - **学习**：理解基础算法实现，扩充解题思路，总结通用模式；
  - **实践做题**：将思路转化为无错代码，验证正确性。
- 没有任何公司会根据“刷题数量”来决定录用，考察的是实际的技术与思维水平 (`17:28`)。

3. **举真题**：展示 Intel/乐视/阿里/百度真题，证明“基础才是核心”；
4. **选工具**：对比各大 OJ，首选 LeetCode 结合 HackerRank；
5. **传心法**：强调原理学习与代码实践相平衡，拒绝体力劳动式刷题。

## 面试视角

- **面试前应先澄清的观念**：算法面试不是 ACM 竞赛，不考察偏难怪题或现场数学公式推导；基础数据结构的使用和基础算法思想才是考察重中之重。
- **推荐的复习顺序**：先掌握基础数据结构（堆、二叉树、图等）的实现与各种排序算法；再通过 LeetCode 对链表、哈希表、DFS/BFS、二分、DP、贪心等主题进行题目实战。
- **刷题心态调整**：切忌陷入“体力劳动”式的盲目刷题；每做一道题要吸取背后的算法思想，保持“原理学习”与“实践写码”的平衡。
