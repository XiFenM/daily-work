# 第 10 章 贪心算法

## 本章解决什么问题

第九章面对一个状态时，会比较多个合法选择并保存子问题的最优值；第十章进一步追问：

> 能否证明某一个局部选择一定可以出现在某个全局最优解中，从而立刻作出选择，不再保留其他分支？

这正是贪心算法的价值和风险所在。实现往往只剩“排序 + 一次扫描”，真正困难的是：

1. 选什么局部量作为优先级；
2. 被丢弃的候选为什么永远不必反悔；
3. 当前选择之后是否仍得到同类子问题；
4. 如何用反例否定错误规则，或用交换论证证明正确规则；
5. 题目的端点、相等元素和输入修改语义是否与证明一致。

本章三课形成一条完整主线：

```text
10-01 用 Assign Cookies 建立“排序后做局部选择”的直觉
  ↓
10-02 用 Non-overlapping Intervals 对照 DP 与贪心
  ↓
10-03 先用反例淘汰错误规则，再用交换论证检验贪心选择性质
```

因此，本章的统一解题闭环是：

```text
明确目标与可行性
→ 提出局部选择规则
→ 先主动寻找最小反例
→ 定义排序、扫描状态与丢弃条件
→ 证明一次贪心选择可安全进入某个最优解
→ 证明选择后仍是同类剩余问题
→ 重复选择并得到整体最优
→ 最后分析复杂度、端点和工程契约
```

## 贪心算法不只是“每次选当前最好”

10-01 对贪心算法的直观描述是：每一步都采取当前看来最好或最优的选择；课程同时强调，代码通常很短，难点是判断问题能否使用贪心并证明它正确。[course_direct | 10-01:ev-001]

仅有“局部最优”这句话并不足以构成算法。一个可审核的贪心方案至少需要四部分：[editorial_inference]

| 部分       | 要回答的问题                                                 |
| ---------- | ------------------------------------------------------------ |
| 候选顺序   | 按什么主键排序？升序还是降序？相等时如何处理？               |
| 可行性条件 | 当前候选在什么条件下可以加入答案？                           |
| 状态更新   | 接受或拒绝候选后，哪些边界、指针或计数发生变化？             |
| 正确性依据 | 为什么当前选择可替换某个最优解的对应选择，且不损害剩余选择？ |

错误贪心通常不是代码写错，而是第一列看起来合理、第四列却无法成立。

## 10-01：Assign Cookies 的排序与双指针

### 问题模型

LeetCode 455 Assign Cookies 给出：[course_direct + visual_direct | 10-01:ev-002]

- 小朋友的最低需求 `g[i]`；
- 饼干尺寸 `s[j]`；
- 每个小朋友最多得到一块饼干；
- 只有 `s[j] >= g[i]` 时该小朋友才满足；
- 目标是最大化满足人数。

课程采用降序策略：[course_direct + visual_direct | 10-01:ev-003, 10-01:ev-004]

```text
把 g 和 s 都按降序排序
gi 指向当前需求最大的未处理小朋友
si 指向当前尺寸最大的未使用饼干

若 s[si] >= g[gi]：
    分配成功，答案 +1
    gi、si 都后移
否则：
    放弃当前小朋友
    只让 gi 后移
```

### 为什么失败时可以放弃当前小朋友

由于 `s[si]` 已是所有剩余饼干中最大的，如果：

```text
s[si] < g[gi]
```

那么任何更小的剩余饼干也不可能满足 `g[gi]`。因此放弃当前需求最大的孩子不会漏掉可行匹配。[course_direct | 10-01:ev-003]

这一步证明的是一个**不可能性剪枝**：当前孩子已经无法由任何剩余资源满足。

### 为什么成功时可以使用最大饼干

课程给出局部直觉，但没有完成形式化的多步交换证明；规范化证据因此把正确性标为 `exchange_argument + partial`。[course_direct | 10-01:ev-003；人工 QA]

可以作如下编辑补全：[editorial_inference]

1. 设当前最大需求为 `G`，当前最大饼干为 `S`，且 `S >= G`；
2. 取任意一个能达到最优满足人数的匹配；
3. 若该匹配已把 `S` 给 `G`，无需改变；
4. 若它用另一块 `S' <= S` 满足 `G`，把 `S` 与 `S'` 对调不会破坏可行性；
5. 若 `G` 在该最优匹配中未被满足，而 `S` 满足了需求不大于 `G` 的另一人，则用 `S` 改为满足 `G`，满足人数不减；
6. 因而存在一个最优匹配包含当前贪心配对；移除这一对后，剩余仍是同类匹配问题。

这里的第 6 步是从“一次交换安全”走向“整个算法正确”的关键。它不是视频已经完整展开的证明，不能标成课程直接内容。

### 状态与循环不变量

在每轮开始时可以把状态解释为：[editorial_inference | 基于 10-01:ev-004]

- `g[0...gi)`：已经匹配，或已证明无法由当时的剩余饼干满足而被安全跳过的较大需求；
- `s[0...si)`：已经分配的较大饼干；
- `res`：已建立的可行匹配数；
- `g[gi...]` 与 `s[si...]`：尚未处理的同类子问题。

循环结束于某个数组耗尽：没有孩子则答案已确定；没有饼干则不可能再增加满足人数。[course_direct + visual_direct | 10-01:ev-004]

### 复杂度与工程语义

课程把排序主导的总时间写为 `O(n log n)`，扫描为线性。[course_direct | 10-01:ev-005]

若两数组长度分别为 `G`、`S`，更精确的编辑表达是：[editorial_inference]

```text
时间：O(G log G + S log S)
扫描：O(G)，因为每轮都执行 gi++
```

课程没有直接给出辅助空间结论，所以 normalized 保持 `space = null`。屏幕代码没有建立与输入等长的新数组，但标准库排序的调用栈和实现细节是否计入辅助空间取决于具体实现；这些只能作为编辑或工程补充，不能写成课程的 `O(1)` 结论。

屏幕函数接收两个非常量引用并原地排序，所以调用后输入顺序会改变。[visual_direct + editorial_inference | 10-01:ev-004]

人工测试结果：[local_qa]

- 9 组代表用例与 10,000 组随机小规模暴力匹配 oracle 全部一致；
- AddressSanitizer 与 UndefinedBehaviorSanitizer 通过；
- 严格 `-Werror` 暴露 2 处有符号/无符号比较告警；
- 屏幕包含 `<algorithm>`，但 `std::greater<int>` 没有显式包含其标准声明头 `<functional>`。

相同需求或相同尺寸的元素可以互换，未展示稳定排序或额外二级键；这一点已作为明确的 tie-break 语义记录，而不是补造课程代码。

课尾展示 LeetCode 392 Is Subsequence 的题名、题面和两组示例，但没有给出题解或代码。[course_direct + visual_direct | 10-01:ev-006]

## 10-02：Non-overlapping Intervals 的 DP 与贪心

### 先把删除问题变成保留问题

LeetCode 435 要求最少删除多少区间，使其余区间互不重叠。课程先改写为：[course_direct | 10-02:ev-002, 10-02:ev-003]

```text
最少删除数 = 区间总数 - 最多可保留的不重叠区间数
```

互补目标把问题从“决定删谁”变成“构造最长可行序列”，更容易连接 LIS 状态和区间调度贪心。

题目明确把 `[1,2]` 与 `[2,3]` 视为不重叠，所以兼容条件是：[course_direct + visual_direct | 10-02:ev-002, 10-02:ev-005, 10-02:ev-008]

```text
current.start >= previous.end
```

这个 `>=` 属于题目契约，不是所有区间问题都能照搬。

### 暴力基线

课程先提出枚举所有区间子集、再检查是否重叠，时间写为 `O(2^n * n)`。[course_direct | 10-02:ev-003]

暴力基线的价值不是实际提交，而是说明：我们原本保留了所有选择组合；DP 和贪心分别用不同理由压缩这些分支。

### 动态规划：固定“以 i 结尾”

课程按 `start` 升序排序，把问题类比为 LIS：[course_direct | 10-02:ev-004, 10-02:ev-005]

屏幕注释写成：

```text
memo[i] 表示使用 intervals[0...i] 的区间能构成的最长不重叠区间序列
```

但实际转移和最终取值表明，更精确的代码语义是：[visual_direct + local_qa | 10-02:ev-005]

```text
memo[i] = 以 intervals[i] 结尾的最长不重叠区间序列长度
```

转移：

```text
memo[i] = 1
for every j < i:
    if intervals[i].start >= intervals[j].end:
        memo[i] = max(memo[i], memo[j] + 1)
```

最终答案必须从全表取最大值：

```text
kept = max_i memo[i]
answer = n - kept
```

若 `memo[i]` 真是“前缀 `[0...i]` 的最优值”，它应具有前缀单调性，且不必最后再遍历全表取最大值。屏幕注释与代码语义的差异已在正式证据中显式校正，不能静默沿用错误注释。

DP 双重循环时间为 `O(n²)`，辅助表为 `O(n)`；课程直接口述了时间复杂度，空间项由代码结构编辑推导。[course_direct + editorial_inference | 10-02:ev-005, 10-02:ev-006]

### 贪心：按结束时间最早选择

进一步观察后，课程改按 `end` 升序排序，每次选择当前最早结束且与上一个已选区间兼容的区间：[course_direct + visual_direct | 10-02:ev-007, 10-02:ev-008]

```text
按 end 升序排序
res = 1
pre = 0

for i = 1 ... n-1:
    if intervals[i].start >= intervals[pre].end:
        res++
        pre = i

return n - res
```

状态语义：

- `pre`：最后一个被保留区间的索引；
- `res`：当前已保留的兼容区间数；
- 已扫描前缀中，算法维持一个结束边界尽量早的可行选择序列。[course_direct + editorial_inference | 10-02:ev-008]

选择更早结束的区间，不是因为它自身“更短”或“价值更大”，而是因为它把后续可行区间的起始门槛压得最低。[course_direct | 10-02:ev-007]

排序为 `O(n log n)`，扫描为 `O(n)`，因此总时间为 `O(n log n)`。[course_direct | 10-02:ev-008, 10-02:ev-009]

课程直接口述的是时间复杂度，没有直接给出空间结论。normalized 只把贪心**扫描显式状态**记为 `O(1)`，并明确排除 `std::sort` 内部空间；完整辅助空间仍取决于排序实现。这一项属于编辑口径，不是课程原话。[editorial_inference]

### DP 与贪心到底是什么关系

两版代码解决同一个“最多保留多少兼容区间”问题，但保留的信息量不同：[course_direct + editorial_inference | 10-02:ev-004–ev-009]

| 维度       | DP 版本                                    | 贪心版本                             |
| ---------- | ------------------------------------------ | ------------------------------------ |
| 排序       | `start` 升序                               | `end` 升序                           |
| 状态       | 每个固定结尾的最优长度                     | 最后选择边界与已选数量               |
| 选择处理   | 枚举所有兼容前驱并取最大                   | 直接接受当前最早结束的兼容区间       |
| 信息压缩   | 同一结尾只保留最优长度；仍保留每个结尾状态 | 进一步只保留一个当前结束前沿与计数   |
| 正确性负担 | 证明状态与转移覆盖所有最优序列             | 额外证明被丢弃结尾不可能带来更好未来 |
| 时间       | `O(n²)`                                    | `O(n log n)`                         |

可以把贪心理解为：证明某一分支足以代表最优解后，把 DP 中需要比较的候选集合压缩到一个。[editorial_inference]

但这不是“所有 DP 都能优化成贪心”。只有当局部选择具有可证明的安全性时，才允许丢弃其他状态。

### 代码验证

人工 QA 对屏幕 DP 与贪心代码进行了同一最优 oracle 对拍：[local_qa]

- 9 组代表用例全部通过；
- 111,111 组小规模穷举输入与暴力最优解一致；
- AddressSanitizer 与 UndefinedBehaviorSanitizer 通过；
- 严格告警模式记录 15 条符号性或 `size_type → int` 转换问题；
- 屏幕片段未显式展示 `<algorithm>`；
- 两版都先检查空输入，再访问首元素；
- 两个比较器都显示了相等主键时的二级排序：DP 按 `start` 后按 `end`，贪心按 `end` 后按 `start`。

测试验证的是当前实现与小规模最优 oracle 一致，不替代适用于任意输入规模的数学证明。

## 10-03：先用反例，再做交换论证

### 反例是淘汰规则的第一工具

10-03 先使用 0-1 背包的单位价值规则作为反例：[course_direct + visual_direct | 10-03:ev-002]

```text
容量 C = 5
物品 (w,v)：(1,6)、(2,10)、(3,12)

按 v/w 从高到低：选前两件，价值 16
更优可行解：选后两件，价值 22
```

这个反例证明“单位价值最高优先”不能保证一般 0-1 背包最优；它不证明所有背包变体都不能使用任何贪心规则。

课程又用 Perfect Squares 的 `n=12` 反例：[course_direct + visual_direct | 10-03:ev-003]

```text
最大平方数优先：9 + 1 + 1 + 1，共 4 个
最优：4 + 4 + 4，共 3 个
```

因此“每次减去当前最大平方数”也不成立。

找反例时应优先构造：[editorial_inference]

- 局部最好选择占用关键资源；
- 两个次优局部选择组合后更好；
- 边界恰好卡在容量、区间端点或计数目标上；
- 输入尽可能小，便于手算并明确违反结论。

一个反例足以否定“对所有输入正确”的算法；大量通过样例仍不能完成普遍证明。

### 课程的区间交换论证

课程回到最大不重叠区间选择。设贪心当前选择结束最早的区间 `i`，某个最优解相应选择区间 `j`，且 `f(i) < f(j)`：[course_direct + visual_direct | 10-03:ev-006, 10-03:ev-007]

交换步骤是：

```text
用 i 替换最优解中的 j
```

因为 `i` 结束得更早，原先排在 `j` 后面的区间仍可排在 `i` 后面，所以替换后的选择数量不减少。于是课程得到一个仍为大小 `k`、包含本次贪心选择 `i` 的解。[course_direct | 10-03:ev-007, 10-03:ev-008]

这证明了关键的**一步交换引理**：在当前剩余实例中，最早结束的可行区间可以安全地作为某个最优解的本次选择。课程尚未把“某次选择”量化到全部迭代步骤。

课程随后把思路概括为：让贪心算法 `A` 的当前选择替换最优算法 `O` 的对应选择，并证明最优性不受影响。[course_direct | 10-03:ev-009]

### 为什么规范化状态仍是 `partial`

视频的一步交换论证基本成立，但若要把整段证明标成形式化完整，还需明确以下义务：[editorial_inference | 人工 QA]

1. **候选集合量化**：`i` 是当前所有可行区间中结束最早者，而不是全局固定第一个区间；
2. **相等结束时间**：课程写 `f(i) < f(j)`，需要说明 `f(i) = f(j)` 时任选其一同样安全；
3. **端点语义**：若把证明用于 10-02 题目，替换安全依赖该题把 `start >= previous.end` 视为兼容；10-03 本课没有重新定义区间开闭与端点相接语义；
4. **剩余问题闭包**：选择 `i` 后，所有起点不早于 `f(i)` 的区间仍构成同类最大兼容子集问题；
5. **重复交换或归纳**：把一步安全选择迭代到整个贪心序列，而不只证明第一步；
6. **终止与后置条件**：没有兼容候选时，已选数量就是最优数量。

课程没有逐项写出这些量词、归纳步骤和边界，因此项目保留：

```text
method = exchange_argument
completeness = partial
```

这不表示课程结论错误，而是区分“课堂中的核心证明思想”与“本项目要求的完整证明对象”。

### 贪心选择性质与最优子结构

课程把贪心选择性质直观表述为：作出贪心选择后，不影响剩余子问题的求解。[course_direct | 10-03:ev-001]

更严格地看，贪心正确性通常同时需要：[editorial_inference]

- **贪心选择性质**：存在一个全局最优解包含当前贪心选择；
- **最优子结构**：固定该选择后，原最优解的剩余部分必须是剩余子问题的最优解。

只有第一条而没有第二条，无法把一次安全选择递归扩展成整条最优序列。

### 课程边界

课尾只列出“最小生成树”和“最短路径”，说明贪心思想会进入更复杂算法。[course_direct + visual_direct | 10-03:ev-010]

视频没有展开：

- Prim、Kruskal 或 Dijkstra 的具体机制；
- 图的连通性、边权或非负权条件；
- 代码和复杂度；
- 各算法的完整正确性证明。

因此本章不从两个题名外推这些内容。

## 一套可复用的贪心证明模板

下面是从三课整理出的面试表达模板。带有形式化补全的部分属于编辑归纳：[course_direct + editorial_inference]

### 1. 明确目标、候选和可行性

```text
目标：最大化/最小化什么？
候选：每一步从哪些对象中选？
可行性：选入后必须保持哪些约束？
```

### 2. 写出贪心规则

```text
按 key 排序
每次取当前 key 最小/最大的可行候选
```

必须说明为何选择这个 key，而不是只说“贪心地选”。

### 3. 主动找反例

尝试让局部选择阻塞两个更好的后续选择。若找到一个反例，规则立即被否定；不要先写完整代码再为错误直觉辩护。

### 4. 证明一次选择安全

选择一个任意最优解 `O`：

- 若 `O` 已含贪心选择 `g`，完成；
- 否则找出 `O` 中与 `g` 对应的选择 `o`；
- 用 `g` 替换 `o`；
- 证明可行性不破坏、目标值不变差。

于是存在一个最优解以 `g` 开头。

### 5. 证明剩余问题闭包

固定 `g` 后，说明剩余候选、剩余资源和目标仍构成同一类问题；最优解剩余部分也必须最优。

### 6. 用归纳或重复交换收尾

对剩余问题重复上述论证，直到没有候选。最后把终止状态与题目目标连接起来。

## 三类排序语义不能混用

| 课次       | 排序对象 | 主键与方向   | 相同主键处理                 | 目的                     |
| ---------- | -------- | ------------ | ---------------------------- | ------------------------ |
| 10-01      | `g`、`s` | 数值降序     | 相等元素可互换；无稳定性要求 | 对齐最大需求与最大资源   |
| 10-02 DP   | 区间     | `start` 升序 | 屏幕比较器再按 `end` 升序    | 保证候选前驱位于更早下标 |
| 10-02 贪心 | 区间     | `end` 升序   | 屏幕比较器再按 `start` 升序  | 维持尽量早的后续可行边界 |

排序不是一个可随意替换的预处理步骤。它定义了状态扫描顺序，也参与正确性证明。

## 常见错误

1. **把“每次选最大/最小”当成证明。** 极值只是规则，不说明丢弃其他候选为何安全。
2. **只测很多样例，不找反例或证明。** 有限测试不能证明对所有输入最优。
3. **找到一个错误贪心，就说问题不能贪心。** 反例只否定那条具体规则。
4. **把分数背包的单位价值规则直接套到 0-1 背包。** 物品不可分割会破坏交换条件。
5. **把 10-02 的 DP 注释当真实状态。** 代码语义是“以 `i` 结尾”，不是笼统前缀最优。
6. **DP 和贪心使用同一个比较器。** 一版按 `start`，另一版按 `end`。
7. **把端点相接统一当重叠或不重叠。** 必须读取题目契约；本题明确不重叠。
8. **忽略相等主键。** 即使结果不受影响，也要说明可互换或二级键。
9. **把一步交换引理当整段算法证明。** 还需剩余问题闭包、重复交换/归纳和终止。
10. **把 `O(n log n)` 只归因于扫描。** 扫描是 `O(n)`，排序才是主导项。
11. **写 `O(1)` 空间却不说明排序口径。** 标准库内部栈是否计入需要声明。
12. **忽略原地排序副作用。** 两课屏幕函数都会改变输入顺序。
13. **把课程列出的练习或算法名扩写成已讲题解。** 392 展示了题面和示例但没有解法；MST、最短路只有题名级信息。
14. **把本地测试通过写成外部平台 Accepted。** 两类证据来源不同。

## 章级闪卡

1. **问**：贪心算法最难的部分是什么？ **答**：证明局部选择能安全进入某个全局最优解，并能递归到剩余子问题。
2. **问**：一个反例能证明什么？ **答**：能否定那条声称对所有输入正确的具体规则。
3. **问**：Assign Cookies 失败分支为什么只移动孩子指针？ **答**：最大剩余饼干都不够，其他饼干更不可能满足当前最大需求。
4. **问**：Assign Cookies 成功分支还缺什么证明？ **答**：证明最大饼干与最大需求的配对可以通过交换进入某个最优匹配。
5. **问**：Non-overlapping Intervals 为什么先改写目标？ **答**：最少删除等于总数减最多保留，把问题变成长可行序列。
6. **问**：10-02 DP 的 `memo[i]` 实际语义？ **答**：以区间 `i` 结尾的最长不重叠序列长度。
7. **问**：为什么 DP 最终取全表最大？ **答**：最优序列不一定以最后一个排序后区间结束。
8. **问**：区间贪心按什么排序？ **答**：按结束时间升序，优先保留最早结束的兼容区间。
9. **问**：为什么不是优先选最短区间？ **答**：最短长度不一定留下最早的后续可行边界。
10. **问**：本题端点相接是否重叠？ **答**：不重叠，所以兼容条件使用 `start >= previous.end`。
11. **问**：10-03 的区间证明完成了什么？ **答**：完成核心的一步替换论证，说明存在包含当前贪心选择的最优解。
12. **问**：为什么仍标 `partial`？ **答**：视频没有完整形式化相等情况、剩余问题闭包、重复交换/归纳和终止。
13. **问**：DP 与贪心的主要信息差？ **答**：DP 保留多个子问题最优状态，贪心证明一个选择足够后丢弃其余候选。
14. **问**：0-1 背包反例的结果？ **答**：单位价值规则得 16，而合法组合可得 22。
15. **问**：Perfect Squares 的反例？ **答**：12 取 9 后需四项，取 4+4+4 只需三项。
