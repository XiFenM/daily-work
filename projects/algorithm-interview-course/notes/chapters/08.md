# 第 8 章 递归和回溯法

## 本章解决什么问题

第七章把递归建立在“输入本身是一棵树”之上；本章向前走一步：

> 输入可以是字符串、数组、整数区间、二维网格或棋盘，但**选择过程**会展开成一棵搜索树。

这时，写出递归函数还不够，还要控制搜索现场：

1. **当前部分解是什么？**
2. **下一步候选从哪里来？**
3. **哪些候选已经被使用或不再合法？**
4. **什么状态只属于当前路径，离开分支时必须恢复？**
5. **什么状态代表整个连通区域已经处理，应该永久保留？**
6. **什么条件可以证明一个分支不可能产生答案，从而提前剪掉？**

八课按这条主线推进：

- [08-01](../lessons/08-01.md) 用电话号码字母组合建立“选择过程生成搜索树”的直觉；
- [08-02](../lessons/08-02.md) 通过实际执行轨迹抽象回溯，并讨论它与暴力枚举的关系；
- [08-03](../lessons/08-03.md) 用 `used`、当前排列与成对恢复解决全排列；
- [08-04](../lessons/08-04.md) 用递增的 `start` 候选边界去掉排列中的顺序差异；
- [08-05](../lessons/08-05.md) 从“剩余候选是否足够填满槽位”推导组合剪枝上界；
- [08-06](../lessons/08-06.md) 把回溯迁移到二维路径搜索，并使用路径局部 `visited`；
- [08-07](../lessons/08-07.md) 用 flood fill 标记整个连通块，访问状态不再撤销；
- [08-08](../lessons/08-08.md) 用列与两组对角线约束剪枝 N Queens。

本章可以压缩成一个可复用流程：

```text
定义当前状态和递归契约
→ 判断是否已经得到完整解
→ 枚举当前状态允许的候选
→ 检查边界、访问状态或约束
→ 做出选择并更新现场
→ 递归探索下一层
→ 按任务语义撤销，或永久保留状态
→ 用搜索树覆盖性与剪枝安全性解释正确性
```

## 搜索树不等于递归调用树

第二章的“递归树”主要用于数复杂度：节点表示一次函数调用，关注分支数、深度和每层工作量。

本章的“搜索空间树”关注的是：

- 节点：一个部分解或搜索状态；
- 边：一次候选选择；
- 路径：从空解到完整解的一系列选择；
- 叶节点：完整答案、失败状态或被剪枝状态。

两个概念可能画成相似的树，但用途不同：

| 维度     | 复杂度调用树                   | 搜索空间树                               |
| -------- | ------------------------------ | ---------------------------------------- |
| 节点含义 | 一次递归调用                   | 当前部分解或决策状态                     |
| 主要问题 | 一共有多少调用、每层做多少工作 | 候选是什么、哪些状态合法、何时撤销或剪枝 |
| 代表课程 | 02-05                          | 08-01 至 08-08                           |
| 常见风险 | 漏算每层工作量                 | 状态污染、重复枚举、错误剪枝             |

因此不能把已有的 `concept:recursion-tree` 直接重命名为搜索空间树；两者应在概念图中保持独立，再通过课程关系连接。

## 回溯的统一状态模型

一个可用的回溯模型至少回答六件事。

### 1. 当前部分解

| 课次  | 部分解                                  |
| ----- | --------------------------------------- |
| 08-01 | 已翻译的字母前缀字符串                  |
| 08-03 | 当前排列向量 `p`                        |
| 08-04 | 当前组合向量 `c`                        |
| 08-06 | 已匹配的网格路径与单词前缀              |
| 08-08 | 前 `index` 行已经放置的皇后列位置 `row` |

### 2. 当前候选

| 课次  | 候选域                                 |
| ----- | -------------------------------------- |
| 08-01 | 当前数字映射出的字母                   |
| 08-03 | 所有尚未使用的数组元素                 |
| 08-04 | `[start, n]` 中的整数                  |
| 08-06 | 当前格子的上、右、下、左合法未访问邻居 |
| 08-08 | 当前行中未占列、未占两组对角线的列     |

### 3. 基本情况

完整解的判断必须与状态定义匹配：

- 08-01：`index == digits.size()`；
- 08-03：已放入的元素数等于输入长度；
- 08-04：`c.size() == k`；
- 08-06：`index` 已指向单词最后一个字符；
- 08-08：已经为 `n` 行放置皇后。

这些条件看似相似，却不能机械统一成一个模板；例如 Word Search 的最后一层还要比较当前位置字符，组合在达到 `k` 时则直接保存。

### 4. 做出选择

选择通常改变两类状态：

- **部分解**：追加字符、元素、坐标或列号；
- **约束状态**：标记元素已用、格子已访问、列或对角线已占用。

若只更新其中一类，递归契约就会失真。

### 5. 递归推进

推进参数必须与候选语义一致：

- 字母组合、排列通常推进到 `index + 1`；
- 组合把下一层候选起点设为 `i + 1`；
- Word Search 把单词索引推进到 `index + 1`，坐标换成邻格；
- N Queens 把当前行推进到下一行。

`i` 与 `i + 1`、当前坐标与新坐标、当前行与下一行，都是回溯代码中的高风险 token。

### 6. 离开分支后的状态

不是所有递归都要撤销；判断标准是：

> 当前修改是否只属于这一条搜索路径？返回后是否还会探索兄弟分支？

这条标准贯穿 08-03、08-06、08-07 和 08-08。

## 排列、组合与剪枝

### 排列：用 `used` 表示候选集合

排列关心顺序。对输入 `[1,2,3]`：

```text
[1,2,3] 与 [2,1,3] 是不同答案
```

每一层都可以从所有未使用元素中选择，所以课程维护：

```text
当前路径 p
used[i]：第 i 个输入元素是否已经在 p 中
```

一次分支的完整生命周期是：

```text
p.push_back(nums[i])
used[i] = true
递归填下一位
p.pop_back()
used[i] = false
```

路径与 `used` 必须一起恢复；只恢复一边会让状态不一致。

### 组合：用 `start` 去掉顺序差异

组合不计顺序：

```text
[1,2] 与 [2,1] 是同一个组合
```

因此不必每层重扫所有数字。选择 `i` 后，下一层只允许从 `i + 1` 开始，候选序列保持严格递增：

```text
当前层候选：[start, n]
选择 i
下一层候选：[i + 1, n]
```

这同时完成两件事：

1. 同一数字不会重复选择；
2. 同一集合不会以不同顺序重复生成。

### 剪枝：剩余候选必须足够

在组合问题中，若当前路径已有 `c.size()` 个元素，还需要：

```text
k - c.size()
```

个元素。当前从 `i` 到 `n` 一共还有：

```text
n - i + 1
```

个候选。继续搜索的必要条件是：

```text
n - i + 1 >= k - c.size()
```

整理得到：

```text
i <= n - (k - c.size()) + 1
```

这不是凭经验写出的“神奇上界”，而是由“剩余候选是否足以填满剩余槽位”推出。严格不等号、括号与末尾 `+1` 都不能丢。

## 网格搜索中的两种访问状态

08-06 与 08-07 都使用：

- 二维坐标；
- 四方向偏移数组；
- 边界检查；
- 访问标记；
- 递归 DFS 骨架。

但二者最重要的区别是访问标记的生命周期。

### Word Search：路径局部标记

`visited[x][y]` 表示这个位置已经出现在**当前单词路径**中。

```text
选择格子 → visited = true
递归试探邻居
失败返回 → visited = false
```

失败后必须恢复，因为另一个起点或兄弟分支仍可能合法使用该格子。

课程代码在成功时直接返回，没有恢复成功路径上的标记；由于整个查找随即结束，没有后续分支读取状态，因此控制流仍然成立。

### Number of Islands：全局处理标记

`visited[x][y]` 表示这个陆地格子已经归入某个被处理的岛屿。

```text
发现新陆地 → 岛屿数加一
DFS 标记整块连通陆地
标记永久保留
继续扫描网格
```

这里若在 DFS 返回时恢复，外层扫描会把同一岛屿的其他格子再次当作新岛屿，导致重复计数。

### 对照表

| 维度           | Word Search                    | Number of Islands                    |
| -------------- | ------------------------------ | ------------------------------------ |
| 搜索目标       | 是否存在一条满足字符顺序的路径 | 统计四连通陆地分量数                 |
| `visited` 含义 | 当前路径已经使用               | 全局已经归入某个连通块               |
| 失败后恢复     | 是                             | 不适用                               |
| DFS 返回后恢复 | 失败分支恢复；成功整体结束     | 否，永久保留                         |
| 外层循环       | 枚举所有可能起点               | 扫描所有格子，遇到新陆地才启动 flood |

因此两课既共享网格搜索骨架，又应在关系图中以 `contrasts_with` 强调状态生命周期，而不是只写一个含糊的 `same_pattern_as`。

## N Queens：把约束检查变成状态

若每放一个皇后都扫描整个棋盘检查冲突，代码会重复做大量工作。课程把已经使用的约束缓存为三组布尔状态：

```text
col[i]       第 i 列是否已有皇后
dia1[index+i]
dia2[index-i+n-1]
```

其中 `index` 表示当前行，`i` 表示候选列。

对角线索引的目的，是让同一条对角线映射到同一个数组位置：

- 一组使用 `row + col`；
- 另一组使用 `row - col + n - 1`，通过平移避免负下标；
- 两组数组长度均为 `2*n - 1`。

一次选择需要同步更新四份状态：

```text
row.push_back(i)
col[i] = true
dia1[index+i] = true
dia2[index-i+n-1] = true
```

递归返回后必须按相反顺序全部恢复。遗漏任何一个布尔数组，都会让后续分支错误地认为某条线仍被占用。

N Queens 展示了回溯与约束满足搜索的关系：不是先生成所有棋盘再检查，而是在每一层利用局部约束阻止非法分支继续生长。

## 正确性：三种证明抓手

### 1. 搜索树覆盖

先说明每个合法答案都对应搜索树中的一条路径：

- 每层枚举了当前状态全部合法候选；
- 递归参数准确表示选择后的新状态；
- 基本情况保存且只保存完整解。

这解释“不漏解”。

### 2. 状态合法性

说明任何被保存的路径都满足题目约束：

- 排列只选 `!used[i]`；
- 组合只从 `start` 之后选择；
- Word Search 只走合法未访问邻格；
- N Queens 只选未占列与未占对角线。

这解释“不产生非法解”。

### 3. 剪枝安全

剪枝不能只说“这样更快”，必须证明被剪分支不可能包含答案。

08-05 的证明核心是：

```text
剩余候选数 < 剩余槽位数
⇒ 无论怎样选择都无法得到长度 k
⇒ 整个分支可以安全舍弃
```

N Queens 的列/对角线检查同样是一类约束剪枝：已经冲突的位置不可能出现在任何合法扩展中。

## 复杂度与实验边界

### 课程直接表达

08-02 的课件把电话号码组合的分支增长写成类似：

```text
3^n = O(2^n)
```

这应按课程原貌保留，但必须附带数学更正：若 `n` 是输入长度，`3^n` **不是** `O(2^n)`；电话号码数字的候选数还不统一，`7`、`9` 有四个字母。更准确的输出数量由每一位候选数的乘积决定。

08-05 直接展示两次平台运行：

- 基线：76 ms；
- 剪枝版：69 ms。

这只能说明该次平台样例中的观测差异，不能证明剪枝改变了渐进复杂度，也不能从一次运行推导稳定加速比例。

### 编辑推导

课程没有系统给出其余题的渐进复杂度。复习时可以基于代码推导，但必须标成 `editorial_inference`：

| 课次  | 时间思路                                               | 辅助空间思路                          |
| ----- | ------------------------------------------------------ | ------------------------------------- |
| 08-01 | 至少与生成答案总字符数成正比                           | 递归深度与当前字符串长度相关          |
| 08-03 | 输出规模为排列数，复制每个长度 `n` 的答案也要计入      | `used`、当前路径与递归深度均为 `O(n)` |
| 08-04 | 输出规模为组合数，复制每个长度 `k` 的答案要计入        | 当前路径与递归深度 `O(k)`             |
| 08-05 | 剪枝减少无效搜索节点，但不应仅凭运行时间宣称降阶       | 与组合基线同量级                      |
| 08-06 | 宽松上界可写 `O(mn·4^L)`，实际受不可回头与字符剪枝影响 | `visited O(mn)` 加递归栈 `O(L)`       |
| 08-07 | 每格最多被全局处理一次，可推导 `O(mn)`                 | `visited O(mn)`，递归栈最坏 `O(mn)`   |
| 08-08 | 搜索规模依赖约束剪枝，不应把 `O(n!)` 冒充课程原话      | 三组占用表、当前路径与递归栈          |

输出敏感问题要把“搜索节点数”“答案数”和“复制答案成本”分开讨论。

## 本章常见错误清单

1. **把输入结构与搜索树混为一谈**：字符串和数组不是树，树来自选择展开。
2. **只写递归，不定义部分解和候选域**：代码可能能跑，却无法解释或验证。
3. **把所有递归 DFS 都叫回溯**：flood fill 没有选择撤销语义时，应称为 DFS/连通块遍历。
4. **排列中忘记恢复 `used[i]`**：后续分支会永久失去元素。
5. **组合递归仍从 `start` 而不是 `i+1` 开始**：可能重复选择或生成重复组合。
6. **剪枝上界漏掉括号或 `+1`**：会多搜无效分支，甚至错误剪掉合法解。
7. **Word Search 失败后不恢复 `visited`**：一次失败污染其他路径。
8. **看到成功分支没恢复就机械判错**：先检查是否整体早退。
9. **flood fill 返回时恢复 `visited`**：同一岛屿会被重复计数。
10. **混淆字符 `'1'` 与整数 `1`**：网格类型是 `char` 时比较对象不同。
11. **N Queens 对角线索引写反**：重点核对 `row+col` 与 `row-col+n-1`。
12. **只恢复棋盘，不恢复占用表**：不同状态源会失去一致性。
13. **把平台运行时间当复杂度证明**：一次 76 ms/69 ms 不能证明渐进结论。
14. **把练习题标题扩写成课程题解**：只被列出的题目不能补造代码与复杂度。

## 面试中的统一表达框架

### 第一步：定义状态

> “当前递归层已经完成了什么？哪些变量共同表示这个部分解？”

例如：

```text
排列：p + used
组合：c + start
Word Search：坐标 + index + visited
N Queens：当前行 + row + col/dia1/dia2
```

### 第二步：定义候选

不要只说“循环所有可能”：

- 候选是否来自映射表？
- 是否必须未使用？
- 是否只允许从递增区间选择？
- 是否必须在网格内？
- 是否要满足列和对角线约束？

### 第三步：说明基本情况

基本情况应和“完整答案”的定义一致，而不是简单背 `index == n`。

### 第四步：说明选择、递归与撤销

按真实执行顺序表达：

> “我先更新当前路径和约束状态，再递归下一层；返回后，如果这些修改只属于当前分支，就逐项恢复。”

### 第五步：证明覆盖与剪枝

至少回答：

1. 为什么所有合法候选都被枚举？
2. 为什么保存的结果一定合法？
3. 为什么撤销后兄弟分支看到正确状态？
4. 为什么剪掉的分支绝不可能完成答案？

### 第六步：复杂度与验证

先说明课程是否直接给出复杂度；若自行推导，定义变量、答案规模和复制成本。最后明确代码是编译、测试还是平台提交证据。

## 章级闪卡

1. **问**：输入不是树，为什么仍称树形问题？ **答**：每一步候选选择会把部分解展开成搜索空间树。
2. **问**：回溯最小状态模型有哪些部分？ **答**：部分解、候选域、基本情况、选择更新、递归推进和离开分支后的状态处理。
3. **问**：排列为什么需要 `used`？ **答**：每层可从所有未使用元素选择，同时必须防止同一元素在一条排列中重复出现。
4. **问**：组合为什么使用 `i+1`？ **答**：下一层只从更大的候选继续，避免元素复用与顺序重复。
5. **问**：组合剪枝上界如何得到？ **答**：由 `n-i+1 >= k-c.size()` 推出 `i <= n-(k-c.size())+1`。
6. **问**：Word Search 的 `visited` 为什么恢复？ **答**：它只描述当前路径，失败分支不能污染兄弟分支。
7. **问**：flood fill 的 `visited` 为什么不恢复？ **答**：它表示格子已归入一个全局处理过的连通块。
8. **问**：N Queens 两组对角线怎样索引？ **答**：一组 `row+col`，另一组 `row-col+n-1`。
9. **问**：`3^n = O(2^n)` 是否成立？ **答**：若 `n` 是同一个增长变量则不成立；应保留课程原话并明确更正。
10. **问**：运行时间从 76 ms 到 69 ms 能证明什么？ **答**：只是一组平台观测，不能单独证明渐进复杂度降低。
