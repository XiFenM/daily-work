# 第 9 章 动态规划基础

## 本章解决什么问题

第八章把问题展开成搜索树，在一条路径上做选择、递归和恢复；第九章从另一类重复工作出发：

> 当许多搜索分支反复求解同一个子问题时，怎样给子问题一个稳定的状态定义，只计算一次，再按依赖顺序组合答案？

本章的重点不是背一条统一的 `dp` 公式，而是建立一套建模流程：

```text
写出原问题或递归语义
→ 识别重复出现的子问题
→ 用最少且足够的参数定义状态
→ 列出从当前状态出发的选择
→ 写出状态转移
→ 确定基本情况与初始化
→ 选择自顶向下或自底向上的计算顺序
→ 明确答案从哪个状态读取
→ 再讨论空间压缩与具体解恢复
```

## 从递归到动态规划

### 纯递归：先把问题说清楚

动态规划通常不是从数组开始，而是从一个有明确返回语义的子问题开始。

以 Climbing Stairs 为例：

```text
ways(n)：爬上 n 阶台阶的方法数
```

最后一步只有两种互斥选择：

```text
从 n-1 阶再走 1 阶
从 n-2 阶再走 2 阶
```

所以：

```text
ways(n) = ways(n-1) + ways(n-2)
```

这一步先保证问题分解不重不漏；是否优化，是下一层问题。

### 重叠子问题：为什么要缓存

在 Fibonacci、Climbing Stairs、Integer Break 和 House Robber 的递归树中，同一个参数状态会沿不同路径重复出现。纯递归会重复展开相同子树。

记忆化搜索的关键动作是：

```text
进入状态
→ 若缓存已有结果，直接返回
→ 否则递归计算
→ 把当前状态结果写入缓存
→ 返回
```

缓存的键必须覆盖决定子问题的全部参数。例如：

- Fibonacci、Climbing Stairs：一个规模参数；
- House Robber：当前后缀起点；
- 0-1 背包：物品边界与剩余容量；
- Partition Equal Subset Sum：当前物品索引与待凑目标和。

若键少了一个维度，不同子问题会错误地共用结果；若多了无关维度，则会降低复用率并浪费空间。

### 自底向上：把依赖顺序显式化

自底向上版本不再依赖函数调用栈，而是先计算基本状态，再按依赖方向填表。

一份完整的自底向上描述至少要包含：

1. 表项语义；
2. 表格范围；
3. 初始化；
4. 转移；
5. 遍历方向；
6. 答案位置。

只写“开一个 `dp` 数组，然后循环”不足以解释算法。

## 动态规划的六问状态模型

面对一个候选 DP 问题，可以依次回答六个问题。

### 1. 状态表示什么？

状态必须是一句可以独立判断对错的话，而不只是变量名。

| 课次  | 状态语义                                                          |
| ----- | ----------------------------------------------------------------- |
| 09-01 | `fib(i)` 或 `memo[i]` 是第 `i` 个斐波那契值                       |
| 09-02 | `ways(i)` 是爬上 `i` 阶的方法数                                   |
| 09-03 | `best(i)` 是把整数 `i` 至少拆成两部分后可得到的最大乘积           |
| 09-04 | `tryRob(index)` 是考虑房屋后缀 `[index...n-1]` 时可偷到的最大价值 |
| 09-05 | `F(i,c)` 是考虑物品 `[0...i]`、容量为 `c` 时的最大价值            |
| 09-07 | 状态表示使用某个物品前缀能否恰好凑出目标和                        |
| 09-08 | `LIS(i)` 是**以 `nums[i]` 结尾**的最长严格上升子序列长度          |
| 09-09 | `LCS(m,n)` 描述两个序列相应前缀或后缀范围上的最长公共子序列长度   |

同一道题可以有不同的合法状态定义。09-04 还把“考虑 `[0...x]`”留作另一种 House Robber 思考方向。定义变化后，初始化、遍历方向与答案位置也必须同步变化。

### 2. 当前状态有哪些选择？

转移来自选择，而不是凭空出现：

- 爬楼梯：最后走 1 阶或 2 阶；
- Integer Break：先拆出 `j`，剩余 `i-j` 可以不再拆，也可以继续拆；
- House Robber：选择某一间房后跳过相邻房；
- 0-1 背包：不选当前物品，或在容量足够时选择一次；
- Partition Equal Subset Sum：当前数字不进入目标子集，或进入；
- LIS：从所有 `j<i` 且 `nums[j]<nums[i]` 的结尾状态转移；
- LCS：当前字符相等时共同推进，不等时比较舍弃一侧的两个状态。

### 3. 基本情况或初始化是什么？

基本情况必须和状态语义一致：

- Climbing Stairs 课程代码用 `memo[0]=1, memo[1]=1`；
- Integer Break 需要维护“至少拆成两部分”的问题契约；
- 0-1 背包二维表首先初始化只考虑第 0 件物品的一行；
- LIS 每个单元素序列都能形成长度为 1 的严格上升子序列，因此表格初值为 1；
- 空输入、容量为 0、总和为奇数等边界应在访问数组前处理。

初始化不是模板装饰。它决定后续表项代表的真实集合。

### 4. 依赖是否已经计算？

计算顺序必须保证转移读取的是预期版本：

- Fibonacci 与 Climbing Stairs 从小下标向大下标；
- 09-04 的后缀状态从右向左；
- 0-1 背包二维表按物品层推进；
- 一维 0-1 背包对容量从大到小更新；
- LIS 的外层 `i` 从左向右，内层只查看 `j<i`；
- LCS 的方向取决于状态采用前缀还是后缀定义，不能脱离定义背循环模板。

### 5. 最终答案在哪里？

答案不一定是数组最后一个表项：

- Fibonacci、Climbing Stairs：读取目标规模状态；
- 0-1 背包：读取处理完全部物品、容量为 `C` 的状态；
- Partition Equal Subset Sum：读取目标容量是否可达；
- LIS：最长序列可以在任何位置结束，所以取 `max_i LIS(i)`，不能直接返回 `memo[n-1]`；
- 需要具体解时，最优值所在位置还是反向追溯的起点。

### 6. 需要最优值，还是一组具体解？

只求数值时，很多历史状态可以覆盖；要恢复选择序列时，必须保留足够的前驱信息。

09-09 用 LIS 与 0-1 背包说明：

```text
求最优值：保存每个状态的最优数值
恢复具体解：从最优终点反向判断哪个前驱产生当前值
```

一维背包压缩会覆盖物品层历史；若没有额外保存选择或前驱，就不能仅凭最终一行还原具体物品组合。

## Integer Break：转移必须覆盖两种剩余语义

把 `i` 拆出第一部分 `j` 后，剩余 `i-j` 有两种合法处理方式：

1. 不再拆：乘积为 `j * (i-j)`；
2. 继续按最优方式拆：乘积为 `j * best(i-j)`。

因此课程代码比较：

```text
best(i) = max over j of:
          j * (i-j)
          j * best(i-j)
```

若只保留第二项，就会强迫剩余部分继续拆，改变原问题；若只保留第一项，又不会复用子问题最优解。

本课是“最优子结构”最清楚的例子：原问题的最优值可以由更小问题的最优值参与组合。但这一性质仍需配合正确状态、选择覆盖和基本情况，不能单独当作完整证明。

## House Robber：状态定义决定代码形状

09-04 把状态定义成：

```text
考虑偷窃 [x...n-1] 范围内房屋时能得到的最大价值
```

课程版本枚举当前后缀中第一间被偷的房屋 `i`，随后子问题从 `i+2` 开始：

```text
f(x) = max over i>=x of value[i] + f(i+2)
```

因此屏幕中的记忆化版和自底向上版都包含一层候选枚举，总时间为二次量级。不要在没有改写转移的情况下，把常见的线性 House Robber 公式冒充成视频原码。

如果把状态改成“考虑 `[0...i]` 的最大价值”，才可以进一步推导常见的两选择转移：是否偷第 `i` 间房。课程只把这个方向留作思考，不能把未展示的实现写成课程直接内容。

## 0-1 背包：二维状态与两个分支

### 问题模型

课程给出：

- 背包容量 `C`；
- `n` 件不同物品，编号 `0...n-1`；
- 第 `i` 件重量 `w(i)`、价值 `v(i)`；
- 每件物品最多选择一次；
- 总重量不超过容量，最大化总价值。

状态：

```text
F(i,c)：考虑物品 [0...i]、容量为 c 时的最大价值
```

转移：

```text
不选 i：F(i-1,c)
选择 i：v(i) + F(i-1,c-w(i))，仅当 w(i) <= c
```

所以：

```text
F(i,c) = max(F(i-1,c), v(i) + F(i-1,c-w(i)))
```

这里两项都读取上一物品层 `i-1`，正是“每件最多一次”的状态保证。

### 为什么简单贪心失败

09-05 尝试优先选择单位重量价值 `v/w` 最高的物品，并给出容量为 5 的反例：贪心得到 16，而另一组合价值为 22。

这个反例只否定当前局部规则对一般 0-1 背包的保证；它不证明所有贪心算法都无效，也不替代第十章对贪心选择性质的系统讨论。

### 从二维表到两行

第 `i` 行只依赖第 `i-1` 行，因此物理存储可以只保留两行：

```text
当前行：i % 2
上一行：(i-1) % 2
```

时间状态数没有变化，仍是物品数乘容量；变化的是辅助空间。

### 从两行到一行

一维数组把“上一行”和“当前行”放在同一个物理数组中。更新第 `i` 件物品时，容量必须倒序：

```text
for j = C down to w[i]:
    memo[j] = max(memo[j], v[i] + memo[j-w[i]])
```

倒序保证 `j-w[i] < j`，读取时较小容量位置尚未在当前物品轮次被覆盖，仍代表上一物品层。若正序更新，可能读取本轮刚写入的值，使同一物品被重复使用，破坏 0-1 约束。

### 变种边界

09-06 还列出：

- 完全背包：每种物品可以无限使用；
- 多重背包：每种物品有给定数量；
- 多维费用背包：同时受重量、体积等多个容量维度限制；
- 带互斥、依赖等物品关系的变种。

课程在完全背包段先说明：容量有限时，每种正重量物品实际可取次数存在上限，因此可以把有限重复份数按 `1,2,4,8,...` 的组来表示；随后才另行引出具有显式 `num(i)` 数量限制的多重背包。[course_direct | 09-06 ev-008]

人工逐句听审确认，这个二进制表示确实由讲师放在“完全背包”段，而不是模型误归类。数学上必须补足边界：先在 `w_i>0` 时令 `M_i=floor(C/w_i)`，再把 `M_i` 拆成若干个 2 的幂与一个 remainder，把每组视为一件 0-1 物品；不能无限添加幂次，也不能漏掉余数组。它优化的是“平铺 `M_i` 份”这一转换，不优于专用完全背包 `O(nC)` DP。[editorial_inference]

课程对其余变体只做概念引入，没有为每种变体给出完整状态、代码和复杂度。

## Partition Equal Subset Sum：从分割到可达性背包

若数组总和 `sum` 为奇数，不可能分成两个等和子集。若为偶数，目标变成：

```text
能否从每个正整数最多选择一次，恰好凑出 C = sum/2？
```

这就是布尔型 0-1 背包：

```text
F(i,c) = F(i-1,c) OR F(i-1,c-nums[i])
```

本课同时展示二维记忆化搜索与一维倒序动态规划。

需要特别保留两个 QA 边界：

1. 课程幻灯片列出 `n<=200`、`C<=10000`，但示例运算量写成 `100*10000=100 万`；若把两项最大值同时代入是 200 万，仍属同一百万级可行性判断。
2. 屏幕一维代码把 `memo[j]` 初始化为 `nums[0]==j`，不是通用 subset-sum 常见的 `memo[0]=true`。它对当前“平分两半”最终判定仍可由补集对称性解释，但复用为一般模板时必须重新定义初始化语义。

## LIS：用“固定结尾”定位子问题

“在 `[0...i]` 中求 LIS”仍可能没有稳定的转移终点；课程把状态进一步定位为：

```text
LIS(i)：以 nums[i] 为结尾的最长严格上升子序列长度
```

于是所有合法前驱都满足：

```text
j < i 且 nums[j] < nums[i]
```

转移为：

```text
LIS(i) = max(1, 1 + LIS(j))
         for every j<i with nums[j]<nums[i]
```

课程用反例强调：

- `memo` 不必单调；
- 不能向左找到一个较小元素就停止；
- 最长序列不一定以最后一个输入元素结束；
- 最终必须取所有 `LIS(i)` 的最大值。

视频只提及还存在结合二分查找/贪心的 `O(n log n)` 非 DP 解法，没有展示实现；正式笔记不补造这段代码。

## LCS、最短路与具体解恢复

### LCS

09-09 用最长公共子序列说明二维序列状态。字符相同时，可以共同推进；字符不同时，比较舍弃一侧字符的两个子问题。

视频展示状态定义和转移，并把完整的递归、记忆化和自底向上实现留作练习。因此本章可以记录公式框架，但不能声称课程已经展示了完整 LCS 代码或复杂度分析。

### Dijkstra 的课程表述边界

课程幻灯片把 Dijkstra 单源最短路径算法放在“也是动态规划”的延伸中，并用：

```text
shortestPath(x) = min(shortestPath(a) + w(a→x))
```

表达从候选前驱松弛到 `x` 的最优值关系。

本章按课程原貌记录这一状态转移视角，但不把它扩写成无条件的算法分类结论：视频没有在本课展开 Dijkstra 的完整贪心选点机制、适用权重条件、实现或复杂度。复习时应区分“最短路数值具有最优子结构/松弛关系”和“具体算法用什么策略确定处理顺序”。

### 具体解恢复

09-09 演示两类反向追溯：

- 从 LIS 最大值位置向左寻找能够接到当前状态的前驱；
- 从 0-1 背包二维表右下角反向判断某件物品是否被选中。

恢复流程通常是：

```text
定位最优终点
→ 比较当前状态与候选前驱
→ 记录产生当前值的选择
→ 移动到前驱状态
→ 到达基本状态后反转或整理结果
```

并列最优时可能存在多条合法路径；课程示例只演示一条具体解，不等于枚举全部最优解。

## 复杂度分析框架

动态规划的时间复杂度通常可以拆成：

```text
状态数量 × 每个状态枚举的转移数量
```

本章代表例子：

| 问题/版本                  | 状态数量           | 单状态工作              | 时间量级          | 辅助空间          |
| -------------------------- | ------------------ | ----------------------- | ----------------- | ----------------- |
| Fibonacci 纯递归           | 调用树指数增长     | 常数                    | 课程记为 `O(2^n)` | 递归栈另计        |
| Fibonacci 记忆化/迭代      | `O(n)`             | 常数                    | `O(n)`            | 缓存或表格 `O(n)` |
| Integer Break 自底向上     | `n` 个目标整数     | 枚举拆分点 `O(n)`       | `O(n²)`           | `O(n)`            |
| House Robber 课程版本      | `n` 个后缀状态     | 枚举第一间偷取房 `O(n)` | `O(n²)`           | `O(n)`            |
| 0-1 背包二维表             | `n(C+1)`           | 常数个选/不选分支       | `O(nC)`           | `O(nC)`           |
| 0-1 背包两行/一行          | 仍为 `n(C+1)`      | 常数                    | `O(nC)`           | `O(C)`            |
| Partition Equal Subset Sum | `n(sum/2+1)`       | 常数个逻辑分支          | `O(n·sum)`        | 一维版 `O(sum)`   |
| LIS 动态规划               | `n` 个固定结尾状态 | 枚举所有更早位置 `O(n)` | `O(n²)`           | `O(n)`            |

其中部分空间结论或实现级时间结论是根据屏幕表格和循环结构做的 `editorial_inference`；单课笔记分别标明课程直接口述与编辑推导，不能在章级表中抹平来源层级。

空间压缩通常只减少存储，不自动降低时间复杂度；反过来，它还可能牺牲具体解恢复所需的历史信息。

## 课程冲突与人工 QA 发现

### 1. Fibonacci 的 `F(0)` 不一致

09-01 幻灯片公式写 `F(0)=1, F(1)=1`，但随后三版 C++ 代码都实现 `F(0)=0, F(1)=1`，运行结果 `fib(10)=55` 也对应后者。两套定义必须分别记录，不能静默统一。

### 2. 数值溢出不是性能提升

09-01 的记忆化版本在 `n=1000` 上调用次数和耗时明显下降，但屏幕中的 32 位 `int` 结果已经溢出。运行得快不等于数值正确；性能实验与结果类型必须分别审查。

### 3. 状态版本不能共用一个笼统模型

记忆化函数、二维表、两行表和一维表即使求同一个问题，也可能具有不同的缓存键、初始化、遍历方向与答案位置。Prompt v1.6 和本地门禁要求把这些版本分开绑定，防止把后一个版本的状态倒灌到前一个版本。

### 4. 课程直接复杂度与编辑推导要分层

若视频只展示数组尺寸和循环结构，本项目可以推导复杂度，但必须标为 `editorial_inference`；不能伪装成讲师口述。09-04、09-05、09-06、09-07 的多项空间/时间分析均按此规则校准。

### 5. 代码通过测试也可能有工程告警

09-05 屏幕代码使用 `std::max` 但没有显式展示 `<algorithm>`；09-07 两段代码在严格 `-Werror` 下存在 `int` 与 `size_type` 的符号性比较告警。测试通过与可移植、零告警构建是不同维度。

### 6. 二进制拆分的课程归属与数学边界要分开

09-06 的音频确实在完全背包段讲到 `1,2,4,8,...` 分组，随后才引入多重背包；笔记保留这一课程顺序。同时，有限容量只会给正重量物品导出有限次数上界，转换时仍需显式截断并保留 remainder，不能把简略口述扩写成无限幂次构造。

## 常见错误

1. **只记数组名，不写状态语义。** `dp[i]` 本身不能说明前缀、后缀、结尾、容量或选择范围。
2. **看到递归就称动态规划。** 还需要重叠子问题、可复用状态和正确转移。
3. **缓存键不完整。** 0-1 背包若只缓存物品索引、不缓存容量，会混合同一物品边界下的不同子问题。
4. **漏掉 Integer Break 的“不再拆”分支。** `j*(i-j)` 与 `j*best(i-j)` 都要比较。
5. **状态定义变了，转移没变。** `[x...n-1]` 与 `[0...x]` 的 House Robber 版本不是换个注释即可。
6. **把常见最优实现冒充课程实现。** 09-04 视频展示的是二次 House Robber 版本，不是常见线性公式。
7. **一维 0-1 背包容量正序。** 这会读取当前物品轮次刚更新的值，可能重复使用同一物品。
8. **把空间压缩写成时间优化。** 状态数和转移数没有随物理存储行数减少。
9. **把 `memo[n-1]` 当成 LIS 答案。** 最长上升子序列可能在更早位置结束。
10. **认为 LIS 表格单调。** 输入值与固定结尾最优长度都可能下降。
11. **压缩表后仍声称能直接恢复物品。** 被覆盖的物品层信息不会自动存在。
12. **把 Dijkstra 的课程状态式当成完整算法。** 本课没有展开选点、权重条件、实现与复杂度。
13. **把 09-10 的题名清单当成题解。** 文本没有题号、平台、题面、状态、代码或复杂度。
14. **把课程 IDE 运行或 LeetCode Accepted 当成本地验证。** 两类证据必须分开。

## 章级闪卡

1. **问**：重叠子问题说明什么？ **答**：不同递归路径会重复求同一状态，适合缓存或按表格顺序只计算一次。
2. **问**：最优子结构等于完整正确性证明吗？ **答**：不等于；还要证明状态、选择覆盖、转移、初始化和答案位置正确。
3. **问**：记忆化与自底向上的主要差异？ **答**：一个按需求递归并缓存，一个显式按依赖顺序填表。
4. **问**：DP 状态最少要说清什么？ **答**：每个维度的范围、值的含义和所代表的输入范围。
5. **问**：Integer Break 为什么比较两种乘积？ **答**：剩余部分可以停止拆分，也可以继续按最优方式拆分。
6. **问**：0-1 背包二维转移的两个分支？ **答**：不选当前物品，或容量允许时选择一次。
7. **问**：一维 0-1 背包为何容量倒序？ **答**：保证读取较小容量时仍是上一物品层，避免当前物品重复使用。
8. **问**：LIS 为什么固定结尾？ **答**：这样才能枚举所有合法前驱并建立稳定转移。
9. **问**：LIS 为什么不能返回最后一格？ **答**：最长序列不一定以最后一个输入元素结束。
10. **问**：空间压缩的主要代价？ **答**：历史层被覆盖，可能无法直接恢复具体选择。
11. **问**：09-01 的 `F(0)` 有什么冲突？ **答**：幻灯片写 1，三版代码与运行结果使用 0。
12. **问**：09-07 的百万级估算如何理解？ **答**：课程代入 100×10000；同时代入给定最大 `n=200` 是 200 万，量级结论不变。
13. **问**：Dijkstra 在本章应怎样表述？ **答**：记录课程给出的最短路状态与松弛式，同时说明本课没有展开完整算法机制。
14. **问**：09-10 提供了什么？ **答**：16 个继续练习的题名，而不是 16 份题解。
