## 删除一个普通节点的基本动作

设 `cur` 指向待删节点的前驱：

```text
cur
 ↓
[2] → [3] → [4]
        ↑
     待删除
```

课程图解和代码使用：

```cpp
ListNode* delNode = cur->next;
cur->next = delNode->next;
delete delNode;
```

[course_direct + visual_direct | ev-003–ev-005 | 视频 01:15–12:03]

三步分别是：

1. 保存待删节点地址；
2. 让前驱直接指向待删节点的后继；
3. 在 C++ 手动释放已经退出主链的节点。

[course_direct + visual_direct | ev-003, ev-004 | 视频 01:15–06:51]

这个动作也能删除尾节点：若 `delNode->next==NULL`，赋值后 `cur->next` 变为 `NULL`。[course_direct | ev-003 | 视频 01:15–03:43]

### 为什么不能直接删除真实头结点

真实头结点没有链表内的前驱，因此不存在可以执行：

```text
前驱->next = head->next
```

的真实节点。[course_direct + visual_direct | ev-003 | 视频 01:15–03:43]

这迫使无虚拟头结点的实现单独修改局部变量 `head`，也正是 `dummyHead` 要消除的特殊性。[course_direct + editorial_inference | 基于 ev-003, ev-005, ev-006 | 视频 01:15–13:12]

## 解法一：不使用虚拟头结点

### 阶段一：清理连续命中的头结点

屏幕代码先执行：

```cpp
while (head != NULL && head->val == val) {
    ListNode* delNode = head;
    head = head->next;
    delete delNode;
}
```

[course_direct + visual_direct | ev-005 | 视频 06:51–12:03]

必须使用 `while`，因为开头可能有多个连续目标值。例如：

```text
6 → 6 → 1 → ...
```

只执行一次 `if` 会删除第一个 6，却留下新的头结点 6；循环会一直删除，直到：

- `head==NULL`，表示整条链表都被删空；或
- `head->val!=val`，表示当前头结点应保留。

[course_direct + editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

每次删除前必须先保存旧头结点，再让 `head` 前移，最后释放旧节点；若先释放旧头再读取其 `next`，就会访问已释放内存。[visual_direct + editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

### 阶段二：重新检查空链表

头部清理后，代码立刻执行：

```cpp
if (head == NULL)
    return NULL;
```

[course_direct + visual_direct | ev-005 | 视频 06:51–12:03]

这是必要门禁。若链表原本为空，或所有节点都等于 `val`，`head` 会是 `NULL`；若继续创建 `cur=head` 并访问 `cur->next`，会产生空指针解引用。[course_direct + editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

### 阶段三：处理剩余节点

此时 `head` 非空且 `head->val!=val`，可以令：

```cpp
ListNode* cur = head;
```

然后检查 `cur->next`：

```cpp
while (cur->next != NULL) {
    if (cur->next->val == val) {
        ListNode* delNode = cur->next;
        cur->next = delNode->next;
        delete delNode;
    }
    else
        cur = cur->next;
}
```

[course_direct + visual_direct | ev-005 | 视频 06:51–12:03]

### 删除后为什么不推进 `cur`

若删除了 `cur->next`，新的 `cur->next` 还没有检查，且它也可能等于 `val`。因此删除分支保持 `cur` 不动，下一轮继续检查新后继。[visual_direct + editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

例如：

```text
1 → 6 → 6 → 2
↑
cur
```

删除第一个 6 后仍应让 `cur` 留在 1，才能继续删除第二个 6。若此时推进 `cur`，就会漏检连续目标值。[editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

只有 `cur->next->val!=val` 时，当前后继才确认应保留，于是用 `cur=cur->next` 扩大已经处理完成的前缀。[visual_direct + editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

## 解法二：使用虚拟头结点统一逻辑

### 创建一个假的头结点

课程创建：

```cpp
ListNode* dummyHead = new ListNode(0);
dummyHead->next = head;
```

[course_direct + visual_direct | ev-006, ev-007 | 视频 12:03–15:19]

结构变成：

```text
dummyHead → 原 head → ...
```

于是：

- 原头结点的前驱是 `dummyHead`；
- 原链表为空时，`dummyHead->next==NULL`；
- 后续始终可以从某个前驱 `cur` 检查 `cur->next`。

[course_direct + visual_direct + editorial_inference | 基于 ev-006, ev-007 | 视频 12:03–15:19]

`dummyHead` 的值 0 不参与判断，因为循环检查的是 `cur->next->val`，不是 `cur->val`。即使 `val==0`，虚拟节点也不会被当作真实数据删除。[visual_direct + editorial_inference | 基于 ev-007 | 视频 13:12–15:19]

### 一个循环覆盖所有真实节点

令：

```cpp
ListNode* cur = dummyHead;
```

之后使用与普通节点完全相同的循环：

```cpp
while (cur->next != NULL) {
    if (cur->next->val == val) {
        ListNode* delNode = cur->next;
        cur->next = delNode->next;
        delete delNode;
    }
    else
        cur = cur->next;
}
```

[course_direct + visual_direct | ev-006, ev-007 | 视频 12:03–15:19]

当第一个真实节点需要删除时，`cur` 就是 `dummyHead`，所以仍然执行统一的“前驱绕过后继”逻辑。无需单独移动 `head`，也无需在头删后额外判断链表是否为空。[course_direct + editorial_inference | 基于 ev-006, ev-007 | 视频 12:03–15:19]

### 返回前释放虚拟节点

`dummyHead` 由 `new` 创建，不属于返回链表的真实数据节点。屏幕代码先保存：

```cpp

```

再执行：

```cpp

```

顺序很重要：释放 `dummyHead` 后不能再通过它读取 `next`，所以必须先把最终真实头指针保存到 `retNode`。[visual_direct + editorial_inference | 基于 ev-007 | 视频 13:12–15:19]

## 状态转移与正确性

规范化证据把两种实现的正确性方法记为 `state_transition`，没有记录课程直接表述的循环不变量，也没有四阶段证明义务。下面的不变量和完整正确性解释属于编辑整理。[editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]

### 无 dummy 版的头部清理状态

每轮头删循环开始时：

- 已经从原链表前端移除的节点都等于 `val`；
- `head` 指向当前剩余链表的第一个节点，或为 `NULL`；
- 未被删除的剩余节点相对顺序保持不变。

[editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

若 `head!=NULL && head->val==val`，前移 `head` 并释放旧头会减少一个待删节点；循环最终得到空链表，或得到首值不等于 `val` 的剩余链表。[course_direct + editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

### 主循环的统一不变量

无论 `cur` 初始为真实 `head` 还是 `dummyHead`，都可以整理为：

> 每轮开始时，从返回入口之后到 `cur` 的已处理真实节点都不等于 `val`；`cur->next` 是下一个尚未裁决的真实节点，或为 `NULL`。

[editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]

两个分支分别保持它：

1. **命中**：绕过并释放 `cur->next`，已处理前缀不变，新的 `cur->next` 仍是下一个未裁决节点；
2. **未命中**：把 `cur` 推进到这个应保留节点，已处理且不含目标值的前缀扩大一个节点。

[visual_direct + editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]

循环终止于 `cur->next==NULL`，此时没有未处理节点；所有保留节点都不等于 `val`，所有被删除节点都等于 `val`，且保留节点相对顺序没有改变。[course_direct + editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]

### 终止性

每一轮要么：

- 删除一个真实节点，使链表节点总数减少 1；要么
- 让 `cur` 向后移动一个真实节点。

有限链表中这两种进展都不可能无限发生，因此循环会到达 `cur->next==NULL`。[editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]

| 动态额外节点   | 无                                 | 一个虚拟节点，返回前需释放            |
| 屏幕代码状态   | `shown_in_video/complete/not_run`  | `shown_in_video/complete/not_run`     |
| 逻辑结构       | 头部特殊循环 + 主循环 + 空链表门禁 | 一个主循环 + 保存返回头 + 释放 dummy  |

## 内存管理与 GC 说法的边界

### C++：先断链，再 `delete`

屏幕 C++ 代码先执行：

```cpp
cur->next = delNode->next;
```

再执行：

```cpp
delete delNode;
```

[visual_direct | ev-004, ev-005, ev-007 | 视频 03:43–15:19]

这样主链先停止引用待删节点，随后释放其内存。不能在 `delete delNode` 之后再读取或写入 `delNode->next`，那会访问已经释放的对象。[visual_direct + editorial_inference | 基于 ev-004, ev-007 | 视频 03:43–15:19]

目标帧中可以看到一行被注释的：

```cpp
// delNode->next = NULL;
```

它位于 `delete delNode;` 之后，不能在 C++ 中直接取消注释并按该顺序执行。[visual_direct + editorial_inference | 基于 ev-004, ev-007 | 视频 03:43–15:19]

### 课程对托管语言的说法

课程提到，在带垃圾回收的语言里可以把待删节点的 `next` 设为 `NULL`，帮助系统识别和回收节点。[course_direct | ev-004 | 视频 03:43–06:51]

这条建议需要按具体语言和运行时理解，不能推广成：

> 所有垃圾回收器都要求先把 `next` 置空，否则节点永远不能回收。

[editorial_inference | 基于 ev-004 | 视频 03:43–06:51]

对常见**追踪式 GC**，对象能否回收通常取决于它是否仍能从 GC roots 到达。节点从主链断开、局部引用也不再存活后，即使该对象内部的 `next` 字段仍非空，它本身也可能已经不可达；因此置空不是所有追踪式 GC 的普遍必要条件。[editorial_inference | 基于 ev-004 | 视频 03:43–06:51]

在某些对象生命周期、引用链、调试或特定运行时场景中，主动断开不再需要的引用可能缩短其他对象的可达时间或表达所有权意图，但是否必要应查阅对应语言和 GC 规则。本课没有展开这些运行时差异。[course_direct + editorial_inference | 基于 ev-004 | 视频 03:43–06:51]

因此正式记忆应分三层：

- 课程直接说法：托管语言中可考虑把链接置空；
- C++ 屏幕实现：断链后 `delete`，不能在释放后访问节点；
- 工程边界：追踪式 GC 以可达性为核心，置空不是统一硬规则。

## 复杂度分析：仅为编辑推导

规范化顶层 `complexity.time/space` 均为 `null`，`complexityAnalyses` 的 `expressionObserved` 也为 `null`。视频没有直接显示复杂度公式。[editorial_inference | 基于 normalized complexity]

设原链表有 `n` 个真实节点。

### 无虚拟头结点版

- 头部循环每次删除一个节点；
- 主循环每次要么删除一个节点，要么让 `cur` 前进；
- 每个真实节点最多被处理常数次；
- 只使用 `head`、`cur`、`delNode` 等固定数量指针。

因此可整理为：

```text
时间复杂度：O(n)
辅助空间复杂度：O(1)
```

[editorial_inference | 基于 ev-005 | 视频 06:51–12:03]

### `dummyHead` 版

- 单个循环以同样方式删除或推进；
- 新建一个虚拟节点只增加常数空间；
- 保存 `retNode` 和释放 dummy 都是常数工作。

因此同样可整理为：

```text
时间复杂度：O(n)
辅助空间复杂度：O(1)
```

[editorial_inference | 基于 ev-007 | 视频 13:12–15:19]

| 方法           | 时间推导 | 辅助空间推导 | 说明                             |
| -------------- | -------- | ------------ | -------------------------------- |
| 无 dummy       | `O(n)`   | `O(1)`       | 两个阶段合计仍只线性处理每个节点 |
| `dummyHead` 版 | `O(n)`   | `O(1)`       | 一个统一循环和一个额外虚拟节点   |

两种实现的渐进复杂度相同。`dummyHead` 的价值是减少分支、统一状态和降低边界出错概率，不是改变渐进数量级。[editorial_inference | 基于 ev-005–ev-007 | 视频 06:51–15:19]

## 边界条件与常见错误

### 课程直接覆盖的边界

- 初始 `head==NULL`；[course_direct | ev-005 | 视频 06:51–12:03]
- 第一个或连续多个头结点等于 `val`；[course_direct | ev-005 | 视频 06:51–12:03]
- 所有节点都等于 `val`，删除后为空；[course_direct | ev-005 | 视频 06:51–12:03]
- 普通节点或尾节点等于 `val`。[course_direct | ev-003, ev-005 | 视频 01:15–03:43；06:51–12:03]

### 常见错误

1. **只用 `if` 删除一个头结点**：会漏掉连续命中的新头。[course_direct + editorial_inference | 基于 ev-005 | 视频 06:51–12:03]
2. **头删后不检查 `head==NULL`**：后续 `cur->next` 会解引用空指针。[course_direct | ev-005 | 视频 06:51–12:03]
3. **删除 `cur->next` 后仍推进 `cur`**：可能跳过新的连续目标节点。[visual_direct + editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]
4. **未命中时不推进 `cur`**：循环状态不变，会形成死循环。[editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]
5. **先 `delete delNode` 再读 `delNode->next`**：会访问已释放对象。[visual_direct + editorial_inference | 基于 ev-004, ev-007 | 视频 03:43–15:19]
6. **忘记释放 `delNode`**：在课程的 C++ 手动内存管理模型中会泄漏被断开的节点。[course_direct + visual_direct | ev-004, ev-007 | 视频 03:43–15:19]
7. **忘记释放动态创建的 `dummyHead`**：虚拟节点不属于返回结果，屏幕代码明确释放它。[course_direct + visual_direct | ev-007 | 视频 13:12–15:19]
8. **释放 dummy 后再读取 `dummyHead->next`**：必须先保存 `retNode`。[visual_direct + editorial_inference | 基于 ev-007 | 视频 13:12–15:19]
9. **把 dummy 的值 0 当作真实输入**：代码只判断 `cur->next`，dummy 值没有数据语义。[visual_direct + editorial_inference | 基于 ev-007 | 视频 13:12–15:19]
10. **把置空引用写成所有 GC 的硬要求**：追踪式 GC 通常按可达性判断对象是否可回收。[course_direct + editorial_inference | 基于 ev-004 | 视频 03:43–06:51]
11. **把 `O(n)/O(1)` 写成视频直接结论**：课程没有展示复杂度公式。[editorial_inference | 基于 ev-005, ev-007 | 视频 06:51–15:19]
12. **把完整屏幕代码写成已运行**：`complete` 只表示可见代码完整，验证仍是 `not_run`。[visual_direct | ev-005, ev-007 | 视频 06:51–15:19]
