## 基线版本：仍遍历到 `n`

课程先提交上一课的代码，核心循环为：

```cpp
for( int i = start ; i <= n ; i ++ ){
    c.push_back(i);
    generateCombinations(n, k, i + 1, c);
    c.pop_back();
}
```

[visual_direct | code-001, ev-001]

它的状态语义不变：

- `c`：当前已经选择的严格递增部分组合；
- `start`：本层最小可选数字；
- `i`：本层正在尝试的候选；
- 下一层传 `i+1`：同一数字不能再次使用，也不生成顺序重复；
- `push_back → recurse → pop_back`：做选择、探索、撤销选择。

[course_direct + visual_direct | ev-001]

### 基线为什么会走无效分支

以课程中的：

```text
n = 4
k = 2
```

为例，根节点若选择 `4`，当前：

```text
c = [4]
还需要 1 个数字
下一层候选 = [5,4] = 空
```

这条分支不可能得到长度为 2 的组合，但基线循环允许根节点尝试 `i=4`，因此仍会做一次加入、递归、返回和撤销。[course_direct + visual_direct | ev-002]

类似地，在更一般的输入中，只要某个部分组合后面的候选数少于剩余空位，它就不可能完成；这些节点就是剪枝目标。[course_direct | ev-002, ev-003]

## 剪枝公式逐步推导

### 第一步：还缺多少个数字

目标长度是 `k`，当前已经选择：

```text
c.size()
```

个数字，因此剩余空位数为：

```text
r = k - c.size()
```

[course_direct + visual_direct | ev-003]

这里的 `r` 是为了讲清推导而引入的记号；课程代码直接写 `k-c.size()`，没有新增变量。[补充说明]

### 第二步：从 `i` 开始还有多少候选

当前循环准备选择 `i`，之后可利用的数字来自闭区间：

```text
[i,n]
```

它包含 `i` 和 `n`，元素个数为：

```text
n - i + 1
```

[course_direct + visual_direct | ev-003]

注意这里把**当前准备选择的 `i`**也计入剩余的 `r` 个位置。循环体先执行 `c.push_back(i)`，所以用 `[i,n]` 计数与程序状态一致。[editorial_inference | 基于 code-002]

### 第三步：写出可完成性条件

要填满剩余 `r` 个位置，候选数量至少为 `r`：

```text
n - i + 1 >= r
```

代入：

```text
r = k - c.size()
```

得到：

```text
n - i + 1 >= k - c.size()
```

[course_direct + editorial_inference | 基于 ev-003]

### 第四步：解出 `i` 的上界

移项：

```text
i <= n - r + 1
```

再代回 `r`：

```text
i <= n - (k - c.size()) + 1
```

这就是课程写入循环的精确条件。[course_direct + visual_direct | formula-001, code-002, ev-003]

## 为什么末尾必须有 `+1`

最直接的边界检查是：

```text
k - c.size() == 1
```

即当前只差最后一个数字。此时任何 `i` 直到 `n` 都仍能完成组合，所以正确上界必须是：

```text
i <= n
```

代入课程公式：

```text
i <= n - 1 + 1
i <= n
```

恰好正确。若误写成：

```text
i <= n - (k - c.size())
```

此时就会变成 `i<=n-1`，错误漏掉以 `n` 作为最后一个数字的所有答案。[course_direct + editorial_inference | 基于 ev-003]

`+1` 不是补丁，而是闭区间长度公式 `n-i+1` 自然产生的结果。

## 基线与剪枝版只差在哪里

两版的递归契约、基本情况、状态更新和回溯动作都相同。核心差异只有循环上界：

| 版本   | 循环条件                      | 含义                                     |
| ------ | ----------------------------- | ---------------------------------------- |
| 基线   | `i <= n`                      | 尝试本层所有候选，包括已不可能填满的分支 |
| 剪枝版 | `i <= n - (k - c.size()) + 1` | 只尝试仍有足够候选填满剩余空位的分支     |

[visual_direct | code-001, code-002, ev-001, ev-003]

必须保留的共同逻辑：

```cpp
c.push_back(i);
generateCombinations(n, k, i + 1, c);
c.pop_back();
```

剪枝没有改变“组合按严格递增顺序生成”的规则，也没有改变达到 `c.size()==k` 时保存答案的规则。[course_direct + visual_direct | ev-001, ev-003]

## 为什么剪枝安全

视频用候选数量解释安全性；下面把论证整理完整。

### 被保留的分支

若：

```text
i <= n - (k - c.size()) + 1
```

则：

```text
n - i + 1 >= k - c.size()
```

闭区间 `[i,n]` 至少有足够数字填满剩余位置。它**可能**产生解，因此算法继续探索。[course_direct + editorial_inference | 基于 ev-003]

### 被剪掉的分支

若：

```text
i > n - (k - c.size()) + 1
```

则：

```text
n - i + 1 < k - c.size()
```

即使把 `[i,n]` 中所有数字都选上，也填不满组合。该分支不可能达到 `c.size()==k`，删除它不会漏掉答案。[course_direct + editorial_inference | 基于 ev-003]

### 完备性为何保持不变

对任意合法组合：

```text
a1 < a2 < ... < ak
```

在选择 `aj` 的那一层，序列中仍有：

```text
aj, a(j+1), ..., ak
```

共 `k-j+1` 个实际可用数字，它们都落在 `[aj,n]`。因此该闭区间的候选数不可能少于剩余空位数，合法答案路径不会违反剪枝条件。[editorial_inference]

剪枝删除的是“已经确定无法完成”的内部节点，不是从答案集合中删元素。

```cpp
private:

    // 求解C(n,k), 当前已经找到的组合存储在c中，需要从start开始搜索新的元素

        res.clear();
        if( n <= 0 || k <= 0 || k > n )
            return res;

        vector<int> c;
        generateCombinations(n, k, 1, c);
        return res;
    }
};
```

## 完整课程代码：剪枝版

```cpp
class Solution {
private:
    vector<vector<int>> res;

    // 求解C(n,k), 当前已经找到的组合存储在c中，需要从start开始搜索新的元素
    void generateCombinations(int n, int k, int start, vector<int> &c){
        if( c.size() == k ){
            res.push_back(c);
            return;
        }

        // 还有 k - c.size() 个空位，所以，[i...n]中至少要有 k - c.size() 个元素

            generateCombinations(n, k, i + 1, c);
            c.pop_back();

public:

        vector<int> c;
        generateCombinations(n, k, 1, c);
```

## 边界条件与常见错误

1. **忘记闭区间的 `+1`**：会漏掉使用边界数字 `n` 的合法答案。
2. **把剩余空位写成 `k-c.size()-1`**：公式推导时 `[i,n]` 已经包含当前将选的 `i`，会少算。
3. **用 `[i+1,n]` 的数量却仍与 `k-c.size()` 比较**：混淆选择前和选择后的状态。
4. **把上界改到递归调用参数**：剪枝针对当前层循环的最大候选，不改变下一层仍传 `i+1`。
5. **只写 `i<n-(k-c.size())+1`**：又把本应包含的上界排除。
6. **删除 `pop_back()`**：剪枝不能替代回溯状态恢复。
7. **把基线和优化版都标为同一状态模型**：二者循环条件不同，应分开记录。
8. **把 69 ms 当作复杂度证明**：墙钟观察与渐进分析是两类证据。
9. **声称项目运行通过**：项目只完成了语法编译，课程页面的 Accepted 属于视频证据。
