## 核心概念与定义

### 1. 复杂度实验

本课所说的复杂度实验，是让输入规模按固定倍数增长，记录算法运行时间，并根据耗时比例的长期趋势判断它更接近哪一类增长阶。[视频 00:00:00–00:02:24]

这与“在一个输入上跑得很快”不同。单个绝对耗时会混入机器性能、编译方式和常数成本；倍增实验试图通过比例观察规模项的影响。[视频 00:04:16–00:08:22] [整理推导]

### 2. 倍增比例 `T(2N) / T(N)`

若一段算法的耗时可近似写为：

```text
T(N) ≈ C · f(N)
```

那么相邻两次实验的比值为：

```text
T(2N) / T(N) ≈ [C · f(2N)] / [C · f(N)] = f(2N) / f(N)
```

固定常数 `C` 在相除时抵消，所以比例主要反映 `f(N)` 的增长方式。这一“常数被约掉”的解释是课程明确给出的实验依据。[视频 00:04:16–00:08:22]

### 3. 四类理论趋势

| 理论复杂度   | 规模从 `N` 变为 `2N` 时的理论比例     | 课程中的观察                          | 来源                     |
| ------------ | ------------------------------------- | ------------------------------------- | ------------------------ |
| `O(n)`       | `(2N) / N = 2`                        | `findMax` 的相邻耗时大体约 2 倍       | [视频 00:04:16–00:08:22] |
| `O(n^2)`     | `(2N)^2 / N^2 = 4`                    | `selectionSort` 的相邻耗时大体约 4 倍 | [视频 00:08:22–00:09:58] |
| `O(log n)`   | `log(2N) / log N = 1 + log 2 / log N` | `binarySearch` 的增幅很小             | [视频 00:09:58–00:13:18] |
| `O(n log n)` | `2N log(2N) / (N log N)`，即比 2 稍大 | `mergeSort` 的相邻耗时约 2 倍多一点   | [视频 00:13:18–00:14:53] |

### 1. 被测算法片段

```cpp
namespace MyAlgorithmTester {
    // O(logN)
    int binarySearch(int arr[], int n, int target) {
        int l = 0, r = n - 1;
        while (l <= r) {
            int mid = l + (r - l) / 2;
            if (arr[mid] == target) return mid;
            if (arr[mid] > target) r = mid - 1;
            else l = mid + 1;
        }
        return -1;
    }

    // O(N)
    int findMax(int arr[], int n) {
        assert(n > 0);
        int res = arr[0];
        for (int i = 1; i < n; i++)
            if (arr[i] > res)
                res = arr[i];
        return res;
    }
}
```

`findMax` 一次扫描数组；`binarySearch` 每轮缩小一半有序区间。视频同时展示了 `selectionSort` 和自底向上的 `mergeSort`，但规范化证据没有保存它们的完整代码，因此本笔记不从外部记忆重建。[视频 00:02:24–00:04:16]

## 公式推导

### 1. `O(n)` 与 `O(n^2)` 的倍增比

课程直接使用规模翻倍说明：[视频 00:04:16–00:09:58]

```text
O(n):   T(2N) / T(N) ≈ (C · 2N) / (C · N) = 2
O(n²):  T(2N) / T(N) ≈ (C · (2N)²) / (C · N²) = 4
```

这既解释了为何 `findMax` 应接近 2 倍，也解释了为何选择排序应接近 4 倍。[视频 00:04:16–00:09:58]

### 2. `O(log n)` 的倍增比

视频展示的公式为：[视频 00:09:58–00:12:00]

```text
log(2N) / log(N)
= (log 2 + log N) / log N
= 1 + log 2 / log N
```

随着 `N` 增大，分母 `log N` 增大，附加项 `log 2 / log N` 变小，所以规模翻倍只让对数算法的理论耗时增加很少。[视频 00:09:58–00:12:00]

### 3. `O(n log n)` 的倍增比

根据同课公式可以整理为：[视频 00:09:58–00:14:53] [整理推导]

```text
T(2N) / T(N)
≈ [2N · log(2N)] / [N · log N]
= 2 · [log(2N) / log N]
= 2 · (1 + log 2 / log N)
```

因此比例比 2 稍大，并随着 `N` 增大逐渐接近 2；这是课程对归并排序实验趋势的数学化整理，不是视频中完整展示的第二条公式。[整理推导]

## 正确性解释

本课的结构化证据将方法标为 `experimental_validation`，其核心论点是：比较 `T(2N)` 和 `T(N)` 时，固定常数系数会被抵消，剩余比例反映输入规模项的增长阶。[视频 00:04:16–00:08:22]

但需要区分三件事：

1. **理论推导**说明为什么某段代码应是某个复杂度。
2. **倍增实验**检查实测趋势是否与该预测相符。
3. **功能测试**检查算法返回值是否正确。

本课主要完成第 2 项，并用已知理论复杂度的算法作对照；它没有用实验代替第 1 项，也没有系统验证第 3 项。[视频 00:00:00–00:14:53] [整理推导]

1. **只测一个 `N`**：绝对耗时不能直接揭示增长阶。[视频 00:01:02–00:02:24]

## 复习区

### 核心清单

- 测复杂度要看一系列规模的增长趋势，不是只看一次运行有多快。[视频 00:00:00–00:02:24]
- 用 `2^i` 生成输入，可以直接比较 `T(2N)/T(N)`。[视频 00:01:02–00:08:22]
- `O(n)` 的理论倍增比是 2，`O(n^2)` 是 4。[视频 00:04:16–00:09:58]
- `O(log n)` 的倍增比为 `1 + log 2 / log N`，随 `N` 增大趋近 1。[视频 00:09:58–00:13:18]
- `O(n log n)` 的倍增比略大于 2，增长远慢于平方级。[视频 00:13:18–00:14:53]
- 实验验证增长趋势，不替代静态推导、功能测试或可复现基准。[整理推导]
