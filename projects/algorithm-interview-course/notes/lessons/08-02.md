## 从日志读懂回溯

### 1. 日志插入点

本课在同一递归函数中记录四类事件：

```text
进入函数：
    index : s

准备选择：
    digits[index] = c, use letters[i]

得到答案：
    get s, return

当前层全部候选完成：
    digits[index] = c complete, return
```

[course_direct + visual_direct | code-001, ev-001]

这些日志把原本不可见的调用栈展开成可读事件流。

### 2. `"234"` 的调用前缀

课程控制台显示的轨迹包含：

```text
0 :
digits[0] = 2, use a
1 : a
digits[1] = 3, use d
2 : ad
digits[2] = 4, use g
3 : adg
get adg, return
```

[visual_direct | ev-002]

这段轨迹说明：

1. 深度 `0` 选择 `a`；
2. 深度 `1` 选择 `d`；
3. 深度 `2` 选择 `g`；
4. 深度 `3` 已处理完三位，保存 `adg`；
5. 函数返回深度 `2`，随后尝试该层其他字母；
6. 深度 `2` 的候选全部完成后，再返回深度 `1`。

[course_direct + editorial_inference | 基于 ev-002]

### 3. 返回不是“重新从头计算”

返回发生时，程序回到调用点之后，继续当前 `for` 循环。它不会重新执行上层函数入口，也不会遗忘上层的 `index`、`s` 和循环位置。[editorial_inference based on code-001 and ev-002]

这正是为什么一条路径完成后，搜索可以转向同一父节点的下一个子分支。

## 回溯的概念模型

### 1. 递归负责深入

```cpp
findCombination(digits, index + 1, s + letters[i]);
```

把搜索推进到下一层。[visual_direct | code-001]

### 2. `return` 负责回到调用者

课程用“递归调用的一个重要特征——要返回”引出回溯。[course_direct + visual_direct | ev-004]

返回可由两种情形触发：

- 命中基本情况，获得一个完整答案；
- 当前层候选全部遍历完毕。

[course_direct + visual_direct | code-001, ev-002]

### 3. 调用者负责继续兄弟分支

返回后，调用者的 `for` 循环继续增加 `i`，于是切换到下一个候选字母。[visual_direct + editorial_inference | code-001]

### 4. 本例为何没有显式撤销

当前部分解参数是：

```cpp
const string &s
```

下一层接收：

```cpp
s + letters[i]
```

表达式构造新字符串，调用者的 `s` 没有原地变化。因此函数返回时，调用者自然仍持有原来的前缀。[visual_direct + editorial_inference | code-001]

这不意味着所有回溯代码都不需要撤销。若共享可变路径、访问数组或棋盘状态，选择后通常必须显式恢复；`08-03` 会展示这种模式。[editorial_inference based on current code and chapter outline]

## 调试版屏幕代码

该工件是完整可见的成员函数，不是独立程序；它依赖 `Solution` 类中已有的 `letterMap` 与 `res`。

```cpp
void findCombination(const string &digits, int index, const string &s){
    cout << index << " : " << s << endl;
    if(index == digits.size()){
        res.push_back(s);
        cout << "get " << s << " , return" << endl;
        return;
    }

    char c = digits[index];
    assert(c >= '0' && c <= '9' && c != '1');
    string letters = letterMap[c - '0'];
    for(int i = 0; i < letters.size(); i ++){
        cout << "digits[" << index << "] = " << c << " , use " << letters[i] << endl;
        findCombination(digits, index + 1, s + letters[i]);
    }
    cout << "digits[" << index << "] = " << c << " complete, return" << endl;
    return;
}
```

## 时间复杂度：课程原式与数学纠正

### 1. 课程直接表述

课件完整显示：

```text
时间复杂度：3^n = O(2^n)
```

[visual_direct | formula-001, ev-005]

课程采用的简化模型是：输入长度为 `n`，每位有 3 个候选，因此叶子组合数是：

```text
3^n
```

[course_direct | ev-005]

课程还用 `n ≈ 20` 描述普通机器处理指数算法的粗略规模。[course_direct | ev-005] 这不是与硬件、语言、输出量无关的严格上界。[editorial_inference]

### 2. 为什么 `3^n = O(2^n)` 不成立

若 `3^n` 属于 `O(2^n)`，应存在常数 `C` 和 `n₀`，使：

```text
3^n <= C · 2^n
```

对所有 `n >= n₀` 成立。

两边相除得到：

```text
(3/2)^n <= C
```

但 `(3/2)^n` 随 `n` 无限增长，不可能被固定常数 `C` 约束。因此：

```text
3^n ∉ O(2^n)
```

[editorial_inference]

课程想表达的“二者都是指数级函数”是增长类别的口语概括，不等于它们有同一个 Big O 上界。[editorial_inference]

### 3. 更准确的输出规模

若第 `i` 位候选数为 `b_i`，结果数为：

```text
R = ∏ b_i
```

对于课程映射：

- `2`–`6`、`8` 通常各有 3 个字母；
- `7`、`9` 各有 4 个字母；
- `0`、`1` 由课程实现约定特殊处理。

[visual_direct based on 08-01 code-001；公式为 editorial_inference]

在每位恰有 3 个候选的简化模型下：

```text
R = 3^n
```

若只讨论有效的 `2..9` 数字，最坏分支数可达到 `4^n`；具体实例仍应写成乘积 `R`，避免把所有输入都粗暴写成同一个底数。[editorial_inference]

### 4. 计入字符串输出

每个答案长度为 `n`。仅把 `R` 个答案写入结果就有：

```text
Θ(nR)
```

的字符输出量。本实现还会在递归过程中执行 `s + letters[i]`，因此严谨说明应区分：

- 搜索树节点或叶子数量；
- 前缀字符串构造；
- 最终答案物化；
- 递归栈。

[editorial_inference]

## 边界、易错点与调试

### 1. 只打印进入，不打印返回

会看到递归深度，却看不清控制何时回到父层。课程同时打印命中返回和当前层完成返回，正是为了显示回溯。[course_direct | ev-001, ev-002]

### 2. 把 `return` 理解成终止整个程序

这里的 `return` 只结束当前函数调用；调用者仍会继续自己的循环。[editorial_inference]

### 3. 把自然恢复推广到所有回溯代码

本课 `s` 没有被原地修改。后续使用共享路径或 `used` 时，必须恢复显式状态；是否撤销取决于状态的生命周期。[editorial_inference]

### 4. 无批注照抄 `O(2^n)`

这是本课最重要的证据校准点。正式表达必须并列：

```text
课程原式：3^n = O(2^n)
编辑纠正：3^n ∉ O(2^n)
```

[course_direct + editorial_inference | ev-005]

### 5. 用一次运行证明所有输入正确
