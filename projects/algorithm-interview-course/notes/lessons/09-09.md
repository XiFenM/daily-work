## 一、最长公共子序列 LCS

### 定义

给定字符串 `S1`、`S2`，求同时是二者子序列的最长序列长度。[course_direct + visual_direct | ev-002]

“子序列”表示：

- 可以删除字符；
- 剩余字符不要求连续；
- 但相对顺序必须保持。[标准术语补充]

因此它不是 Longest Common **Substring**。子串要求连续，状态转移和结果提取都不同。[editorial_inference]

课程以 DNA 字符 `A/C/G/T` 的序列相似度作为应用背景。[course_direct + visual_direct | ev-002]

### 状态定义

课程定义：

```text
LCS(m,n) = S1[0...m] 与 S2[0...n]
           的最长公共子序列长度
```

[course_direct + visual_direct | ev-003]

这里 `m,n` 是**末端索引**，不是前缀长度。因而空前缀要用 `m<0` 或 `n<0` 表示。[editorial_inference]

### 课程画面转移式

```text
若 S1[m] == S2[n]：
LCS(m,n) = 1 + LCS(m-1,n-1)

若 S1[m] != S2[n]：
LCS(m,n) = max(LCS(m-1,n), LCS(m,n-1))
```

[course_direct + visual_direct | ev-003]

### 必须补出的基线

画面没有写递归终止条件。按索引口径，完整定义需要：

```text
若 m < 0 或 n < 0：
LCS(m,n) = 0
```

[editorial_inference | 基于 ev-003, ev-004]

若改用“前缀长度”口径 `dp[i][j]`，则更常见的基线是：

```text
dp[0][j] = 0
dp[i][0] = 0
```

两种写法等价，但索引偏移不同，不能混用。[editorial_inference]

### 为什么字符相等时走对角线

若 `S1[m]==S2[n]`，课程把这一公共字符计入答案，并转到两个更短前缀：

```text
1 + LCS(m-1,n-1)
```

[course_direct | ev-003]

正确性直觉是：存在一个以这对相等末字符结尾的最优公共子序列；移除末字符后，剩余部分必须同时来自两个更短前缀。[editorial_inference]

### 为什么字符不等时取两支最大

若末字符不同，它们不可能同时成为同一公共子序列的最后一个字符。任何公共子序列至少不使用其中一个末字符，所以候选包含在：

```text
丢掉 S1[m] -> LCS(m-1,n)
丢掉 S2[n] -> LCS(m,n-1)
```

两者取最大覆盖最优解。[course_direct + editorial_inference | ev-003]

### 示例：`ABCD` 与 `AEBD`

课程递归树从：

```text
ABCD | AEBD
```

出发；末尾 `D==D`，先计 1，再分析：

```text
ABC | AEB
```

继续按相等走对角、不等时分叉，最终得到长度 3。[course_direct + visual_direct | ev-004]

一条具体 LCS 是：

```text
ABD
```

[course_direct + visual_direct | ev-002, ev-004]

### 实现边界

课程明确把以下三种实现留作练习：[course_direct + visual_direct | ev-005]

1. 直接递归；
2. 递归 + 记忆化；
3. 自底向上 DP。

视频没有展示完整代码或运行结果，所以本项目不产生虚构代码工件。

在标准实现假设下，可作如下编辑推导：[editorial_inference]

| 实现         | 时间                              | 辅助空间         | 说明                           |
| ------------ | --------------------------------- | ---------------- | ------------------------------ |
| 未记忆递归   | 最坏指数级，上界可写 `O(2^(M+N))` | `O(M+N)` 栈      | 大量重复前缀状态               |
| 记忆化       | `O(MN)`                           | `O(MN)` + 递归栈 | 每个 `(m,n)` 至多求一次        |
| 二维自底向上 | `O(MN)`                           | `O(MN)`          | 填满前缀状态表，可直接支持回溯 |

## 二、从 DP 视角看最短路

课程幻灯片标题写作：

```text
dijkstra 单源最短路径算法也是动态规划
```

并定义：

```text
shortestPath(i) = 从 start 到 i 的最短路径长度

shortestPath(x)
  = min(shortestPath(a) + w(a->x))
```

[course_direct + visual_direct | ev-006]

这展示的是**最短路最优性方程**：到达 `x` 的一条最短路，其最后一条边可以写成某个前驱 `a -> x`，总长度是到 `a` 的最短距离加边权。[course_direct + editorial_inference | ev-006]

### 表述边界

这一页不足以单独定义完整 Dijkstra：[editorial_inference]

- 没写源点基线 `dist[start]=0`；
- 没写其他点初值为无穷；
- 没限定候选前驱集合；
- 没写松弛操作；
- 没写每轮贪心选取当前距离最小的未确定顶点；
- 没写**非负边权**前提。

因此更稳妥的面试表述是：

> 课程从 Bellman 最优性关系/状态转移的角度连接 Dijkstra 与动态规划思想；标准 Dijkstra 的执行策略通常归入贪心算法，并依赖非负边权。

[editorial_inference]

不要把幻灯片标题扩写成“Dijkstra 在任何图上都是普通表格 DP”。负权图不能直接使用标准 Dijkstra。[补充说明]

本课也没有讲邻接矩阵、邻接表、堆实现或时间复杂度，笔记不替课程补造这些实现细节。

## 三、动态规划如何给出具体解

DP 表通常只保存最优值。若要输出具体方案，需要回答：

> 当前最优状态是从哪个前驱状态转移而来？

[course_direct + editorial_inference | ev-007, ev-008]

一般流程：

1. 从最终最优状态开始；
2. 找到能解释当前值的合法前驱；
3. 若这条转移代表选择了某元素，就记录该元素；
4. 移动到前驱状态；
5. 到达基线后停止；
6. 若按逆序收集，最后反转结果。[editorial_inference]

这里的“反向追溯”与第 8 章的指数级搜索回溯不完全相同：它通常沿已计算的最优状态图走一条路径，不必重新枚举整个搜索树。[editorial_inference]

## 四、LIS 具体解重构

课程复用上一课数组：[course_direct + visual_direct | ev-007]

```text
nums = [10, 9, 2, 5, 3, 7, 101, 18]
memo = [ 1, 1, 1, 2, 2, 3,   4,  4]
```

从一个状态值为 4 的位置开始，课程示例选择 `101`，然后向左恢复：

```text
101 <- 7 <- 3 <- 2
```

反转后得到：

```text
[2, 3, 7, 101]
```

[course_direct + visual_direct | ev-007]

### 形式化前驱条件

若当前末端为 `cursor`，合法前驱 `j` 应满足：

```text
j < cursor
nums[j] < nums[cursor]
memo[j] == memo[cursor] - 1
```

[editorial_inference | 基于 ev-007 与 09-08 状态定义]

三个条件分别保证：

- 相对顺序正确；
- 数值严格上升；
- 长度恰好减少 1，确实位于某条最优链上。

只看 `memo[j]==memo[cursor]-1` 不够，因为值可能不小于当前元素；只看数值更小也不够，因为未必能解释最优长度。[editorial_inference]

### 多解与平局

示例最后一个 `18` 的状态也是 4，因此可以从不同末端恢复另一条 LIS。重构返回一条合法最优序列即可；若题目要求全部具体解，就需要分支探索所有同值前驱，问题规模会改变。[editorial_inference]

## 五、0-1 背包具体解重构

课程表格：[course_direct + visual_direct | ev-008]

```text
物品 id:     0   1   2
weight:      1   2   3
value:       6  10  12
capacity:    5
```

二维 DP 最终值：

```text
memo[2][5] = 22
```

课程红色箭头从右下角追溯到：

```text
(2,5) -> (1,2) -> (0,0)
```

对应选择物品 2（重量 3、价值 12）和物品 1（重量 2、价值 10），总重量 5、总价值 22。[course_direct + visual_direct | ev-008]

### 一般追溯规则

在状态 `(i,c)`：[editorial_inference | 基于 ev-008]

- 当 `i>0` 且 `memo[i][c] == memo[i-1][c]` 时，存在一个最优解不选物品 `i`，移动到 `(i-1,c)`；
- 当 `i>0` 且当前值由 `v[i] + memo[i-1][c-w[i]]` 得到时，可记录物品 `i`，移动到 `(i-1,c-w[i])`；
- 到达第 0 行时要单独判断：若 `c>=w[0]` 且 `memo[0][c]==v[0]`，记录物品 0；随后结束追溯。另一种等价做法是在表中增加“尚未考虑任何物品”的空基线行，再统一应用前两条规则；
- 平局时，两条路都可能导向正确的最优解；固定一条即可恢复一个方案。

追溯不只是比较数值，还要确认容量足够以及选择分支等式成立。[editorial_inference]

## 六、空间压缩与可追溯性的取舍

课程指出：把 0-1 背包二维表压缩为一维数组后，之前各物品行的信息丢失，无法再像动画那样沿二维表直接反推具体物品。[course_direct | ev-008]

准确边界是：

> **只保留最终一维值数组，且不保存任何额外决策信息时**，直接回溯所需的历史来源不再可见。

[course_direct + editorial_inference | ev-008]

这不等于“任何 `O(C)` 值空间方案在理论上都绝对不能输出解”。可选工程策略包括：[editorial_inference]

- 额外保存父指针或决策记录；
- 在第二遍中根据原输入重新计算部分状态；
- 使用检查点，在空间与重算时间之间折中；
- 若只需最优值，继续使用纯一维压缩。

面试时应先确认输出要求，再决定是否值得压缩状态。[course_direct + editorial_inference | ev-008]

## 正确性骨架：值与路径

动态规划值正确，只说明最终状态保存了最优目标值；重构还需满足：[editorial_inference]

1. 每一步选中的前驱确实能产生当前值；
2. 移动后状态规模严格减小，最终会到达基线；
3. 记录的选择与状态变化一致；
4. 平局策略不会降低最优值；
5. 反向得到的元素顺序在输出前被正确恢复。

LIS 中“长度少 1 + 数值更小 + 下标更早”保证链合法；背包中“值等式 + 容量扣减 + 行号减一”保证物品组合与 DP 值一致。[editorial_inference | ev-007, ev-008]

## 面试回答策略

### 遇到 LCS

1. 先澄清是 subsequence 还是 substring；
2. 定义两个前缀的二维状态；
3. 明确索引口径或长度口径；
4. 写出空前缀基线；
5. 分字符相等/不等两种转移；
6. 若只求长度，可讨论滚动数组；
7. 若要具体序列，保留二维表或额外父指针；
8. 在标准实现假设下给出 `O(MN)` 时间，并标明空间取决于是否重构。[editorial_inference]

### 遇到最短路

1. 先确认边权是否非负；
2. 区分最优性方程与具体算法执行顺序；
3. 不因课程标题就省略 Dijkstra 的贪心定点与松弛逻辑；
4. 负权边应转向其他算法，不直接套 Dijkstra。[editorial_inference]

### 遇到“输出具体方案”

1. 先判断 DP 值表是否保留足够历史；
2. 定义前驱条件；
3. 处理平局；
4. 保证状态严格缩小；
5. 明确返回任意一个、字典序最小、还是全部方案；
6. 再讨论空间压缩是否仍合适。[course_direct + editorial_inference | ev-007, ev-008]

## 课程结尾的备考建议

课程强调算法面试中的动态规划通常以基础模型与状态设计为主，难度不必与算法竞赛中的高级 DP 等同；有效准备方式仍是通过题目积累状态定义与转移经验。[course_direct | ev-009]

这不意味着可以只背题型。至少要能当场解释：

- 状态为什么足够；
- 基线是什么；
- 转移为什么不遗漏；
- 计算顺序为何满足依赖；
- 最优值如何提取；
- 是否需要恢复具体解。[editorial_inference]
