## 核心概念与定义

### 1. 数据规模 `n`

`n` 表示输入问题的规模。它不是固定指某种数据结构的长度，而要在具体问题中说明其含义；本课后半段就同时使用了“字符串数量 `n`”和“最长字符串长度 `s`”两个规模变量。[视频 00:00:38–00:01:49][02-01-ev-002]（ev-002）；[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008）

面试表达中不能只说“复杂度是 `O(n)`”而不定义 `n`。同一个字母若在不同步骤代表不同对象，复杂度式即使形式正确，也可能没有可解释性。[整理推导，依据 ev-007、ev-008]

### 2. 大 O 的课程直观模型

课程先给出一个面向实践的直观描述：

> `O(f(n))` 表示运行算法所需要执行的指令数与 `f(n)` 成正比。[视频 00:00:38–00:01:49][02-01-ev-002]（ev-002）

结构化证据把它归一化为：

```text
Instructions = C × f(n)
```

其中 `C` 是与当前实现和基本操作有关的常数，`f(n)` 描述工作量随规模增长的形状。[视频 00:00:38–00:03:29][02-01-range-038-209]（ev-002、formula-001）

这一定义用于建立直觉，不应被读成“复杂度可以直接给出精确秒数”。本课后续专门通过不同常数的交叉说明：同一增长阶之外仍有实现常数，而不同增长阶的优势也可能要到一定规模后才显现。[视频 00:03:29–00:07:42][02-01-ev-004]（ev-004）

### 3. 常见增长阶

本课图中并列展示了以下增长趋势：[视频 00:07:42–00:08:04][02-01-ev-005]（ev-005）

| 量级       | 课程图中的名称 | 随输入扩大的直观趋势              |
| ---------- | -------------- | --------------------------------- |
| `O(1)`     | Constant       | 工作量不随 `n` 的增长而按比例扩大 |
| `O(log n)` | Logarithmic    | 增长缓慢                          |
| `O(n)`     | Linear         | 与规模线性增长                    |
| `O(n²)`    | Quadratic      | 二次增长                          |
| `O(cⁿ)`    | Exponential    | 指数增长                          |

“增长缓慢”“指数增长”等描述是对课程曲线的编辑性概括，不替代具体算法中的变量、常数和输入情况说明。[整理推导]

### 4. 上界与面试中的约定

### 5. 主导项规则

当各项使用同一个规模变量 `n` 时，可以比较其增长阶并保留主导项：[视频 00:09:57–00:12:47][02-01-ev-007]（ev-007、formula-002）

```text
O(n log n + n)  = O(n log n)
O(n log n + n²) = O(n²)
```

这里删除低阶项，不是说那部分工作在程序中不存在，而是它不会决定规模趋大时的主导增长趋势。[整理推导，依据 ev-007]

### 6. 多变量复杂度

如果各项由互不相关的规模变量控制，就没有依据简单地把其中一项删掉。例如：[视频 00:09:57–00:12:47][02-01-ev-007]（ev-007）

```text
O(A log A + B)
O(A log A + B²)
O(V + E)
```

在邻接表图遍历的示例中，`V` 是顶点数，`E` 是边数。因为两者分别描述输入的不同维度，课程保留 `O(V + E)`，而不是武断地写成 `O(V)` 或 `O(E)`。[视频 00:09:57–00:12:47][02-01-ev-007]（ev-007、formula-003）

### 7. 输入相关的复杂度

复杂度可能随输入排列而改变。本课列出：[视频 00:17:25–00:19:55][02-01-ev-009]（ev-009）

| 算法     |     最好情况 | 最差情况 |     平均情况 |
| -------- | -----------: | -------: | -----------: |

### 为什么常数不能在小规模下完全忽略

课程比较两个抽象算法：[视频 00:03:29–00:07:42][02-01-ev-004]（ev-004）

```text
算法 A：10000 · n      → O(n)
算法 B：10 · n²        → O(n²)
```

按视频给出的规模计算：

|     `n` |   A 的指令数 |   B 的指令数 | 当下更少          |
| ------: | -----------: | -----------: | ----------------- |
|    `10` |    `100,000` |      `1,000` | B                 |
|   `100` |  `1,000,000` |    `100,000` | B                 |
| `1,000` | `10,000,000` | `10,000,000` | 相同              |
|   `10⁶` |       `10¹⁰` |       `10¹³` | A，少约 `1000` 倍 |

这说明两个层面不能混为一谈：

1. 在渐进增长上，线性 A 最终优于二次 B。
2. 在有限且较小的数据规模下，较大的常数会让 A 暂时更慢。[视频 00:03:29–00:07:42][02-01-ev-004]（ev-004）

视频还提到，高级排序实现可能在子问题规模足够小时切换到插入排序，以利用小规模阶段的实际表现。这是一个实现优化方向；本课没有给出切换阈值或具体实现。[视频 00:03:29–00:07:42][02-01-ev-004]（ev-004）

## 思考题：字符串数组的两阶段排序

### 题目

给定一个字符串数组：

1. 先把数组中的每一个字符串按字母序排序；
2. 再把整个字符串数组按字典序排序；
3. 求整个操作的时间复杂度。[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008）

视频没有提供平台、函数签名或额外输入约束；这是复杂度推导题，而不是需要提交代码的完整编程题。

### 变量与成本模型

- `n`：字符串数组中的字符串个数。
- `s`：最长字符串的长度。
- 单个字符串内部排序按 `O(s log s)` 计。
- 字符串数组排序按 `O(n log n)` 次比较计；一次字符串比较最多按 `O(s)` 计。[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008、cx-001）

### 逐步推导

1. **排序一个字符串内部的字符：**

   ```text
   O(s log s)
   ```

2. **数组里共有 `n` 个字符串：**

   ```text
   n × O(s log s) = O(n · s log s)
   ```

3. **把 `n` 个字符串按字典序排序：**排序过程需要 `O(n log n)` 次字符串比较；每次比较最多检查 `s` 个字符，因此：

   ```text
   O(n log n) × O(s) = O(s · n log n)
   ```

4. **两阶段相加并提取公因子：**

   ```text
   O(n · s log s + s · n log n)
   = O(n · s · (log s + log n))
   ```

结论：

```text
O(n · s · (log s + log n))
```

以上变量、成本模型和推导均来自课程直接讲解。[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008、cx-001）

### 为什么不能直接写 `O(n log n)`

这个错误会漏掉两个成本：

- 每个字符串内部也要排序；
- 字典序比较本身要读取字符，不是本课成本模型中的 `O(1)` 操作。[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008）

本题最重要的不是最后一行代数化简，而是先识别出两个独立规模 `n` 与 `s`，再为每个阶段定义基本操作。[整理推导，依据 ev-008]

## 边界条件、易错点与自检

1. **把大 O 当成精确耗时。** 本课只用它表达随规模增长的量级；常数会影响有限规模下的实际结果。[视频 00:00:38–00:07:42][02-01-range-038-462]（ev-002–ev-004）
2. **认为更低阶的算法在任何 `n` 上都必然更快。** `10000n` 与 `10n²` 的对比显示，小规模下可能相反。[视频 00:03:29–00:07:42][02-01-ev-004]（ev-004）
3. **在独立变量之间强行比较主导项。** `A` 与 `B`、`V` 与 `E` 没有已知关系时，必须保留各维度。[视频 00:09:57–00:12:47][02-01-ev-007]（ev-007）
4. **混淆字符串长度 `s` 与字符串个数 `n`。** 两者控制不同层次的工作量。[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008）
5. **把字符串比较视为 `O(1)`。** 本课的推导按一次比较最多 `O(s)` 计算。[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008）
6. **只报一个复杂度，不说输入情况。** 插入排序和快速排序都展示了最好、最差、平均情况之间的差异。[视频 00:17:25–00:19:55][02-01-ev-009]（ev-009）

### 回答前的最小自检

- 我是否定义了每个变量？
- 顺序阶段是相加，还是存在嵌套导致相乘？
- 被删掉的项是否真的使用同一个可比较的规模变量？
- “一次操作”的成本是否被误当成常数？
- 我的结论描述的是最好、最差还是平均情况？
- 题目问的是渐进量级，还是某个固定规模下的实际运行时间？[整理推导]

## 面试表达脚本

下面的表达顺序由课程示例整理而来，不是视频逐字稿：

1. **先定义规模：**“我用 `n` 表示……，另外用 `s` 表示……，它们是两个独立维度。”[整理推导，依据 ev-007、ev-008]
2. **说明成本模型：**“我把一次……作为基本操作；这里一次字符串比较最坏需要查看 `s` 个字符，所以不能按常数计算。”[整理推导，依据 ev-008]
3. **分段计算：**“第一阶段是……，成本为……；第二阶段是……，成本为……；因为它们顺序执行，所以相加。”[整理推导，依据 ev-008]
4. **谨慎化简：**“这两项都由同一个 `n` 控制时可以比较主导项；如果是独立的 `A/B` 或 `V/E`，我会保留两项。”[整理推导，依据 ev-007]
5. **补充输入情况：**“这个结论是平均/最坏情况；如果输入接近有序，复杂度可能变化。”[整理推导，依据 ev-009]
6. **区分渐进与实测：**“大 O 描述增长量级；固定规模下还要考虑常数，若需要精确判断应再做实验。”[整理推导，依据 ev-004]

## 复习区

### 核心清单

- 大 O 描述工作量随规模增长的量级，不是一次运行的精确秒数。[视频 00:00:38–00:07:42][02-01-range-038-462]（ev-002–ev-004）
- 常数可影响小规模表现；增长阶决定规模足够大后的趋势。[视频 00:03:29–00:07:42][02-01-ev-004]（ev-004）
- 同一变量下保留主导项；独立变量下不要随意删项。[视频 00:09:57–00:12:47][02-01-ev-007]（ev-007）
- 字符串排序题必须同时保留字符串数 `n` 与最长长度 `s`。[视频 00:12:47–00:17:25][02-01-ev-008]（ev-008）
- 说明复杂度时必须注明最好、最差或平均情况。[视频 00:17:25–00:19:55][02-01-ev-009]（ev-009）

### 闪卡问题

1. 本课如何用指令数解释 `O(f(n))`？
2. 为什么 `O(n)` 算法在小规模下可能比 `O(n²)` 算法慢？
3. 什么时候可以把 `O(n log n + n)` 化简为 `O(n log n)`？
4. 为什么 `O(V + E)` 不能直接删掉 `V` 或 `E`？
5. 字符串数组两阶段排序中的 `n` 和 `s` 分别表示什么？
6. 数组级字典序排序为什么带有额外的 `O(s)` 比较成本？
7. 插入排序和快速排序的最好、最差、平均复杂度分别是什么？

### 建议练习

2. `[整理推导]` 改变 `10000n` 与 `10n²` 中的常数，手算新的交叉规模，并解释为什么这不改变两者的大 O。
