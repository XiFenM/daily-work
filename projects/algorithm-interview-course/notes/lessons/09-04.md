## 一句话结论

先把函数契约说完整：


若枚举该后缀中第一间被抢的房屋 `j`，下一状态必须跳过 `j+1`，于是：


## 暴力枚举为什么代价高

对每间房都有两种决定：

```text
抢 / 不抢
```

`n` 间房共有：

```text
2^n
```

种子集。对每个子集，还要检查是否包含相邻房屋，并计算价值和；课程把这一步计为 `O(n)`，因此总时间为：

```text
O((2^n) * n) = O(n * 2^n)
```

[course_direct + visual_direct | cx-001, ev-002]

这个分析针对“先枚举完整组合，再检查约束”的暴力方案；不能把它与后面的递归树节点数混成同一个实现细节。[补充说明]

## 决策树怎样暴露重叠子问题

课程不按“当前房抢或不抢”画树，而是在当前后缀中直接枚举第一间被抢房屋：

```text
考虑 [0...n-1]
├─ 抢 0 -> 考虑 [2...n-1]
├─ 抢 1 -> 考虑 [3...n-1]
├─ 抢 2 -> 考虑 [4...n-1]
└─ ...
```

[course_direct + visual_direct | ev-003]

进入 `[2...n-1]` 后又可以抢 2、抢 3……；进入 `[3...n-1]` 后也会产生 `[5...n-1]` 等后缀。不同路径会重复请求同一个区间状态，这就是记忆化可以消除的重复。[course_direct + visual_direct | ev-003]

重叠的是“同一个后缀起点”，所以缓存键只需 `index`；不需要把已经获得的总价值放进状态。[editorial_inference | 基于 ev-003, ev-005]

## 状态定义：先说清函数契约

课程强调：

```text
考虑偷窃 [x...n-1] 范围里的房子
```

是函数的定义。[course_direct + visual_direct | ev-004]

更完整地写：

```text
f(x) = 在只能从索引 x 到 n-1 的房屋中选择、且不能选择相邻房屋时，
       能获得的最大宝物价值
```

[course_direct + editorial_inference | 基于 ev-004]

这个契约包含三部分：

1. **输入边界**：从 `x` 开始；
2. **可选区域**：闭区间 `[x,n-1]`；
3. **返回语义**：满足不相邻约束的最大收益。

只说“`f(x)` 是答案”不够，因为没有说明它对应哪一个子问题。

## 状态转移：枚举第一间被抢房屋

对 `f(x)`，假设第一间被抢的是 `j`：

- 当前获得 `value[j]`；
- `j+1` 不能抢；
- 剩余问题从 `j+2` 开始，即 `f(j+2)`。

因此：

```text
f(x) = max {
  value[x]   + f(x+2),
  value[x+1] + f(x+3),
  ...,
  value[n-2],
  value[n-1]
}
```

统一写作：

```text
f(x) = max_{j=x...n-1}(value[j] + f(j+2))
```

并约定：

```text
f(k) = 0,  k >= n
```

[course_direct + visual_direct | formula-001, ev-004；editorial_inference | 统一边界写法]

课程幻灯片直接展开的是 `f(0)`；把它规范化为任意 `f(x)` 是保持同一函数契约的编辑整理。[补充说明]

## 为什么这个转移覆盖全部合法答案

视频通过状态转移说明求法；下面把正确性论证整理完整。

### 完备性

任意非空合法方案在 `[x...n-1]` 中都有唯一的第一间被抢房屋 `j`。转移枚举所有 `j=x...n-1`，因此不会漏掉任何非空方案。[editorial_inference]

### 可行性

选了 `j` 后只递归到 `j+2`，所以后续方案不可能再选 `j+1`。若子问题自身满足不相邻约束，拼接后仍合法。[course_direct + editorial_inference | 基于 ev-004]

### 最优性

固定第一间房为 `j` 后，后续若不用 `f(j+2)` 的最优解，就能用更优后缀替换它，使总收益更大；因此该分支的最优值是 `value[j]+f(j+2)`。再对所有可能的 `j` 取最大值，就得到 `f(x)`。[editorial_inference]

空方案通过边界值 0 被覆盖；在课程的非负价值语境下，枚举式以 `res=0` 开始也不会强迫选择负收益房屋。[visual_direct + editorial_inference | code-001]

## 自顶向下：记忆化搜索

课程最终代码按原片校正为：

```cpp
#include <iostream>
#include <vector>

using namespace std;

class Solution {
private:
    // memo[i] 表示考虑抢劫 nums[i...n) 所能获得的最大收益
    vector<int> memo;

    // 考虑抢劫 nums[index...nums.size()) 这个范围的所有房子
    int tryRob(vector<int>& nums, int index) {
        if (index >= nums.size()) {
            return 0;
        }
        if (memo[index] != -1) {
            return memo[index];
        }
        int res = 0;
        for (int i = index; i < nums.size(); i++) {
            res = max(res, nums[i] + tryRob(nums, i + 2));
        }
        memo[index] = res;
        return res;
    }

public:
    int rob(vector<int>& nums) {
        memo = vector<int>(nums.size(), -1);
        return tryRob(nums, 0);
    }
};
```

[visual_direct | code-001, ev-005]

### 执行顺序

1. `index >= nums.size()`：后缀为空，返回 0；
2. `memo[index] != -1`：该后缀已求过，直接返回；
3. 从 `index` 到末尾枚举第一间房 `i`；
4. 计算 `nums[i] + tryRob(nums,i+2)`；
5. 把最大值写回 `memo[index]`；
6. 入口从 `index=0` 求整个数组。

[course_direct + visual_direct | state-001, code-001, ev-005]

### 一个容易忽略的事实：记忆化后仍是 `O(n²)`

记忆化只保证每个 `index` 的完整函数体至多执行一次，但每个状态内部仍扫描一个后缀：

```text
index = 0  扫描约 n 个候选
index = 1  扫描约 n-1 个候选
...
index = n-1 扫描 1 个候选
```

总工作量为：

```text
n + (n-1) + ... + 1 = Θ(n²)
```

因此项目从代码结构推导：

```text
时间：O(n²)
辅助空间：O(n)
```

辅助空间包含长度 `n` 的 `memo` 和最坏 `O(n)` 的递归栈。[editorial_inference | cx-003, cx-004]

课程没有在记忆化代码段直接写出这两个渐进界，所以规范化记录没有把它们填进该 solution 的课程直接复杂度字段。[补充说明]

## 自底向上：按后缀起点从右向左填表

课程的第二份完整代码为：

```cpp
#include <iostream>
#include <vector>

using namespace std;

class Solution {
public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) {
            return 0;
        }
        // memo[i] 表示考虑抢劫 nums[i...n-1] 所能获得的最大收益
        vector<int> memo(n, -1);
        memo[n - 1] = nums[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                memo[i] = max(memo[i], nums[j] + (j + 2 < n ? memo[j + 2] : 0));
            }
        }
        return memo[0];
    }
};
```

[visual_direct | code-002, ev-006]

### 为什么外层 `i` 必须递减

计算 `memo[i]` 时会读取：

```text
memo[j+2],  j >= i
```

这些索引都在 `i` 的右侧。只有先完成更靠右的后缀，再向左计算，依赖才已经可用。[editorial_inference | 基于 state-002, code-002]

### 为什么要先处理空数组

非空时可以初始化：

```cpp
memo[n-1] = nums[n-1];
```

若 `n==0`，`n-1` 无效，因此必须先返回 0。[course_direct + visual_direct | ev-006]

### 为什么访问 `j+2` 要判断

当 `j` 是最后一间或倒数第二间房时，后续没有可选房屋，收益应为 0：

```cpp
(j + 2 < n ? memo[j + 2] : 0)
```

[course_direct + visual_direct | ev-006]

### 复杂度

课程明确指出双重循环为：

```text
时间 O(n²)
```

[course_direct | cx-002, ev-006]

从代码显式分配长度 `n` 的数组可编辑推导：

```text
辅助空间 O(n)
```

[editorial_inference | cx-005]

自底向上版本是同一后缀枚举转移的另一种执行方式，不是渐进时间更优的版本，因此规范化阶段将其标成 `alternative`，而非 `optimized`。[补充说明]

## 改变状态定义：课程练习与编辑解答分开

课程只提出：

```text
考虑偷窃 [0...x] 范围里的房子
```

并留作思考，没有展示后续公式或代码。[course_direct + visual_direct | ev-007]

若把练习补完，可以定义：

```text
g(i) = 只考虑 [0...i] 时可获得的最大收益
```

对第 `i` 间房只有两类互斥选择：

```text
不抢 i：g(i-1)
抢 i：nums[i] + g(i-2)
```

因此：

```text
g(i) = max(g(i-1), nums[i] + g(i-2))
```

配合：

```text
g(-1)=0
g(0)=nums[0]
```

可以得到 `O(n)` 时间、`O(n)` 表空间，并进一步压缩到 `O(1)` 额外空间。[editorial_inference | 对 ev-007 练习的补解]

## 常见错误

1. **状态定义不完整**：只说 `memo[i]` 是最大值，却不说明对应 `[i...n-1]`。
2. **递归仍从 `index+2` 走**：本层枚举的是 `i`，下一状态必须是 `i+2`。
3. **缓存写错键**：本次函数求的是 `index` 状态，应写 `memo[index]`，不是 `memo[i]`。
4. **把记忆化自动判成 `O(n)`**：每个状态内部仍扫描后缀，总和是二次。
5. **自底向上从左向右填**：`memo[i]` 依赖右侧 `memo[j+2]`，方向会反。
6. **忘记 `n==0`**：会在 `memo[n-1]` 处越界。
7. **直接读取 `memo[j+2]`**：末尾两个候选会越界。
8. **把 bottom-up 标作更快版本**：视频中的两版转移都枚举第一间房，渐进时间相同。
9. **把前缀线性转移当作视频代码**：它是对课程练习的编辑补解。
10. **把扩展题当作已讲解**：课程只介绍题面，没有给出实现。

前七项依据课程状态和代码；后三项是证据边界。[course_direct + editorial_inference | ev-004–ev-008]
