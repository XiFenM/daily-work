## 课程定位

这是动态规划章节的概念入口。课程没有从抽象定义开始，而是让同一个 Fibonacci 状态经历三种求值策略：

1. 按递推式直接递归；
2. 发现重叠子问题后加入缓存；
3. 按依赖顺序从小到大填表。

[course_direct | ev-001, ev-006, ev-009, ev-013, ev-015, ev-016]

本课最重要的认知不是“动态规划等于写数组”，而是：**先把原问题拆成子问题；若子问题重复出现，就保存答案，让每个子问题只求一次。** 自顶向下实现是记忆化搜索，自底向上实现是动态规划。[course_direct | ev-015, ev-016]

## 一句话结论

当递归树里出现大量相同状态时，保持状态定义与递推关系不变，用记忆化把“重复展开”改成“缓存命中”，或按依赖方向直接填表，就能把本例的指数时间降为线性时间。[course_direct + editorial_inference | ev-006, ev-009, ev-010, ev-013–ev-016]

## 版本一：纯递归

### 屏幕代码

```cpp
int fib(int n) {
    if (n == 0)
        return 0;
    if (n == 1)
        return 1;
    return fib(n - 1) + fib(n - 2);
}
```

[visual_direct | code-001, ev-003]

### 状态五要素

| 要素     | 定义                                       |
| -------- | ------------------------------------------ |
| 状态     | `fib(n)`：代码口径下第 `n` 个 Fibonacci 数 |
| 基本值   | `fib(0)=0`，`fib(1)=1`                     |
| 转移     | `fib(n)=fib(n-1)+fib(n-2)`，适用于 `n>1`   |
| 求值顺序 | 自顶向下；每个调用先递归请求两个更小状态   |
| 答案     | 顶层调用 `fib(n)` 的返回值                 |

[visual_direct + editorial_inference | code-001]

### 为什么慢

递归树不是只有 `n` 层这么简单：每个非基本状态继续分成两个调用，而多个路径会到达同一个 `fib(k)`。例如 `fib(5)` 中 `fib(3)`、`fib(2)` 会反复出现。[course_direct + visual_direct | ev-006]

课程用两个维度验证这一点：

| 输入 | 课程演示耗时 | 调用次数    |
| ---- | ------------ | ----------- |
| 10   | `4e-06 s`    | 未展示      |
| 20   | `0.000104 s` | `21891`     |
| 40   | `1.28333 s`  | `331160281` |
| 42   | `3.47917 s`  | 未展示      |

[visual_direct | ev-004, ev-005, ev-008]

这些是单次课堂环境的观测值，不是跨机器性能基准；稳定结论是增长趋势与重复计算结构。[supplemental]

## 版本二：记忆化搜索

### 屏幕代码核心

```cpp
vector<int> memo;

int fib(int n) {
    if (n == 0)
        return 0;
    if (n == 1)
        return 1;
    if (memo[n] == -1)
        memo[n] = fib(n - 1) + fib(n - 2);
    return memo[n];
}
```

[visual_direct | code-002, ev-009]

调用入口还必须把 `memo` 建成至少 `n+1` 个元素，并用未计算哨兵初始化；这部分不应从片段中省略成“缓存会自动存在”。[course_direct + visual_direct | ev-009]

### 状态五要素

| 要素     | 定义                                                     |
| -------- | -------------------------------------------------------- |
| 状态     | `fib(n)` 仍表示代码口径下第 `n` 项；`memo[n]` 缓存该答案 |
| 初始化   | 缓存初值为 `-1`；`n=0/1` 直接返回基本值                  |
| 转移     | 仅当 `memo[n]==-1` 时递归计算两项之和并写入              |
| 求值顺序 | 自顶向下、按需访问；缓存命中后不再展开                   |
| 答案     | 顶层 `fib(n)`；计算过的子状态保留在 `memo`               |

[course_direct + visual_direct | ev-009, ev-012]

### 哨兵值为什么有前提

本例 Fibonacci 结果非负，因此 `-1` 可代表“尚未计算”。若题目合法答案可能为 `-1`，就必须改用独立访问标记、可空类型或其他不冲突的表示。[course_direct | ev-009]

### 效果

- `n=40`：课程画面显示 79 次 `fib` 调用；
- `n=1000`：显示耗时 `6.5e-05 s`、1999 次调用；
- 调用次数符合演示代码的 `2n-1` 量级；
- 每个索引的真正状态值至多计算一次，时间降为 `O(n)`。[course_direct + visual_direct | ev-010, ev-011]

## 版本三：自底向上动态规划

### 屏幕代码

```cpp
int fib(int n) {
    vector<int> memo(n + 1, -1);
    memo[0] = 0;
    memo[1] = 1;
    for (int i = 2; i <= n; i++)
        memo[i] = memo[i - 1] + memo[i - 2];
    return memo[n];
}
```

[visual_direct | code-003, ev-013]

### 状态五要素

| 要素     | 定义                                        |
| -------- | ------------------------------------------- |
| 状态     | `memo[i]`：代码口径下第 `i` 个 Fibonacci 数 |
| 初始化   | `memo[0]=0`，`memo[1]=1`                    |
| 转移     | `memo[i]=memo[i-1]+memo[i-2]`               |
| 遍历顺序 | `i` 从 `2` 递增到 `n`，保证依赖项先被计算   |
| 答案     | `memo[n]`                                   |

[course_direct + visual_direct | ev-013]

课程运行画面在 `n=1000` 时显示 `fib(1000)=1556111435`、耗时 `6e-05 s`；该数值仍是 32 位 `int` 溢出结果，不能当作精确 Fibonacci 值。[course_direct + visual_direct | ev-014]

### 循环不变量（整理证明）

进入索引 `i` 时，`memo[0...i-1]` 已按代码口径保存正确值：

1. 初始化后，`memo[0]`、`memo[1]` 正确；
2. 若前缀正确，则两项相加得到正确的 `memo[i]`；
3. 写入后，正确前缀扩展到 `0...i`；
4. 循环结束时 `memo[n]` 已正确，因此返回值满足后置条件。

[editorial_inference | 基于 code-003, ev-013]

### `n=0` 越界缺陷

当 `n=0` 时，`vector<int> memo(n+1, -1)` 只有一个元素，合法索引只有 `0`，但下一行仍写 `memo[1]=1`。本项目在最小外壳中用 AddressSanitizer 运行该输入，确认 `heap-buffer-overflow`。[supplemental]

安全修复可以是先处理小输入：

```cpp
if (n == 0)
    return 0;
```

也可以保证数组至少有两个元素，但提前返回更直接。以上修复不属于屏幕原码，不能回写成课程展示内容。[supplemental]

## 三种求值策略对照

| 维度         | 纯递归             | 记忆化搜索           | 自底向上动态规划           |
| ------------ | ------------------ | -------------------- | -------------------------- |
| 状态定义     | `fib(n)`           | `fib(n)` / `memo[n]` | `memo[i]`                  |
| 转移         | 两个递归调用之和   | 未命中时递归并缓存   | 直接读前两项填表           |
| 顺序         | 自顶向下，重复展开 | 自顶向下，按需求值   | 自底向上，按依赖顺序       |
| 重复计算     | 大量存在           | 缓存后消除           | 不产生                     |
| 函数栈       | 有                 | 有                   | 无递归栈                   |
| 课程时间结论 | `O(2^n)`           | `O(n)`               | `O(n)`                     |
| 本地验证     | 代表输入通过       | 代表输入通过         | 正输入通过，`n=0` 越界失败 |

## 正确性边界

课程直接展示了递推式、基本值、缓存与填表代码，但没有给出形式化归纳证明。可整理为：[editorial_inference]

1. **基本情况**：先固定同一套 `fib(0)`、`fib(1)` 定义；
2. **依赖正确性**：若 `n-1` 与 `n-2` 的值正确，则其和就是 `n` 的值；
3. **记忆化保持**：缓存只保存按同一递推关系首次算出的结果，命中不会改变语义；
4. **自底向上保持**：递增遍历使两个依赖项在使用前已经正确；
5. **边界安全**：自底向上实现还必须保证初始化写入位于数组范围内。

正确性与内存安全是两个义务：递推式可以正确，具体代码仍可能在 `n=0` 越界。[supplemental]

## 数值范围与溢出

课程在 `n=1000` 的运行画面得到 `1556111435`，并明确指出 `int` 已经溢出。[course_direct + visual_direct | ev-011]

- `fib(1000)` 也远超 64 位整数；
- 若题目要求精确大数，需要大整数；
- 若题目要求模某个数，应在每次转移时取模；
- 数值类型与算法时间复杂度是不同设计维度。
