## 核心概念与定义

### 1. 复杂度震荡

复杂度震荡是指：数据结构在容量临界点附近交替增删，扩容和缩容被连续触发，使原本应当偶尔发生的 `O(n)` 复制变成几乎每次操作都发生。[视频 00:03:41–00:05:10]

它揭示了均摊证明的一个必要检查：不仅要分析“全是添加”或“全是删除”的单向序列，还要检查对手式的混合操作序列是否能让昂贵操作紧挨着发生。[视频 00:02:13–00:05:10] [整理推导]

### 2. Lazy 缩容

Lazy 缩容把回收空间的时机延后：[视频 00:05:10–00:06:56]

```text
当 size == capacity / 4：
    resize(capacity / 2)
```

缩容完成后：

- 元素数仍为旧容量的 `1/4`；
- 新容量为旧容量的 `1/2`；
- 因此新数组处于半满状态，而不是刚好满状态。[视频 00:05:10–00:06:56] [整理推导]

这段空闲空间就是缓冲：接下来必须再发生一批添加，才会重新装满并扩容，不能通过一次 `push_back` 立即反向触发昂贵操作。[视频 00:05:10–00:06:56]

### 3. 均摊分析的对抗性检查

02-06 的核心问题是“一次昂贵扩容能否分摊到前面的许多插入”；本课进一步问“是否存在一种操作顺序，使两次昂贵复制紧邻出现”。[视频 00:02:13–00:05:10] [整理推导]

因此，一个可靠的均摊结论至少要说明：

1. 昂贵操作何时触发；
2. 两次昂贵操作之间至少隔着多少便宜操作；
3. 这批便宜操作是否足以承担复制成本。[视频 00:02:13–00:06:56] [整理推导]

## Bug 修复：先保存待删除元素

朴素实现可能先减小 `size`、再缩容、最后从 `data[size]` 返回被删元素。但 `resize` 只复制缩容后仍然有效的 `size` 个元素；原尾部元素不在复制范围内，缩容后再读取该位置就不能保证得到原值。[视频 00:00:00–00:02:13] [整理推导]

课程给出的修复顺序是：

1. `T ret = data[size - 1]`：先保存旧尾部；
2. `size--`：更新逻辑元素个数；
3. 必要时缩容；
4. `return ret`：返回已经保存的值。[视频 00:00:00–00:02:13]

结合 Lazy 条件后的屏幕代码为：[视频 00:00:00–00:02:13] [视频 00:06:17–00:06:56]

```cpp
// Average: O(1)
T pop_back() {
    assert(size > 0);
    T ret = data[size - 1];
    size--;
    if (size == capacity / 4)
        resize(capacity / 2);
    return ret;
}
```

## 复杂度推导

### 1. 只看删除：半容量缩容似乎可行

视频先考察一个容量为 `2n` 的数组。从满数组开始连续删除，直到剩下 `n` 个元素时执行 `resize(n)`：[视频 00:02:13–00:03:41]

- 前面的删除操作各花费常数时间；
- 触发缩容时需要复制剩余的 `n` 个元素，再完成本次删除相关工作；
- 把这次线性复制分摊到约 `n` 次删除，平均到每次仍为常数级。

所以若只看单向连续删除，`size == capacity/2` 时缩容似乎也能得到 `pop_back` 均摊 `O(1)`。[视频 00:02:13–00:03:41]

### 2. 反例：临界点交替增删

问题出在它与“满时扩到 2 倍”的策略组合后。[视频 00:03:41–00:05:10]

设当前状态为：

```text
size = 2n
capacity = 2n
```

交替执行：

| 操作             | 状态变化                                            | 昂贵动作                            |
| ---------------- | --------------------------------------------------- | ----------------------------------- |
| `push_back`      | 数组已满，先把容量从 `2n` 扩到 `4n`，再加入一个元素 | 复制 `O(n)` 个元素                  |
| `pop_back`       | 删除后 `size` 回到 `2n`，恰等于新容量 `4n` 的一半   | 又缩回 `2n`，再次复制 `O(n)` 个元素 |
| 再次 `push_back` | 数组又处于刚好满的状态                              | 再次扩容并复制                      |

[视频 00:03:41–00:05:10] [整理推导]

这样，扩容与缩容之间只隔了一个操作，复制成本没有足够多的便宜操作可供分摊。该极端序列中，每次增删都可能退化为 `O(n)`；这就是复杂度震荡。[视频 00:03:41–00:05:10]

### 3. Lazy 缩容怎样打破震荡

改为在 `size == capacity/4` 时才缩容到 `capacity/2`：[视频 00:05:10–00:06:56]

假设旧容量为 `C`：

```text
缩容前：size = C/4, capacity = C
缩容后：size = C/4, capacity = C/2
```

缩容后数组只有半满。要再次触发扩容，至少还需添加约 `C/4` 个元素；因此不能用一次删除、一次添加就在同一临界点来回触发复制。[视频 00:05:10–00:06:56] [整理推导]

昂贵缩容由之前的一批删除承担，昂贵扩容也由之后的一批添加承担，视频据此给出 `pop_back` 均摊 `O(1)`，并与前课 `push_back` 的均摊 `O(1)` 组合。[视频 00:02:13–00:06:56]

### 4. 复杂度结论的层次

| 操作与策略                 | 单次可能成本      | 视频中的序列结论          |
| -------------------------- | ----------------- | ------------------------- |
| 普通尾插/尾删              | `O(1)`            | 便宜操作                  |
| 触发扩容或缩容的 `resize`  | `O(n)`            | 昂贵但应当稀疏发生        |
| 2 倍扩容下的 `push_back`   | 最坏可 `O(n)`     | 均摊 `O(1)`（承接 02-06） |
| 半满即缩容、临界点交替增删 | 每次可触发复制    | 极端序列退化为 `O(n)`     |
| 四分之一满才缩到一半       | 缩容当次可 `O(n)` | `pop_back` 均摊 `O(1)`    |

## 边界条件、易错点与测试

### 视频明确呈现的边界和错误

- `pop_back` 只能在 `size > 0` 时执行。[视频 00:00:00–00:02:13]
- 必须在缩容前保存待返回元素。[视频 00:00:00–00:02:13]
- 不能在 `size == capacity/2` 时立即缩容，否则临界点交替增删会震荡。[视频 00:03:41–00:06:56]
- Lazy 策略的两个数不能只记一个：触发条件是四分之一满，目标容量是原来的一半。[视频 00:05:10–00:06:56]

### 常见误区

1. **只分析连续删除**：得到半满缩容均摊 `O(1)` 后就停止，没有测试混合操作序列。[视频 00:02:13–00:05:10]
2. **让扩容阈值与缩容后的状态贴在一起**：一次增、一次删即可来回 `resize`。[视频 00:03:41–00:05:10]
3. **先缩容、后读取被删值**：被删位置不在复制范围中，返回值可能丢失。[视频 00:00:00–00:02:13]
4. **把 Lazy 理解成“不缩容”**：它仍会回收空间，只是推迟到四分之一满，并只缩到一半。[视频 00:05:10–00:06:56]
5. **只报均摊 `O(1)`，不展示最坏序列**：无法说明策略为何能抵抗震荡。[视频 00:02:13–00:06:56]
6. **过度解读跑分**：小规模数据已经出现非单调值，不能要求每次翻倍都精确得到 2 倍时间。[视频 00:06:56–00:08:30]

5. **分别报复杂度**：“触发 `resize` 的单次操作仍可能是 `O(n)`，但 `push_back` 和 `pop_back` 都可维持均摊 `O(1)`。”[视频 00:02:13–00:06:56] [整理推导]
6. **补数据正确性**：“`pop_back` 若要返回被删元素，必须在可能重分配内存之前先保存它。”[视频 00:00:00–00:02:13]

## 复习区

### 核心清单

- 半满即缩容只在单向删除分析中看似安全。[视频 00:02:13–00:03:41]
- 临界点交替增删会让每次操作都触发 `resize`，退化为 `O(n)`。[视频 00:03:41–00:05:10]
- Lazy 策略：四分之一满时缩到一半。[视频 00:05:10–00:06:56]
- 缩容前先保存 `pop_back` 的返回元素。[视频 00:00:00–00:02:13]
- 触发 `resize` 的单次成本仍高；均摊结论来自昂贵操作之间的足够间隔。[视频 00:02:13–00:06:56] [整理推导]
- 计时实验看总体增长趋势，不要求小样本严格单调。[视频 00:06:56–00:08:30]

### 闪卡问题

1. 为什么在 `size == capacity/2` 时缩容，单看连续删除仍能得到均摊 `O(1)`？
2. 怎样构造一个让半满缩容发生复杂度震荡的操作序列？
3. Lazy 缩容的触发阈值和目标容量分别是什么？
4. 缩容后为什么不会立刻被一次 `push_back` 触发扩容？
