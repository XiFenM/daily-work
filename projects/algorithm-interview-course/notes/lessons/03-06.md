## 解法一：双层遍历

### 思路

最直接的方案是枚举所有 `i < j`，检查：

```text
numbers[i] + numbers[j] == target
```

[视频 00:03:00–00:04:35]

下面是根据课程思路整理的伪代码，不是屏幕中的完整代码对象：[视频 00:03:00–00:04:35] [整理推导]

```text

    for j = i+1 .. n-1:
        if numbers[i] + numbers[j] == target:
```

## 解法二：枚举一个数，二分查找另一个数

### 思路

固定 `numbers[i]` 后，第二个数必须等于：

```text

```

因为数组有序，可以在 `i` 之后的剩余区间中二分查找这个补数。[视频 00:04:36–00:06:58]

## 解法三：对撞指针

### 状态定义

初始化：

```cpp
int l = 0;
int r = numbers.size() - 1;
```

`l` 指向当前候选区间最小元素，`r` 指向当前候选区间最大元素；若题目保证的解尚未找到，则它的两个位置都应位于闭区间 `[l,r]` 内。[视频 00:06:59–00:11:54]

循环只在 `l < r` 时进行，这同时保证：

- 两个索引指向不同位置；
- 当前候选区间至少还有两个元素。

[视频 00:09:37–00:11:54] [整理推导]

### 三种比较结果

令：

```text
sum = numbers[l] + numbers[r]
```

1. `sum == target`：找到答案，返回 1-based 索引 `{l+1,r+1}`；[视频 00:06:59–00:11:54]
2. `sum < target`：当前和太小，令 `l++`；[视频 00:06:59–00:11:54]
3. `sum > target`：当前和太大，令 `r--`。[视频 00:06:59–00:11:54]

“对撞”指的就是左右两个指针从序列两端向中间移动，而不是两个从同一侧前进的指针。[视频 00:13:48–00:14:31]

## 为什么可以淘汰端点

### 情形一：当前和小于 `target`

假设：

```text
numbers[l] + numbers[r] < target
```

由于数组升序，对任意 `k` 满足 `l < k <= r`，都有：

```text
numbers[k] <= numbers[r]
```

于是：

```text
numbers[l] + numbers[k]
<= numbers[l] + numbers[r]
< target
```

也就是说，`numbers[l]` 连当前区间最大的 `numbers[r]` 都凑不够目标，更不可能和区间内其他更小或相等的元素组成答案。因此位置 `l` 可以整体淘汰，更新为 `l++` 不会漏解。[视频 00:06:59–00:09:36] [整理推导]

### 情形二：当前和大于 `target`

假设：

```text
numbers[l] + numbers[r] > target
```

对任意 `k` 满足 `l <= k < r`，有：

```text
numbers[k] >= numbers[l]
```

于是：

```text
numbers[k] + numbers[r]
>= numbers[l] + numbers[r]
> target
```

`numbers[r]` 连当前区间最小的 `numbers[l]` 配对都已经过大，和其他更大或相等的元素配对只会更大。因此位置 `r` 可以整体淘汰，更新为 `r--` 也不会漏解。[视频 00:06:59–00:09:36] [整理推导]

### 为什么证明依赖“有序”

两个淘汰式分别使用了 `numbers[k] <= numbers[r]` 和 `numbers[k] >= numbers[l]`。若数组无序，端点不再代表当前最小值和最大值，`sum` 太小或太大都不能安全排除整个端点。[视频 00:00:00–00:02:59] [视频 00:06:59–00:09:36] [整理推导]

```cpp
#include <iostream>
#include <vector>
#include <cassert>
#include <stdexcept>

using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& numbers, int target) {
        assert(numbers.size() >= 2);

        int l = 0, r = numbers.size() - 1;
        while (l < r) {
            if (numbers[l] + numbers[r] == target) {
                int res[2] = {l + 1, r + 1};
                return vector<int>(res, res + 2);
            }
            else if (numbers[l] + numbers[r] < target)
                l++;
            else
                r--;
        }

        throw invalid_argument("The input has no solution.");
    }
};
```

### 为什么对撞指针是 `O(n)`

初始距离是 `r-l=n-1`。每轮若未返回，就执行 `l++` 或 `r--`，使距离至少减少 1；因此检查次数至多与 `n` 成线性关系。[视频 00:06:59–00:11:54] [整理推导]

### 为什么额外空间是 `O(1)`

算法只维护 `l`、`r` 和固定大小的两个返回索引；返回向量始终只含两个元素，不随 `n` 增长，所以额外空间为 `O(1)`。[视频 00:09:37–00:12:00]

屏幕代码多次计算 `numbers[l] + numbers[r]`，会增加常数级重复工作，但不改变 `O(n)` 渐进结论；可在个人实现中用局部变量缓存 `sum`，这不是课程代码的必要修正。[视频 00:09:37–00:11:54] [整理推导]

## 边界条件与易错点

### 视频直接覆盖的契约

1. **两个位置不同**：使用 `while(l < r)`，不允许指针重合后把同一元素使用两次。[视频 00:00:00–00:02:59] [视频 00:09:37–00:11:54]
2. **1-based 输出**：内部下标必须在返回时各加 1。[视频 00:00:00–00:02:59] [视频 00:09:37–00:11:54]
3. **无解处理**：题面保证有解，但代码仍在循环后抛出异常。[视频 00:00:00–00:02:59] [视频 00:12:00–00:13:47]
4. **最小长度**：代码用断言要求至少两个元素。[视频 00:12:00–00:13:47]

### 常见逻辑错误

1. **无视有序性继续双层遍历**：功能上可行，但错过从 `O(n²)` 到 `O(n)` 的核心优化。[视频 00:03:00–00:09:36]
2. **和太小时移动右指针**：右端已经是当前最大值，向左只会让和更小，无法解决“不够大”。[视频 00:06:59–00:09:36] [整理推导]
3. **和太大时移动左指针**：左端已经是当前最小值，向右只会让和更大，无法解决“过大”。[视频 00:06:59–00:09:36] [整理推导]
4. **直接返回 `{l,r}`**：会错误地输出 0-based 索引。[视频 00:09:37–00:11:54]
5. **在二分方案中搜索整个数组**：可能重复选择位置 `i`；应只搜索其后区间。[视频 00:00:00–00:06:58] [整理推导]
6. **把对撞指针套到无序数组**：端点没有最小/最大含义，淘汰证明失效。[视频 00:00:00–00:09:36] [整理推导]
