### `n` 从 1 开始

本课围绕“倒数第 1 个是尾节点、倒数第 `N` 个是头节点”的位置语义展开。设链表共有 `N` 个真实节点，则合法参数满足：


## 解法一：两次遍历

### 第一次遍历：计算总长度

从 `head` 出发沿 `next` 走到 `NULL`，统计真实节点总数。为避免和函数参数 `n` 冲突，本笔记把这个规模记为大写 `N`；课程复杂度画面使用的是小写 `n`。[course_direct + editorial_inference | 基于 ev-003 | 视频 02:11–03:45]

### 第二次遍历：定位目标或其前驱

已知 `N` 后，倒数第 `n` 个节点的 0-based 正向索引是：

```text
N - n
```

若直接从真实头结点计数，可以走到这个索引并同步保留其前驱后删除，但删除头结点需要额外处理；若从虚拟头结点出发寻找前驱，则向前移动 `N-n` 次后，当前位置就是目标前驱。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 02:11–06:26]

例如 `N=5,n=2`：

```text
目标 0-based 索引 = 5 - 2 = 3
目标值 = 4
目标前驱值 = 3
```

[course_direct + editorial_inference | 基于 ev-002, ev-003 | 视频 00:48–03:45]

### 两次遍历不等于 `O(2N)`

第一遍至多访问 `N` 个节点，第二遍也至多访问 `N` 个节点，总工作量至多是常数倍的 `N`：

```text
N + N = 2N = O(N)
```

课程直接给出时间 `O(n)`、空间 `O(1)`；本笔记仅把规模变量重命名为 `N`。[course_direct + editorial_inference | 基于 ev-003 | 视频 02:11–03:45]

该方法的不足不是渐进复杂度更差，而是没有满足“能否只遍历一遍”的进一步优化目标。[course_direct | ev-003, ev-004 | 视频 02:11–06:26]

## 解法二：虚拟头结点 + 固定间距双指针

### 为什么先加 `dummyHead`

在真实头结点前创建一个虚拟节点：

```text
dummyHead → head → ... → tail → NULL
```

并令：

```cpp
dummyHead->next = head;
```

[course_direct + visual_direct | ev-004, ev-005 | 视频 03:45–11:56]

这样无论目标是头结点、中间节点还是尾节点，目标都存在一个统一的前驱：

- 删除头结点时，前驱是 `dummyHead`；
- 删除其他节点时，前驱是真实链表中的某个节点。

[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

删除动作因此统一为：

```cpp
ListNode* delNode = p->next;
p->next = delNode->next;
delete delNode;
```

[visual_direct | ev-005 | 视频 06:26–11:56]

### 初始化两个指针

课程让两个指针都从虚拟头结点出发：

```cpp
ListNode* p = dummyHead;
ListNode* q = dummyHead;
```

[course_direct + visual_direct | ev-004, ev-005 | 视频 03:45–11:56]

规范化状态模型把 `p` 记为慢指针、`q` 记为快指针。这里的“快”不是指它在同步阶段每轮走更多步，而是指它先获得领先距离；同步阶段两者每轮都只走一步。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### `q` 为什么先走 `n+1` 步

代码执行：

```cpp
for (int i = 0; i < n + 1; i++) {
    assert(q);
    q = q->next;
}
```

[visual_direct | ev-005 | 视频 06:26–11:56]

预走结束后，从 `p` 沿 `next` 到达 `q` 需要 `n+1` 次跃迁。这里把 `NULL` 也视为链表尾部之后的终止位置，以便统一计算距离。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

需要的是 `n+1` 而不是 `n`，因为最终希望 `p` 停在**目标前驱**：

```text
p → 待删节点 → ... 共 n 个真实节点 ... → NULL
```

从 `p` 到 `NULL` 正好经过 `n+1` 条 `next` 边：

1. 第一条边从 `p` 到待删节点；
2. 之后覆盖从待删节点到尾节点的 `n-1` 条真实节点间边；
3. 最后一条边从尾节点到 `NULL`。

[course_direct + editorial_inference | 基于 ev-004 | 视频 03:45–06:26]

若只让 `q` 领先 `n` 步，终止时 `p` 会落在待删节点自身附近，不能直接用统一的 `p->next` 完成删除。[editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### 同速前进

建立间距后，代码执行：

```cpp
while (q != NULL) {
    p = p->next;
    q = q->next;
}
```

[visual_direct | ev-005 | 视频 06:26–11:56]

每轮两个指针都沿 `next` 前进一步，所以它们之间的跃迁距离保持不变。当 `q` 到达 `NULL`，`p` 就到达待删节点的前驱。[course_direct + visual_direct | ev-004, ev-005 | 视频 03:45–11:56]

## 固定间距不变量

规范化证据把本课正确性方法记录为 `state_transition`，不是具有四阶段课程证明的 `loop_invariant`。课程直接给出固定距离与转移；下面的精确初始化、保持和退出解释是基于这些画面的整理推导。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### 状态定义

在同步循环开始时：

- `p`、`q` 都位于从 `dummyHead` 到 `NULL` 的同一条链上；
- 从 `p` 沿 `next` 到 `q` 恰好需要 `n+1` 次跃迁；
- `q` 位于 `p` 前方，或者已经是终止位置 `NULL`。

[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### 初始化

两个指针最初都在 `dummyHead`，距离为 0。让 `q` 执行 `n+1` 次 `q=q->next` 后，`p` 不动，因此距离建立为 `n+1`。[course_direct + visual_direct | ev-004, ev-005 | 视频 03:45–11:56]

在合法契约 `1<=n<=N` 下，这 `n+1` 次跃迁始终可以从非空节点出发：当 `n=N` 时，最后一次恰好从尾节点走向 `NULL`。[editorial_inference | 基于 ev-002, ev-004, ev-005 | 视频 00:48–11:56]

### 保持

若循环条件 `q!=NULL` 成立，一轮同时执行：

```text
p 前进一步
q 前进一步
```

两者在同一条单链上移动相同边数，所以它们之间的 `n+1` 跃迁距离保持不变。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### 终止

`q` 每轮都向尾部推进一个节点，有限链表上最终会到达 `NULL`。退出时，从 `p` 到 `NULL` 仍有 `n+1` 次跃迁，因此 `p->next` 到 `NULL` 覆盖的真实节点数正好为 `n`；`p->next` 就是倒数第 `n` 个节点。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### 删除后的后置状态

执行：

```cpp
ListNode* delNode = p->next;
p->next = delNode->next;
delete delNode;
```

会绕过并释放目标节点，同时保持目标之前和之后的剩余链段相连。[visual_direct + editorial_inference | 基于 ev-005 | 视频 06:26–11:56]

这只能证明屏幕可见删除片段的局部效果。函数最终返回哪个指针、是否释放 `dummyHead`，因画面未显示完整尾部而不能从 `ev-005` 直接确认。[visual_direct | ev-005 | 视频 06:26–11:56]

## 边界条件

### 删除头结点：`n=N`

`q` 从 `dummyHead` 走 `N+1` 步后恰好到达 `NULL`，同步循环不执行，`p` 仍停在 `dummyHead`。因此 `p->next` 就是真实头结点，删除逻辑不需要单独分支。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### 删除尾节点：`n=1`

`q` 先走两步，随后与 `p` 同速前进。退出时 `p` 停在尾节点的前驱，`p->next` 是尾节点。[editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### 单节点链表：`N=1,n=1`

`q` 从 `dummyHead` 经过唯一真实节点后到达 `NULL`，`p` 保持在 `dummyHead`，因此唯一节点可以被统一删除。[editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

### `n>N`

屏幕循环在每次读取 `q->next` 前执行 `assert(q)`。调试构建中，当预走次数超过链表可达范围时，断言会失败；但题面是否保证合法、发布构建是否启用断言仍需按接口约定处理。[course_direct + visual_direct + editorial_inference | 基于 ev-002, ev-005 | 视频 00:48–02:11；06:26–11:56]

### `n=0`：屏幕断言与契约冲突

屏幕代码：

```cpp
assert(n >= 0);
```

允许 `n=0` 继续执行，但倒数位置按 1 起算时，`0` 没有合法含义。[course_direct + visual_direct | ev-002, ev-005 | 视频 00:48–02:11；06:26–11:56]

按可见代码推演，`n=0` 时 `q` 只领先一步；同步循环结束后 `p` 会位于尾节点，因而：

```text
delNode = p->next = NULL
```

```cpp
/// Definition for singly-linked list.
struct ListNode {
    int val;
    ListNode *next;
    ListNode(int x) : val(x), next(NULL) {}
};

class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        assert(n >= 0);

        ListNode* dummyHead = new ListNode(0);
        dummyHead->next = head;

        ListNode* p = dummyHead;
        ListNode* q = dummyHead;
        for (int i = 0; i < n + 1; i++) {
            assert(q);
            q = q->next;
        }

        while (q != NULL) {
            p = p->next;
            q = q->next;
        }

        ListNode* delNode = p->next;
        p->next = delNode->next;
        delete delNode;
```

## 复杂度分析

### 先统一变量

课程复杂度画面使用 `O(n)`，其中小写 `n` 表示链表规模；但函数签名里的参数 `n` 表示“倒数第几个”。本笔记采用：

```text
N = 链表真实节点总数
n = 要删除的倒数位置，1 <= n <= N
```

[course_direct + editorial_inference | 基于 ev-002, ev-003, ev-005 | 视频 00:48–11:56]

### 两次遍历法

- 第一遍访问 `N` 个节点；
- 第二遍最多再访问 `N` 个节点；
- 时间复杂度整理为 `O(N)`；
- 只保存长度、计数和常数个指针，辅助空间 `O(1)`。

课程原始写法为时间 `O(n)`、空间 `O(1)`。[course_direct + editorial_inference | 基于 ev-003 | 视频 02:11–03:45]

### 固定间距双指针法

- `q` 预走 `n+1` 步；
- 同步阶段执行 `N-n` 次；
- 总移动量为 `(n+1)+(N-n)=N+1`，因此时间 `O(N)`；
- `dummyHead`、`p`、`q`、`delNode` 等都是常数个节点或指针引用，辅助空间 `O(1)`。

[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]

| 方法           | 遍历组织                       | 时间   | 辅助空间 | 课程重点                 |
| -------------- | ------------------------------ | ------ | -------- | ------------------------ |
| 两次遍历       | 求长度，再按正向位置定位       | `O(N)` | `O(1)`   | 正确但要走两遍           |
| 固定间距双指针 | 预走建立间距，再同步推进到末尾 | `O(N)` | `O(1)`   | 一次连续扫描定位目标前驱 |

两者渐进复杂度相同。优化点是减少独立遍历轮次，并建立一个可直接定位前驱的状态，而不是把时间复杂度从平方级降到线性级。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 02:11–06:26]

## 常见错误

1. **混淆 `N` 和 `n`**：前者是链表长度，后者是倒数位置；复杂度 `O(N)` 不是“与倒数位置成线性”。[course_direct + editorial_inference | 基于 ev-002, ev-003, ev-005 | 视频 00:48–11:56]
2. **只让 `q` 领先 `n` 步**：退出时无法保证 `p` 是目标前驱。[course_direct + editorial_inference | 基于 ev-004 | 视频 03:45–06:26]
3. **不使用虚拟头结点却忘记删除头结点特判**：`n=N` 时目标没有真实前驱。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]
4. **先移动 `p` 再建立完整间距**：破坏固定距离初始化。[editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]
5. **循环到 `q->next==NULL` 就停止**：这对应另一种间距定义；若仍使用本课的 `n+1` 初始化，会产生 off-by-one。[editorial_inference | 基于 ev-004, ev-005 | 视频 03:45–11:56]
6. **把 `assert(n >= 0)` 当成契约已验证**：它不能拒绝 `n=0`。[visual_direct + editorial_inference | 基于 ev-002, ev-005 | 视频 00:48–11:56]
7. **依赖 `assert` 作为生产错误处理**：断言可能被编译配置关闭，且课程接口是否保证合法必须先澄清。[course_direct + editorial_inference | 基于 ev-002, ev-005 | 视频 00:48–11:56]
8. **断链后不释放 `delNode`**：屏幕代码明确执行 `delete delNode;`。[course_direct + visual_direct | ev-005 | 视频 06:26–11:56]
9. **声称屏幕完整展示了返回与 dummy 清理**：人工 QA 只能看到删除语句，尾部不可核实。[visual_direct | ev-005 | 视频 06:26–11:56]
