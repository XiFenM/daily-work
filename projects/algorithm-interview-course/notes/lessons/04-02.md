### 为什么缺失键会得到 0

对非 `const std::map<Key,T>` 使用 `operator[]` 时，如果键不存在，会插入该键，并对映射值 `T` 做值初始化；本课的 `T` 是 `int`，所以初始值为 `0`。[course_direct + visual_direct + editorial_inference | 基于 ev-003 | 视频 03:47–08:16]

“默认值是 0”只适用于这里的 `int` 映射值。若 `T` 是其他类型，应按该类型的值初始化或默认构造语义分析，不能把数字 `0` 当作所有 `map` 的普遍默认值。[editorial_inference | 基于 ev-003 | 视频 03:47–08:16]

### `find` 与 `operator[]` 的语义不同

- `find(key)` 查询键是否存在，不因未命中而创建键；
- `operator[](key)` 需要返回一个可写值引用，未命中时会先创建键值项。

[course_direct + visual_direct | ev-003 | 视频 03:47–08:16]

因此，下面这句虽然看起来只是“检查是否大于 0”，但对不存在的 `nums2[i]` 具有写副作用：

```cpp
if (record[nums2[i]] > 0)
```

它会把未出现于 `nums1` 的值作为“键 → 0”插入 `record`。这不会让错误值进入结果，但会改变 `map` 的内容和大小。[course_direct + editorial_inference | 基于 ev-002, ev-003 | 视频 01:20–08:16]

## 值归零不等于键删除

`map` 中一项包含两个相互独立的事实：

1. 键是否存在；
2. 这个键映射到什么值。

把 `record[x]` 减到 `0` 只修改第二项，不会自动改变第一项。此时 `find(x) != end()` 仍然成立。[course_direct + visual_direct | ev-004 | 视频 08:16–11:35]

若要让 `find(x)` 返回未找到，必须显式执行：

```cpp
record.erase(x);
```

[course_direct + visual_direct | ev-004 | 视频 08:16–11:35]

对本题而言，保留 `x → 0` 不会破坏基线算法的输出正确性，因为条件还检查了 `> 0`；但它会留下已经耗尽或原本不存在的零值键，弱化“键存在就表示仍有配额”的状态语义。[editorial_inference | 基于 ev-002–ev-004 | 视频 01:20–11:35]

```cpp
#include <iostream>
#include <vector>
#include <map>

using namespace std;

class Solution {
public:
    vector<int> intersect(vector<int>& nums1, vector<int>& nums2) {
        map<int, int> record;
        for (int i = 0; i < nums1.size(); i++) {
            if (record.find(nums1[i]) == record.end())
                record.insert(make_pair(nums1[i], 1));
            else
                record[nums1[i]]++;
        }

        vector<int> resultVector;
        for (int i = 0; i < nums2.size(); i++) {
            if (record.find(nums2[i]) != record.end() &&
                record[nums2[i]] > 0) {
                resultVector.push_back(nums2[i]);
                record[nums2[i]]--;
                if (record[nums2[i]] == 0)
                    record.erase(nums2[i]);
            }
        }

        return resultVector;
    }
};
```



### 状态转移

- 当前 `x` 的剩余次数为 `0`：不输出，`out_i(x)` 已达到 `c1(x)`，继续跳过才能避免超过第一数组频次；

## 复杂度分析

规范化证据没有给出本课时间或空间复杂度；视频结尾预告下一课再讨论 `set`、`map` 的底层实现与复杂度。因此以下仅为根据当前 `std::map` 代码做的编辑性上界分析。[course_direct + editorial_inference | 基于 ev-002, ev-005, ev-006 | 视频 01:20–03:47；11:35–13:05.960]

令：

- `n = nums1.size()`；
- `m = nums2.size()`；
- `u` 为 `nums1` 的不同值数量；
- `d` 为基线扫描中“只在 `nums2` 出现”的不同值数量；
- `k` 为输出长度。

### 基线版本

基线对不存在于 `record` 的 `nums2` 值使用 `operator[]`，会插入零值键，所以 `map` 最多增长到 `u+d` 个键。按有序 `std::map` 的对数级操作复杂度保守估算：

```text
时间：O((n + m) log(n + m) + k)
空间：O(u + d + k)
```

[editorial_inference | 基于 ev-002, ev-003 | 视频 01:20–08:16]

### 显式版本

显式版本未命中时只做 `find`，不会插入 `nums2` 独有的键；匹配配额耗尽后还会 `erase`，所以频次表大小不超过 `u`：

```text
时间：O((n + m) log max(u, 2) + k)
空间：O(u + k)
```

[editorial_inference | 基于 ev-004, ev-005 | 视频 08:16–11:56]

这里的 `+k` 表示构造返回向量的写入成本。若分析约定返回结果不计辅助空间，应明确说明口径；频次 `map` 本身仍需 `O(u)`。[editorial_inference | 基于 ev-002, ev-005 | 视频 01:20–03:47；11:35–11:56]

显式重构的主要价值仍是语义清晰和避免零值垃圾键；不能因为规范化阶段名叫 `optimized`，就声称课程已经测得它更快。[course_direct + editorial_inference | 基于 ev-003–ev-005 | 视频 03:47–11:56]

### 编辑性解答：双指针

若两个数组都已按同一顺序排序，可维护 `i`、`j`：

1. `nums1[i] < nums2[j]`：`nums1[i]` 不可能再与后面的更大值匹配，移动 `i`；
2. `nums1[i] > nums2[j]`：移动 `j`；
3. 两者相等：把该值加入结果，并同时移动 `i`、`j`。

[editorial_inference | 基于 ev-006 及第 3 章对撞指针方法 | 视频 11:56–13:05.960]

对 LeetCode 350，每次相等只消费两边各一个元素，所以重复值自然会匹配 `min(c1(x), c2(x))` 次；对 LeetCode 349，则还要跳过重复值或对结果去重。[editorial_inference | 基于 ev-001, ev-006 | 视频 00:00–01:20；11:56–13:05.960]

若输入已经有序，双指针的编辑性复杂度为：

```text
时间 O(n+m)，额外空间 O(1)（不计返回结果）
```

这不是视频已完成的题解或实测结论，而是对思考题的笔记补全。[editorial_inference | 基于 ev-006 | 视频 11:56–13:05.960]

### 二分查找方向

课程证据提到二分查找与有序输入的联系。若采用二分查找，还必须处理重复次数和“已经消费的位置”，不能只证明某个值存在就重复输出；视频没有展开这套状态设计。[course_direct + editorial_inference | 基于 ev-006 | 视频 11:56–13:05.960]
