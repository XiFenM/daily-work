## 一句话结论

预先统计每个 `C[k] + D[l]` 出现的频次；随后枚举每个 `(i,j)`，查询补数 `0 - A[i] - B[j]`，并把该补数的**全部频次**累加到答案。这样把四重枚举压缩为两次二重枚举，在课程的哈希均摊模型下，时间和辅助空间均为 `O(N²)`。[ev-004；视频 03:00–04:58] [ev-005；视频 04:58–09:05]

## 问题与输入契约

题目要求统计有多少组索引 `(i,j,k,l)` 满足：

```text
A[i] + B[j] + C[k] + D[l] == 0
```

四个数组各含 `N` 个元素，`0 <= N <= 500`。[ev-001；视频 00:00–01:17]

需要注意，答案统计的是**索引组合数**，不是不同和值的数量，也不是去重后的四元组值集合。即使不同的 `(k,l)` 产生相同 `C[k] + D[l]`，它们仍代表不同的候选索引对，必须分别计数。[ev-004；视频 03:00–04:58]

本课证据只记录了数组等长和 `N` 的范围，没有完整记录元素数值范围或返回值上界；因此本笔记不额外宣称 `int` 在所有可能输入上都不会溢出。[补充说明]

## 第二步：把 `D` 放进查找表，得到 `O(N³)`

把 `D` 中的值放入查找表后，可以枚举 `A[i]、B[j]、C[k]`，再查询：

```text
neededD = 0 - A[i] - B[j] - C[k]
```

这样不必继续线性枚举 `D[l]`，四重循环减少为三重循环。[ev-003；视频 01:58–03:00]

课程给出的规模是：

```text
500³ = 125,000,000
```

即约 **1.25 亿** 次三元组合检查；对课程采用的一秒时间预算仍然过慢。[ev-003；视频 01:58–03:00]

课程口径下：

- 时间：`O(N³)`；
- 辅助空间：保存 `D` 的查找状态，`O(N)`。[ev-003；视频 01:58–03:00]

### 频次问题在这一阶段仍然存在

如果 `D` 中同一个值出现多次，仅记录“是否存在”同样会漏掉不同的 `l`。视频在 `C+D` 优化阶段明确强调必须保存频次；把这一原则迁移到 `D` 表时，也应保存 `neededD` 出现的次数，而不是只加一。这是从最终计数语义得到的整理推导，本课没有展示 `O(N³)` 版本代码。[ev-004；视频 03:00–04:58] [整理推导]

## 第三步：把 `C+D` 的所有和放进 map

### 把四元等式拆成两个二元部分

原条件可以重写为：

```text
A[i] + B[j] = -(C[k] + D[l])
```

或：

```text
C[k] + D[l] = 0 - A[i] - B[j]
```

[ev-004；视频 03:00–04:58]

由此可先枚举所有 `(k,l)`，把它们的和存入查找表：

```text
key   = C[k] + D[l]
value = 产生这个 key 的 (k,l) 索引对数量
```

[ev-004；视频 03:00–04:58] [ev-005；视频 04:58–09:05]

之后只需枚举 `(i,j)` 并查补数。四个维度被拆成两个 `N²` 阶段，而不是继续同时枚举四个索引。[整理推导]

### 为什么键选 `C+D`

选择 `C+D` 不是因为这两个数组天然比 `A+B` 特殊，而是因为把四个变量对半拆分后，任意一边都可以预处理。课程随后给出的双表变体也说明，`A+B` 和 `C+D` 的角色是对称的。[ev-004；视频 03:00–04:58] [ev-006；视频 09:05–11:03]

本课真正要迁移的方法是：

> 把会被反复查询的组合结果预先作为 key，而不是局限于把输入元素本身作为 key。

### 幻灯片中的 map 与代码中的 `unordered_map`

课程讲思路时使用“map / 查找表”表示“键到频次”的抽象关系，实际 C++ 代码使用的是：

## 为什么必须存频次，不能只用 set

若只使用 `set`，它只能回答“这个和有没有出现”，不能回答“这个和由多少个不同的 `(k,l)` 产生”。但题目统计索引四元组；每个匹配的 `(k,l)` 都要贡献一组答案。[ev-004；视频 03:00–04:58]

因此需要：

```cpp
record[C[k] + D[l]]++;
```

而不是只把 `C[k] + D[l]` 放入集合。[ev-005；视频 04:58–09:05]

### 最小反例

下面是依据课程计数语义构造的纸面例子，不是视频运行样例：[整理推导]

```text
A = [0, 1]
B = [0, 1]
C = [0, 0]
D = [0, 0]
```

`C[k] + D[l] == 0` 有 4 组不同索引对：

```text
(k,l) = (0,0), (0,1), (1,0), (1,1)
```

`A[i] + B[j] == 0` 只有 `(i,j) = (0,0)`。因此答案应增加 4：

```text

```

### `record`

### `res`



## 视频中的完整代码

```cpp
#include <iostream>
#include <vector>
#include <unordered_map>
#include <cassert>

using namespace std;

class Solution {
public:
    int fourSumCount(vector<int>& A, vector<int>& B,
                     vector<int>& C, vector<int>& D) {
        assert(A.size() == B.size() &&
               B.size() == C.size() &&
               C.size() == D.size());

        unordered_map<int, int> record;
        for (int i = 0; i < C.size(); i++)
            for (int j = 0; j < D.size(); j++)
                record[C[i] + D[j]]++;

        int res = 0;
        for (int i = 0; i < A.size(); i++)
            for (int j = 0; j < B.size(); j++)
                if (record.find(0 - A[i] - B[j]) != record.end())
                    res += record[0 - A[i] - B[j]];

        return res;
    }
};
```

## 正确性解释

课程直接说明了“保存 `C+D` 的频次，再按补数累加”的计数逻辑；下面用初始化、保持、终止与后置条件整理它，不是讲师逐字形式化证明。[ev-004；视频 03:00–04:58] [ev-005；视频 04:58–09:05] [整理推导]

### 1. 建表初始化

`record` 初始为空。每处理一个 `(k,l)`，就令：

```text
record[C[k] + D[l]] += 1
```

因此双重循环结束后，每个键的值恰好等于产生该和的索引对数量。[整理推导]

### 2. 查询阶段的不变量

在查询阶段处理完若干个 `(i,j)` 后：

```text
res = 已处理的所有 (i,j) 能组成的合法 (i,j,k,l) 总数
```

对当前 `(i,j)`，只有满足：

```text
C[k] + D[l] = 0 - A[i] - B[j]
```

的索引对能组成合法四元组，而其数量正是 `record[complement]`。因此累加这一频次既不漏计，也不多计。[ev-004；视频 03:00–04:58] [ev-005；视频 04:58–09:05] [整理推导]

### 3. 终止

两组双重循环都遍历有限数组：

- 第一组覆盖所有 `N²` 个 `(k,l)`；
- 第二组覆盖所有 `N²` 个 `(i,j)`。

循环结束后，所有索引四元组都被唯一归入某个当前 `(i,j)` 与其补数频次中。[整理推导]

### 4. 后置条件

每个合法四元组有唯一的前半索引对 `(i,j)` 和后半索引对 `(k,l)`，所以它恰好在处理该 `(i,j)` 时被 `record[complement]` 计入一次。最终 `res` 就是题目要求的总数。[整理推导]

## 复杂度分析

### 时间复杂度

建表阶段：

```text
N² 个 (k,l) × 每次哈希更新均摊 O(1) = O(N²)
```

查询阶段：

```text
N² 个 (i,j) × 每次哈希查询均摊 O(1) = O(N²)
```

所以：

```text
O(N²) + O(N²) = O(N²)
```

[ev-005；视频 04:58–09:05]

这是课程在 `unordered_map` 均摊常数操作模型下的结论。本课没有展开碰撞退化时的最坏情况，不能把它改写成无条件最坏界。[补充说明]

### 辅助空间复杂度

`C` 和 `D` 有 `N²` 个索引对。若每个索引对产生的和都不同，`record` 最多有 `N²` 个键；若许多和重复，键数会更少，但频次之和仍为 `N²`。[ev-004；视频 03:00–04:58] [ev-005；视频 04:58–09:05] [整理推导]

因此课程给出的辅助空间上界为：

```text
O(N²)
```

[ev-005；视频 04:58–09:05]

### 三阶段对照

| 方案                | 预处理内容     | 主枚举    | 课程时间 | 辅助空间 | `N=500` 的主数量级 |
| ------------------- | -------------- | --------- | -------- | -------- | ------------------ |
| 四重暴力            | 无             | `A×B×C×D` | `O(N⁴)`  | `O(1)`   | `62,500,000,000`   |
| 把 `D` 放表         | `D` 的值/频次  | `A×B×C`   | `O(N³)`  | `O(N)`   | `125,000,000`      |
| 把 `C+D` 及频次放表 | `C×D` 的组合和 | `A×B`     | `O(N²)`  | `O(N²)`  | `250,000`          |

[ev-002；视频 01:17–01:58] [ev-003；视频 01:58–03:00] [ev-004；视频 03:00–04:58] [ev-005；视频 04:58–09:05]

这个对照展示了典型的空间换时间：保存的组合从一个数组扩大到两个数组的笛卡尔积，辅助空间从 `O(N)` 上升为 `O(N²)`，主枚举则从三层降为两层。[整理推导]

## 双表变体

课程还提出对称变体：[ev-006；视频 09:05–11:03]

```text
recordAB[x] = 产生 A[i] + B[j] == x 的 (i,j) 数量
recordCD[y] = 产生 C[k] + D[l] == y 的 (k,l) 数量
```

然后对 `recordAB` 中每个和 `x`，在 `recordCD` 中查找 `-x`。[ev-006；视频 09:05–11:03]

要计算索引四元组数，匹配时应累加：

```text
recordAB[x] × recordCD[-x]
```

因为前半部分有 `recordAB[x]` 种索引对，后半部分有 `recordCD[-x]` 种索引对，两者可以任意组合。频次相乘是依据计数乘法原理的整理推导；视频没有展示双表变体的完整代码。[ev-006；视频 09:05–11:03] [整理推导]

在课程的哈希模型下：

- 建立两张表各需要 `O(N²)`；
- 遍历其中一张表的至多 `N²` 个键，并在另一张表中均摊 `O(1)` 查询；
- 总时间仍为 `O(N²)`；
- 两张表总空间仍为 `O(N²)`，只是常数因子更大。[ev-006；视频 09:05–11:03] [整理推导]

若对两张表的所有键做双重嵌套匹配，可能重新膨胀到 `O(N⁴)`；保持 `O(N²)` 的关键是“遍历一张表，对另一张表做补数查询”，不是任意方式地遍历两个表。[整理推导]

## 边界条件与常见错误

### 边界条件

1. **`N = 0`**：题面允许。两组双重循环都不执行，`res` 保持 0。[ev-001；视频 00:00–01:17] [整理推导]
2. **四个数组长度不等**：题目契约说它们等长，屏幕代码用 `assert` 检查；若断言被移除，代码仍分别按各数组实际长度循环，但这已经超出课程给定契约。[ev-001；视频 00:00–01:17] [ev-005；视频 04:58–09:05] [补充说明]
3. **大量重复和**：必须把频次完整累加，不能只记录存在性。[ev-004；视频 03:00–04:58]
4. **没有补数**：`find` 失败，不修改 `res`。[ev-005；视频 04:58–09:05]
5. **数值和计数范围**：屏幕代码用 `int` 存键与答案，但本课证据没有完整记录元素值域或答案上界，无法仅凭 `N <= 500` 证明所有中间和与计数都不会溢出。[补充说明]

### 常见错误

- 仍然同时枚举四个数组，只把查找表当成附加结构，没有真正消去循环层级。[ev-002；视频 01:17–01:58] [ev-003；视频 01:58–03:00]
- 只把 `D` 放入表就停止优化，忽略 `N=500` 时 `N³` 仍约为 1.25 亿。[ev-003；视频 01:58–03:00]
- 使用 `set` 保存 `C+D`，把相同和的多个索引对压成一个存在标记。[ev-004；视频 03:00–04:58]
- 查补数时写成 `A[i] + B[j]`，忘记取相反数；目标方程要求查 `0-A[i]-B[j]`。[ev-004；视频 03:00–04:58] [ev-005；视频 04:58–09:05]
- 命中后只执行 `res++`，没有累加 `record[complement]` 的全部频次。[ev-005；视频 04:58–09:05]
- 在双表变体中只加两个频次而不是相乘，或对两表键做笛卡尔积扫描。[ev-006；视频 09:05–11:03] [整理推导]
- 把哈希单次 `O(1)` 写成无条件最坏情况保证；本课只支持课程采用的均摊模型。[ev-005；视频 04:58–09:05] [补充说明]
