## 解法一：固定起点的路径计数

先定义辅助函数：

> `findPath(node, num)`：在以 `node` 为起点且必须包含 `node` 的所有向下路径中，返回节点和等于 `num` 的路径数量。[course_direct + visual_direct | ev-004 | 视频 05:57–09:11]

对非空节点，处理分为三步：

1. 若 `node->val == num`，以当前节点结束的路径是一条解，令 `res += 1`；
2. 去左子树寻找剩余和为 `num - node->val` 的路径；
3. 去右子树寻找剩余和为 `num - node->val` 的路径。[course_direct + visual_direct | ev-004 | 视频 05:57–09:11]

这里的“剩余和”不是全局变量。每个递归调用都接收属于自己路径前缀的新目标，因此左右分支互不影响。[editorial_inference | 基于 code-001 的值传递参数]

### 为什么命中后不能返回

错误写法的直觉是：

```cpp
if (node->val == num)
    return 1;
```

这会漏掉以同一节点为起点、但在当前命中点之后继续延伸的合法路径。课程明确以负数说明：后续若先下降、再被另一个节点抵消，较长路径仍可能得到相同目标和，因此必须先 `res += 1`，再继续递归左右子树。[course_direct + visual_direct | ev-004 | 视频 05:57–09:11]

同一个控制流理由也覆盖值为 `0` 的后继节点：例如目标为 `5`，路径 `5` 与 `5 -> 0` 都应计数。[editorial_inference | 由“命中后仍可有零和后缀”推出；课程直接举的是负数场景]

## 解法二：枚举所有可能起点

主函数契约是：

> `pathSum(root, sum)`：返回所有完全位于 `root` 所代表子树内、节点和等于 `sum` 的向下路径数量。[course_direct + visual_direct | ev-003, ev-005 | 视频 02:07–14:11.16]

任意一条位于当前子树内的合法路径，其首节点必然且只能落入以下一类：

1. 首节点就是 `root`；
2. 首节点位于 `root->left` 子树；
3. 首节点位于 `root->right` 子树。[course_direct + visual_direct | ev-003, ev-005 | 视频 02:07–14:11.16]

因此递推式是：

```text
pathSum(root, sum)
  = findPath(root, sum)
  + pathSum(root->left, sum)
  + pathSum(root->right, sum)
```

第一项固定路径起点为 `root`；第二、三项保留原目标和，因为它们是在各自子树中重新选择起点。[course_direct + visual_direct | ev-003, ev-005 | 视频 02:07–14:11.16]

### 三类为何互斥且完备

- **互斥**：一条路径只有一个首节点；该首节点不可能同时等于 `root`、位于左子树和位于右子树。
- **完备**：当前子树中的任意节点只能是 `root`，或属于左子树，或属于右子树；所以任意合法路径的首节点必属于三者之一。
- **不重复**：外层递归只按首节点所属区域分类；固定首节点后，`findPath` 再按终点所在分支计数，两个层次的分类职责不同。[editorial_inference | 基于 ev-003, ev-005 与二叉树子树互斥性]

## 完整课程代码

```cpp
#include <iostream>

using namespace std;

/// Definition for a binary tree node.
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};

class Solution {
public:
    // 在以root为根节点的二叉树中，寻找和为sum的路径，返回这样的路径个数
    int pathSum(TreeNode* root, int sum) {
        if( root == NULL )
            return 0;

        int res = findPath( root, sum );
        res += pathSum( root->left, sum );
        res += pathSum( root->right, sum );

        return res;
    }

private:
    // 在以node为根节点的二叉树中，寻找包含node的路径，和为sum
    // 返回这样的路径个数
    int findPath( TreeNode* node, int num ){
        if( node == NULL )
            return 0;

        int res = 0;
        if( node->val == num )
            res += 1;

        res += findPath( node->left, num - node->val );
        res += findPath( node->right, num - node->val );

        return res;
    }
};
```

## 正确性论证

### `findPath` 的归纳证明

以 `node` 子树高度作归纳：

- **空树**：没有以空节点为起点的路径，返回 `0` 正确。
- **非空节点**：所有以 `node` 为起点的向下路径，要么在 `node` 结束，要么下一步进入左子树，要么下一步进入右子树。
- 当 `node->val == num` 时，第一类贡献一条；左右递归分别完整统计后两类，且两类不重叠。
- 因此三项之和恰好是所有以 `node` 为起点、和为 `num` 的路径数量。[editorial_inference | 基于 ev-004 与 code-001]

### `pathSum` 的归纳证明

以 `root` 子树的节点数作归纳：

- **空树**：没有路径，返回 `0`。
- **非空树**：按路径唯一首节点分成从 `root` 开始、左子树内开始、右子树内开始三类。
- `findPath(root, sum)`、`pathSum(root->left, sum)`、`pathSum(root->right, sum)` 分别准确统计这三类。
- 三类互斥且完备，所以相加后的结果准确且无重复。[editorial_inference | 基于 ev-003, ev-005 与 code-001]

## 复杂度

课程没有给出本实现的复杂度结论。[补充说明 | 基于完整视频证据范围]

设节点数为 `n`、树高为 `h`：

- 每个节点都会作为一次外层 `pathSum` 的起点；对应的 `findPath` 会扫描该节点的后代。
- 总工作量等于所有起点的子树规模之和，也可理解为祖先—后代节点对的数量，因此上界为 `O(nh)`。
- 平衡树中 `h = O(log n)`，由此得到 `O(n log n)`；极度倾斜时 `h = O(n)`，最坏为 `O(n²)`。
- 任一时刻的递归深度受树高控制；`findPath` 返回后外层才继续递归，所以辅助调用栈为 `O(h)`，而不是把两层深度相乘。[editorial_inference | 基于 code-001 的调用顺序]
