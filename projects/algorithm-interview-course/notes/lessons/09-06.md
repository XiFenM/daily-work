## 一句话结论

二维转移：

```text
F(i,c) = max(F(i-1,c), v[i] + F(i-1,c-w[i]))
```

只读取上一行，所以可以先滚动成两行。再压成一行时，更新第 `i` 件物品必须执行：

```cpp
for (int j = C; j >= w[i]; --j)
    memo[j] = max(memo[j], v[i] + memo[j-w[i]]);
```

倒序保证 `memo[j-w[i]]` 尚未被第 `i` 轮更新，仍表示 `F(i-1,j-w[i])`；这就是一维 0-1 背包的核心不变量。[course_direct + visual_direct | formula-001, ev-006, ev-007]

## 起点：二维 0-1 背包表

上一课的状态为：

```text
F(i,c) = 使用物品 [0...i]、容量为 c 时可获得的最大价值
```

转移为：

```text
F(i,c) = max(
    F(i-1,c),
    v[i] + F(i-1,c-w[i])
)
```

第二支只在 `c>=w[i]` 时可用。[course_direct + visual_direct | formula-001, ev-002]

课程开头直接给出二维基线：

```text
时间：O(n*C)
空间：O(n*C)
```

[course_direct + visual_direct | cx-001, ev-001]

优化的切入点不是“公式能不能少算”，而是“计算第 `i` 行时，哪些历史行还会被读取”。

## 依赖图：为什么只需要上一行

对任意单元 `F(i,c)`，依赖只有：

```text
F(i-1,c)
F(i-1,c-w[i])
```

它们都在第 `i-1` 行。第 `i-2` 行及更早的值不会被第 `i` 行直接读取；一旦第 `i-1` 行完整可用，更早行即可回收。[course_direct + visual_direct | ev-002, ev-003]

这得到两行存储：

```text
上一行：读
当前行：写
```

写完当前行后，角色交换。

## 两行滚动数组

课程不真的移动整行，而是让物品索引的奇偶性选择物理行：

```text
当前物理行：i % 2
上一物理行：(i - 1) % 2
```

[course_direct + visual_direct | ev-003, ev-004]

对应转移：

```cpp
memo[i%2][j] = memo[(i-1)%2][j];
if (j >= w[i])
    memo[i%2][j] = max(
        memo[i%2][j],
        v[i] + memo[(i-1)%2][j-w[i]]
    );
```

[visual_direct | code-001, ev-004]

### 两行不变量

在开始计算物品 `i` 前：

```text
memo[(i-1)%2][j] = F(i-1,j)，对所有 0<=j<=C
```

计算完当前行后：

```text
memo[i%2][j] = F(i,j)，对所有 0<=j<=C
```

下一轮把这一行当成上一行。[course_direct + editorial_inference | 基于 ev-003, ev-004]

### 为什么两行里容量可以正序

当前写入 `memo[i%2][j]`，所有依赖都来自另一个物理行 `memo[(i-1)%2][...]`。当前行的覆盖不会污染上一行，因此 `j` 从小到大或从大到小都不影响数据依赖；课程代码使用从小到大。[editorial_inference | 基于 code-001]

## 两行滚动数组完整代码

```cpp
class Knapsack01{
public:
    int knapsack01(const vector<int>& w, const vector<int>& v, int C){
        assert(w.size() == v.size() && C >= 0);
        int n = w.size();
        if( n == 0 || C == 0 )
            return 0;

        vector<vector<int>> memo(2, vector<int>(C+1, -1));

        for(int j = 0 ; j <= C ; j++ )
            memo[0][j] = ( j >= w[0] ? v[0] : 0 );

        for(int i = 1 ; i < n ; i ++ )
            for(int j = 0 ; j <= C ; j ++ ){
                memo[i%2][j] = memo[(i-1)%2][j];
                if( j >= w[i] )
                    memo[i%2][j] = max( memo[i%2][j] , v[i] + memo[(i-1)%2][j-w[i]] );
            }

        return memo[(n-1)%2][C];
    }
};
```

[visual_direct | code-001, ev-004]

### 初始化为什么仍是第 0 行

只考虑物品 0：

```text
memo[0][j] = 0     , j < w[0]
memo[0][j] = v[0]  , j >= w[0]
```

物品 0 仍最多选择一次；空间压缩没有改变 0-1 语义。[course_direct + visual_direct | ev-004]

### 最终返回哪一行

最后一个物品索引为 `n-1`，它写入的物理行是：

```text
(n-1) % 2
```

所以返回：

```cpp
memo[(n-1)%2][C]
```

[course_direct + visual_direct | ev-004]

## 从两行到一行：问题变在哪里

若只保留：

```text
memo[0...C]
```

读取上一行和写入当前行发生在同一数组中。现在遍历方向会决定：

```text
memo[j-w[i]]
```

究竟还是上一轮的 `F(i-1,j-w[i])`，还是已经变成当前轮的 `F(i,j-w[i])`。[course_direct + visual_direct | ev-005, ev-006]

## 一维倒序的精确不变量

在第 `i` 轮开始前：

```text
memo[j] = F(i-1,j)，对所有 j
```

容量从 `C` 向 `w[i]` 递减。正准备更新 `memo[j]` 时：

- `memo[j]` 尚未在本轮写过，仍是 `F(i-1,j)`；
- `j-w[i] < j`，较小容量还没有被倒序循环访问，`memo[j-w[i]]` 仍是 `F(i-1,j-w[i])`。

因此赋值：

```text
memo[j] = max(
    F(i-1,j),
    v[i] + F(i-1,j-w[i])
)
```

恰好得到 `F(i,j)`。[course_direct + editorial_inference | 基于 ev-006]

当本轮结束：

```text
memo[j] = F(i,j)，对所有 0<=j<=C
```

其中 `j<w[i]` 的格子无需改动，因为当前物品装不下，`F(i,j)=F(i-1,j)`。[editorial_inference]

## 为什么容量正序会错

假设正在处理一件：

```text
重量 = 2
价值 = 10
```

且进入本轮前 `memo[0...4]` 都是 0。若容量正序：

```text
j=2：memo[2] = max(0,10+memo[0]) = 10
j=4：memo[4] = max(0,10+memo[2]) = 20
```

第二步读取的 `memo[2]` 已在同一轮变成 10，于是把当前物品用了两次。结果 20 不属于 0-1 背包，而是重复使用语义。[editorial_inference | 对 ev-006 的最小反例]

倒序时先算 `j=4`，此时 `memo[2]` 还是上一轮的 0，只会得到 10；等稍后更新 `j=2`，不会再反过来影响已经完成的 `j=4`。

## 一维倒序完整代码

```cpp
class Knapsack01{
public:
    int knapsack01(const vector<int>& w, const vector<int>& v, int C){
        assert(w.size() == v.size() && C >= 0);
        int n = w.size();
        if( n == 0 || C == 0 )
            return 0;

        vector<int> memo(C+1, -1);

        for(int j = 0 ; j <= C ; j++ )
            memo[j] = ( j >= w[0] ? v[0] : 0 );

        for(int i = 1 ; i < n ; i ++ )
            for(int j = C ; j >= w[i] ; j -- ){
                memo[j] = max( memo[j] , v[i] + memo[j-w[i]] );
            }

        return memo[C];
    }
};
```

[visual_direct | code-002, ev-007]

### 循环下界为什么是 `w[i]`

只有容量满足：

```text
j >= w[i]
```

时才能选择物品 `i`。更小容量的状态只能保持“不选”结果，不必进入循环；同时这也保证 `j-w[i]` 不为负。[course_direct + visual_direct | ev-007]

### 最终为什么直接返回 `memo[C]`

所有物品处理完成后，一维数组已经表示最后一行：

```text
memo[j] = F(n-1,j)
```

所以答案是：

```cpp
return memo[C];
```

[course_direct + visual_direct | ev-007]

## 变体一：完全背包

课程定义：

```text

```

### 课程实际讲解顺序

人工听审 15:12–17:11 可确认讲师依次说明：

1. 虽然每种物品可无限使用，但背包容量有限；
2. 因而某种物品实际可取份数存在最大值；
3. 可以先转成一个含有限重复物品的列表，再按 0-1 背包处理；
4. 不必平铺成 `1,1,1,...`，可以用 `1,2,4,8,...` 分组减少列表长度；
5. 这段讲完后才引出多重背包。

[course_direct + visual_direct | ev-008, ev-009]

因此不能把二进制分组静默改归到多重背包；它在课程原话中确实属于完全背包的有限化方案。

### 严格数学边界：先有限化

若：

```text
w[i] > 0
```

容量为 `C`，第 `i` 种物品最多只可能取：

```text
M_i = floor(C / w[i])
```

份。超过该数量必然超容量。于是“无限”在这个固定实例中可以安全截成 `0...M_i`。[editorial_inference | 对 ev-008 的形式化]

若 `w[i]=0` 且 `v[i]>0`，价值可能无界，`floor(C/w[i])` 也没有定义；所以这条转换必须以正重量为前提。[editorial_inference]

### 严格数学边界：不是只取二进制置位

要表示 `0...M_i` 中的**每一种份数**，标准分组是：

```text
1,2,4,...,最后的 remainder
```

各组总和必须恰好是 `M_i`，并保持子集和覆盖整个区间。

例如：

```text
M_i = 13
分组 = 1,2,4,6
```

而不是只把 13 写成二进制置位：

```text
1,4,8
```

因为 `{1,4,8}` 的子集和不能表示 2、3、6、7 等份数；`{1,2,4,6}` 可以覆盖 0...13。[editorial_inference]

每个大小为 `k` 的组成为一件伪物品：

```text
weight = k * w[i]
value  = k * v[i]
```

每组最多选一次，于是可以交给 0-1 背包 DP。[editorial_inference]

### 它优化的究竟是什么

逐份平铺会为第 `i` 种物品创建 `M_i` 件伪物品；二进制分组只需：

```text
O(log(M_i+1))
```

组。总伪物品数由：

```text
Σ M_i
```

降为：

```text
Σ O(log(M_i+1))
```

[editorial_inference]

但若使用专门的完全背包一维转移，常见实现可以直接做到 `O(nC)` 时间、`O(C)` 空间。二进制分组后的 0-1 DP 通常是：

```text
O(C * Σ log(M_i+1))
```

所以课程所谓“优化”应准确理解为：**相对把每一份都显式复制进物品列表的有限化方案，减少伪物品数量**；不能外推为优于专用完全背包 DP。[editorial_inference]

课程没有展示完全背包专用代码、循环方向或复杂度，这些比较只用于厘清边界。[补充说明]

## 常见错误

1. **压缩空间时改变状态语义**：逻辑上仍是 `F(i,j)`，只是不再保存所有行。
2. **两行滚动读写同一物理行**：当前行必须用 `i%2`，上一行用 `(i-1)%2`。
3. **最终固定返回第 0 或第 1 行**：应返回 `(n-1)%2` 对应的行。
4. **一维数组容量正序**：会读取本轮已更新的较小容量，重复使用当前物品。
5. **把倒序理由背成口号**：应能说明 `j-w[i]<j`，倒序使较小位置尚未覆盖。
6. **循环到 `j=0` 再判断**：课程直接把下界设为 `w[i]`，同时保证索引非负。
7. **忘记第 0 件物品初始化**：数组初始 `-1` 不是合法 DP 基线。
8. **空物品时访问 `w[0]`**：课程先处理 `n==0 || C==0`。
9. **声称空间优化降低了时间复杂度**：两版压缩代码仍有两层循环。
10. **把压缩版 `O(nC)` 时间说成课程本段原话**：当前证据只支持代码推导。
11. **把二进制分组改归多重背包**：课程实际先在完全背包段讲它。
12. **对完全背包无限添加 `1,2,4,8,...` 组**：必须先由容量截出有限 `M_i`。
13. **只使用 `M_i` 的二进制置位**：不能覆盖 `0...M_i` 的所有取用份数。
14. **省略最后 remainder**：分组总数可能不足或超过 `M_i`。
15. **宣称二进制分组优于专用完全背包 DP**：课程只相对逐份展开称其为优化。
16. **把变体介绍当作完整解法**：后半段没有代码实现。

前八项依据课程依赖和代码；后八项用于复杂度与变体证据边界。[course_direct + editorial_inference | ev-002–ev-011]

## 面试表达脚本

> “二维 0-1 背包的 `F(i,j)` 只依赖上一行两个位置，所以先能把 `n` 行压成两行，用 `i%2` 轮换。继续压成一行时，我会让容量从 `C` 降到 `w[i]`。更新 `memo[j]` 时，`j-w[i]` 更小，尚未在本轮被覆盖，因此仍是 `F(i-1,j-w[i])`；若容量正序，它会变成当前轮值，相当于重复使用第 `i` 件物品。空间从 `O(nC)` 降为 `O(C)`，这两份代码的时间仍是 `O(nC)`。”
