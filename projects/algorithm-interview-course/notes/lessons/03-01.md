## 核心概念与定义

### 1. 二分查找

对于有序数组，先检查候选区间中间位置 `mid`：

- `arr[mid] == target`：查找完成；
- `target > arr[mid]`：目标若存在，只可能在右侧；
- `target < arr[mid]`：目标若存在，只可能在左侧。

由此，每轮都能排除已经比较的 `mid` 以及不可能包含目标的一侧。[视频 00:03:30–00:04:59] [视频 00:05:00–00:13:40]

### 2. 闭区间 `[l, r]`

本课给 `l` 和 `r` 的定义是：“在 `[l...r]` 的范围里寻找 `target`”。这是前闭后闭区间，意味着：

- `l` 是仍可能包含目标的最左索引；
- `r` 是仍可能包含目标的最右索引；
- 当 `l == r` 时，区间仍有一个元素；
- 只有当 `l > r` 时，候选区间才为空。

[视频 00:05:00–00:13:40]

### 3. 循环不变量

课程把循环不变量解释为：循环中的具体变量值虽然不断变化，但有一个逻辑声明在每轮始终保持成立。本课的不变量可表述为：

> 若 `target` 存在于数组中且尚未返回，则它一定在当前闭区间 `[l, r]` 内。

[视频 00:05:00–00:13:40]

不变量不是额外写在算法旁边的一句口号；它直接约束初始化、循环条件和更新规则。只改其中一个符号而不调整其他部分，就可能破坏整套逻辑。[视频 00:05:00–00:13:40] [整理推导]

## 解法构造：让定义驱动代码

### 第一步：定义候选集合

先写下注释：

```cpp
// 在 [l...r] 的范围里寻找 target
```

因为数组合法索引是 `0` 到 `n - 1`，覆盖全部初始候选的闭区间应是：

```cpp
int l = 0, r = n - 1;
```

[视频 00:05:00–00:13:40]

### 第二步：由“区间是否非空”推出循环条件

闭区间在 `l == r` 时仍含一个候选，因此该位置还必须检查：

```cpp
while (l <= r)
```

若误写成 `l < r`，当区间缩至单个元素时会提前退出，最后一个候选没有被比较。[视频 00:05:00–00:13:40]

### 第三步：比较中点并排除已检查位置

```cpp
int mid = (l + r) / 2;
```

若 `arr[mid]` 命中，直接返回 `mid`。未命中时，因为数组有序：

- `target > arr[mid]`：`mid` 及其左侧都可排除，新区间为 `[mid + 1, r]`；
- `target < arr[mid]`：`mid` 及其右侧都可排除，新区间为 `[l, mid - 1]`。

[视频 00:05:00–00:13:40]

这里的 `+1` 和 `-1` 不是可有可无的技巧。`mid` 已经比较且确认不等于目标，继续把它留在候选区间既违反区间语义，也可能让边界停止收缩。[视频 00:05:00–00:13:40] [整理推导]

### 第四步：空区间对应未找到

循环退出意味着 `l > r`，闭区间已为空；若此前没有命中，就返回 `-1`。[视频 00:05:00–00:13:40]

## 视频中的完整实现

以下代码按视频画面转录。结构化证据未记录 OCR 疑点，但其验证状态为 `not_run`；本项目没有重新编译或测试。[视频 00:05:00–00:13:40]

```cpp
template<typename T>
int binarySearch(T arr[], int n, T target) {

    int l = 0, r = n - 1; // 在 [l...r] 的范围里寻找 target
    while (l <= r) { // 当 l == r 时，区间 [l...r] 依然是有效的
        int mid = (l + r) / 2;
        if (arr[mid] == target)
            return mid;
        if (target > arr[mid])
            l = mid + 1; // target 在 [mid+1...r] 中
        else // target < arr[mid]
            r = mid - 1; // target 在 [l...mid-1] 中
    }

    return -1;
}
```

### 关于 `mid` 的补充

视频画面使用 `(l + r) / 2`。在 `l + r` 可能超过整数类型上限的实现环境中，常见的防溢出写法是：

```cpp
int mid = l + (r - l) / 2;
```

这是基于整数算术边界的补充建议，不是本课画面中展示的代码，不能反向归为讲师原话。[补充说明]

## 边界条件与易错点

### 视频直接强调的边界

1. **单元素候选区间**：`l == r` 仍有效，所以条件必须允许这一轮检查。[视频 00:05:00–00:13:40]

3. **不能混搭区间语义**：`r = n - 1` 对应闭区间；下一课将把 `r` 改为 `n`，届时其他条件也必须随定义变化。[视频 00:15:00–00:15:27]

### 根据代码补充的检查项

1. **空数组 `n = 0`**：初始化得到 `[0, -1]`，循环不进入并返回 `-1`；这是按代码推演，不是课程单独展示的测试。[整理推导]
2. **目标小于最小值或大于最大值**：边界应持续收缩直至空区间，不能越界访问。[整理推导]
3. **重复元素**：普通二分查找只返回某个命中位置；若题目要求第一个或最后一个位置，需要不同的返回契约和边界规则。[整理推导]
4. **整数溢出**：极端索引下 `(l + r) / 2` 可能溢出，可考虑 `l + (r - l) / 2`。[补充说明]
5. **无序输入**：大小比较不再能安全排除半个区间，算法的正确性前提被破坏。[视频 00:03:30–00:04:59]

### 典型错误及其原因

| 错误组合                             | 破坏之处                                                                 | 可能后果           |
| ------------------------------------ | ------------------------------------------------------------------------ | ------------------ |
| `r = n - 1`，却写 `while (l < r)`    | 把闭区间的单元素状态误当成空区间                                         | 漏掉最后一个候选   |
| `target < arr[mid]` 时写 `r = mid`   | 未命中的 `mid` 仍留在闭区间；当 `l == mid == r` 或区间很小时可能不再缩小 | 重复检查或死循环   |
| `target > arr[mid]` 时写 `l = mid`   | 同样未排除已检查位置                                                     | 重复检查或死循环   |
| 初始化使用 `r = n`，却仍按闭区间访问 | 索引 `n` 不属于长度为 `n` 的数组                                         | 越界风险           |
| 只背代码，不写 `[l, r]` 的含义       | 无法判断循环条件、更新与退出条件是否属于同一约定                         | 修改时容易混搭模板 |
