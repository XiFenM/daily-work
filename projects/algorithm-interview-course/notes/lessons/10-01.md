## 一句话结论

## 问题建模

### 输入与约束

- `g[i]`：孩子 `i` 的贪心指数，即能让该孩子满足的最小饼干尺寸；
- `s[j]`：饼干 `j` 的尺寸；
- 只有 `s[j] >= g[i]` 时，饼干 `j` 才能满足孩子 `i`；
- 每个孩子最多得到一块饼干；
- 每块饼干也只能用于一次；
- 目标是最大化被满足的孩子数量，而不是最大化尺寸总和或剩余量。

[course_direct | ev-002]

### 课程示例

| `g`       | `s`       | 最多满足人数 | 关键原因                                                             |
| --------- | --------- | -----------: | -------------------------------------------------------------------- |
| `[1,2,3]` | `[1,1]`   |          `1` | 两块尺寸 1 的饼干都只能满足需求 1 的孩子，但同一孩子不能重复获得饼干 |
| `[1,2]`   | `[1,2,3]` |          `2` | 可以分别用尺寸 1、2 或更大的可行饼干满足两个孩子                     |

[course_direct + visual_direct | ev-002]

## 为什么先排序

贪心规则依赖“当前最大剩余需求”和“当前最大剩余资源”。原数组若无序，指针位置不能代表极值；先排序把全局候选选择变成顺序扫描。[course_direct | ev-003]

屏幕代码使用：

```cpp
sort(g.begin(), g.end(), greater<int>());
sort(s.begin(), s.end(), greater<int>());
```

[visual_direct | code-001, ev-004]

排序后的含义是：

- `g[0] >= g[1] >= ...`；
- `s[0] >= s[1] >= ...`；
- 指针之后的元素不会大于当前元素；
- 因此 `s[si] < g[gi]` 时，后续任何饼干也都不可能满足当前孩子。

[visual_direct + editorial_inference | code-001]

## 降序双指针的状态模型

### 变量语义

| 变量    | 精确定义                                    | 初始化     | 何时更新             |
| ------- | ------------------------------------------- | ---------- | -------------------- |
| `si`    | 当前最大未使用饼干在降序 `s` 中的下标       | `0`        | 匹配成功时 `si++`    |
| `gi`    | 当前需求最大的未处理孩子在降序 `g` 中的下标 | `0`        | 成功或失败都 `gi++`  |
| `res`   | 已成功满足的孩子数                          | `0`        | 匹配成功时 `res++`   |
| `g`,`s` | 已降序排列的需求与尺寸序列                  | 扫描前排序 | 扫描期间元素不再改变 |

[visual_direct | state-001, code-001, ev-004]

### 两个转移

#### 转移一：当前最大饼干能够满足当前最贪心孩子

条件：

```cpp
s[si] >= g[gi]
```

更新：

```cpp
res++;
si++;
gi++;
```

这次匹配消费一块饼干和一个孩子，答案计数增加一。[visual_direct | code-001, ev-004]

#### 转移二：当前最大饼干仍然不够

条件：

```cpp
s[si] < g[gi]
```

更新：

```cpp
gi++;
```

因为 `s[si]` 已是最大剩余饼干，后面的饼干只会更小，所以当前孩子不可能被任何剩余饼干满足。应跳过孩子，同时保留这块饼干去尝试需求更小的孩子。[course_direct + visual_direct | ev-003, code-001]

### 终止与边界安全

循环条件是：

```cpp
while (gi < g.size() && si < s.size())
```

孩子或饼干任一侧耗尽，继续扫描都不可能增加匹配数。条件检查发生在数组访问前，因此空数组和单侧为空会直接返回 `0`，不会进入 `s[si]` 或 `g[gi]` 访问。[visual_direct + editorial_inference | code-001]

## 降序写法与升序对偶不要混写

| 维度       | 本课降序实现           | 等价的升序实现                 |
| ---------- | ---------------------- | ------------------------------ |
| 当前孩子   | 需求最大               | 需求最小                       |
| 当前饼干   | 尺寸最大               | 尺寸最小                       |
| 成功       | 两指针都移动           | 两指针都移动                   |
| 失败含义   | 最大饼干仍不够当前孩子 | 当前饼干太小，不能满足当前孩子 |
| 失败时移动 | 跳过孩子               | 跳过饼干                       |

右列是帮助辨析的 `editorial_inference`，不是本课屏幕代码。两种写法都能正确，但排序方向、指针语义和失败分支必须成套出现。

## 屏幕代码

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end(), greater<int>());
        sort(s.begin(), s.end(), greater<int>());

        int si = 0, gi = 0;
        int res = 0;
        while(gi < g.size() && si < s.size()) {
            if(s[si] >= g[gi]) {
                res++;
                si++;
                gi++;
            }
            else
                gi++;
        }

        return res;
    }
};
```

[visual_direct | code-001, ev-004]

### 代码行为与工程边界

1. **输入会被修改**：`g`、`s` 按非 `const` 引用传入，函数直接原地排序。调用方若需要原顺序，应先复制或改用索引副本。[visual_direct + supplemental | code-001]
2. **`<functional>` 未显式包含**：`std::greater` 的规范头文件是 `<functional>`。屏幕代码只包含 `<algorithm>` 等头文件；本机 libc++ 因传递包含可以编译，但这不是可移植保证。[supplemental]
3. **有符号/无符号比较**：`gi`、`si` 是 `int`，`vector::size()` 返回无符号 `size_type`。普通严格警告产生两条 `-Wsign-compare`；加 `-Werror` 时编译失败。[supplemental]
4. **相等元素无需稳定顺序**：相同需求或相同尺寸在匹配条件下可互换。屏幕没有稳定排序或第二关键字，不能补造 tie-break。[editorial_inference | 基于 code-001]
5. **结果范围安全**：`res` 最大不超过 `min(|g|,|s|)`；在题目可由 `vector` 表示的常规规模下不存在值累加爆炸，但类型选择仍应与接口约束一致。[editorial_inference]

## 正确性：课程理由与完整证明分开

### 课程直接覆盖的部分

课程给出的核心理由是：

- 若最大饼干都无法满足该孩子，则其他剩余饼干更不可能满足，可以安全跳过该孩子。


### 可整理出的完整交换论证

以下是 `editorial_inference`，不是课程逐句证明：

1. 设当前最大需求为 `G`，最大饼干为 `S`。
2. 若 `S < G`，所有剩余饼干都不大于 `S`，因此没有任何饼干能满足该孩子；删除该孩子不改变最优匹配数。
3. 若 `S >= G`，考虑任意一个当前子问题的最优匹配。
4. 若该匹配已经把 `S` 给了需求 `G` 的孩子，无需修改。
5. 若需求 `G` 的孩子使用另一块饼干 `C`，而 `S` 未使用，则可用 `S` 替换 `C`，匹配数不变。
6. 若需求 `G` 的孩子使用 `C`，而 `S` 给了另一个需求不超过 `G` 的孩子，则交换两块饼干：`S` 仍能满足 `G`，且 `C >= G`，自然也能满足需求不超过 `G` 的另一孩子；匹配数不变。
7. 若最优匹配没有满足需求 `G` 的孩子，则 `S` 不会闲置，否则还能新增一次匹配；把 `S` 从原孩子改配给需求 `G` 的孩子，匹配数保持不变。
8. 因而总存在一个最优解包含当前贪心配对。删除这一对后，剩余部分仍是同类型的更小匹配问题。
9. 重复上述过程，得到与某个全局最优解相同的满足人数。

这个证明补齐了安全删除、交换可行性、目标值不下降和子问题闭包。因为课程没有逐项展示，正式证据仍不能提升为 `complete`。

## 相等元素与 tie-break

若两个孩子需求相等，交换两人的顺序不会改变任何饼干的可行性；若两块饼干尺寸相等，交换两块饼干也不会改变可满足集合。因此相等元素可互换，算法不需要稳定排序。[editorial_inference | 基于 ev-003, code-001]

应避免写成：

- “相等时优先原下标更小者”；
- “必须稳定排序”；
- “相等时存在课程指定的第二关键字”。

这些规则均未在视频中出现，也不影响题目目标。[visual_direct | code-001]

## 复杂度：保留课程原式，再精确规范化

课程口述：

- `while` 双指针扫描是 `O(n)` 级别；
- 排序是 `O(n log n)` 级别；
- 总体由排序主导，为 `O(n log n)`。

[course_direct | ev-005]

课程使用一个 `n` 统一概括输入规模。若分别记：

- `G = |g|`：孩子数；
- `S = |s|`：饼干数；

则两次排序和扫描分别为：

```text
sort(g): O(G log G)
sort(s): O(S log S)
scan:    O(G)
```

所以规范化总时间为：

```text
O(G log G + S log S)
```

当 `n = max(G,S)` 时，它与课程的 `O(n log n)` 上界一致。[editorial_inference | 基于 ev-004, ev-005]
