## 核心概念与定义

### 1. Invert Binary Tree

课程把反转二叉树展示为镜像操作：对树中的每个节点，都交换它的左子树和右子树。[course_direct + visual_direct | ev-002 | 视频 00:36–01:22]

不能只在根节点交换一次。根的两个子树各自内部也必须递归完成同样的镜像翻转。[course_direct + visual_direct | ev-002, ev-004]

### 2. 原地修改

屏幕代码没有分配新节点，也没有构造第二棵树。两个递归调用修改现有左右子树，随后：

```cpp
swap(root->left, root->right);
```

直接改变当前节点的两个孩子指针。[visual_direct | ev-004 | 视频 03:08–05:12]

最终：

```cpp
return root;
```

返回的仍是传入的根指针值；树中节点的连接方向已经被改变。[course_direct + visual_direct | ev-004]

“原地”不等于“辅助空间是 `O(1)`”：代码仍然使用递归调用栈。[editorial_inference | 基于 code-001]

### 3. 递归函数语义

本课可以把函数语义写成：

> `invertTree(root)` 原地翻转以 `root` 为根的整棵二叉树，并返回同一个根指针；若 `root == NULL`，返回 `NULL`。

[course_direct + editorial_inference | 基于 ev-004]

有了这句契约，就不必手动展开所有递归层：


### 为什么递归调用的返回值没有赋值

屏幕代码写的是：

```cpp

invertTree(root->right);
```

而不是：

```cpp

root->right = invertTree(root->right);
```

[visual_direct | ev-004]

这是因为课程实现原地修改子树。调用返回时，原孩子指针仍指向已经翻转完成的那棵子树；当前层只需交换两个孩子指针。[course_direct + editorial_inference | 基于 ev-004]

## 递归契约与正确性解释

### 契约

> `invertTree(root)` 原地把以 `root` 为根的树变成其镜像，并返回同一个 `root`；空树返回 `NULL`。

[course_direct + editorial_inference | 基于 ev-004]

### 基本情况

当 `root == NULL`，空树没有孩子可以交换：

```cpp
return NULL;
```

结果仍是空树，契约成立。[course_direct + visual_direct | ev-004]

### 递归情况

假设两个递归调用满足契约：

1. 原左子树已经原地变为其镜像；
2. 原右子树已经原地变为其镜像。

当前层执行：

```cpp
swap(root->left, root->right);
```

于是镜像后的原右子树成为新左子树，镜像后的原左子树成为新右子树，整个以 `root` 为根的结构完成镜像。[course_direct + editorial_inference | 基于 ev-004]

### 返回值

节点本身没有被替换，只有孩子指针被交换，因此返回原 `root` 即可。[course_direct + visual_direct | ev-004]

### 终止性

每次递归都进入当前节点的孩子；在有限、无环二叉树上最终到达 `NULL` 并返回。[editorial_inference | 基于 ev-004]

课程直接展示并解释了递归结构，但上述按契约分层的证明是笔记整理，不是视频中的形式化证明文本。[course_direct + editorial_inference | ev-004]

### 1. 空树

必须在解引用 `root->left` 前处理：


### 2. 只交换根节点

仅在最外层执行一次 `swap` 只会互换两棵未镜像的子树，不能保证所有后代节点都翻转。[editorial_inference | 基于 ev-002, ev-004]
