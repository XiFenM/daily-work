## 题目与契约

给定整数数组 `nums` 和整数 `k`，判断是否存在两个不同索引 `i`、`j`，满足：

```text
nums[i] == nums[j]
|i-j| <= k
```

[course_direct + visual_direct | ev-001 | 视频 00:00–00:35]

为了逐项扫描，可以把较晚的索引记作 `i`，较早的索引记作 `j`。于是当前轮只需检查：

```text
max(0, i-k) <= j <= i-1
```

这正是“当前索引之前、距离不超过 `k`”的全部候选。[editorial_inference | 基于 ev-001, ev-003 | 视频 00:00–03:46]

规范化复杂度变量把 `k` 的领域记录为 `k >= 0`。若接口允许负数，题意本身就没有非负索引差能满足条件，且屏幕代码中的有符号/无符号比较会需要额外防护；本课代码按非负 `k` 理解。[course_direct + editorial_inference | 基于 ev-001, ev-005 | 视频 00:00–00:35；08:58–09:37]

## 解法一：暴力枚举

最直接的方法是枚举索引对 `(i,j)`，同时检查值相等和索引差约束。[course_direct | ev-002 | 视频 00:35–00:53]

伪代码可整理为：

```text
for i in [0,n):
    for j in [i+1,n):
        if nums[i] == nums[j] and j-i <= k:
            return true
return false
```

[editorial_inference | 基于 ev-001, ev-002 | 视频 00:00–00:53]

课程直接给出的时间复杂度是 `O(n²)`。仅按上述双循环观察，额外状态是固定数量索引和比较变量，可整理为辅助空间 `O(1)`；空间结论不是 `ev-002` 观察文本中单独展开的推导。[course_direct + editorial_inference | 基于 ev-002 | 视频 00:35–00:53]

暴力法的问题是重复检查大量距离过远或彼此无关的数对，没有利用“每轮只关心最近 `k` 个先前位置”的局部性。[editorial_inference | 基于 ev-002, ev-003 | 视频 00:35–03:46]

## 解法二：固定候选窗口 + `unordered_set`

### 图示中的 `k+1` 元素区间

课程先把问题画成连续区间 `[l,l+k]`。这个区间包含 `k+1` 个位置，任意两个端点的最大索引差恰好为 `k`；若区间内有重复值，就存在一个满足距离约束的索引对。[course_direct + visual_direct | ev-003 | 视频 00:53–03:46]

实现时不需要在每轮完整重扫这个区间，而是维护先前候选值的查找表，再用当前值做一次成员查询。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]

### 第 `i` 轮查询前的精确状态

沿着没有提前返回的执行路径，在执行：

```cpp
record.find(nums[i])
```

之前，有：

```text
record = { nums[j] | max(0,i-k) <= j <= i-1 }
```

也就是说，`record` 对应的不是包含当前索引的 `[i-k,i]`，而是当前值之前的候选区间 `[max(0,i-k),i-1]`，元素个数最多为 `k`。[visual_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]

由于执行路径尚未返回 `true`，这个先前窗口中不存在重复值；因此用只存唯一值的 `unordered_set` 不会丢失当前查询所需的索引存在性信息。[editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

### 第一步：先查询当前值

```cpp
if (record.find(nums[i]) != record.end())
    return true;
```

[visual_direct | ev-004 | 视频 03:46–08:58]

若命中，集合中的同值来自某个先前索引 `j ∈ [max(0,i-k),i-1]`，所以：

```text
nums[j] == nums[i]
i-j <= k
```

返回 `true` 满足题意。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]

必须先查再插。若先把 `nums[i]` 插入，随后查询一定会找到刚插入的当前元素，相当于错误地让 `i` 与自己配对。[visual_direct + editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

### 第二步：未命中后插入

```cpp
record.insert(nums[i]);
```

[visual_direct | ev-004 | 视频 03:46–08:58]

查询未命中意味着当前值尚不在候选集合中，所以这次插入会把集合大小增加一。插入后，集合临时对应：

```text
{ nums[j] | max(0,i-k) <= j <= i }
```

最多覆盖 `k+1` 个连续索引，正好与课程图示区间一致。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]

### 第三步：达到 `k+1` 时删除最左值

```cpp
if (record.size() == k + 1)
    record.erase(nums[i-k]);
```

[visual_direct | ev-004 | 视频 03:46–08:58]

插入前集合最多有 `k` 个值，且当前值未命中；因此插入后大小最多为 `k+1`，不会跳到更大。`size() == k+1` 表示临时窗口已经完整覆盖 `[i-k,i]`，下一轮不再需要最左索引 `i-k`，所以删除 `nums[i-k]`。[course_direct + editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

课程用 `i=k` 核对边界：

```text
i-k = 0
```

此时临时窗口是 `[0,k]`，共 `k+1` 个位置；若前面的查询没有发现重复，就删除 `nums[0]`，为下一轮保留索引 `[1,k]`。[course_direct | ev-004 | 视频 03:46–08:58]

删除之后，循环结束状态为：

```text
record = { nums[j] | max(0,i-k+1) <= j <= i }
```

把下一轮索引写成 `i+1`，该区间正好等于：

```text
[max(0,(i+1)-k), (i+1)-1]
```

所以它恢复了下一轮查询前的不变量，并且候选数至多为 `k`。[editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

## 查询前、插入后与删除后的三种窗口

最容易混淆的是“窗口含不含当前值”。可用下表区分：[editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]

| 时刻               | 索引范围            | 最大位置数 | 作用                             |
| ------------------ | ------------------- | ---------- | -------------------------------- |
| 查询 `nums[i]` 前  | `[max(0,i-k), i-1]` | `k`        | 保存允许与当前值配对的先前候选   |
| 查询未命中并插入后 | `[max(0,i-k), i]`   | `k+1`      | 临时形成课程图示的完整可比较区间 |
| 必要删除后         | `[max(0,i-k+1), i]` | `k`        | 为第 `i+1` 轮恢复先前候选窗口    |

课程中“窗口最大长度是 `k+1`”描述的是把当前元素与先前候选合在一起的比较区间；代码注释“保持 `record` 中最多有 `k` 个元素”描述的是每轮清理后的持久状态。两者所指时刻不同，并不矛盾。[course_direct + editorial_inference | 基于 ev-003, ev-004, ev-006 | 视频 00:53–08:58；09:37–10:26]

## 视频中的完整代码

以下代码来自规范化屏幕证据 `code-001`。OCR 不确定项为空，验证状态为 `not_run`；本项目没有编译、运行或提交在线评测。[visual_direct | ev-004 | 视频 03:46–08:58]

```cpp
#include <iostream>
#include <vector>
#include <unordered_set>

using namespace std;

class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        unordered_set<int> record;
        for (int i = 0; i < nums.size(); i++) {
            if (record.find(nums[i]) != record.end())
                return true;

            record.insert(nums[i]);

            // 保持 record 中最多有 k 个元素
            if (record.size() == k + 1)
                record.erase(nums[i-k]);
        }

        return false;
    }
};
```

### 代码顺序不能随意调整

正确顺序是：

```text
查询当前值 → 未命中后插入 → 必要时删除最旧值
```

[visual_direct | ev-004 | 视频 03:46–08:58]

- 把插入放到查询前，会让当前值与自己匹配；
- 把删除放到查询前，可能提前移除距离恰好为 `k` 的合法候选；
- 删除 `nums[i-k+1]` 会错过一个仍应为下一轮保留的值；
- 删除 `nums[i-k-1]` 又会留下已经距离过远的值。

[editorial_inference | 基于 ev-001, ev-004 | 视频 00:00–00:35；03:46–08:58]

### 为什么 `i-k` 不会成为负索引

沿未返回路径，插入后 `record.size() == k+1` 只有在已经处理至少 `k+1` 个位置时才可能成立，即 `i >= k`。因此进入删除分支时 `i-k >= 0`；课程也用 `i=k` 得到删除索引 `0` 进行核对。[course_direct + editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

这条安全性依赖题意中的 `k >= 0`，也依赖“查询未命中后插入会增加集合大小”的执行路径；脱离这些前提不能机械复用该判断。[editorial_inference | 基于 ev-004, ev-005 | 视频 03:46–09:37]

## 正确性解释

规范化证据把本课方法记为 `state_transition`。课程直接说明了窗口、查找、插入和删除；下面用查询前不变量整理充分性、完备性和终止性。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]

### 初始化

`i=0` 前，候选区间是：

```text
[max(0,0-k), -1] = [0,-1]
```

它为空，`record` 也为空，因此查询前不变量成立。[editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

### 保持

若第 `i` 轮查询未命中：

1. 插入 `nums[i]`，把当前索引加入临时区间；
2. 若临时区间达到 `k+1` 个位置，删除其最左端 `i-k`；
3. 剩余索引区间变成 `[max(0,i-k+1),i]`，恰好是下一轮所需的先前候选。

[course_direct + editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

### 返回 `true` 的充分性

只有当前值已存在于查询前 `record` 时才返回。集合中的值必来自索引范围 `[max(0,i-k),i-1]`，因此存在不同索引 `j<i`，同时满足值相等和 `i-j<=k`。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]

### 不漏解的完备性

若存在合法对 `j<i` 且 `i-j<=k`，则处理 `i` 前有 `j>=i-k`，所以索引 `j` 尚未因过期而删除，`nums[j]` 在 `record` 中。查询 `nums[i]` 时必然命中并返回 `true`。[editorial_inference | 基于 ev-001, ev-003, ev-004 | 视频 00:00–08:58]

### 终止与返回 `false`

循环索引 `i` 每轮增加一；若扫描完整个有限数组仍未命中，说明每个元素出现时，其最近 `k` 个先前位置中都没有同值元素，因此不存在合法索引对，返回 `false`。[course_direct + editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

这是一段人工不变量论证，不是机器形式化验证，也不表示屏幕代码已在本项目运行。

## 边界条件

### `k=0`

查询前合法先前区间始终为空。每轮未命中后插入当前值，集合大小变成 `1=k+1`，随即删除 `nums[i]`，为下一轮恢复空集合。因此算法不会让某个索引与自己匹配，最终返回 `false`。[editorial_inference | 基于 ev-001, ev-004 | 视频 00:00–00:35；03:46–08:58]

### `k>=n`

没有元素会因距离超过 `k` 而提前过期；算法等价于在整个已扫描前缀中检查重复。持久集合最多存 `n` 个值，课程的 `O(k)` 上界仍成立，但更紧的空间表达是 `O(min(n,k))`。[editorial_inference | 基于 ev-004, ev-005 | 视频 03:46–09:37]

### 空数组或单元素数组

循环分别执行零次或一次，不可能形成两个不同索引，返回 `false`。[editorial_inference | 基于 ev-001, ev-004 | 视频 00:00–00:35；03:46–08:58]

### 值域

算法只做哈希、相等比较和集合删除，对正数、零和负数使用相同逻辑；视频没有给出整数溢出相关运算。[editorial_inference | 基于 ev-004 | 视频 03:46–08:58]

## 复杂度分析

### 暴力法

课程直接给出双重枚举时间复杂度：

```text
O(n²)
```

[course_direct | ev-002 | 视频 00:35–00:53]

### `unordered_set` 窗口法

课程的成本模型是：

- 数组只扫描一遍；
- `unordered_set` 的查找、插入、删除按**平均 `O(1)`** 计算；
- 因而平均时间复杂度为 `O(n)`；
- 查找表持久状态至多保存 `k` 个候选，辅助空间为 `O(k)`。

[course_direct | ev-005 | 视频 08:58–09:37]

需要精确区分两个时刻：

- 每轮结束后 `record.size() <= k`；
- 插入当前值之后、删除之前，可能短暂达到 `k+1`。

这不改变渐进空间 `O(k)`；若同时考虑数组长度，更紧可写为 `O(min(n,k))`，临时峰值至多再多一个元素。[course_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 03:46–09:37]

`unordered_set` 的常数时间是平均/期望成本，并非所有输入和哈希状态下的最坏保证。若发生严重哈希冲突，单次操作可能退化，整体最坏情况可达 `O(n²)`；这是对课程平均成本模型的工程边界补充，不否定视频给出的平均 `O(n)`。[editorial_inference | 基于 ev-005 | 视频 08:58–09:37]

| 方法           | 时间        | 辅助空间      | 口径                             |
| -------------- | ----------- | ------------- | -------------------------------- |
| 双重枚举       | `O(n²)`     | `O(1)`        | 时间为课程直述；空间按伪代码整理 |
| 哈希窗口       | 平均 `O(n)` | `O(k)`        | 课程按哈希操作平均 `O(1)` 推导   |
| 哈希窗口紧空间 | 同上        | `O(min(n,k))` | 编辑性细化                       |

## 常见错误与建议测试

### 常见错误

1. **先插后查**：必然找到当前值自身。[visual_direct + editorial_inference | 基于 ev-004 | 视频 03:46–08:58]
2. **查询前先删除 `nums[i-k]`**：会漏掉索引差恰好等于 `k` 的合法对。[course_direct + editorial_inference | 基于 ev-004 | 视频 03:46–08:58]
3. **删除错位**：删除项必须是 `nums[i-k]`，课程用 `i=k` 时删除索引 0 核对。[course_direct | ev-004 | 视频 03:46–08:58]
4. **把查询前窗口写成 `[i-k,i]`**：当前值尚未插入；精确范围应是 `[max(0,i-k),i-1]`。[editorial_inference | 基于 ev-004 | 视频 03:46–08:58]
5. **认为集合全程最多 `k` 个元素**：插入后、清理前可短暂达到 `k+1`；每轮结束才恢复至多 `k`。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 00:53–08:58]
