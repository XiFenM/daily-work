## 一句话结论

遍历到 `nums[i]` 时，先令：

```text
complement = target - nums[i]
```

再只去查已经处理过的前缀 `[0,i-1]`。找到补数就返回当前索引与历史索引；找不到才执行 `record[nums[i]]=i`。这一“先查后插”顺序同时解决了自匹配和重复值配对问题。[视频 00:07:28–00:11:43；ev-007、ev-008]

## 解法一：暴力枚举

### 思路

使用双重循环枚举所有不同位置组成的数对，再检查两数和是否等于 `target`。[视频 00:02:11–00:02:40；ev-003]

下面是按课程思路整理的伪代码，不是视频中的完整代码对象：

```text
for i = 0 .. n-2:
    for j = i+1 .. n-1:
        if nums[i] + nums[j] == target:
            return [i, j]
```

[视频 00:02:11–00:02:40；ev-003] [整理推导]

限定 `j>i` 可以同时：

- 避免 `(i,j)` 与 `(j,i)` 被重复检查；
- 保证两个索引不同；
- 覆盖全部无序位置对。

## 解法二：排序后使用对撞指针

### 时间优化

若先排序，就可以复用 03-06 的对撞指针：

1. 排序耗时 `O(n log n)`；
2. 两个指针从两端向中间扫描耗时 `O(n)`；
3. 总时间为：

```text
O(n log n) + O(n) = O(n log n)
```

[视频 00:02:40–00:04:02；ev-004]

排序后，当前和偏小就移动左指针，偏大就移动右指针；这一淘汰逻辑依赖有序性。完整指针证明在 03-06 展开，本课重点是评估它能否满足当前题目的输出契约。[视频 03-06 00:06:59–00:12:00；03-06 ev-004、ev-005、ev-006] [视频 00:02:40–00:04:02；ev-004]

### 为什么不能直接排序原数组

本题要求返回**原始索引**。若直接原地排序 `nums`，排序后位置不再等于元素在输入中的位置，因此即使找到两个值，也无法直接给出题目要求的索引。[视频 00:02:40–00:04:02；ev-004]

若坚持采用排序路线，需要在排序前把每个元素与原始索引绑定，例如整理为 `(value,originalIndex)` 后按 `value` 排序。这是课程指出的“额外预处理”方向，不是视频中的完整实现。[视频 00:02:40–00:04:02；ev-004] [整理推导]

因此，排序加双指针并非逻辑上不能解决，而是：

- 时间只能降到 `O(n log n)`；
- 还必须额外保存并恢复原始索引；
- 相比之下，查找表可以在不重排输入的情况下直接保存索引。

## 解法四：动态查找表——边查边存

### 核心状态

处理第 `i` 个元素之前：

```text
record 只包含下标 [0,i-1] 的已处理元素
```

每个表项表示：

```text
历史元素值 → 某个对应的历史原始索引
```

[视频 00:07:28–00:11:43；ev-007、ev-008]

当前元素需要的补数是：

```cpp
int complement = target - nums[i];
```

[视频 00:09:35–00:11:43；ev-008]

### 两种状态转移

#### 1. 查到补数

若：

```cpp
record.find(complement) != record.end()
```

则表中存在历史索引 `j=record[complement]`。因为 `j<i`：

- `j` 与当前 `i` 一定是不同位置；
- `nums[j]=complement`；
- `nums[i]+nums[j]=target`。

代码返回 `{i,record[complement]}`。[视频 00:07:28–00:11:43；ev-007、ev-008] [整理推导]

#### 2. 没查到补数

只有在查询失败后才执行：

```cpp
record[nums[i]] = i;
```

随后进入下一轮。这样下一轮开始时，表中仍只含新下标之前的历史元素。[视频 00:07:28–00:11:43；ev-007、ev-008]

### 为什么顺序必须是“先查询，再插入”

如果先把当前值插入：

```cpp
record[nums[i]] = i;
```

再查 `target-nums[i]`，当：

```text
target == 2 * nums[i]
```

时，查找可能命中刚插入的当前索引 `i`，错误地把同一位置使用两次。[视频 00:00:00–00:01:20；ev-001] [视频 00:07:28–00:11:43；ev-007、ev-008] [整理推导]

先查后插则从结构上消除了这一分支：查询集合中根本没有当前索引。[视频 00:07:28–00:11:43；ev-007、ev-008]

### 为什么动态 Map 能处理重复值

设：

```text
nums = [42, 42]
target = 84
```

- `i=0`：查 `42` 未命中，插入 `42→0`；
- `i=1`：先查 `42`，命中历史索引 0，返回 `{1,0}`；
- 当前的 `42→1` 根本不会在命中前覆盖历史索引。

[视频 00:05:23–00:09:35；ev-006、ev-007] [整理推导]

即使历史前缀中某个值出现多次，后一次写入会覆盖同值的更早索引，但对于 Two Sum 的“存在任意一组不同索引”目标，保留任意一个历史补数索引就足以构造答案。[视频 00:07:28–00:11:43；ev-007、ev-008] [整理推导]

## 视频中的完整 C++ 代码

```cpp
#include <iostream>
#include <vector>
#include <cassert>
#include <unordered_map>

using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int,int> record;
        for(int i = 0; i < nums.size() ; i++){
            int complement = target - nums[i];
            if(record.find(complement) != record.end()){
                int res[2] = {i, record[complement]};
                return vector<int>(res, res+2);
            }
            record[nums[i]] = i;
        }
        throw invalid_argument("The input has no solution");
    }
};
```

|   0 |         2 |            7 | `{}`            | 未命中，写入 `2→0` |
|   1 |         7 |            2 | `{2→0}`         | 命中，返回 `{1,0}` |

[视频 00:07:28–00:11:43；ev-007、ev-008] [整理推导]

幻灯片示例写作 `[0,1]`，屏幕代码按 `{i,record[complement]}` 的顺序会构造 `[1,0]`。两者指向同一对位置，但结构化题面没有记录返回索引是否必须升序；面试中若输出顺序有要求，应额外澄清或按要求排序。[视频 00:00:00–00:01:20；ev-001] [视频 00:09:35–00:11:43；ev-008] [整理推导]

### 重复值样例

```text

```

| `i` | `complement` | 查询前 `record` | 结果                       |
| --: | -----------: | --------------- | -------------------------- |
|   0 |            3 | `{}`            | 插入 `3→0`                 |
|   1 |            3 | `{3→0}`         | 返回 `{1,0}`，两个索引不同 |

## 复杂度分析

### 四种方案对照

| 方案           | 时间复杂度   | 辅助空间          | 主要限制                 | 来源                        |
| -------------- | ------------ | ----------------- | ------------------------ | --------------------------- |
| 暴力双层枚举   | `O(n²)`      | `O(1)` 为实现推导 | 评测中会超时             | ev-003，02:11–02:40         |
| 排序加双指针   | `O(n log n)` | 视频未给最终口径  | 原始索引会丢失，需预处理 | ev-004，02:40–04:02         |
| 全量单索引 Map | `O(n)` 量级  | `O(n)` 量级       | 重复键覆盖，设计不完整   | ev-005、ev-006，04:02–07:28 |
| 动态查找表     | `O(n)`       | `O(n)`            | 依赖哈希表平均常数操作   | ev-007–ev-009，07:28–12:37  |

### 课程对最终方案的口径

课程明确给出：

```text
时间复杂度：O(n)
空间复杂度：O(n)
```

[视频 00:11:43–00:12:37；ev-009]

原因是：

- 数组只遍历一遍；
- 每轮对 `unordered_map` 做一次查找，并在未命中时做一次插入；
- 课程按哈希表查找、插入平均 `O(1)` 计算；
- 最坏情况下所有已处理元素都进入表，最多存储 `O(n)` 个映射。

[视频 00:07:28–00:12:37；ev-007、ev-008、ev-009]

严格区分平均和最坏情况时，`unordered_map` 的单次操作并非无条件最坏 `O(1)`；哈希退化时可能变慢。本课给出的 `O(n)` 时间是常见哈希表平均成本模型下的口径。[视频 00:11:43–00:12:37；ev-009] [补充说明]

## 边界条件、易错点与工程风险

### 视频直接强调

1. **索引基数**：本题从 0 开始；不要机械沿用 03-06 的 1-based 返回。[视频 00:01:20–00:02:11；ev-002]
2. **唯一解与失败行为**：课程说明题面保证唯一解，同时讨论了无解和多解应先沟通。[视频 00:01:20–00:02:11；ev-002]
3. **两个位置必须不同**：不能用同一个元素两次。[视频 00:00:00–00:01:20；ev-001]
4. **不能只用 Set**：题目要求索引，所以要保存 `value→index`。[视频 00:04:02–00:05:23；ev-005]
5. **直接排序会丢原始索引**：必须额外关联原位置。[视频 00:02:40–00:04:02；ev-004]
6. **全量预存会覆盖重复键的旧索引**：单值 Map 不保留重复值的全部位置。[视频 00:05:23–00:07:28；ev-006]
7. **动态方案必须先查后插**：否则当前元素可能与自身匹配。[视频 00:07:28–00:09:35；ev-007]

### 由代码推导

1. **空数组或单元素数组**：循环结束后抛出 `invalid_argument`，因为不可能组成两个不同位置。[视频 00:09:35–00:11:43；ev-008] [整理推导]
2. **重复值答案**：第二次遇到该值时，第一次的位置已经在表中，能够正常返回。[视频 00:05:23–00:09:35；ev-006、ev-007] [整理推导]
3. **返回顺序**：代码返回当前索引在前、历史索引在后，不保证数值递增或索引递增；视频没有记录顺序要求。[视频 00:09:35–00:11:43；ev-008] [整理推导]
4. **同值历史覆盖**：动态表可能只保留某个值最近写入的历史索引，但任意历史补数索引已经足够回答存在性和构造一组答案。[视频 00:07:28–00:11:43；ev-007、ev-008] [整理推导]

### 工程补充

1. `target-nums[i]` 仍在 `int` 中计算；若题目数值范围允许结果越界，需要使用更宽的中间类型。视频没有在本课讨论这一点。[补充说明]
2. `nums.size()` 返回无符号大小类型，屏幕代码的 `i` 是 `int`；极端容器长度下需要统一索引类型。[补充说明]
3. 可把 `record.find(complement)` 的迭代器保存下来，并用 `iterator->second` 读取索引，避免在命中后再通过 `operator[]` 查询一次。[整理推导]
4. 屏幕代码使用 `invalid_argument` 却未显式展示 `<stdexcept>`，本地编译前应按工具链要求补齐，但补齐结果不能冒充视频原码。[补充说明]

### 常见错误

- 把 `record` 写成 `unordered_set<int>`，最后只能知道补数存在，无法返回其索引。[视频 00:04:02–00:05:23；ev-005]
- 直接排序 `nums` 后返回排序下标，丢失输入的原始位置。[视频 00:02:40–00:04:02；ev-004]
- 先批量写完全部 `value→index`，却没有设计重复键和自匹配规则。[视频 00:05:23–00:07:28；ev-006]
- 在单次遍历中先执行 `record[nums[i]]=i` 再查补数，可能命中当前索引自身。[视频 00:07:28–00:11:43；ev-007、ev-008] [整理推导]
- 找到补数后返回两个数值而不是两个原始索引。[视频 00:00:00–00:05:23；ev-001、ev-005]
- 把哈希表的平均 `O(1)` 操作误说成任何情况下都严格最坏 `O(1)`。[视频 00:11:43–00:12:37；ev-009] [补充说明]
- 把课后 3Sum、4Sum、3Sum Closest 的常见答案从记忆补成课程已经讲授的题解。[视频 00:12:37–00:16:57；ev-010、ev-011、ev-012]
