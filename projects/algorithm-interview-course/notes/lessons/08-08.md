## 为什么按行递归

`putQueen(n,index,row)` 的 `index` 表示当前要处理的行。每层只为这一行选择一个列位置，然后递归到 `index+1`。[course_direct + visual_direct | ev-003, ev-005]

这种问题分解自动带来两个性质：

- 每次递归深度只对应一行；
- `row` 每层只压入一个列号；
- 因而任何到达 `index==n` 的路径都恰好有 `n` 个选择，也就是每行一个皇后；
- 无需另设“哪些行已占用”的布尔数组。[course_direct + editorial_inference | 基于 ev-003、ev-005]

这里变量名 `row` 容易误导：它不是布尔行状态，而是一个**按行排列的列索引序列**。`row[r]` 表示第 `r` 行皇后所在的列。[visual_direct + editorial_inference | ev-005]

## 搜索树与剪枝

在第 `index` 行，循环：

```cpp
for (int i = 0; i < n; i++)
```

依次尝试所有列。每个候选先检查：

```cpp
!col[i]
&& !dia1[index+i]
&& !dia2[index-i+n-1]
```

若任一标记为 `true`，说明与已有皇后冲突，该分支无需再向下展开；这就是课程动画中的剪枝。[course_direct + visual_direct | ev-003–ev-005]

剪枝只排除已经违反约束的部分棋盘。一个合法完整布局的每个前缀都合法，因此不会因为这三项检查而被错误截断。[editorial_inference | 基于问题约束与 code-001]

## 三类占用数组

当前格坐标写作：

```text
行 = index
列 = i
```

### 列：`col[i]`

共有 `n` 列，索引范围为：

```text
0 <= i <= n-1
```

所以：

```cpp
col = vector<bool>(n, false);
```

[course_direct + visual_direct | ev-004, ev-005]

### 对角线一：`dia1[index+i]`

同一条右上—左下对角线上的格子，行列和相同。行、列都在 `[0,n-1]`，所以：

```text
0 <= index + i <= 2n - 2
```

共有 `2n-1` 个可能索引：

```cpp
dia1 = vector<bool>(2*n-1, false);
```

[course_direct + visual_direct | ev-004, ev-005]

### 对角线二：`dia2[index-i+n-1]`

同一条左上—右下对角线上的格子，行列差相同。原始差值范围是：

```text
-(n-1) <= index - i <= n-1
```

为了避免负下标，统一加 `n-1`：

```text
0 <= index - i + n - 1 <= 2n - 2
```

因此同样需要 `2n-1` 个布尔值：

```cpp
dia2 = vector<bool>(2*n-1, false);
```

[course_direct + visual_direct | ev-004, ev-005]

若漏掉 `+n-1`，右上区域会产生负差值，无法安全索引 `vector`。[course_direct + editorial_inference | ev-004, ev-005]

## 选择—递归—撤销

一个合法候选的完整状态转移是：

```cpp
row.push_back(i);
col[i] = true;
dia1[index+i] = true;
dia2[index-i+n-1] = true;

putQueen(n, index+1, row);

col[i] = false;
dia1[index+i] = false;
dia2[index-i+n-1] = false;
row.pop_back();
```

[course_direct + visual_direct | ev-005]

可以分成三阶段：

1. **选择**：把第 `index` 行的列 `i` 放入部分答案，并占用对应列和两条对角线；
2. **递归**：在这一部分棋盘基础上处理下一行；
3. **撤销**：下一层返回后，恢复三个占用标记并删除当前列，使下一个候选从同一个父状态开始。[course_direct + visual_direct | ev-005]

撤销必须与选择对称。只恢复布尔数组但忘记 `row.pop_back()`，或只弹出 `row` 却保留占用标记，都会污染兄弟分支。[editorial_inference | 基于 code-001]

## 递归不变量与终止

### 进入不变量

进入 `putQueen(n,index,row)` 时：

- `row.size()==index`；
- `row[0...index-1]` 分别记录此前每一行选择的列；
- `col`、`dia1`、`dia2` 恰好反映这些皇后的占用；
- 当前部分棋盘没有列或对角线冲突。[editorial_inference | 基于 ev-003–ev-005]

### 保持

候选通过三项检查后，与现有部分棋盘不冲突。同步压入 `row` 并设置三个标记，就得到满足同一不变量的 `index+1` 状态；递归返回后执行完全撤销，恢复父层不变量。[editorial_inference | 基于 ev-004, ev-005]

### 终止

当：

```cpp
index == n
```

说明第 `0...n-1` 行都已成功放置皇后。代码调用 `generateBoard` 生成棋盘、加入 `res`，然后返回。[course_direct + visual_direct | ev-005]

每次递归令 `index+1`，最大达到 `n`；每层循环也只有 `n` 个候选，因此整个搜索有限。[editorial_inference]

## 棋盘构造

`generateBoard` 先创建全是点号的 `n × n` 棋盘：

```cpp
vector<string> board(n, string(n, '.'));
```

再执行：

```cpp
board[i][row[i]] = 'Q';
```

把第 `i` 行的皇后放到已记录列。`assert(row.size()==n)` 明确要求只对完整选择序列生成棋盘。[course_direct + visual_direct | ev-005]

## 课程核心 `Solution` 与本地编译外壳

视频中第 1 行显示为折叠的 `#include ...`，无法从画面确认具体头文件。以下 `<vector>`、`<string>`、`<cassert>` 仅是本地语法编译所需的最小外壳；`using namespace std` 与 `Solution` 类实现来自可核对的课程画面。[补充说明 | code-001]

```cpp
#include <vector>
#include <string>
#include <cassert>

using namespace std;

class Solution {
private:
    vector<vector<string>> res;
    vector<bool> col, dia1, dia2;

    void putQueen(int n, int index, vector<int>& row) {
        if (index == n) {
            res.push_back(generateBoard(n, row));
            return;
        }

        for (int i = 0; i < n; i++) {
            // 尝试将第index行的皇后摆放在第i列
            if (!col[i]
                && !dia1[index+i]
                && !dia2[index-i+n-1]) {
                row.push_back(i);
                col[i] = true;
                dia1[index+i] = true;
                dia2[index-i+n-1] = true;

                putQueen(n, index+1, row);

                col[i] = false;
                dia1[index+i] = false;
                dia2[index-i+n-1] = false;
                row.pop_back();
            }
        }
        return;
    }

    vector<string> generateBoard(int n, vector<int>& row) {
        assert(row.size() == n);
        vector<string> board(n, string(n, '.'));
        for (int i = 0; i < n; i++)
            board[i][row[i]] = 'Q';
        return board;
    }

public:
    vector<vector<string>> solveNQueens(int n) {
        res.clear();

        col = vector<bool>(n, false);
        dia1 = vector<bool>(2*n-1, false);
        dia2 = vector<bool>(2*n-1, false);

        vector<int> row;
        putQueen(n, 0, row);

        return res;
    }
};
```

## 正确性说明

以下证明是笔记根据课程状态转移整理的 `editorial_inference`。

### 所有输出都合法

到达 `index==n` 时：

- 每一行恰好通过一个递归层选择了一个列；
- 候选进入前检查 `col`，所以没有两皇后同列；
- 检查 `dia1`、`dia2`，所以没有两皇后共享任一对角线；
- `generateBoard` 按 `row` 把恰好 `n` 个皇后写入棋盘。[editorial_inference | 基于 ev-004, ev-005]

因此加入 `res` 的每个棋盘都是合法解。

### 所有合法解都会被找到

对任一合法棋盘，按第 0 行到第 `n-1` 行读取其皇后列，得到唯一列序列。代码在每一行都会枚举这一个列；因为完整棋盘合法，其每个前缀也不冲突，所以这些候选不会被三项检查错误剪掉。该序列最终到达 `index==n` 并被记录。[editorial_inference]

### 不会重复输出同一解

不同搜索路径至少在某一行选择了不同列，因此生成的 `row` 序列不同；同一列序列只由唯一的逐行选择路径产生，所以同一棋盘不会被重复加入。[editorial_inference]

## 复杂度

课程没有直接给出复杂度。为了避免只写一个含义不明的 `O(n!)`，可以分开表示。

设：

- `T` 为搜索实际到达的部分棋盘状态数；
- `S` 为合法解数量。

则：

- 每个非叶状态最多检查 `n` 个列候选，搜索检查成本可写为 `O(nT)`；
- 每生成一个解，`generateBoard` 创建并填写 `n × n` 棋盘，成本为 `O(n²)`；
- 总时间可写为 `O(nT + S·n²)`；
- 若只需给一个不利用对角线剪枝的宽松阶乘上界，`T` 不超过各深度排列状态之和，可将搜索部分写为 `O(n·n!)`；
- `col`、`dia1`、`dia2`、`row` 与递归栈合计 `O(n)` 辅助空间；
- 返回结果本身占 `O(S·n²)`，不能混入“辅助空间”后仍只写 `O(n)`。[editorial_inference | 基于 code-001]

不同资料对 N Queens 常用的粗略复杂度记法可能不同；面试时应先声明是否计算每层候选检查与输出构造。本笔记不把任何一种写法冒充课程结论。

## 输入前提与边界

### `n >= 1`

课程代码使用：

```cpp
vector<bool>(2*n-1, false)
```

它按正整数棋盘设计。若 `n==0`，`2*n-1` 为负数，不能作为这份实现的安全 `vector` 长度；课程没有为零尺寸棋盘定义语义。[editorial_inference | 基于 code-001]

### `n==1`

唯一候选 `(0,0)` 无冲突，算法会生成 `["Q"]`。[editorial_inference]

### `n==2` 或 `n==3`

## 常见错误

1. **额外枚举行号**：按行递归已经固定当前行，再枚举行会重复建模。[editorial_inference]
2. **把 `row` 当作行占用数组**：它实际按行保存列索引。[visual_direct | ev-005]
3. **两类对角线公式混用**：一个使用和 `index+i`，另一个使用差平移 `index-i+n-1`。[course_direct + visual_direct | ev-004, ev-005]
4. **漏掉 `+n-1`**：会让部分 `dia2` 下标为负。[course_direct + editorial_inference | ev-004]
5. **对角线数组只分配 `n` 个位置**：棋盘每个方向都有 `2n-1` 条对角线。[course_direct | ev-004]
6. **标记后忘记撤销**：兄弟分支会继承不属于自己的占用状态。[course_direct + visual_direct | ev-005]
7. **撤销顺序不完整**：三个布尔数组与 `row` 必须全部恢复。[editorial_inference]
8. **到 `index==n` 后不返回**：会继续访问不存在的第 `n` 行语义。[course_direct + visual_direct | ev-005]
9. **每找到解只保存 `row` 的引用**：课程立即把它转换为独立棋盘并存入 `res`。[visual_direct + editorial_inference | ev-005]
10. **把课程运行演示写成本项目已测试**：两类证据的主体不同。[补充说明 | ev-006, code-001]
11. **把 N-Queens II 或 Sudoku 当作已讲解方案**：课程只展示题目和方向。[补充说明 | ev-007, ev-008]

## 闪卡

1. **问**：为什么没有 `rowUsed`？ **答**：递归深度已经固定当前行，每层恰好放一个皇后。
2. **问**：`row` 保存什么？ **答**：按行保存列索引，`row[r]` 是第 `r` 行皇后的列。
3. **问**：`dia1` 的索引是什么？ **答**：`index+i`，范围 `0...2n-2`。
4. **问**：`dia2` 为什么要加 `n-1`？ **答**：原始行列差可能为负，加偏移后映射到 `0...2n-2`。
5. **问**：两个对角线数组长度是多少？ **答**：都是 `2*n-1`。
6. **问**：何时记录一个解？ **答**：`index==n`，说明全部 `n` 行已经放置。
7. **问**：为什么递归后必须撤销？ **答**：占用状态只属于当前部分棋盘，兄弟候选必须从父状态开始。
8. **问**：本项目是否运行了课程的 `n=4/n=8` 演示？ **答**：没有；课程视频展示了运行，本项目只语法编译代码工件。
9. **问**：复杂度为何要单独写输出项？ **答**：每个解都要构造 `n²` 个棋盘字符，总输出大小为 `S n²`。
