## 核心概念与定义

### 1. 均摊时间复杂度

均摊分析不只盯住一次最昂贵操作，而是把一段操作序列的总成本除以操作次数，观察每次操作平均需要承担多少成本。[视频 00:00:00–00:00:44] [视频 00:10:00–00:13:08]

在本课中：

- 普通 `push_back`：数组未满，直接写入尾部，成本为常数级。
- 扩容 `push_back`：数组已满，先复制全部现有元素，再插入新元素，单次可达 `O(n)`。
- 均摊结论：扩容并非每次发生；以 2 倍增长容量时，连续操作的总成本为线性量级，因此每次均摊为 `O(1)`。[视频 00:04:04–00:13:08]

视频代码注释使用 `Average: O(1)`。本笔记按课程语境将其解释为**操作序列的均摊复杂度**，不把它改写成基于随机输入分布的概率平均结论。[视频 00:12:23–00:13:08] [补充说明]

### 2. 动态数组

本课把动态数组描述为对底层连续数组的封装：当前空间满时，申请更大的数组，把旧元素复制过去，再继续添加。[视频 00:00:44–00:09:59]

`MyVector` 的三个关键成员是：[视频 00:01:59–00:04:04]

- `data`：指向底层数组；
- `capacity`：底层数组最多可容纳的元素数；
- `size`：当前已经存放的元素数。

必须区分 `size` 与 `capacity`：前者描述实际元素，后者描述已申请空间。`size == capacity` 才表示当前数组已满。[视频 00:01:59–00:07:50]

### 3. 几何扩容

视频选择把容量扩大为原来的 2 倍：[视频 00:04:04–00:07:50]

```cpp
if (size == capacity) {
    resize(2 * capacity);
}
```

这样一次扩容后会得到与当前数据量同量级的空闲空间，后续需要经过很多次普通插入才会再次扩容。[视频 00:04:04–00:07:50] [整理推导]

课程对比指出，如果每次只增加固定常数（如 `+100`），数据规模变大后会频繁触发需要复制全部元素的 `resize`，整体性能会退化。[视频 00:04:04–00:07:50]

## `MyVector` 代码结构

视频展示并逐步补全的代码可整理为：[视频 00:01:59–00:09:59]

```cpp
template <typename T>
class MyVector {
private:
    T* data;
    int capacity; // 数组可以容纳的最大元素个数
    int size;     // 当前元素个数

    void resize(int newCapacity) {
        assert(newCapacity >= size);
        T* newData = new T[newCapacity];
        for (int i = 0; i < size; i++) {
            newData[i] = data[i];
        }
        delete[] data;
        data = newData;
        capacity = newCapacity;
    }

public:
    MyVector() {
        data = new T[10];
        capacity = 10;
        size = 0;
    }

    ~MyVector() {
        delete[] data;
    }

    // Average: O(1)
    void push_back(T e) {
        if (size == capacity) {
            resize(2 * capacity);
        }
        data[size++] = e;
    }

    T pop_back() {
        assert(size > 0);
        size--;
        return data[size];
    }
};
```

这是一段教学用简化实现。视频本课尚未为 `pop_back` 加入缩容，且结构化证据没有记录复制异常、移动语义等完整容器设计问题；不能据此声称它等价于标准库 `vector`。[视频 00:00:44–00:15:16] [补充说明]

## 复杂度推导

### 1. `resize` 的单次成本

若当前有 `n = size` 个元素，`resize` 中的循环逐个复制这 `n` 个元素，因此单次时间复杂度是 `O(n)`。[视频 00:07:50–00:09:59]

代码中还包括申请新数组、释放旧数组和更新指针；视频的复杂度结论以复制循环为主导项。[视频 00:07:50–00:09:59] [整理推导]

### 2. `push_back` 的单次最坏成本

数组未满时，只需写入 `data[size]` 并更新 `size`，是常数级操作；数组刚好满时，需要先执行 `O(n)` 的 `resize`，因此单次最坏情况可为 `O(n)`。[视频 00:04:04–00:09:59] [整理推导]

### 3. `push_back` 的均摊成本

视频假设当前容量为 `n`，考察从空闲容量逐步填满并触发下一次扩容的一串添加操作：[视频 00:10:00–00:13:08]

1. 前 `n` 次添加各花费 1，总成本为 `n`。
2. 第 `n+1` 次添加触发扩容：复制 `n` 个元素，再插入 1 个元素。
3. 因而按明细计数，总成本是 `n + n + 1 = 2n + 1`；视频图示用 `2n` 概括其主导数量级。
4. 平均到 `n+1` 次操作：

```text
(2n + 1) / (n + 1)
```

该值被一个常数界定，并随 `n` 增大接近 2，所以均摊时间复杂度为 `O(1)`。[视频 00:10:00–00:13:08] [整理推导]

`2n` 与 `2n+1` 的差异不影响大 O 结论；这里保留明细，是为了让“复制”和“新元素写入”两项都可见。

### 4. 为什么固定增量会变差

课程明确指出固定 `+100` 会让大规模下的 `resize` 过于频繁。[视频 00:04:04–00:07:50]

进一步按课程成本模型整理：若每次只增加固定容量 `c`，插入 `n` 个元素时会扩容约 `n/c` 次；后期每次又要复制越来越多的已有元素，复制成本形成递增求和。由此可解释为什么它不能获得本课 2 倍扩容所展示的同样均摊结论。[整理推导]

## 正确性与状态不变量

视频没有给出形式化正确性证明，但代码与讲解体现了以下约束：[视频 00:01:59–00:09:59]

## 边界条件、易错点与测试

### 视频明确呈现的边界

- `resize` 以 `assert(newCapacity >= size)` 防止新容量容不下现有元素。[视频 00:07:50–00:09:59]
- `push_back` 必须在 `size == capacity` 时先扩容，不能先写越界位置。[视频 00:04:04–00:07:50]
- `pop_back` 以 `assert(size > 0)` 拒绝空数组删除。[视频 00:01:59–00:04:04]

### 常见误区

1. **看到一次 `resize` 是 `O(n)`，就把每次 `push_back` 都写成 `O(n)`**：忽略昂贵操作之间存在大量普通插入。[视频 00:07:50–00:13:08]
2. **只报均摊 `O(1)`，不承认单次最坏 `O(n)`**：均摊结论没有消除触发扩容时的复制。[视频 00:07:50–00:13:08] [整理推导]
3. **把 `size` 和 `capacity` 混为一谈**：可能导致过早扩容、越界写入或错误的成本推导。[视频 00:01:59–00:07:50]
4. **用固定增量扩容却沿用 2 倍扩容的证明**：两种策略触发昂贵复制的频率不同。[视频 00:04:04–00:07:50]
5. **把实验当证明**：一次机器上的近似线性趋势不能替代操作计数。[视频 00:10:00–00:14:40] [整理推导]
6. **在本课就假定缩容策略已经正确**：本课只提出问题；如果删除时设计不当，会在下一课出现复杂度震荡。[视频 00:14:40–00:15:16]
