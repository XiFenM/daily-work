完全平方数是某个整数的平方，例如：

```text
1, 4, 9, 16, ...
```

课程示例：

```text

n = 13

```

### 为什么一定有解

`1` 本身是完全平方数，所以任意正整数 `n` 至少可以写成：

```text
n = 1 + 1 + ... + 1
```

一共 `n` 项。因此在课程的 `n > 0` 前提下，问题不会无解。[course_direct | ev-002]

这只证明“存在一种表示”，并不自动证明某个具体实现一定返回最优值；最优性还要依赖图建模与 BFS 的层序性质。[editorial_inference]

## 为什么直接贪心不成立

一个自然想法是：每一步都减去不超过当前数的最大完全平方数。

对 `n=12`：

```text
贪心：12 - 9 - 1 - 1 - 1 = 0
使用 4 个平方数

最优：12 - 4 - 4 - 4 = 0
使用 3 个平方数
```

[course_direct | ev-003 | 视频 03:44–05:20]

这个反例说明，局部选择“当前最大的平方数”不能保证全局项数最少。面试中提出贪心方案后，应先寻找交换论证或反例；没有证明时不能仅凭直觉宣布贪心正确。[course_direct + editorial_inference | 基于 ev-003]

## 把整数问题建模成图

### 节点

把每个剩余值看成一个状态节点：

```text
0, 1, 2, ..., n
```

[course_direct + visual_direct | ev-004 | 视频 05:20–08:08]

### 边

对当前节点 `x`，若：

```text
i >= 1
i * i <= x
```

则可以从 `x` 转移到：

```text
x - i * i
```

这条边表示“在表示中选用一个平方数 `i²`”。[course_direct + visual_direct + editorial_inference | 基于 ev-004, ev-005]

### 起点与终点

```text
起点：n
终点：0
```

从 `n` 到 `0` 的一条长度为 `d` 的路径会给出一个含 `d` 项的平方数分解；反过来，任意含 `d` 项的分解，按某个选取顺序排列后也会给出一条长度为 `d` 的路径。这里不要求把交换顺序后的路径视为同一条路径。[course_direct + editorial_inference | 基于 ev-004]

因此：

```text
最少平方数个数
= 从 n 到 0 的最少边数
= 隐式无权图中的最短路径长度
```

[editorial_inference | 基于课程建模 ev-004]

### 为什么是无权图

每条边都代表恰好选用一个平方数，代价统一为 `1`。目标只关心用了多少项，不关心平方数本身的大小。因此可以按无权图处理，使用 BFS 按层搜索。[course_direct + editorial_inference | 基于 ev-001, ev-004]

## 解法一：不去重的 BFS

课程先写出一个直接版本。队列中每项保存：

```text
(num, step)
```

- `num`：当前剩余整数；
- `step`：从起点 `n` 到达当前状态已经使用的平方数个数。

[course_direct + visual_direct | ev-005 | 视频 08:08–12:15]

屏幕完整代码为：

```cpp
class Solution {
public:
    int numSquares(int n) {
        assert(n > 0);
        queue<pair<int, int>> q;
        q.push(make_pair(n, 0));

        while (!q.empty()) {
            int num = q.front().first;
            int step = q.front().second;
            q.pop();

            if (num == 0)
                return step;

            for (int i = 1; num - i * i >= 0; i++)
                q.push(make_pair(num - i * i, step + 1));
        }

        throw invalid_argument("No Solution.");
    }
};
```

[visual_direct | code-001, ev-005 | 视频 08:08–12:15]

### 状态转移

从 `(num, step)` 出队后，对所有满足 `num-i² >= 0` 的 `i`，生成：

```text
(num - i², step + 1)
```

[course_direct + visual_direct | ev-005]

### 为什么会 MLE

这个图不是树。同一个整数状态可以沿不同路径到达。例如，不同的平方数选择顺序可能得到相同剩余值。基线代码没有记录“该状态已经入过队”，所以相同节点会反复出现，队列中会累积大量由不同路径前缀产生的重复状态项，而不是至多 `n+1` 个不同状态。[course_direct + editorial_inference | 基于 ev-005, ev-006]

课程指出这个版本会触发 `Memory Limit Exceeded`，并据此引入 `visited`。[course_direct | ev-005, ev-006]

## 解法二：`visited` 去重 + 提前返回

优化版增加：

```cpp
vector<bool> visited(n + 1, false);
visited[n] = true;
```

课程讲解并在屏幕代码中实现了 `visited` 去重与生成目标时的提前返回。[course_direct + visual_direct | ev-006 | 视频 12:15–17:34] 每次生成候选 `a` 时，代码依次执行：

1. `a < 0`：停止枚举；
2. `a == 0`：直接返回 `step + 1`；
3. `a > 0 && !visited[a]`：入队，并立刻标记；
4. `visited[a]` 已为真：跳过重复状态。

[visual_direct | code-002, ev-006 | 视频 12:15–17:34]

第 1 项可以停止，是因为 `i` 继续增大只会让 `a = num-i²` 更小；这句原因解释是本笔记从循环和表达式推导出来的。[editorial_inference | 基于 code-002, ev-006]

屏幕最终代码为：

```cpp
class Solution {
public:
    int numSquares(int n) {
        assert(n > 0);
        queue<pair<int, int>> q;
        q.push(make_pair(n, 0));

        vector<bool> visited(n + 1, false);
        visited[n] = true;

        while (!q.empty()) {
            int num = q.front().first;
            int step = q.front().second;
            q.pop();

            for (int i = 1;; i++) {
                int a = num - i * i;

                if (a < 0)
                    break;
                if (a == 0)
                    return step + 1;

                if (!visited[a]) {
                    q.push(make_pair(a, step + 1));
                    visited[a] = true;
                }
            }
        }

        throw invalid_argument("No Solution.");
    }
};
```

[visual_direct | code-002, ev-006 | 视频 12:15–17:34]

### 为什么在入队时标记

若等到出队时才设置 `visited`，同一层的多个父节点仍可能在它第一次出队前把它重复放入队列。入队后立即标记，可以在候选产生阶段就消除重复项。[editorial_inference | 基于屏幕代码 ev-006]

### 为什么可以复用第一次到达

图中每条边的代价都是 `1`。BFS 先处理较浅层，再处理较深层，所以一个状态第一次入队时，对应的 `step` 已是从 `n` 到它的最少边数。以后更晚到达同一状态的路径不会更短，可以安全跳过。[editorial_inference | 基于 ev-001, ev-004, ev-006]

## 正确性解释

课程没有给出形式化四段证明。下面是基于课程状态图的编辑性验证。

### 1. 建模等价性

从 `x` 到 `x-i²` 的一条边对应选择一个平方数 `i²`。因此长度为 `d` 的 `n→0` 路径会产生一个含 `d` 项的平方数分解，而任意这样的分解也能按某个选取顺序构成一条长度为 `d` 的路径；不同选取顺序可能是不同路径，不在此主张严格的一一映射。[editorial_inference | 基于 ev-004]

### 2. BFS 层数语义

初始 `(n,0)` 位于第 0 层；从 `(num,step)` 生成的所有后继都带 `step+1`。队列 FIFO 使较小步数的状态先于更大步数的状态展开。[editorial_inference | 基于 ev-005, ev-006]

### 3. 去重安全性

某状态第一次入队时已经取得最小步数。后续到达它的路径不可能更短，因此 `visited` 不会丢失更优解。[editorial_inference | 基于 ev-006]

### 4. 提前返回安全性

当处理步数为 `step` 的节点并生成 `a==0` 时，得到一条长度 `step+1` 的解。由于队列中不可能尚未处理比 `step` 更浅的节点，后续也不可能发现长度小于 `step+1` 的解。[editorial_inference | 基于 ev-006]

### 5. 终止性

优化版只允许 `0..n` 中每个正状态至多入队一次；每次转移还严格减小当前数。状态数有限，而且 `1` 保证存在通向 `0` 的路径，所以算法会返回。[course_direct + editorial_inference | 基于 ev-002, ev-006]

### 课程直接证据

### 优化版的编辑分析

设输入正整数为 `n`：

- 不同状态最多有 `n+1` 个；
- 对状态 `x`，循环枚举 `1²..⌊√x⌋²`；
- 总枚举次数不超过：

```text
Σ(x=1..n) floor(√x) = O(n√n)
```

因此可以给出一个直接上界：

```text
时间：O(n√n)
辅助空间：O(n)
```

[editorial_inference | 基于 code-002, ev-006]

空间包括：

- `visited`：`n+1` 个布尔标记；
- 队列：去重后至多保存 `O(n)` 个不同状态。

这不是课程明确宣布的复杂度，也没有把 `vector<bool>` 的位压缩实现细节计入渐进结论。

### 基线版

基线版按路径而不是按唯一状态扩展，重复项数量可能非常大。课程以 MLE 说明其实用失败，但没有给出精确渐进上界；本笔记不把它简化成优化版的 `O(n√n)`。[course_direct + editorial_inference | 基于 ev-005]

### 2. 平方数枚举必须从 `i=1` 开始

若允许 `i=0`，转移会从 `num` 回到自身，失去严格下降性质并制造无意义循环。[editorial_inference | 基于代码]

### 3. 防止乘法溢出

屏幕条件直接计算 `i*i`。在本题常见约束下可能足够，但若接口允许更大整数，应考虑 `i <= num / i` 或更宽整数类型。[补充说明]

### 4. `visited` 要在入队时设置

先 `push` 再立即 `visited[a] = true`，二者属于同一次状态接纳动作。把标记推迟到出队会保留大量重复候选。[visual_direct + editorial_inference | 基于 ev-006]

### 5. 不把 MLE 误判为 BFS 不适用

失败的是“把图当树、没有去重”的实现，不是 BFS 建模本身。修复点是记录已发现状态。[course_direct | ev-005, ev-006]

### 6. `throw` 是防御性尾部

在 `n>0` 且 `1` 可用的课程契约下，理论上存在到 `0` 的路径。屏幕仍保留：

2. “从 `x` 可以转到所有 `x-i² >= 0`，每条边代表使用一个平方数，代价都为 1。”
3. “所以题目等价于求隐式无权图中 `n` 到 `0` 的最短路径。”
4. “用队列做 BFS，队列元素保存 `(num, step)`。”
5. “图中同一状态可由多条路径到达，必须在入队时用 `visited` 去重，否则会重复扩展甚至 MLE。”
6. “第一次生成 `0` 时处于最浅可达层，返回 `step+1`。”
7. “课程没有直接给复杂度；按代码枚举所有状态及其平方数后继，可给出 `O(n√n)` 时间、`O(n)` 辅助空间的编辑上界。”
8. “最后说明 `n>0`、乘法溢出和标记时机等边界。”
