```cpp
#include <iostream>
#include <vector>
#include <unordered_set>

using namespace std;

// 时间复杂度: O(n)
// 空间复杂度: O(n)
class Solution {
public:
    vector<int> intersection(vector<int>& nums1, vector<int>& nums2) {

        // O(n)
        unordered_set<int> record(nums1.begin(), nums1.end());

        // O(n)

        for (int i = 0; i < nums2.size(); i++)

                resultSet.insert(nums2[i]);

        // O(n)
        return vector<int>(resultSet.begin(), resultSet.end());
    }
};
```

## 350 重构：`map` 改为 `unordered_map`

### 重构前的复杂度

课程回看 `map` 版本：[ev-003；视频 04:37–05:35]

1. 扫描 `nums1`，在 `map` 中建立频次：单次查找/修改按 `O(log n)`，总计 `O(n log n)`；
2. 扫描 `nums2`，查找并更新剩余频次：总计 `O(n log n)`；
3. 总时间复杂度为 `O(n log n)`，空间复杂度为 `O(n)`。

### 视频中的重构代码

```cpp
#include <iostream>
#include <vector>
#include <unordered_map>

using namespace std;

// 时间复杂度: O(n)
// 空间复杂度: O(n)
class Solution {
public:
    vector<int> intersect(vector<int>& nums1, vector<int>& nums2) {

        // O(n)
        unordered_map<int, int> record;
        for (int i = 0; i < nums1.size(); i++)
            record[nums1[i]]++;

        // O(n)
        vector<int> resultVector;
        for (int i = 0; i < nums2.size(); i++)
            if (record[nums2[i]] > 0) {
                resultVector.push_back(nums2[i]);
                record[nums2[i]]--;
            }

        return resultVector;
    }
};
```

## 边界条件与常见误区

### 课程直接提醒的边界

在课后练习部分，课程提醒字符串类查找表问题要主动确认：

- 空字符串；
- 字符集范围；
- 大小写是否敏感。[ev-009；视频 12:07–18:59]

这些条件会改变键空间、归一化方式与答案契约，不能在没有确认时自行假设。[整理推导]

### 常见误区

1. **只看 `set` 和 `map` 的名字，不看底层实现**：有序与无序版本的操作成本和顺序能力不同。[ev-005；视频 06:16–07:36] [ev-006；视频 07:37–08:45]
2. **认为 `unordered_*` 永远更好**：需要最大最小值、前驱后继、范围或排位能力时，失去顺序会直接丢失所需信息。[ev-005；视频 06:16–07:36]
3. **把哈希 `O(1)` 写成无条件最坏情况保证**：课程使用 `O(1)` 分析交集题，但没有展开最坏情况。[ev-004；视频 05:36–06:15] [补充说明]
4. **假设 `unordered_set` 的迭代结果已排序**：视频明确说哈希表失去数据顺序性。[ev-005；视频 06:16–07:36]
5. **把 349 和 350 都写成集合**：350 需要保留重复次数，集合无法表达剩余频次。[ev-003；视频 04:37–05:35] [ev-008；视频 10:40–12:06]
6. **350 命中后不递减计数**：会让同一个 `nums1` 元素被重复使用，答案重数可能过多。[ev-008；视频 10:40–12:06] [整理推导]
7. **把输出顺序变化误判成 349 错误**：349 允许任意顺序；正确性应按集合内容而非向量排列判断。[视频 04-01 03:48–05:22] [整理推导]
8. **声称屏幕代码已通过本地测试**：结构化证据的代码验证状态是 `not_run`，本课也没有记录独立实验。[补充说明]
