## 题目与契约

课程展示的题意：

```text

```

- `n > 0`；
- 每一步只能是 1 或 2；
- 目标是不同走法的数量，而不是最少步数或路径本身。[course_direct + editorial_inference | ev-001]

```text

```

## 建模：为什么从“最后一步”出发

任何到达第 `n` 阶的合法路径，最后一步只有两种情况：

1. 从 `n-1` 走 1 阶到 `n`；
2. 从 `n-2` 走 2 阶到 `n`。

两类不可能同时成立，所以互斥；每条合法路径最后一步又必属于其中一类，所以完备。由加法原理：[course_direct + editorial_inference | ev-002]

```text
ways(n) = ways(n - 1) + ways(n - 2)
```

这比“看起来像 Fibonacci”更可靠：先由题目语义得到状态转移，再识别它与 Fibonacci 的形式联系。[editorial_inference]

## 基本状态 `ways(0)=1` 的语义

本课最终代码使用：

```text
ways(0) = 1
ways(1) = 1
```

[course_direct + visual_direct | ev-003, ev-006]

`ways(0)=1` 不是说现实中“零阶台阶要走一步”，而是说：当剩余台阶恰好为 0 时，有一种完成方式——不再做任何动作。这个空方案是组合计数递推的乘法/拼接单位，使 `ways(2)=ways(1)+ways(0)=2` 正常成立。[course_direct + editorial_inference | ev-003]

要同时记住两个边界：

- 公开接口题面只要求 `n>0`；
- 递归内部需要访问状态 `n=0`。

## 版本一：纯递归

### 屏幕代码

```cpp
class Solution {
private:
    int calcWays(int n) {
        if (n == 0 || n == 1)
            return 1;
        return calcWays(n - 1) + calcWays(n - 2);
    }

public:
    int climbStairs(int n) {
        return calcWays(n);
    }
};
```

[visual_direct | code-001, ev-003]

### 状态五要素

| 要素     | 定义                                   |
| -------- | -------------------------------------- |
| 状态     | `calcWays(n)`：爬完 `n` 阶的不同走法数 |
| 基本值   | `calcWays(0)=1`，`calcWays(1)=1`       |
| 转移     | `calcWays(n-1)+calcWays(n-2)`          |
| 求值顺序 | 自顶向下，每个状态递归进入两个更小状态 |
| 答案     | `calcWays(n)`                          |

[course_direct + visual_direct | ev-002, ev-003]

### 局限

递归树会反复计算相同的 `calcWays(k)`。课程在图中高亮 `n-2`、`n-3` 的重复节点，这正是重叠子问题。[course_direct + visual_direct | ev-004]

## 版本二：记忆化搜索

### 屏幕代码

```cpp
class Solution {
private:
    vector<int> memo;

    int calcWays(int n) {
        if (n == 0 || n == 1)
            return 1;
        if (memo[n] == -1)
            memo[n] = calcWays(n - 1) + calcWays(n - 2);
        return memo[n];
    }

public:
    int climbStairs(int n) {
        memo = vector<int>(n + 1, -1);
        return calcWays(n);
    }
};
```

[visual_direct | code-002, ev-005]

### 状态五要素

| 要素     | 定义                                             |
| -------- | ------------------------------------------------ |
| 状态     | `calcWays(n)` 语义不变；`memo[n]` 缓存该状态答案 |
| 初始化   | 建立 `n+1` 个元素的缓存，以 `-1` 表示未计算      |
| 转移     | 未命中时计算两个更小状态之和并写回               |
| 求值顺序 | 自顶向下、按需；命中后直接返回                   |
| 答案     | 顶层 `calcWays(n)`                               |

[course_direct + visual_direct | ev-005]

“加入缓存”没有改变状态或转移，只改变每个状态的求值次数。这是从递归迁移到记忆化时最稳定的思考方式。[editorial_inference]

### 数组为什么是 `n+1`

缓存需要直接访问 `memo[n]`，索引范围是 `0...n`，因此元素数量必须是 `n+1`。课程明确提醒少一个元素会越界。[course_direct | ev-005]

## 版本三：自底向上动态规划

### 屏幕代码

```cpp
class Solution {
public:
    int climbStairs(int n) {
        vector<int> memo(n + 1, -1);
        memo[0] = 1;
        memo[1] = 1;
        for (int i = 2; i <= n; i++)
            memo[i] = memo[i - 1] + memo[i - 2];
        return memo[n];
    }
};
```

[visual_direct | code-003, ev-006]

### 动态规划五要素

| 要素     | 定义                                      |
| -------- | ----------------------------------------- |
| 状态     | `memo[i]`：爬完 `i` 阶的不同走法数        |
| 初始化   | `memo[0]=1`，`memo[1]=1`                  |
| 转移     | `memo[i]=memo[i-1]+memo[i-2]`             |
| 遍历顺序 | `i` 从 2 递增到 `n`；使用前两个依赖已填好 |
| 答案     | `memo[n]`                                 |

[course_direct + visual_direct | ev-006]

### 循环不变量（整理证明）

进入第 `i` 次循环前，`memo[0...i-1]` 已分别保存对应台阶数的走法总数：

1. `memo[0]`、`memo[1]` 初始化正确；
2. 最后一步分类证明两个前驱之和覆盖 `i` 的所有走法；
3. 写入 `memo[i]` 后，正确前缀扩展一位；
4. 循环结束后 `memo[n]` 正确。

[editorial_inference | 基于 ev-002, ev-006]

### `n=0` 的接口扩展陷阱

屏幕代码在公开契约 `n>0` 下不会接收 `n=0`。若自行把接口扩展为允许 0，则：

```cpp
vector<int> memo(1, -1);
memo[0] = 1; // 合法
memo[1] = 1; // 越界
```

因此扩展接口时要先特判 `n==0`，或让容器至少有两个元素。这是工程边界补充，不是对公开题解的否定。[supplemental]

## 正确性说明

课程直接给出了递归分类和三版代码，没有形式化证明。完整义务可整理为：[editorial_inference]

### 1. 分类不重

最后一步长度不可能同时为 1 和 2，因此来自 `n-1` 与来自 `n-2` 的路径集合没有交集。

### 2. 分类不漏

题目只允许走 1 或 2 阶，所以每条到达 `n` 的路径必在两类之一。

### 3. 基本状态一致

三版代码都使用 `ways(0)=ways(1)=1`；记忆化与填表不能换成另一套初始化。

### 4. 求值顺序满足依赖

递归参数持续变小，最终触及 0 或 1；自底向上按索引递增，读取的 `i-1`、`i-2` 已计算。
