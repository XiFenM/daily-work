## 状态设计一：闭区间与空窗口

课程把窗口定义为双闭区间：

```text
s[l...r]
```

也就是说，窗口包含索引 `l` 和 `r`。为了让初始窗口不含任何字符，代码使用：

```cpp
int l = 0, r = -1;
```

[视频 00:05:54–00:09:46]

此时 `[0,-1]` 是空区间，并且长度公式仍保持一致：

```text
r - l + 1 = -1 - 0 + 1 = 0
```

[整理推导]

这一定义带来三点好处：

1. 第一个准备加入的字符统一写成 `s[r+1]`，初始就是 `s[0]`。
2. 窗口长度始终使用 `r-l+1`，不需要为首轮单独分支。
3. 空字符串满足 `l == s.size() == 0`，主循环直接结束并返回 `0`。

## 状态设计二：`freq[256]`

`freq[x]` 表示字符值 `x` 在当前窗口 `s[l...r]` 中出现的次数。课程使用：

```cpp
int freq[256] = {0};
```

[视频 00:02:34–00:09:46]

在本题不变量成立时，每个槽位实际上只有两种有效状态：

| `freq[c]` | 含义                                    |
| --------- | --------------------------------------- |
| `0`       | 字符 `c` 当前不在窗口中，可以加入       |
| `1`       | 字符 `c` 已在窗口中，再加入就会形成重复 |

窗口扩张时，对新字符的槽位加一；窗口收缩时，对离开字符的槽位减一。[视频 00:02:34–00:09:46]

这里不应该只把 `freq` 理解为“为了提速额外加的一张表”。它与 `l`、`r` 一起构成算法状态：边界改变时若忘记同步更新频次，下一轮的合法性判断就不再可信。[视频 00:02:34–00:09:46] [整理推导]

## 两类状态转移

### 1. 下一个字符未出现：扩张右边界

条件是：

```cpp
r + 1 < s.size() && freq[s[r+1]] == 0
```

随后执行：

```cpp
freq[s[++r]]++;
```

[视频 00:05:54–00:09:46]

`++r` 先把右边界移到新字符，再把这个字符的频次从 `0` 加到 `1`。由于加入前已经确认其不在窗口中，扩张后的窗口仍无重复。[视频 00:02:34–00:09:46]

### 2. 下一个字符重复，或右端已经到头：收缩左边界

另一个分支执行：

```cpp
freq[s[l++]]--;
```

[视频 00:05:54–00:09:46]

下标使用的是递增前的 `l`：先让左端字符离开频次表，再把 `l` 向右移动一位。分成两种情况理解：

- **`s[r+1]` 与窗口重复**：不断移走左端字符，直到窗口中原来的同字符被移除；下一轮就可以安全扩张 `r`。
- **`r` 已经位于字符串末尾**：再也没有字符可加入，代码继续收缩窗口，直到 `l == s.size()`，主循环结束。

[视频 00:02:34–00:09:46] [整理推导]

即使收缩时移走的不是造成阻塞的那个字符，窗口仍然合法，因为从一个无重复窗口删除元素不会制造重复；它只是还没有解除“下一个字符不能加入”的阻塞。[整理推导]

### 3. 更新答案

每轮状态转移后执行：

```cpp
res = max(res, r - l + 1);
```

[视频 00:05:54–00:09:46]

扩张可能得到新的最长窗口；收缩只会让当前长度变小，因此不会降低已经记录的 `res`。把更新放在统一位置使两个分支共享同一套长度计算。[视频 00:05:54–00:09:46] [整理推导]

```cpp
#include ...

using namespace std;

class Solution {
public:
    int lengthOfLongestSubstring(string s) {

        int freq[256] = {0};
        int l = 0, r = -1; // 滑动窗口为 s[l...r]
        int res = 0;

        while (l < s.size()) {

            if (r + 1 < s.size() && freq[s[r+1]] == 0)
                freq[s[++r]]++;
            else
                freq[s[l++]]--;

            res = max(res, r-l+1);
        }

        return res;
    }
};
```

## 正确性解释

规范化证据把本课方法记为 `state_transition`，而不是声称视频给出了完整形式化证明。下面按状态转移整理正确性要点。[视频 00:02:34–00:09:46] [整理推导]

### 初始化

- `[l,r] = [0,-1]` 是空窗口，因此天然没有重复字符。
- `freq` 全部初始化为 `0`，与空窗口完全一致。
- `res=0` 与目前尚未观察到非空合法子串一致。

[视频 00:05:54–00:09:46] [整理推导]

### 保持

- 扩张分支只加入频次为 `0` 的字符；加入后该频次为 `1`，窗口继续无重复。
- 收缩分支从合法窗口删除一个字符；删除不可能引入重复，并且频次与边界同步更新。
- 两个分支结束后，`freq` 仍精确描述新的 `[l,r]`。

[视频 00:02:34–00:09:46] [整理推导]

### 进度与终止

每轮不是令 `r` 增加一，就是令 `l` 增加一。二者都不向左回退：

- `r` 最多从 `-1` 增至 `n-1`，扩张不超过 `n` 次；
- `l` 最多从 `0` 增至 `n`，收缩不超过 `n` 次。

因此循环迭代次数至多是线性数量级，并最终在 `l == n` 时结束。[视频 00:05:54–00:09:46] [整理推导]

### 为什么不会漏掉最优解

当下一个字符可以加入时，算法立即扩张；当它与窗口重复时，更小的 `l` 都包含那个阻塞字符，不能形成以新位置为右端点的合法窗口，所以算法逐步右移 `l`，直到该字符可以加入。每个右端点能形成的关键合法窗口都在此过程中被记录，`res` 取这些窗口长度的最大值。[整理推导]

## 复杂度分析

### 时间复杂度：`O(n)`

虽然代码只有一个 `while`，有时同一个待加入字符会触发多轮收缩，但不能把这种局部重复误判为 `O(n^2)`：

- `r` 只增不减，每个字符最多通过右边界进入窗口一次；
- `l` 只增不减，每个字符最多通过左边界离开窗口一次；
- 每轮只做固定次数的数组访问、比较和加减。

总状态转移次数不超过约 `2n`，所以渐进时间为 `O(n)`。[视频 00:05:54–00:09:46] [整理推导]

## 字符索引与实现边界

### 1. 必须先做右边界检查

代码把条件写成：

```cpp
r + 1 < s.size() && freq[s[r+1]] == 0
```

C++ 的 `&&` 从左到右短路求值。只有 `r+1` 仍是合法字符串索引时，才会读取 `s[r+1]`；顺序颠倒会先发生越界访问。[视频 00:05:54–00:09:46]

### 2. `char` 可能是有符号类型

`std::string::operator[]` 返回 `char`。不同实现中，普通 `char` 可能等价于 `signed char`；若字节值大于 127，提升为 `int` 后可能是负数，于是：

```cpp
freq[s[r+1]]
```

可能访问 `freq` 左侧的非法位置。若输入严格限定为 7 位 ASCII（0–127），不会触发这个问题；若希望处理完整 0–255 字节范围，应先转换：

```cpp
auto index = static_cast<unsigned char>(s[r+1]);
```

离开窗口时也应对 `s[l]` 使用相同转换。这是 C++ 类型规则带来的补充风险，视频没有展开。[补充说明]

### 3. `freq[256]` 不等于支持任意 Unicode 字符

UTF-8 中一个用户可见字符可能由多个字节构成。直接遍历 `std::string` 并按 256 个字节值计数，得到的是“最长无重复字节片段”，不一定是“最长无重复 Unicode 码点或字形簇子串”。若题目语义允许 Unicode，需要先明确计数单位并采用相应解码与查找结构。[补充说明]

### 4. `int` 与 `size_t`

`s.size()` 返回无符号的 `size_t`，而屏幕代码的 `l`、`r` 是 `int`。正常面试规模下代码可工作，但若字符串长度超过 `int` 可表示范围，指针递增和有符号/无符号比较会出现风险。工程代码可以统一采用足够宽且语义一致的索引类型。[补充说明]
