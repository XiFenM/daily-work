## 树形解空间

### 第一层

对 `[1,2,3]`，第一个位置可以选择：

```text
1
2
3
```

[course_direct + visual_direct | ev-002]

### 第二层

若第一层选择 `1`，剩余候选是：

```text
2
3
```

于是：

```text
1 -> 2 -> 3  得到 [1,2,3]
1 -> 3 -> 2  得到 [1,3,2]
```

[course_direct + visual_direct | ev-002]

然后回到根层，分别选择 `2` 和 `3`，得到其余四个排列。[course_direct + visual_direct | ev-002]

### 树节点对应什么

在本课实现中，一个递归节点可由以下状态描述：

```text
(index, p, used)
```

- `index`：已经放入 `p` 的元素个数；
- `p`：当前排列前缀；
- `used[i]`：输入下标 `i` 是否已出现在当前 `p` 中。

[visual_direct | code-001, ev-004]

`index` 与 `p.size()` 在正确执行中保持相等。这是由初始化和每次递归前恰好追加一个元素推得的编辑不变量；课程注释直接表达了相同语义，但没有把它命名为形式化不变量。[course_direct + editorial_inference | code-001]

## 递归表达式

屏幕给出：

```text
Perms(nums[0...n-1])
= {取出一个数字}
  + Perms(nums[{0...n-1} - 这个数字])
```

[visual_direct | formula-001, ev-003]

这表示：

1. 枚举当前层要取出的数字；
2. 固定该数字为当前排列的下一项；
3. 对剩余未使用数字求排列；
4. 将当前选择放到子问题结果之前。

[course_direct + editorial_inference | ev-003]

实现没有真的构造“剩余数组”，而是保留原 `nums`，通过 `used` 动态表示剩余候选集合。[visual_direct + editorial_inference | code-001]

## 状态模型：选择、递归、撤销

### 函数契约

屏幕注释直接说明：

```text
p 中保存一个有 index 个元素的排列；
向这个排列末尾添加第 index + 1 个元素，
获得一个有 index + 1 个元素的排列。
```

[visual_direct | code-001, ev-004]

可整理为：

```text
generatePermutation(nums, index, p)

进入时：
    p 已有 index 个元素；
    used 精确标记 p 使用的输入下标。

任务：
    枚举所有未使用下标，
    生成所有以 p 为前缀的完整排列。
```

[前两行 course_direct；任务表述为 editorial synthesis based on ev-003, ev-004]

### 一次完整状态转移

```cpp
if (!used[i]) {
    p.push_back(nums[i]);
    used[i] = true;
    generatePermutation(nums, index + 1, p);
    p.pop_back();
    used[i] = false;
}
```

[visual_direct | code-001, ev-004]

按生命周期拆开：

| 阶段   | `p`            | `used[i]`   | 目的                       |
| ------ | -------------- | ----------- | -------------------------- |
| 选择前 | 当前前缀       | `false`     | 下标 `i` 可选              |
| 选择   | 追加 `nums[i]` | 置 `true`   | 建立子分支状态             |
| 递归   | 多一个元素     | `true`      | 生成该前缀下全部排列       |
| 撤销 1 | 删除末尾       | 仍为 `true` | 恢复路径长度               |
| 撤销 2 | 已恢复         | 置 `false`  | 允许兄弟分支再次使用该下标 |

[visual_direct + editorial_inference | code-001, ev-005]

### 为什么必须恢复两份状态

只执行 `p.pop_back()`：

- 路径长度恢复；
- 但 `used[i]` 仍为 `true`；
- 后续分支会错误地永久禁用该元素。

只执行 `used[i] = false`：

- 候选资格恢复；
- 但 `p` 仍含旧元素；
- 后续分支会在污染的排列前缀上继续追加。

[editorial_inference]

课程把这种手动设置变量后再“恢复原状”称为回溯的核心状态操作。[course_direct | ev-005]

### `used` 不是重复值去重

对本课互不相同的输入：

```text
used[i] == true
```

只说明下标 `i` 已出现在当前路径，不能再次选择。[visual_direct | code-001]

如果输入是 `[1,1,2]`，两个值为 `1` 的元素拥有不同下标。当前代码会把它们当作不同选择，可能产生内容相同的排列；LeetCode 47 需要额外去重设计，但本课没有展开。[editorial_inference + 补充说明 | ev-006]

[visual_direct | code-001, ev-004]

```cpp
using namespace std;

class Solution {
private:
    vector<vector<int>> res;
    vector<bool> used;

    void generatePermutation(const vector<int>& nums, int index, vector<int>& p) {
        if (index == nums.size()) {
            res.push_back(p);
            return;
        }

        for (int i = 0; i < nums.size(); i++) {
            if (!used[i]) {
                p.push_back(nums[i]);
                used[i] = true;
                generatePermutation(nums, index + 1, p);
                p.pop_back();
                used[i] = false;
            }
        }
        return;
    }

public:
    vector<vector<int>> permute(vector<int>& nums) {
        res.clear();
        if (nums.size() == 0)
            return res;

        used = vector<bool>(nums.size(), false);
        vector<int> p;
        generatePermutation(nums, 0, p);
        return res;
    }
};
```

### 关键 token 核对

- 结果类型是 `vector<vector<int>>`；
- 状态数组是 `vector<bool> used`；
- `nums` 在递归函数中以 `const vector<int>&` 传入；
- `p` 以 `vector<int>&` 共享修改；
- 基例是 `index == nums.size()`；
- 候选循环每层都从 `i = 0` 开始；
- 候选条件是 `!used[i]`；
- 选择顺序是先 `push_back`，再 `used[i] = true`；
- 递归参数是 `index + 1`；
- 撤销顺序是先 `p.pop_back()`，再 `used[i] = false`；
- 公开接口对空数组直接返回空结果；
- `used` 初始化长度为 `nums.size()`，初值全为 `false`。

## 正确性解释

课程直接给出递归树、状态注释和恢复代码，但没有逐条形式证明。以下为结构归纳。[editorial_inference]

### 1. 初始化

公开接口建立：

```text
index = 0
p = []
used = [false, false, ..., false]
```

所以 `p` 含 0 个元素，且没有输入下标被占用，满足契约。[visual_direct + editorial_inference | code-001]

### 2. 保持

若某层进入时：

- `p` 含 `index` 个元素；
- `used` 与 `p` 中使用的下标一致；

选择任一 `!used[i]` 后：

- `p` 增加一个元素；
- `used[i]` 变为 `true`；
- 下一层接收 `index + 1`。

因此下一层仍满足契约。[editorial_inference]

### 3. 基例

当：

```text
index == nums.size()
```

`p` 已含 `n` 个元素；由于每次只选 `!used[i]`，每个输入下标恰好使用一次，因此 `p` 是一个完整排列。[visual_direct + editorial_inference | code-001]

### 4. 完备性

任取一个目标排列：

- 第一层循环一定会枚举它的第一个元素下标；
- 固定该下标后，下一层一定会枚举目标排列的第二个未使用下标；
- 继续归纳，整条目标选择序列一定存在于递归树中。

因此所有排列都会生成。[editorial_inference]

### 5. 不重复性

输入元素彼此不同。任意两个不同递归路径，至少在某一层选择了不同下标，因此该位置的值也不同，生成的排列内容不同。[editorial_inference]

这一步依赖“元素各不相同”的题面约束；输入有重复值时结论不成立。[course_direct + editorial_inference | ev-001, ev-006]

### 6. 恢复保证兄弟分支独立

递归返回后：

```cpp
p.pop_back();
used[i] = false;
```

把 `p` 和 `used` 恢复到选择 `i` 之前的状态，所以下一个循环候选从相同父状态开始。[course_direct + editorial_inference | ev-004, ev-005]

### 7. 终止性

每次递归把 `index` 增加 1，最大达到 `nums.size()`；当输入有限时递归必然终止。[editorial_inference]


### 时间

代码在每个完整排列处执行：

```cpp

```

这会复制长度为 `n` 的向量。仅最终答案复制就需要：

```text
Ω(n · n!)
```

工作量。[editorial_inference]

递归内部每个状态还会扫描 `0...n-1` 的候选并检查 `used[i]`。用于面试的稳妥输出敏感上界可写：

```text
O(n · n!)
```

同时说明它已包含输出物化成本；不同计数口径可能把状态扫描与结果复制分别展开。[editorial_inference]

不计结果集：

- `used` 长度为 `n`；
- `p` 最长为 `n`；
- 递归深度为 `n`；
- 因此主要辅助空间是 `O(n)`。

计入结果集后，总空间由输出主导：

```text
Θ(n · n!)
```

## 边界条件、易错点与测试

### 1. 空数组语义

屏幕代码：

```cpp
if (nums.size() == 0)
    return res;
```

所以空输入返回 `[]`。[visual_direct | code-001]

在组合数学中，空集合常被认为有一个空排列 `[[]]`；课程实现选择了不同接口语义。面试时应按题目契约确认。[editorial_inference]

### 2. 忘记 `p.pop_back()`

路径长度不会恢复，下一兄弟分支从错误前缀继续。[editorial_inference]

### 3. 忘记 `used[i] = false`

该输入下标会对后续兄弟分支保持不可用，导致漏解。[editorial_inference]

### 4. 撤销顺序或位置错误

撤销必须发生在递归调用返回之后、进入下一个候选之前。若放到递归前，下一层看不到当前选择；若放到整个循环后，只能恢复最后一次选择。[editorial_inference]

### 5. 用值判断是否使用

本课使用下标 `i` 作为身份。直接按值查找会混淆“相同值”和“同一个输入元素”，也会影响重复元素版本的设计。[editorial_inference]

### 6. 把 `used` 叫作去重数组

对 LeetCode 46，它防止当前路径复用下标；对 LeetCode 47，仅有这份 `used` 不足以消除重复值产生的重复结果。[补充说明]

### 7. 忘记清空成员结果

`res` 是成员变量。`res.clear()` 保证同一对象多次调用不会混入旧排列。[visual_direct + editorial_inference | code-001]

## 面试表达脚本

> “题目保证元素互不相同。我把搜索状态定义成当前排列 `p`、当前深度 `index` 和下标占用数组 `used`。每层枚举所有 `!used[i]` 的候选：先把 `nums[i]` 加入 `p` 并标记占用，再递归构造下一个位置；返回后执行 `pop_back` 和 `used[i] = false`，让兄弟分支从同一父状态出发。`index == n` 时保存答案。共有 `n!` 个结果，每个长度为 `n`，所以输出本身就是 `Θ(n·n!)`；辅助状态不计结果为 `O(n)`。”
