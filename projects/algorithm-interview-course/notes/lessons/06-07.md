## 思路二：哈希表 + 容量为 `k` 的最小堆

### 第一步：统计频率

```cpp
unordered_map<int, int> freq;
for (int i = 0; i < nums.size(); i++) {
    freq[nums[i]]++;
}
```

[visual_direct | code-001, ev-004]

扫描后，`freq[x]` 表示元素 `x` 在原数组中的总出现次数。[course_direct + visual_direct | state-001, ev-004]

### 第二步：定义最小堆

屏幕代码使用：

```cpp
priority_queue<
    pair<int, int>,
    vector<pair<int, int>>,
    greater<pair<int, int>>
> pq;
```

[visual_direct | code-001, ev-004]

每项按：

```text
(频率, 元素值)
```

存储，因此频率位于 `pair.first`，课程用 `pq.top().first` 读取当前堆中最小频率。[course_direct + visual_direct | ev-004]

`greater<pair<int,int>>` 对 `pair` 使用字典序比较：先比较频率，频率相同再比较元素值。课程只强调“把频率放在 first 以便比较”；相同频率时的具体元素顺序不是本课讨论重点。[course_direct + editorial_inference | 基于 ev-004]

### `state-001`：堆状态与转移

状态包括：

- `freq`：所有不同元素及其总频率；
- `pq`：当前保留的至多 `k` 个候选，堆顶是其中最小频率；
- `iter`：当前正在处理的频率表条目。

[visual_direct | state-001, ev-004]

转移分三种：

```text
pq.size() < k：
    直接 push 当前候选

pq.size() == k 且 current.frequency > pq.top().frequency：
    pop 堆顶
    push 当前候选

pq.size() == k 且 current.frequency <= pq.top().frequency：
    不改变堆
```

[course_direct + visual_direct | ev-003, ev-004]

第三种转移由屏幕 `if` 分支没有执行替换这一事实得到；课程没有单独把它写成状态规则。[visual_direct + editorial_inference | 基于 code-001, ev-004]

### 为什么使用最小堆

容量只有 `k`，需要随时找到“当前 Top K 中最弱的候选”。最小堆把最小频率放在堆顶：

- 新候选不比它强，就没有必要进入；
- 新候选频率更高，就淘汰堆顶并接纳新候选。

[course_direct | ev-003]

若使用最大堆，堆顶会是最强候选，不能以同样方式在常数次访问中找到应淘汰的最低频候选。[editorial_inference | 基于 ev-003]

### 屏幕可见的局部代码

```cpp
using namespace std;

class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        assert(k > 0);

        unordered_map<int, int> freq;
        for (int i = 0; i < nums.size(); i++) {
            freq[nums[i]]++;
        }

        assert(k <= freq.size());

        priority_queue<
            pair<int, int>,
            vector<pair<int, int>>,
            greater<pair<int, int>>
        > pq;
        for (
            unordered_map<int, int>::iterator iter = freq.begin();
            iter != freq.end();
            iter++
        ) {
            if (pq.size() == k) {
                if (iter->second > pq.top().first) {
                    pq.pop();
                    pq.push(make_pair(iter->second, iter->first));
                }
            } else {
                pq.push(make_pair(iter->second, iter->first));
            }
        }

        vector<int> res;
        while (!pq.empty()) {
            res.push_back(pq.top().second);
            pq.pop();
        }

        return res;
    }
};
```

### 堆不变量的编辑性解释

处理完频率表的任意前缀后，`pq` 至多含 `k` 项；当已经处理的不同元素至少有 `k` 个时，堆内保存该前缀中频率最高的 `k` 个候选，堆顶是这些候选中的最低频项。[editorial_inference | 基于 state-001, ev-003, ev-004]

保持理由：

1. 未满时，接纳当前候选不会超过容量；
2. 已满且新频率更高时，用它替换当前最低频项，Top K 集合得到改善；
3. 已满且新频率不更高时，跳过它不会丢失一个严格更高频候选。

## 正确性解释

课程给出了容量为 `k` 的最小堆结论，但没有形式化证明。以下是基于 `state-001` 的编辑性验证。

### 1. 初始化

处理候选不足 `k` 个时全部入堆，因此堆就是已处理候选的全集。[editorial_inference | 基于 state-001]

### 2. 维护

当堆已满：

- 新频率严格更高时，它应取代当前 Top K 中最低频项；
- 新频率不更高时，现有 `k` 项都不比它弱，跳过不损失严格更优候选。

[editorial_inference | 基于 state-001, ev-003, ev-004]

### 3. 终止

频率表每个条目只处理一次。遍历结束后没有未考察候选，课程结论所称的 Top K 集合保留在堆中；随后循环弹出 `second` 字段形成结果数组。[course_direct + visual_direct + editorial_inference | 基于 ev-003, ev-004]

这里不额外证明截止频率并列时应返回哪个元素，也不保证输出顺序。[补充说明]
