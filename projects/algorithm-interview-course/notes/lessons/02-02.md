## 核心概念与定义

### 1. 数据规模

数据规模是输入数据的数量或大小，本课通常记为 `n`。算法复杂度只有与具体 `n` 结合，才能回答“在这个限制下大概能不能跑完”。[视频 00:00:00–00:01:01][02-02-ev-001]（ev-001）

例如，`O(n²)` 只说明增长形状；当 `n = 10⁵` 时，平方项达到 `10¹⁰` 级别，课程用它解释选择排序为何长时间占用 CPU、表现得像计算机“假死”。[视频 00:00:00–00:01:01][02-02-ev-001]（ev-001）；[视频 00:04:26–00:08:43][02-02-ev-003]（ev-003）

### 2. 从复杂度到可处理规模

课程用“约一秒内解决问题”作为统一参照，把复杂度换算成经验规模：[视频 00:04:26–00:08:43][02-02-ev-003]（ev-003）

| 时间复杂度   | 课程给出的约一秒经验规模 | 课程中的量级理由                                |
| ------------ | -----------------------: | ----------------------------------------------- |
| `O(n³)`      |           `n ≤ 10²` 级别 | 面试反推示例中指出 `n ≤ 100` 时可以考虑三次方案 |
| `O(n²)`      |                `n ≈ 10⁴` | `(10⁴)² = 10⁸` 次基本操作，课程机器上约在一秒内 |
| `O(n log n)` |                `n ≈ 10⁷` | `log₂(10⁷)` 为 20 多，乘积约 `2 × 10⁸` 次操作   |
| `O(n)`       |                `n ≈ 10⁸` | 计时实验中 `10⁸` 次循环约为 0.41 秒             |

这些数字是课程用于建立数量级直觉的**经验估计**，不是跨语言、跨机器、跨操作类型的固定上限。[视频 00:01:01–00:08:43][02-02-range-061-523]（ev-002、ev-003）

### 3. 空间复杂度

本课从“额外开辟多少存储”来介绍空间复杂度：[视频 00:08:43–00:09:51][02-02-ev-004]（ev-004）

- 一维辅助数组随 `n` 增长：`O(n)`；
- 二维辅助数组随两个 `n` 维度增长：`O(n²)`；
- 只使用常数个变量：`O(1)`。

课程没有在此处讨论输入存储、输出存储是否计入，也没有给出更复杂的数据结构模型；本笔记因此把结论限定为视频明确讨论的辅助空间。

### 4. 递归栈空间

递归调用时，系统需要为每一层保存函数运行状态。若递归深度随 `n` 线性增长，栈中同时存在的调用框架数量也随 `n` 增长，因此本课把递归累加 `sum2` 的栈空间写为 `O(n)`。[视频 00:09:51–00:11:26][02-02-ev-005]（ev-005、cx-005）

这与函数体里“没有显式创建数组”并不矛盾：系统调用栈也是算法运行所需的空间。[视频 00:09:51–00:11:26][02-02-ev-005]（ev-005）

## 从规模反推复杂度

### `10⁵` 数据上的选择排序


## 代码对比：循环空间与递归栈

### 循环累加 `sum1`

```cpp
int sum1( int n ){
    assert( n >= 0 );
    int ret = 0;
    for( int i = 0 ; i <= n ; i++ )
        ret += i;
    return ret;
}
```

视频指出，除输入参数外，函数只使用 `ret` 和循环变量 `i` 等常数个局部变量，所需辅助空间不随 `n` 增长，因此为 `O(1)`。[视频 00:09:51–00:11:26][02-02-ev-005]（ev-005、cx-004）

### 递归累加 `sum2`

```cpp
int sum2( int n ){
    assert( n >= 0 );
    if( n == 0 )
        return 0;
    return n + sum2(n-1);
}
```

`sum2(n)` 会依次调用 `sum2(n-1)`，直到 `sum2(0)`。递归深度为 `n` 级别，系统栈中要保存相应数量的函数状态，因此空间为 `O(n)`。[视频 00:09:51–00:11:26][02-02-ev-005]（ev-005、cx-005）

## 边界条件、易错点与测试

### 课程直接支持的风险

1. **只看复杂度、不代入最大 `n`。** `O(n²)` 在小规模可能可用，在 `n = 10⁵` 时却达到 `10¹⁰` 级别。[视频 00:00:00–00:01:01][02-02-ev-001]（ev-001、ev-003）
2. **把一秒经验表当成精确硬限制。** 硬件不同会改变具体耗时，课程只强调数量级基本一致。[视频 00:01:01–00:08:43][02-02-range-061-523]（ev-002、ev-003）
3. **用极短运行测试得出强结论。** `10¹` 到 `10³` 的结果会受到计时精度影响。[视频 00:01:01–00:04:26][02-02-ev-002]（ev-002）
4. **只统计显式容器，忽略递归栈。** 即使函数没有新建数组，深度为 `n` 的递归仍占 `O(n)` 栈空间。[视频 00:09:51–00:11:26][02-02-ev-005]（ev-005）
5. **忽略递归深度风险。** 结构化证据记录：深层递归可能消耗大量系统栈，进而出现栈溢出。[视频 00:09:51–00:11:26][02-02-ev-005]（ev-005）
