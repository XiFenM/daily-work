## 候选域是闭区间 `[start,n]`

代码写成：

```cpp
for (int i = start; i <= n; i++)
```

[visual_direct | code-001, ev-003]

这里 `start` 和 `n` 都是**可取的数字值**，不是数组下标；候选域包含两端：

```text
[start,n]
```

因此循环条件必须是：

```text
i <= n
```

若误写为 `i<n`，所有需要选择数字 `n` 的组合都会丢失。[editorial_inference]

### 下一层为什么是 `i+1`

当当前层选择 `i` 后：

```cpp
generateCombinations(n, k, i + 1, c);
```

[visual_direct | code-001, ev-003]

这同时完成两个约束：

1. **不能重复使用同一个数字**：下一层不再包含 `i`；
2. **不生成顺序重复**：下一层也不再考虑任何小于 `i` 的数字。

于是 `c` 中的数字始终严格递增。[course_direct + editorial_inference | 基于 ev-002, ev-003]

这里必须传 `i+1`，而不是 `start+1`。同一层循环中的 `i` 会变化，下一层下界必须跟随**刚刚实际选中的数字**。[editorial_inference]

## 回溯三步

课程代码的核心循环是：

```cpp
for (int i = start; i <= n; i++) {
    c.push_back(i);
    generateCombinations(n, k, i + 1, c);
    c.pop_back();
}
```

[visual_direct | code-001, ev-003]

### 1. 做选择

```cpp
c.push_back(i);
```

把当前候选加入部分组合。此后子调用看到的 `c` 已经包含 `i`。

### 2. 递归探索

```cpp
generateCombinations(n, k, i + 1, c);
```

下一层在更大的数字中继续填充剩余位置。

### 3. 撤销选择

```cpp
c.pop_back();
```

子调用返回后，删除本层刚加入的数字，使 `c` 恢复到进入本轮之前的状态，再尝试下一个 `i`。[course_direct + visual_direct | ev-003]

若遗漏 `pop_back()`，同层下一轮会在上一个分支残留的状态上继续追加，`c` 不再代表当前路径，基本情况也会失去语义。[editorial_inference]

## 完整课程代码

视频 IDE 的头文件区域折叠为 `#include ...`。下面只转录完整可见的算法主体，不补造具体头文件：

```cpp
using namespace std;

class Solution {
private:
    vector<vector<int>> res;

    // 求解C(n,k), 当前已经找到的组合存储在c中，需要从start开始搜索新的元素
    void generateCombinations(int n, int k, int start, vector<int> &c){
        if( c.size() == k ){
            res.push_back(c);
            return;
        }

        for( int i = start ; i <= n ; i ++ ){
            c.push_back(i);
            generateCombinations(n, k, i + 1, c);
            c.pop_back();
        }

        return;
    }
public:
    vector<vector<int>> combine(int n, int k) {
        res.clear();
        if( n <= 0 || k <= 0 || k > n )
            return res;

        vector<int> c;
        generateCombinations(n, k, 1, c);
        return res;
    }
};
```

## 正确性解释

视频用递归树解释搜索过程，但没有给出形式化证明。下面是依据代码整理的 `editorial_inference`。

### 可靠性：输出的每个对象都是合法组合

当一个对象写入 `res` 时：

1. `c.size()==k`，长度正确；
2. `c` 中每个数字来自 `1...n`；
3. 下一层总从 `i+1` 开始，所以数字严格递增；
4. 严格递增意味着同一数字不会重复使用。

因此每个输出都是合法的 `k` 元组合。

### 完备性：每个合法组合都能被生成

对任意合法组合：

```text
a1 < a2 < ... < ak
```

初始层的 `[1,n]` 包含 `a1`；选择 `a1` 后，下一层 `[a1+1,n]` 包含 `a2`；依此类推，存在唯一一条分支依次选择 `a1...ak`，最终写入结果。

### 唯一性：同一组合不会重复生成

每条搜索路径严格递增。一个组合排序后只有一个递增序列，因此不存在另一条不同选择顺序生成同一集合。

### 终止性

每次递归后：

- `c.size()` 增加 `1`；
- `start` 更新为 `i+1`，严格增大。

要么先达到长度 `k`，要么候选闭区间变空；两种情况都会返回。

## 复杂度：课程结论与编辑分析分开

### 课程直接结论

视频没有给出 Big O、递归状态总数或辅助空间公式。因此规范化证据中的复杂度字段保持 `null`。[补充说明]

### 输出下界

设：

```text
R = C(n,k)
```

表示组合数量。结果中有 `R` 个向量，每个长度为 `k`；仅把答案实体化就要写入：

```text
k · R
```

个整数。因此任何返回全部组合的实现都有输出成本：

```text
Ω(k · C(n,k))
```

[editorial_inference]

### 这份基线代码的搜索工作

基线会访问长度从 `0` 到 `k` 的递增部分组合，也会进入某些候选不足、最终无法达到 `k` 的状态。忽略结果向量复制时，可用：

```text
Σ(d=0..k) C(n,d)
```

描述递归状态数量的一个直接计数口径；每个完整答案又在 `res.push_back(c)` 时复制 `k` 个整数。[editorial_inference]

这比未经说明只写 `O(C(n,k))` 更准确，因为它区分了：

- 内部搜索节点；
- 完整答案数量；
- 每个答案的复制长度。

### 空间

不计返回结果：

- 当前部分组合 `c` 最长为 `k`；
- 递归深度最多为 `k`；
- 因而辅助路径与调用栈为 `O(k)`。

计入返回结果后，保存全部答案需要 `Θ(k·C(n,k))` 个整数。[editorial_inference]

## 边界条件与常见错误

1. **把闭区间写成 `i<n`**：会漏掉所有包含 `n` 的组合。
2. **下一层仍传 `start`**：会重新选择旧候选，产生重复或不符合预期的路径。
3. **下一层传 `i`**：允许同一数字被重复选择，不再是本题代码语义。
4. **下一层传 `start+1`**：下界没有跟随本轮实际选择的 `i`。
5. **遗漏 `pop_back()`**：兄弟分支共享污染后的 `c`。
6. **达到 `k` 后不返回**：若继续循环，会产生长度大于 `k` 的无用状态。
7. **把 `c` 按值传递却仍按当前成本描述**：会改变每层复制行为。
8. **忘记 `res.clear()`**：同一个 `Solution` 对象多次调用时可能混入旧结果。
9. **把 `k==0` 的数学约定补进课程代码**：屏幕代码明确在 `k<=0` 时返回空结果。
10. **提前使用下一课剪枝上界**：本课基线循环明确是 `i<=n`。

前六项来自代码语义检查；后四项用于说明实现和证据边界。[visual_direct + editorial_inference | 基于 code-001]
