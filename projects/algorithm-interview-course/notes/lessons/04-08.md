### 视频题面

## 第一步：把绝对值条件改写成闭区间

令当前处理的值为：

```text
v = nums[i]
```

窗口中某个已有值为 `x`。题目要求：

```text
|v - x| <= t
```

课程把它展开为：

```text
v - t <= x <= v + t
```

[视频 00:01:04–00:03:59；ev-002]

因此，本轮不需要在窗口中寻找一个确定的补数，而是要回答：

> 当前有序集合中，是否存在任意元素落在闭区间 `[v-t,v+t]` 内？

[视频 00:01:04–00:03:59；ev-002]

闭区间符号很重要。上界判断必须使用 `<= v+t`，因为“差值恰好等于 `t`”仍满足题目条件；误写成 `< v+t` 会漏掉边界答案。[视频 00:01:04–00:06:48；ev-002、ev-003]

## 第二步：为什么需要有序查找表

上一节的“是否出现过相同值”可以用哈希集合的 `find(v)` 解决；本课要找的却是一个范围内的任意值。课程指出，如果查找表具有顺序性，就可以寻找：

- 大于等于某值的最小元素，即 `ceil` 语义；
- 小于等于某值的最大元素，即 `floor` 语义；
- 在 C++ `std::set` 中，对应地使用 `lower_bound`。

[视频 00:01:04–00:03:59；ev-002]

课程选择：

```cpp
record.lower_bound(v - t)
```

它返回集合中第一个满足：

```text
x >= v - t
```

的元素位置。[视频 00:01:04–00:06:48；ev-002、ev-003]

设这个最小候选为 `x0`：

1. 如果 `lower_bound(v-t) == record.end()`，集合中不存在任何不小于下界的元素，自然没有答案。
2. 如果 `x0 <= v+t`，那么 `x0` 落入闭区间 `[v-t,v+t]`，本轮找到合法元素。
3. 如果 `x0 > v+t`，由于 `x0` 已是不小于下界的最小元素，后面的元素只会更大，因此也不可能落入区间。

[视频 00:01:04–00:06:48；ev-002、ev-003] [整理推导]

这说明有序性并不是实现细节，而是“只检查一个候选就能回答整个区间是否为空”的基础。[视频 00:01:04–00:03:59；ev-002] [整理推导]

## 第三步：精确定义滑动窗口

### 查询前的窗口

处理下标 `i` 时，只能与先前的下标比较。为了保证索引差不超过 `k`，本轮查询前 `record` 表示的候选索引窗口是：

```text
[i-k, i-1]
```

在数组左端没有负下标，因此更精确地写为：

```text
[max(0, i-k), i-1]
```

[视频 00:01:04–00:06:48；ev-002、ev-003] [整理推导]

`record` 保存的是这些索引所贡献的**值集合**，而不是索引本身。课程在代码中用注释强调，窗口维护后集合中最多保留 `k` 个元素。[视频 00:03:59–00:06:48；ev-003]

### 为什么窗口不包含 `i`

本轮查询发生在插入 `nums[i]` 之前，所以 `record` 只含先前元素。这样查询成功时，命中的元素必然来自另一个先前索引，不会把当前元素自己当成答案。[视频 00:03:59–00:06:48；ev-003] [整理推导]

如果先插入 `nums[i]` 再查询，并且 `t>=0`，当前值与自身的差为 0，会造成错误的自匹配。[整理推导]

### 每轮的三个动作

课程代码的顺序必须整体记忆：

1. **先查**：在旧窗口 `[i-k,i-1]` 的值集合中查询 `[nums[i]-t,nums[i]+t]`。
2. **再插入**：未找到答案时执行 `record.insert(nums[i])`。
3. **最后淘汰**：若插入后 `record.size() == k+1`，删除 `nums[i-k]`，为下一轮恢复最多 `k` 个窗口元素。

[视频 00:03:59–00:06:48；ev-003]

在没有提前返回的正常路径上，插入后窗口会短暂覆盖至当前索引 `i`；淘汰最左侧的 `i-k` 后，下一轮开始前恰好留下后续仍可能合法的索引范围。[视频 00:03:59–00:06:48；ev-003] [整理推导]

## 正确性解释

下面是依据课程状态模型整理的解释，不把它冒充为视频中的形式化证明。[视频 00:01:04–00:06:48；ev-002、ev-003] [整理推导]

### 1. 索引条件

第 `i` 轮只查询窗口 `[max(0,i-k),i-1]`。其中任意先前索引 `j` 都满足：

```text
0 < i - j <= k
```

因此只要查询命中，索引差条件便成立。[视频 00:01:04–00:06:48；ev-002、ev-003] [整理推导]

### 2. 数值条件

`lower_bound(v-t)` 返回第一个不小于下界的候选。代码继续检查：

```text
candidate <= v + t
```

两者合在一起就是：

```text
v - t <= candidate <= v + t
```

也即：

```text
|v - candidate| <= t
```

[视频 00:01:04–00:06:48；ev-002、ev-003]

### 3. 为什么没有漏掉范围内的元素

若集合中存在合法值 `x`，它一定满足 `x>=v-t`。`lower_bound(v-t)` 得到的最小候选 `x0` 不会大于这个合法值，所以：

```text
x0 <= x <= v+t
```

代码会返回 `true`。反过来，若最小候选已经大于 `v+t`，集合中所有更大的元素也都不合法。[视频 00:01:04–00:03:59；ev-002] [整理推导]

### 4. 为什么先查再插入

查询时 `record` 尚未包含 `nums[i]`，所以命中的候选来自先前索引；查询失败后才把当前值加入窗口，为未来下标提供候选。[视频 00:03:59–00:06:48；ev-003] [整理推导]

### 5. 终止与返回

循环依次处理 `i=0...nums.size()-1`。任意一轮找到合法候选就立即返回 `true`；全部元素处理完仍未命中则返回 `false`。[视频 00:03:59–00:06:48；ev-003]

## 第一版：`set<int>` 实现

视频首先把上一节的 `unordered_set` 改为有序的 `set<int>`，并使用 `lower_bound` 做范围查找。[视频 00:03:59–00:06:48；ev-003]

以下代码来自规范化的屏幕代码证据；本项目没有本地编译或运行，验证状态仍为 `not_run`。[视频 00:03:59–00:06:48；ev-003]

```cpp
class Solution {
public:
    bool containsNearbyAlmostDuplicate(vector<int>& nums, int k, int t) {
        set<int> record;
        for (int i = 0; i < nums.size(); i++) {
            if (record.lower_bound(nums[i] - t) != record.end() &&
                *record.lower_bound(nums[i] - t) <= nums[i] + t)
                return true;
            record.insert(nums[i]);
            if (record.size() == k + 1)
                record.erase(nums[i - k]);
        }
        return false;
    }
};
```

关键 token 包括：

- `set<int>`：要求有序集合，而不是 `unordered_set`。[视频 00:03:59–00:06:48；ev-003]
- `lower_bound(nums[i]-t)`：寻找不小于闭区间下界的首个元素。[视频 00:03:59–00:06:48；ev-003]
- `!= record.end()`：必须先确认迭代器可解引用。[视频 00:03:59–00:06:48；ev-003]
- `<= nums[i]+t`：闭区间上界必须包含等号。[视频 00:03:59–00:06:48；ev-003]
- `record.insert(nums[i])`：查询结束后才插入当前值。[视频 00:03:59–00:06:48；ev-003]
- `record.size() == k+1` 与 `erase(nums[i-k])`：插入后按 `k` 淘汰窗口左端。[视频 00:03:59–00:06:48；ev-003]

C++ 的 `&&` 从左到右短路求值，所以只有第一次 `lower_bound` 不等于 `end()` 时，第二次调用的返回值才会被解引用。[视频 00:03:59–00:06:48；ev-003] [整理推导]

## 边界条件与易错点

### 视频直接揭示的风险

1. **32 位整数边界**：`nums[i]+t` 或 `nums[i]-t` 可能在比较前就溢出。[视频 00:06:48–00:09:51；ev-004、ev-005]
2. **容器类型与运算类型要同时变宽**：`set<long long>` 与显式 64 位边界运算缺一不可。[视频 00:08:11–00:09:51；ev-005]
3. **范围查询需要顺序性**：不能直接用只支持相等查找的 `unordered_set::find` 代替 `lower_bound`。[视频 00:01:04–00:06:48；ev-002、ev-003]
4. **上界包含等号**：代码使用 `<= nums[i]+t`，与“差不超过 `t`”一致。[视频 00:00:00–00:06:48；ev-001、ev-003]
5. **数据范围应在写代码前确认**：课程结尾建议面试时主动询问变量范围，提前识别溢出问题。[视频 00:09:51–00:10:54；ev-006]

### 由代码状态推导的边界

1. **空数组**：循环不进入，返回 `false`。[视频 00:03:59–00:06:48；ev-003] [整理推导]
2. **单元素数组**：没有先前元素可匹配，最终返回 `false`。[视频 00:03:59–00:06:48；ev-003] [整理推导]
3. **`k=0`**：每轮查询前窗口为空；插入后立即达到 `k+1` 并删除当前值，因此不会把不同索引配成答案。[视频 00:03:59–00:06:48；ev-003] [整理推导]
4. **恰好等于上下界**：`lower_bound` 和 `<=` 共同保证 `v-t`、`v+t` 都被接受。[视频 00:01:04–00:06:48；ev-002、ev-003]
5. **必须先检查 `end()`**：直接解引用没有候选的迭代器会产生无效访问；当前 `&&` 顺序通过短路求值避免这一点。[视频 00:03:59–00:06:48；ev-003] [整理推导]
6. **参数符号范围未记录**：若 `k` 或 `t` 允许负数，需要重新定义题意和代码行为，不能仅凭课程标题假设；应在面试中澄清。[视频 00:09:51–00:10:54；ev-006] [整理推导]

### 常见实现错误

- 把 `set` 写回 `unordered_set`，却仍试图执行范围查询。[视频 00:01:04–00:06:48；ev-002、ev-003]
- 用 `find(nums[i])` 只寻找相等值，遗漏差值在 `1...t` 内的合法候选。[视频 00:01:04–00:03:59；ev-002]
- 把 `lower_bound(nums[i]-t)` 误写成 `lower_bound(nums[i]+t)`，查询起点错误。[视频 00:01:04–00:06:48；ev-002、ev-003]
- 忘记 `!=record.end()` 就解引用迭代器。[视频 00:03:59–00:06:48；ev-003]
- 上界用 `< nums[i]+t`，漏掉差值恰好为 `t` 的答案。[视频 00:00:00–00:06:48；ev-001、ev-003]
- 先插入再查询，可能把当前元素自己匹配为差值 0。[视频 00:03:59–00:06:48；ev-003] [整理推导]
- 淘汰 `nums[i-k+1]` 或在查询前淘汰 `nums[i-k]`，造成窗口少保留一个仍满足索引差 `k` 的候选。[视频 00:03:59–00:06:48；ev-003] [整理推导]
- 只改成 `set<long long>`，却仍在 `int` 中计算 `nums[i]±t`。[视频 00:06:48–00:09:51；ev-004、ev-005] [整理推导]

## 可读性与工程改写

视频代码重复调用了两次相同的 `lower_bound`。在不改变算法的前提下，可以保存迭代器：

```cpp
const long long value = nums[i];
const long long tolerance = t;
auto candidate = record.lower_bound(value - tolerance);

if (candidate != record.end() && *candidate <= value + tolerance) {
    return true;
}
```

这样既避免重复查询，也让下界、候选和上界的角色更清楚。这是工程性改写，不是视频逐帧代码，也没有在本项目运行。[整理推导]

如果进一步整理完整工程实现，还应：

- 显式包含所需头文件；
- 统一索引类型，避免 `int` 与 `vector::size_type` 混用；
- 根据题目正式约束决定如何处理负的 `k`、`t`；
- 为极值运算保留足够宽的类型。
