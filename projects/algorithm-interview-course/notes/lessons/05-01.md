## 核心概念与定义

### 1. 单链表的访问模型

课程对比了数组和链表：

- 数组可以根据索引直接定位元素，课程把随机访问成本记为 `O(1)`；
- 单链表没有同样的随机访问能力，要访问后面的节点，必须从头结点开始沿 `next` 逐个前进。

[course_direct | ev-001 | 视频 00:00–01:13]

屏幕代码中的节点包含一个值 `val` 和一个后继指针 `next`；`head` 是进入整条链表的入口，尾节点的 `next` 指向 `NULL`。[visual_direct | ev-002, ev-005 | 视频 01:14–02:57；08:45–13:50]

本课的反转目标不是把值重新排列在原节点中，而是让同一批节点之间的有向边全部反向。[course_direct + visual_direct | ev-002, ev-003 | 视频 01:14–05:54]

### 2. 反转链表

对原链表：

```text
1 → 2 → 3 → 4 → 5 → NULL
```

反转后得到：

```text
5 → 4 → 3 → 2 → 1 → NULL
```

[course_direct + visual_direct | ev-002 | 视频 01:14–02:57]

原来的头结点 `1` 变成尾节点，所以它最终应指向 `NULL`；原来的尾节点 `5` 变成新头结点，所以函数最终应返回指向 `5` 的指针。[visual_direct + editorial_inference | 基于 ev-002, ev-004, ev-005 | 视频 01:14–13:50]

### 3. 三个指针的角色

### 4. “先保存，再改链”

若当前状态是：

```text
pre     cur
 ↓       ↓
... ←   2 → 3 → 4 → NULL
```

而我们直接执行：

```cpp
cur->next = pre;
```

那么从 `cur` 出发的原前向边已经被覆盖。若没有其他指针保存节点 `3`，后面的 `3 → 4 → NULL` 就失去了可达入口。[course_direct + visual_direct | ev-003 | 视频 02:58–05:54]

因此必须先执行：

```cpp
ListNode* next = cur->next;
```

此时即便稍后覆盖 `cur->next`，尚未处理链段仍可通过局部变量 `next` 找回。[course_direct + visual_direct | ev-003, ev-004, ev-005 | 视频 02:58–13:50]

```cpp
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        ListNode* pre = NULL;
        ListNode* cur = head;
        while (cur != NULL) {
            ListNode* next = cur->next;

            cur->next = pre;
            pre = cur;
            cur = next;
        }

        return pre;
    }
};
```

## 精确状态转移

### 循环开始前的状态

把原链表按“已处理 / 当前节点 / 未处理后缀”拆开。进入每轮循环时，可整理出如下状态：

1. `pre` 指向已经反转好的前缀链段；
2. `cur` 指向尚未处理后缀的第一个节点；
3. 已处理链段与未处理链段合起来恰好覆盖原链表中的全部节点；
4. 若 `cur == NULL`，未处理链段为空，算法结束。

[editorial_inference | 基于 ev-003, ev-004, ev-005 | 视频 02:58–13:50]

`next` 是循环体内的临时变量，不是跨轮次保持的第三条永久链段。它只在当前轮保存“覆盖 `cur->next` 之后仍要访问的入口”。[visual_direct + editorial_inference | 基于 ev-005 | 视频 08:45–13:50]

### 步骤一：保存原后继

```cpp
ListNode* next = cur->next;
```

执行前，`cur->next` 是从当前节点通往未处理后缀其余部分的唯一已知边；执行后，即使这条边被覆盖，局部变量 `next` 仍保存原后继节点。[course_direct + visual_direct | ev-003, ev-004, ev-005 | 视频 02:58–13:50]

此时链表本身还没有改变，只是多保存了一个入口。[editorial_inference | 基于 ev-003, ev-004 | 视频 02:58–08:44]

### 步骤二：反转当前节点的边

```cpp
cur->next = pre;
```

这一步把当前节点接到已反转链段的前面。原来从 `cur` 指向未处理后缀的边被改为指向 `pre`；尚未处理的后缀仍可由刚保存的 `next` 到达。[course_direct + visual_direct | ev-003, ev-004, ev-005 | 视频 02:58–13:50]

完成后，`cur` 已经成为“扩展后已反转链段”的新头，但变量 `pre` 还暂时指向扩展前的旧头。[editorial_inference | 基于 ev-004, ev-005 | 视频 05:55–13:50]

### 步骤三：提交新的已反转链段入口

```cpp
pre = cur;
```

把 `pre` 更新到当前节点后，`pre` 正式指向包含本轮节点的已反转链段。[course_direct + visual_direct | ev-004, ev-005 | 视频 05:55–13:50]

这一步必须发生在下一轮开始前，否则算法会失去已反转链段的新入口。[editorial_inference | 基于 ev-004, ev-005 | 视频 05:55–13:50]

### 步骤四：进入未处理后缀

```cpp
cur = next;
```

把 `cur` 移到本轮开始时保存的原后继节点。于是：

- 已反转链段比上一轮多一个节点；
- 未处理链段比上一轮少一个节点；
- 两条链段仍分别由 `pre` 与 `cur` 可达；
- 下一轮可以用同一套状态语义继续处理。

[course_direct + visual_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 05:55–13:50]

### 为什么顺序不能打乱

- 若先覆盖 `cur->next`、后保存 `next`，保存到的将是反向链段入口，而不是原后继，未处理后缀会失联。[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 02:58–08:44]
- 若先执行 `pre = cur`，再执行 `cur->next = pre`，当前节点会指向自己，形成自环，而不是接到旧的 `pre`。[editorial_inference | 基于 ev-004, ev-005 | 视频 05:55–13:50]
- 若没有在本轮结束时执行 `cur = next`，算法就无法进入下一个原链表节点。[course_direct + visual_direct | ev-004, ev-005 | 视频 05:55–13:50]

因此四条语句不是可任意换位的模板，而是一条由数据依赖决定的状态转移序列。[editorial_inference | 基于 ev-003–ev-005 | 视频 02:58–13:50]

```text
cur = head
```

已处理前缀为空，其反转结果也为空，所以 `pre = NULL` 正确；未处理后缀是整条原链表，所以 `cur = head` 正确。两部分合起来覆盖全部节点。[visual_direct + editorial_inference | 基于 ev-004, ev-005 | 视频 05:55–13:50]

### 保持

假设某轮开始时不变量成立且 `cur != NULL`：

1. `next = cur->next` 保存未处理后缀除当前节点外的入口；
2. `cur->next = pre` 把当前节点接到已反转链段前面；
3. `pre = cur` 让 `pre` 指向扩展后的反转链段；
4. `cur = next` 让 `cur` 指向缩短后的未处理链段。

因此本轮恰好从未处理部分取出一个节点并加入已反转部分，没有丢失、复制或跳过节点，不变量继续成立。[course_direct + visual_direct + editorial_inference | 基于 ev-003–ev-005 | 视频 02:58–13:50]

### 终止

每轮都把 `cur` 推进到原链表的下一个节点，未处理节点数减少 1。对含 `n` 个节点的有限无环链表，执行至多 `n` 轮后 `cur == NULL`，循环终止。[editorial_inference | 基于 ev-004, ev-005 | 视频 05:55–13:50]

### 后置条件

循环退出时未处理链段为空。由不变量可知，原链表全部节点都位于 `pre` 指向的已反转链段中，而且边的方向已经逐个反转；返回 `pre` 即得到新头结点。[visual_direct + editorial_inference | 基于 ev-002, ev-004, ev-005 | 视频 01:14–13:50]

原头结点在第一轮执行 `cur->next = pre` 时指向初始的 `NULL`，因此最终成为合法尾节点。[visual_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 02:58–08:44]

### 时间复杂度

课程给出的结论是：

```text
O(n)
```

算法沿原链表遍历一次；每个节点进入循环一次，每轮只做固定次数的指针读取、写入和赋值，因此总工作量与节点数成正比。[course_direct | ev-005 | 视频 08:45–13:50]

### 辅助空间复杂度

```text
O(1)
```

## 边界条件、易错点与测试

### 课程直接支持的边界

#### 空链表

若 `head == NULL`：

```text
pre = NULL
cur = NULL
```

循环条件一开始就不成立，函数直接返回 `NULL`。课程特别说明，不应在循环前无条件执行 `head->next`；把 `next = cur->next` 放进 `while (cur != NULL)` 内，可以避免空指针解引用。[course_direct + visual_direct | ev-005 | 视频 08:45–13:50]

#### 单节点链表

若链表为：

```text
1 → NULL
```

唯一一轮先保存 `next = NULL`，再令 `1->next = pre = NULL`，之后 `pre` 指向节点 1、`cur` 变为 `NULL`，返回的仍是这个节点。[course_direct + editorial_inference | 基于 ev-005 | 视频 08:45–13:50]

### 最重要的实现错误

1. **没有先保存原后继**：覆盖 `cur->next` 后无法继续访问未处理链段。[course_direct + visual_direct | ev-003–ev-005 | 视频 02:58–13:50]
2. **把 `next = cur->next` 放在循环外且未先判断空链表**：`head == NULL` 时会解引用空指针。[course_direct + visual_direct | ev-005 | 视频 08:45–13:50]
3. **返回 `head` 或 `cur`**：退出时 `cur == NULL`，原 `head` 已成为尾节点；新头结点由 `pre` 保存。[visual_direct + editorial_inference | 基于 ev-002, ev-005 | 视频 01:14–13:50]
4. **先更新 `pre` 再改 `cur->next`**：会让当前节点指向自身，形成自环。[editorial_inference | 基于 ev-004, ev-005 | 视频 05:55–13:50]
5. **通过交换或回写 `val` 冒充结构反转**：不满足课程强调的指针操作要求。[course_direct | ev-002 | 视频 01:14–02:57]
6. **把视频 Accepted 写成本地测试结果**：当前项目没有执行该代码，验证状态仍是 `not_run`。[visual_direct + editorial_inference | 基于 ev-005 | 视频 08:45–13:50]

### 应对“为什么不能先改指针再保存后继”

可以直接回答：

> `cur->next` 在当前轮仍是进入未处理后缀的入口。一旦先改为 `pre`，沿 `cur` 已经只能回到反转部分；如果没有 `next` 保存原边终点，剩余节点就不可达。

### 应对“为什么返回 `pre`”

可以回答：

> `cur` 每轮进入原链表的下一个节点，最终必然走到 `NULL`；`pre` 每轮接收刚处理完的节点，所以退出时它指向包含全部节点的反转链段头。
