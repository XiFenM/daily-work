## 递归契约

代码注释直接写出：

```text
从 board[startx][starty] 开始，寻找 word[index...word.size())
```

[course_direct + visual_direct | ev-005 | 视频 07:48–11:45]

可以把契约整理为：

> `searchWord(board, word, index, startx, starty)` 判断：在不重复使用当前路径已访问位置的前提下，能否从 `(startx, starty)` 开始依次匹配 `word[index...]`。[course_direct + editorial_inference | 基于 ev-005、ev-008 与 code-001]

### 基本情况

当：

```cpp
index == word.size() - 1
```

只需判断当前位置字符是否等于最后一个待匹配字符，不再展开邻居。[course_direct + visual_direct | ev-005 | 视频 07:48–11:45]

### 递归推进

当前位置等于 `word[index]` 时：

1. 把当前位置标记为当前路径已使用；
2. 枚举四个方向；
3. 新坐标必须在网格内且尚未被当前路径使用；
4. 递归匹配 `index + 1`；
5. 任一方向成功就立即返回 `true`；
6. 四个方向都失败后恢复当前位置，再返回 `false`。[course_direct + visual_direct | ev-006–ev-008 | 视频 11:45–20:00]

## 四方向偏移量

课程使用：

```cpp
int d[4][2] = {
    {-1, 0},
    {0, 1},
    {1, 0},
    {0, -1}
};
```

顺序对应上、右、下、左。[course_direct + visual_direct | ev-006 | 视频 11:45–15:33]

对当前坐标 `(startx, starty)`：

```cpp
int newx = startx + d[i][0];
int newy = starty + d[i][1];
```

这使四个方向共享同一段合法性检查与递归逻辑，避免复制四个几乎相同的 `if` 分支。[course_direct + visual_direct | ev-006]

边界函数为：

```cpp
bool inArea(int x, int y) {
    return x >= 0 && x < m && y >= 0 && y < n;
}
```

## `visited` 的路径局部语义

`visited[x][y] == true` 的准确含义是：

> 位置 `(x, y)` 已经出现在**当前正在尝试的那条单词路径**中。[course_direct + visual_direct | ev-008 | 视频 17:50–20:00]

因此它不是“这个格子从此永久处理完毕”。失败回退时必须：

```cpp
visited[startx][starty] = false;
```

否则一次失败尝试会污染其他起点或兄弟分支，使本来合法的路径被错误剪掉。[course_direct + editorial_inference | ev-008 与 code-001]

### 成功分支为什么没有恢复

课程代码在递归成功时直接：

```cpp
return true;
```

它会跳过本层后面的 `visited[startx][starty] = false`。[visual_direct | ev-008 | 视频 17:50–20:00]

这不是当前程序的错误：

- 成功后不再继续枚举其他方向；
- 上层 `searchWord` 也沿调用链立即返回；
- 最外层 `exist` 随即返回 `true`；
- 后续没有搜索会再读取这份 `visited` 状态。[editorial_inference | 基于 code-001 的控制流]

若函数需要收集所有路径、成功后继续搜索，或在**不重新初始化 `visited`** 的情况下直接复用搜索状态，则必须重新审视成功路径上的恢复策略。当前公开入口 `exist` 每次调用都会重建 `visited`，所以连续调用同一个 `Solution` 对象不受上一次成功路径残留的影响。[editorial_inference | 基于 code-001]

## 完整课程代码

```cpp
#include <iostream>
#include <vector>
#include <cassert>

using namespace std;

class Solution {
private:
    int d[4][2] = {{-1,0}, {0,1}, {1,0}, {0,-1}};
    int m, n;
    vector<vector<bool>> visited;

    bool inArea(int x, int y) {
        return x >= 0 && x < m && y >= 0 && y < n;
    }

    // 从board[startx][starty]开始，寻找word[index...word.size())
    bool searchWord(const vector<vector<char>>& board,
                    const string& word,
                    int index,
                    int startx,
                    int starty) {
        if (index == word.size() - 1) {
            return board[startx][starty] == word[index];
        }

        if (board[startx][starty] == word[index]) {
            visited[startx][starty] = true;

            for (int i = 0; i < 4; i++) {
                int newx = startx + d[i][0];
                int newy = starty + d[i][1];
                if (inArea(newx, newy)
                    && !visited[newx][newy]
                    && searchWord(board, word, index + 1, newx, newy)) {
                    return true;
                }
            }

            visited[startx][starty] = false;
        }
        return false;
    }

public:
    bool exist(vector<vector<char>>& board, string word) {
        m = board.size();
        assert(m > 0);
        n = board[0].size();

        visited = vector<vector<bool>>(m, vector<bool>(n, false));

        for (int i = 0; i < board.size(); i++) {
            for (int j = 0; j < board[i].size(); j++) {
                if (searchWord(board, word, 0, i, j)) {
                    return true;
                }
            }
        }
        return false;
    }
};

int main() {
    return 0;
}
```

## 正确性说明

以下证明是对课程状态转移的编辑整理。

### 路径合法性

递归只在三个条件同时满足时进入下一格：

1. 新坐标位于网格内；
2. 新位置不在当前路径的 `visited` 中；
3. 递归最终能匹配剩余后缀。

因此返回成功的路径只使用横纵相邻格子，并且不会重复使用位置。[editorial_inference | 基于 ev-002、ev-006–ev-008 与 code-001]

### 完备性

外层双循环把每个格子都作为起点；内层对每个匹配位置枚举上、右、下、左所有合法未访问邻居。因此，任何满足题面规则的路径都会对应搜索树中的一条分支。[editorial_inference | 基于 ev-004–ev-009]

### 状态隔离

某一分支失败时恢复当前标记，所以失败分支不会禁止兄弟分支使用同一位置。成功时程序整体结束，不需要为不存在的后续搜索恢复状态。[editorial_inference | 基于 ev-008 与 code-001]

## 复杂度

设：

- 网格有 `m × n` 个位置；
- 单词长度为 `L`；
- 搜索只允许四邻接，且同一路径不重复使用位置。

课程没有给出复杂度。根据代码可作如下编辑推导：

- 外层最多尝试 `m × n` 个起点；
- 每层最多考察四个方向；
- 递归深度最多为 `L`；
- 因此一个直观的宽松时间上界是 `O(mn · 4^L)`；
- 考虑路径不能立刻回到已访问的父格，除首层外有效分支通常至多为 3，可写成更紧的搜索树上界 `O(mn · 4 · 3^{L-1})`，但边界、字符不匹配和网格规模会进一步剪枝；
- `visited` 使用 `O(mn)` 空间；
- 递归栈最多 `O(L)`；
- 总辅助空间为 `O(mn + L)`。[editorial_inference | 基于 code-001]

这些是最坏上界，不是课程直接结论，也不表示所有输入都会展开完整搜索树。

## 输入前提与边界

### 空网格

代码执行：

```cpp
m = board.size();
assert(m > 0);
n = board[0].size();
```

因此它要求 `board` 至少有一行；启用断言时空网格会触发断言，而不是返回 `false`。[course_direct + visual_direct | ev-007, ev-009] [editorial_inference | 行为说明]

### 空单词

代码没有显式处理 `word.empty()`。若网格非空，首次调用会访问 `word[0]`，所以空单词不在这份实现的安全输入契约内。[editorial_inference | 基于 code-001]

### 网格形状

`n` 取自 `board[0].size()`，`inArea` 对所有行都使用同一个 `n`；实现按矩形网格设计。[editorial_inference | 基于 code-001]

### 单字符单词

`index == word.size() - 1` 在第一次调用就成立，直接比较起点字符。外层会尝试所有格子，因此只要任一格等于该字符就返回 `true`。[editorial_inference | 基于 code-001]

## 常见错误

1. **把 `visited` 当成全局永久去重**：本题标记属于当前路径，失败时必须恢复。[course_direct | ev-008]
2. **忘记检查 `!visited[newx][newy]`**：会允许同一位置在一条单词路径中重复出现，违反题面。[course_direct + visual_direct | ev-002, ev-008]
3. **方向数组坐标写反**：`d[i][0]` 更新行，`d[i][1]` 更新列。[course_direct + visual_direct | ev-006]
4. **先访问网格再检查边界**：新坐标必须先通过 `inArea`。[course_direct + visual_direct | ev-007, ev-008]
5. **基本情况提前或滞后**：本代码在 `index` 指向最后一个字符时直接比较当前位置。[course_direct + visual_direct | ev-005]
6. **看到成功路径未恢复就机械判错**：要先检查调用者是否沿成功链整体返回。[editorial_inference | 基于 code-001]
7. **把宽松复杂度上界写成课程原话**：课程没有直接分析复杂度。[补充说明]
8. **把 Word Search 的路径局部标记直接套到 flood fill**：二者是否恢复访问状态取决于任务语义，需在下一课单独核对。[editorial_inference | 关系候选]

## 闪卡

1. **问**：`searchWord` 的子问题是什么？ **答**：从当前坐标开始，在遵守路径内不重复位置的前提下匹配 `word[index...]`。
2. **问**：`visited` 为什么必须在失败时恢复？ **答**：它只属于当前路径；不恢复会让失败分支污染其他起点或兄弟分支。
3. **问**：成功分支没有恢复为什么仍正确？ **答**：成功后每层都立即返回，`exist` 整体结束，没有后续搜索读取残留状态。
4. **问**：方向数组四项是什么？ **答**：`{-1,0}`、`{0,1}`、`{1,0}`、`{0,-1}`，对应上、右、下、左。
5. **问**：基本情况检查什么？ **答**：当 `index` 指向最后一个字符时，直接比较当前位置字符。
6. **问**：课程是否直接给出 `O(mn · 4^L)`？ **答**：没有；这是基于代码的宽松编辑上界。
7. **问**：Word Search 与本课程下一课的 flood fill 最值得比较的状态差异是什么？ **答**：前者失败时恢复路径局部访问标记；后者永久保留已经归入连通块的访问标记。
