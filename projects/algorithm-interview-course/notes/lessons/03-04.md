## 主问题：Move Zeros

给定数组 `nums`，把所有 `0` 移到末尾，同时保持所有非零元素原来的相对顺序，并在原数组上完成操作。[视频 00:00:00–00:04:56]

本课的关键约束是：

- 不能依赖与 `n` 同阶的辅助数组，目标是原地完成。[视频 00:00:00–00:04:56]
- 非零元素必须稳定，即先出现的非零值在结果中仍先出现。[视频 00:00:00–00:02:39]
- 结果不仅要让非零前缀正确，后缀还必须全部是 `0`。[视频 00:00:00–00:04:56]

## 共享状态模型：`[0, k)` 是什么

三版算法都令：

```text
k = 下一个非零元素应写入或交换到的位置
[0, k) = 已扫描部分中的全部非零元素，且顺序与原数组一致
```

[视频 00:00:00–00:09:20]

初始 `k = 0`，所以 `[0,0)` 是空区间，正确表示“尚未收集任何非零元素”。每处理一个非零值，先把它放到 `k` 所指位置，再令 `k++`，使非零前缀扩大一个位置。[视频 00:00:00–00:09:20]

需要特别区分两类附加状态：

- **覆写 + 补零版**只保证 `[0,k)` 的非零前缀正确；扫描途中 `[k,i]` 可能含零，也可能残留被覆写前的旧值，不能宣称它全为零。[视频 00:00:00–00:04:56] [整理推导]
- **交换版与避免自交换版**还保持更强性质：处理完索引 `i` 后，`[k,i]` 全部为零。因为每次把非零值交换到 `k` 时，`k` 位置原有的零被带到当前 `i`。[视频 00:04:56–00:09:20]

这一区别解释了为什么第一版需要末尾补零，而后两版不需要。[视频 00:00:00–00:08:06] [整理推导]

## 三阶段解法演进

### 阶段一：覆写非零前缀，再补零

扫描数组，遇到非零值就执行：

```cpp
nums[k++] = nums[i];
```

扫描结束后，`[0,k)` 已经按顺序保存全部非零元素；但原数组后缀仍可能保留旧值，因此必须显式把 `[k,n)` 写成零。[视频 00:00:00–00:04:56]

视频代码：

```cpp
class Solution {
public:
    // 时间复杂度 O(n)
    // 空间复杂度 O(1)
    void moveZeroes(vector<int>& nums) {
        int k = 0; // nums 中, [0...k) 的元素均为非 0 元素

        // 遍历到第 i 个元素后, 保证 [0...i] 中所有非 0 元素
        // 都按照顺序排列在 [0...k) 中
        for (int i = 0; i < nums.size(); i++)
            if (nums[i])
                nums[k++] = nums[i];

        // 将 nums 剩余的位置设置为 0
        for (int i = k; i < nums.size(); i++)
            nums[i] = 0;
    }
};
```

[视频 00:02:39–00:04:56]

这一版常见错误是只完成第一段循环，忘记补零；这样非零前缀可能正确，但整个数组未满足“所有零都在末尾”的后置条件。[视频 00:00:00–00:04:56]

### 阶段二：用交换把零同步送到后面

进一步观察：当扫描到一个非零值时，与当前 `nums[k]` 交换，既能把非零值放入前缀，也能把 `k` 位置的零移到当前扫描位置。于是不用等扫描结束后再补零。[视频 00:04:56–00:08:06]

视频代码：

```cpp
class Solution {
public:
    // 时间复杂度 O(n)
    // 空间复杂度 O(1)
    void moveZeroes(vector<int>& nums) {
        int k = 0; // nums 中, [0...k) 的元素均为非 0 元素

        // 遍历到第 i 个元素后, 保证 [0...i] 中所有非 0 元素
        // 都按照顺序排列在 [0...k) 中
        // 同时, [k...i] 为 0
        for (int i = 0; i < nums.size(); i++)
            if (nums[i])
                swap(nums[k++], nums[i]);
    }
};
```

[视频 00:07:05–00:08:06]

虽然代码只有一个扫描循环，但 `swap` 本身包含多次读写；“少一个循环”不自动等于每种输入上都按同一比例更快。课程在下一步正是继续按数据分布检查无效交换。[视频 00:07:05–00:09:20] [整理推导]

### 阶段三：避免 `i == k` 时的自交换

若数组完全没有零，例如 `[1,2,3]`，扫描过程中始终有 `i == k`。阶段二会让每个元素与自己交换，结果虽正确，却做了无意义工作。[视频 00:08:06–00:09:20]

最终代码只在 `i != k` 时交换：

```cpp
class Solution {
public:
    // 时间复杂度 O(n)
    // 空间复杂度 O(1)
    void moveZeroes(vector<int>& nums) {
        int k = 0; // nums 中, [0...k) 的元素均为非 0 元素

        // 遍历到第 i 个元素后, 保证 [0...i] 中所有非 0 元素
        // 都按照顺序排列在 [0...k) 中
        // 同时, [k...i] 为 0
        for (int i = 0; i < nums.size(); i++)
            if (nums[i]) {
                if (i != k)
                    swap(nums[k++], nums[i]);
                else // i == k
                    k++;
            }
    }
};
```

[视频 00:08:06–00:09:20]

`i == k` 表示当前元素前面没有尚未移到后方的零，当前非零值已经处在正确的稳定前缀位置；直接扩大 `k` 即可。[视频 00:08:06–00:09:20] [整理推导]

该优化不改变渐近复杂度。它减少的是全非零或长非零前缀中的自交换次数，属于针对输入分布的常数级改进。[视频 00:08:06–00:09:20] [整理推导]

## 正确性解释

### 阶段一：覆写 + 补零

课程直接给出了 `[0,k)` 的状态含义；下列四阶段是为复习整理的不变量检查。[视频 00:00:00–00:04:56] [整理推导]

| 阶段     | 检查内容                                                                           |
| -------- | ---------------------------------------------------------------------------------- |
| 初始化   | `k = 0`，空区间 `[0,0)` 恰好包含已扫描部分的全部非零元素（此时为零个）             |
| 保持     | 遇零时 `k` 不变；遇非零时把它写到 `nums[k]` 后 `k++`，非零值按扫描先后顺序进入前缀 |
| 终止     | 全部元素扫描后，`[0,k)` 含原数组所有非零值且相对顺序不变                           |
| 后置条件 | 第二段循环把 `[k,n)` 全部写零，因此整个数组满足“稳定非零前缀 + 全零后缀”           |

[视频 00:00:00–00:04:56] [整理推导]

### 阶段二与三：交换

交换版维护更强的不变量：处理完 `i` 后，`[0,k)` 是稳定非零前缀，`[k,i]` 是全零区间。[视频 00:04:56–00:09:20]

- 若 `nums[i] == 0`，不移动 `k`，当前零自然扩展 `[k,i]`。[整理推导]
- 若 `nums[i] != 0` 且 `i != k`，交换后非零值进入 `k`，原来 `k` 位置的零来到 `i`，然后 `k++`；两个区域同时扩大或平移且性质不变。[视频 00:04:56–00:09:20] [整理推导]
- 若 `nums[i] != 0` 且 `i == k`，零区间为空，当前值本就紧接非零前缀；只需 `k++`。[视频 00:08:06–00:09:20]
- 扫描结束时 `i == n`，`[0,k)` 包含全部非零值，`[k,n)` 全为零，且交换只让当前非零值越过已经遇到的零，不改变非零值之间的先后顺序。[视频 00:04:56–00:09:20] [整理推导]

## 边界条件、易错点与测试

### 关键边界

1. **空数组**：循环均不进入，`k = 0`，结果仍为空。[整理推导]
2. **全零数组**：`k` 始终为 0；交换版不发生交换，整个数组保持全零。[整理推导]
3. **全非零数组**：阶段二会逐个自交换；阶段三的 `i != k` 条件专门避免这一开销。[视频 00:08:06–00:09:20]
4. **零在开头或连续出现**：`k` 停留在第一个待填位置，后续非零值按扫描顺序进入前缀。[视频 00:00:00–00:07:05] [整理推导]
5. **零在末尾**：非零前缀处理完成后，末尾零无需改变；最终版不会无故打乱前缀。[整理推导]

### 典型错误

- 覆写版忘记第二段补零，导致后缀残留旧非零值。[视频 00:00:00–00:04:56]
- 把 `[0,k)` 误写成“包含索引 `k`”，进而在更新顺序上出现偏差；`k` 指向的是下一个待放位置。[视频 00:00:00–00:09:20]
- 交换后忘记 `k++`，后续非零值会覆盖或反复交换同一位置。[视频 00:07:05–00:09:20] [整理推导]
- 看到单循环就宣称渐近复杂度优于覆写版；三版时间仍都是 `O(n)`。[视频 00:02:39–00:09:20]
- 为避免自交换而在 `i == k` 分支忘记 `k++`，会破坏 `[0,k)` 对非零前缀长度的记录。[视频 00:08:06–00:09:20]

## 复习区

### 核心清单

- 三版都维护 `[0,k)` 为稳定的非零前缀。[视频 00:00:00–00:09:20]
- 覆写版扫描后必须把 `[k,n)` 补零。[视频 00:00:00–00:04:56]
- 交换版额外保持处理区中的 `[k,i]` 全为零，因此不需要补零循环。[视频 00:04:56–00:08:06]

### 闪卡问题
