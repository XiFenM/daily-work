## 题目、连续性与返回契约

### 题目

给定数组 `nums` 和目标 `s`，找到一个最短的连续子数组，使其中元素之和 `sum >= s`，返回该子数组的长度。[视频 00:00:43–00:02:06]

视频示例：

```text
nums = [2,3,1,2,4,3]
s = 7
```

最短合法窗口是 `[4,3]`，和为 7，长度为 2，因此返回 `2`。[视频 00:00:43–00:02:06]

### 什么是连续子数组

连续子数组对应原数组中的一个区间 `nums[i...j]`，必须包含索引 `i` 到 `j` 之间的所有元素。不能为了凑和而跳过中间位置；那会变成子序列或元素集合问题。[视频 00:02:06–00:03:59]

### 无解与多解

- 若不存在任何连续子数组满足 `sum >= s`，返回 `0`。[视频 00:02:06–00:03:59]
- 若有多个合法区间，只需返回最短长度；多个区间长度相同不影响返回值。若题目改为返回具体区间，才需要继续澄清平局规则。[视频 00:02:06–00:03:59] [整理推导]

### 正数条件：本笔记的证据边界

结构化题面与抽帧只明确显示“整型数组”和数字 `s`，没有把“元素均为正数、`s` 为正数”单列为约束；但视频所示窗口转移要获得后文的单调性与正确性，必须把它视为算法适用前提。[视频 00:00:43–00:02:06] [整理推导]

具体作用是：

- `nums[x] > 0`：右端纳入元素后 `sum` 严格增大；左端移出元素后 `sum` 严格减小。
- `s > 0`：初始空窗口的 `sum=0` 必然小于 `s`，第一次状态转移会扩张右端，而不会错误地从空窗收缩。

[整理推导]

若只允许非负数，窗口和仍是非降/非升的，类似策略通常仍可成立，但不再保证每次改变 `sum` 都是严格的；本课按正数输入解释。[补充说明]

## 解法演进

### 阶段一：重新计算每个区间的和，`O(n³)`

最直接的方法是枚举所有起点 `i` 与终点 `j`，再遍历 `i...j` 求和：[视频 00:03:59–00:05:39]

```text
for i = 0 ... n-1
    for j = i ... n-1
        sum = nums[i] + ... + nums[j]
        若 sum >= s，更新最短长度
```

区间数量是 `O(n²)`；每个区间重新求和最坏需要 `O(n)`，所以总时间为 `O(n³)`。[视频 00:03:59–00:05:39] [整理推导]

结构化证据把该基线的额外空间记为 `O(1)`，但视频主线在这里强调的是时间瓶颈；本笔记不把空间作为这一步的优化重点。[视频 00:03:59–00:05:39]

### 阶段二：复用求和结果，`O(n²)`

视频提出能否把暴力解法优化到 `O(n²)`。做法是固定左端 `i` 后，让右端 `j` 向右移动，并在已有和上加 `nums[j]`，避免为相邻区间从头求和。[视频 00:03:59–00:05:39]

下面的伪代码是对“复用求和”的编辑性展开，视频没有展示完整实现：[整理推导]

```text
for i = 0 ... n-1
    sum = 0
    for j = i ... n-1
        sum += nums[j]
        若 sum >= s，更新最短长度
```

仍需枚举 `O(n²)` 个 `(i,j)` 区间，但每次扩展只做 `O(1)` 增量计算，因此总时间降为 `O(n²)`。[视频 00:03:59–00:05:39] [整理推导]

### 阶段三：滑动窗口，`O(n)`

二次解法仍会为每个起点重新让右端扫描。正数条件允许两个边界只向前移动：

- 当前和不足时，收缩左端只会让和更小，不能产生合法窗口；唯一有希望的方向是扩张右端。
- 当前和已经达标时，继续扩张只会让窗口更长；为了寻找更短答案，应收缩左端。

[视频 00:05:39–00:07:56] [整理推导]

这正是把 `O(n²)` 的独立区间枚举压缩为一条单调状态轨迹的原因。[整理推导]

## 窗口状态模型

### 闭区间 `[l,r]`

课程把窗口定义为：

```text
nums[l...r]
```

这是左右端都包含的闭区间，窗口长度为：

```text
r - l + 1
```

[视频 00:05:39–00:13:14]

### 初始空窗口为什么是 `l=0, r=-1`

初始化：

```cpp
int l = 0, r = -1;
int sum = 0;
```

形式上的 `[0,-1]` 不含任何数组位置，表示空窗口；其长度 `r-l+1` 恰好为 0，窗口和也为 0。[视频 00:07:56–00:13:14]

这个定义让第一次扩张可以统一写成 `++r` 后纳入 `nums[r]`，不需要为第一个元素单独分支。[视频 00:07:56–00:13:14] [整理推导]

## 状态转移

### 转移一：和不足且右侧还有元素——扩张

条件：

```cpp
r + 1 < nums.size() && sum < s
```

操作：

```cpp
sum += nums[++r];
```

先检查 `r+1` 合法，再前移右端并把新元素纳入窗口，保证 `sum` 与新的 `[l,r]` 同步。[视频 00:07:56–00:13:14]

正数条件下，`sum < s` 时向左收缩只会进一步减小和，所以不会错过更短合法窗口；扩张是唯一可能达到阈值的方向。[整理推导]

### 转移二：已达标——收缩左端

当 `sum >= s` 时，当前窗口已经是候选。代码在前一轮达标时已记录其长度，随后通过：

```cpp
sum -= nums[l++];
```

尝试去掉最左元素，检查能否在保持 `sum >= s` 的同时获得更短窗口。[视频 00:05:39–00:13:14] [整理推导]

操作顺序很重要：先从 `sum` 减去旧的 `nums[l]`，再让 `l` 前进；否则 `sum` 就不再对应更新后的窗口。[视频 00:07:56–00:13:14]

### 转移三：和不足但右端已经到头——继续收缩以结束

若 `r+1 == n` 且 `sum < s`，无法再加入新元素，代码也会进入 `else`，不断移出左端直到 `l == n`，循环结束。[视频 00:07:56–00:13:14]

在正数数组中，此时收缩不可能让不足的和重新达标；这条路径的作用是有界地清空剩余窗口并推进到终止状态，不会漏掉候选答案。[整理推导]

### 结果更新为什么放在转移之后

每次扩张或收缩后，代码统一执行：

```cpp
if (sum >= s)
    res = min(res, r - l + 1);
```

[视频 00:07:56–00:13:14]

- 若一次扩张首次使窗口达标，同一轮立即记录。
- 若一次收缩后仍达标，同一轮记录更短长度。
- 若收缩使和跌破阈值，不更新；下一轮转为扩张。

当前合法窗口在被收缩前已经由上一次状态更新记录，因此把检查放在转移后不会丢掉它。[视频 00:05:39–00:13:14] [整理推导]

```cpp
#include <iostream>
#include <vector>
#include <cassert>

using namespace std;

class Solution {
public:
    int minSubArrayLen(int s, vector<int>& nums) {

        int l = 0, r = -1; // nums[l...r] 为我们的滑动窗口
        int sum = 0;
        int res = nums.size() + 1;

        while (l < nums.size()) {

            if (r + 1 < nums.size() && sum < s)
                sum += nums[++r];
            else
                sum -= nums[l++];

            if (sum >= s)
                res = min(res, r - l + 1);
        }

        if (res == nums.size() + 1)
            return 0;

        return res;
    }
};
```

## 正确性解释

结构化证据把正确性方法标为状态转移，并记录“窗口移动能够无遗漏覆盖可能成为解的连续区间”；它没有给出完整证明义务。以下论证是在**正数输入与 `s>0` 前提下**对课堂动画和代码的编辑性整理。[视频 00:05:39–00:13:14] [整理推导]

### 1. 初始化

`l=0, r=-1, sum=0` 表示空窗口，`res=n+1` 表示尚未找到合法长度。因为任何实际子数组长度都不超过 `n`，哨兵不会与真实答案混淆。[视频 00:07:56–00:13:14]

### 2. 状态保持

每轮只做一种操作：

- 扩张时把新右端恰好加进 `sum`；
- 收缩时把旧左端恰好从 `sum` 移出。

所以转移后 `sum` 始终等于当前闭区间 `[l,r]` 的元素和。[视频 00:05:39–00:13:14] [整理推导]

### 3. 为什么移动方向不会漏掉更优解

- `sum < s`：由于元素为正，删除左端只会让和更小；所有以当前或更右的左端、同一 `r` 结尾的更短窗口都不可能达标，因此可以安全扩张 `r`。[整理推导]
- `sum >= s`：当前窗口已经记录。固定 `r` 时，只有右移 `l` 才可能得到更短的合法窗口，所以反复收缩直到不再达标。[视频 00:05:39–00:07:56] [整理推导]
- 对每一个被右端访问到的位置，算法都会检查由当前左端收缩得到的合法窗口；因此全局最短长度会被 `res` 记录。[整理推导]

### 4. 终止与后置条件

`r` 只增不减，最多从 `-1` 到 `n-1`；`l` 只增不减，最多从 `0` 到 `n`。当 `l == n` 时循环终止。[视频 00:07:56–00:14:09]

- 若 `res <= n`，它是所有已访问合法窗口中的最短长度，而上述移动规则不会漏掉更短合法区间。[整理推导]
- 若 `res` 仍为 `n+1`，说明没有发现合法窗口，按题目契约返回 `0`。[视频 00:02:06–00:03:59] [视频 00:07:56–00:13:14]

这是一份基于状态单调性的人工论证，不是机器形式化证明；屏幕代码也没有在本项目本地运行。[补充说明]

## 正数条件为什么不可忽略

滑动窗口不是“看到连续子数组就一定能用”。这段代码依赖如下单调性：[整理推导]

```text
加入右端正数  => sum 增大
移除左端正数  => sum 减小
```

若允许负数：

- 扩张窗口可能让 `sum` 降低；
- 移除一个负数反而可能让 `sum` 升高；
- `sum < s` 时“只扩张、不收缩”的判断不再安全；
- `sum >= s` 后一次收缩跌破阈值，也不能说明继续收缩没有机会重新达标。

[整理推导]

例如 `s=5, nums=[4,-3,5,1]`：长度 1 的 `[5]` 是最优解，但按屏幕代码的移动顺序，窗口在和跌破 5 后会先扩张到末尾，再移除 `-3`，记录到 `[5,1]` 的长度 2，可能错过 `[5]`。这是用于说明适用边界的编辑性反例，不是视频示例。[补充说明]

包含任意整数时，通常需要前缀和与其他数据结构或不同算法；本课没有展开替代方案，因此本笔记不补写完整题解。[补充说明]

## 复杂度分析

### 为什么不是 `O(n²)`

代码只有一个 `while`，但即使把“扩张”和“收缩”想象成嵌套动作，也不能简单相乘。关键是两个指针从不回退：[视频 00:13:14–00:14:09]

- `r` 最多前进 `n` 次，每个元素至多入窗一次；
- `l` 最多前进 `n` 次，每个元素至多出窗一次；
- 每轮必定让 `r` 或 `l` 前进一步，循环次数不超过线性数量级，粗略上界可写成 `2n` 次指针移动。

[视频 00:13:14–00:14:09] [整理推导]

忽略常数系数后，时间复杂度为 `O(n)`。[视频 00:13:14–00:14:09]

### 空间复杂度

算法只维护 `l`、`r`、`sum`、`res` 等固定数量变量，没有与 `n` 同阶的辅助数组，因此额外空间为 `O(1)`。[视频 00:13:14–00:14:09]

| 暴力枚举 + 重新求和 | `O(n²)` 个区间，每个再用 `O(n)` 求和         | `O(n³)` | `O(1)`（按伪代码） | [视频 00:03:59–00:05:39] [整理推导] |
| 枚举 + 增量求和     | 固定左端，右端扩张时复用已有和               | `O(n²)` | `O(1)`（按伪代码） | [视频 00:03:59–00:05:39] [整理推导] |
| 滑动窗口            | 左右端都单调前进，每个元素最多入窗、出窗一次 | `O(n)`  | `O(1)`             | [视频 00:05:39–00:14:09]            |

`O(n²)` 方案的完整伪代码和空间说明是依据“复用求和”整理的；视频只明确提出该优化方向与复杂度，没有展示其完整代码。[视频 00:03:59–00:05:39] [整理推导]

## 边界条件、易错点与测试

### 视频直接强调的边界

1. **无解**：`res` 保持 `n+1`，最终返回 `0`。[视频 00:02:06–00:03:59] [视频 00:07:56–00:13:14]
2. **空窗口**：闭区间表示下使用 `l=0,r=-1`，而不是让 `r=0` 后又声称窗口为空。[视频 00:07:56–00:13:14]
3. **右端越界**：访问新元素前检查 `r+1 < nums.size()`。[视频 00:07:56–00:13:14]
4. **哨兵**：`res=n+1` 是不可能的合法长度，可区分“尚无答案”与真实最短值。[视频 00:07:56–00:13:14]
5. **更新顺序**：扩张时先 `++r` 再加 `nums[r]`；收缩时先减 `nums[l]` 再 `l++`。[视频 00:07:56–00:13:14]

### 编辑补充的适用边界

1. **空数组且 `s>0`**：循环不进入，哨兵保持，返回 0。[整理推导]
2. **`s<=0`**：初始空窗已满足 `sum>=s`，屏幕代码会进入收缩分支并从空窗移除 `nums[0]`，不符合状态定义；因此必须保留 `s>0` 前提。[整理推导]
3. **负数元素**：破坏窗口和单调性，本课的移动规则不再保证正确。[整理推导]
4. **整数溢出**：视频使用 `int sum`；若元素和可能超过 `int` 范围，应根据题目约束换用更宽类型。视频没有讨论这一点。[补充说明]
5. **`nums.size()` 与 `int` 混用**：极端大容器可能有类型收窄问题；属于工程补充，不是课程主线。[补充说明]

### 常见错误

- 把子数组理解成可以跳过元素的子序列。[视频 00:02:06–00:03:59]
- 把初始 `r` 写为 0，却仍设置 `sum=0`，造成窗口与累计和不一致。[视频 00:07:56–00:13:14] [整理推导]
- 窗口达标后只更新答案、不继续收缩，因而错过更短窗口。[视频 00:05:39–00:07:56]
- 收缩时先 `l++` 再减 `nums[l]`，移除了错误元素。[视频 00:07:56–00:13:14]
- 右端到头且和不足时不推进 `l`，造成循环不能结束。[视频 00:07:56–00:13:14] [整理推导]
- 只看指针组合就套用滑动窗口，没有检查正数/非负数带来的单调性。[整理推导]
- 看到两根指针分别移动，就把总工作量相乘为 `O(n²)`；它们各自只走一遍，应相加而不是相乘。[视频 00:13:14–00:14:09] [整理推导]

## 复习区

### 核心清单

- 子数组必须连续；无解返回 0。[视频 00:02:06–00:03:59]
- 暴力重新求和是 `O(n³)`，复用求和是 `O(n²)`。[视频 00:03:59–00:05:39]
- 窗口采用闭区间 `[l,r]`，`l=0,r=-1` 表示空窗。[视频 00:07:56–00:13:14]
- `sum<s` 且还能右移时扩张；否则收缩左端；转移后若达标就更新 `res`。[视频 00:05:39–00:13:14]
- 正数条件使扩张和收缩对 `sum` 具有单调方向，是贪心移动不漏解的基础。[整理推导]
- `l`、`r` 均只前进不回退，每个元素最多入窗、出窗一次，所以时间 `O(n)`。[视频 00:13:14–00:14:09]
- 只使用固定数量变量，额外空间 `O(1)`。[视频 00:13:14–00:14:09]
- 屏幕代码未在本项目本地运行，建议测试不是已验证结果。[补充说明]
