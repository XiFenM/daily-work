## 状态模型：选择、递归与自然恢复

### 函数契约

```text
findCombination(digits, index, s)

前置语义：
    s 是 digits[0...index-1] 的一个合法翻译

本层任务：
    枚举 digits[index] 的候选，
    生成从该部分解继续向下的所有完整组合

结果写入：
    成员变量 res
```

[course_direct + visual_direct | ev-006, ev-007]

### 状态转移

代码的核心只有一条分支转移：

```cpp
findCombination(digits, index + 1, s + letters[i]);
```

[visual_direct | code-001]

它包含：

1. **选择**：`letters[i]` 表示的候选字符；
2. **构造下一状态**：`s + letters[i]`；
3. **递归**：处理 `index + 1`；
4. **恢复**：调用返回后，调用者原来的 `s` 仍然不变。

第 4 点来自 C++ 表达式语义的编辑解释：`s + letters[i]` 生成临时新字符串，递归形参虽是 `const string&`，但只读地绑定该临时值；调用者的原字符串没有被原地修改。视频此时尚未使用“手动撤销”代码。[editorial_inference]

### 与显式回溯的区别

如果改为共享可变字符串，常见写法会是：

```text
追加一个字母
递归
删除刚追加的字母
```

但这不是本课屏幕代码，不能把这段替代模板冒充课程实现。本课真实实现通过每层构造新字符串避免共享状态污染。[补充说明 + editorial_inference]

```cpp
using namespace std;

class Solution {
private:
    const string letterMap[10] = {
        " ",    //0
        "",     //1
        "abc",  //2
        "def",  //3
        "ghi",  //4
        "jkl",  //5
        "mno",  //6
        "pqrs", //7
        "tuv",  //8
        "wxyz"  //9
    };

    vector<string> res;

    // s中保存了此时从digits[0...index-1]翻译得到的一个字母字符串
    // 寻找和digits[index]匹配的字母，获得digits[0...index]翻译得到的解
    void findCombination(const string &digits, int index, const string &s){
        if(index == digits.size()){
            // 保存s
            res.push_back(s);
            return;
        }

        char c = digits[index];
        assert(c >= '0' && c <= '9' && c != '1');
        string letters = letterMap[c - '0'];
        for(int i = 0 ; i < letters.size() ; i ++){
            findCombination(digits, index + 1, s + letters[i]);
        }

        return;
    }

public:
    vector<string> letterCombinations(string digits) {
        res.clear();
        if(digits == "")
            return res;

        findCombination(digits, 0, "");
        return res;
    }
};
```

- `letterMap[10]`，不是 9；
- `0` 映射为 `" "`，含一个空格；
- `1` 映射为 `""`；
- 断言是 `c >= '0' && c <= '9' && c != '1'`；
- 映射下标是 `c - '0'`；
- 循环是 `i < letters.size()`；
- 递归索引是 `index + 1`；
- 部分解是 `s + letters[i]`；
- 空输入判断发生在首次递归之前；
- 每次公开接口调用先执行 `res.clear()`。

## 正确性解释

课程给出递归语义、树形图和代码，但没有逐条写出形式证明。以下证明为编辑归纳。[editorial_inference]

### 1. 初始化

公开接口调用：

```cpp
findCombination(digits, 0, "");
```

此时前 0 位已翻译出的字符串确实为空，满足契约。[course_direct + visual_direct | ev-007]

### 2. 保持

假设进入某层时，`s` 是 `digits[0...index-1]` 的一个合法翻译。

对 `digits[index]` 的任一候选 `letters[i]`：

```text
s + letters[i]
```

就是 `digits[0...index]` 的一个合法翻译；递归索引推进到 `index + 1`，因此下一层契约成立。[editorial_inference based on code-001]

### 3. 完备性

本层循环遍历 `letters` 中每个候选；每个候选分支又递归枚举后续位置的全部候选。按剩余字符数归纳，所有候选序列都会到达一个叶子。[editorial_inference]

### 4. 不重复路径

在同一映射字符串内部，每个候选字符只对应一条循环分支；一条完整的选择序列对应一条根到叶路径。若各数字映射中的字符互不重复，则不同选择序列生成不同字符串。[editorial_inference]

### 5. 终止性

每次递归都把 `index` 增加 1；`digits.size()` 有限，所以最终到达：

```text
index == digits.size()
```

并返回。[course_direct + editorial_inference | ev-007]

## 时间与空间复杂度

### 课程直接证据

本课没有给出时间复杂度、辅助空间或递归栈分析；规范化证据中的 `complexity` 因此保留为空。[补充说明]

### 输出敏感的编辑分析

设输入长度为 `n`，第 `i` 位的候选数为 `b_i`。

令深度 `k` 的前缀数量为：

```text
P_k = b_0 × b_1 × ... × b_(k-1)
```

最终答案数量 `R = P_n`。每个答案字符串长度为 `n`，仅保存最终输出就需要：

```text
Θ(nR)
```

个字符量。[editorial_inference]

递归树节点数可写成：

```text
1
+ b_0
+ b_0 b_1
+ ...
+ b_0 b_1 ... b_(n-1)
```

本实现每次用 `s + letters[i]` 构造并复制下一层前缀，因此时间不能只写“叶子数 `R`”。按构造字符串的长度计数，一个对所有映射都适用的表达是：

```text
O(P_1 + 2P_2 + ... + nP_n)
```

若输入限定为经典的 `2..9`，每位至少有 3 个候选，上式由末层主导，可简化为 `Θ(nR)`；但课程代码还允许候选数为 1 的 `0`。例如全是 `0` 时 `R = 1`，逐层前缀复制仍为 `Θ(n²)`，所以不能无条件把 `O(nR)` 当作普适上界。[editorial_inference]

辅助状态：

- 不计结果集时，递归深度是 `O(n)`；
- 每层都持有自己的字符串参数，实现中的同时存活前缀字符量可能累计到 `O(n²)`；
- 计入输出后，结果集本身是 `Θ(nR)` 字符量。

[editorial_inference；具体编译器字符串实现可能影响常数]

## 边界条件、易错点与测试

### 1. 空字符串

如果直接调用递归：

```text
findCombination("", 0, "")
```

终止条件会把 `""` 加入结果，得到含一个空字符串的向量。课程因此在公开接口先返回空结果。[course_direct + visual_direct | ev-004, ev-007]

### 2. 数字 `1`

映射表为 `""`，同时断言明确排除 `'1'`。启用断言时输入含 `1` 会终止程序，而不是安静返回空结果。[visual_direct + editorial_inference | code-001]

### 3. 数字 `0`

课程代码把 `0` 映射为一个空格 `" "`。这与许多在线题目版本只接受 `2..9` 的契约未必相同；面试时应先确认，不要擅自替换。[visual_direct + 补充说明 | code-001]

### 4. 非数字字符

断言开启时会被范围条件拒绝；若断言被编译关闭，`c - '0'` 可能越出 `letterMap` 边界。课程没有给出发布环境的错误处理策略。[editorial_inference]

### 5. 忘记清空成员结果

`res` 是成员变量。若公开接口不先 `res.clear()`，同一个 `Solution` 对象的多次调用会串入旧结果。[visual_direct + editorial_inference | code-001]

### 6. 把自然恢复误写成共享修改

当前代码传入 `s + letters[i]`。如果改成先修改共享 `s`，却不增加对应撤销，兄弟分支会相互污染。[editorial_inference]
