## 核心概念与定义

### 1. 本题为什么没有传统前驱改链入口

普通单链表删除某节点 `x` 时，若能访问它的前驱 `prev`，通常会让：

```text
prev->next = x->next
```

这样前驱直接绕过 `x`。[editorial_inference | 基于 ev-002 | 视频 00:17–01:46]

本题画面中的函数签名是：

```cpp
void deleteNode(ListNode* node)
```

函数只收到待删除节点本身，没有收到 `head`，也没有收到 `node` 的前驱节点。[course_direct + visual_direct | ev-002 | 视频 00:17–01:46]

单链表节点只知道自己的后继，不能沿 `next` 反向找到前驱。因此当前函数无法直接写出 `prev->next = node->next`。[course_direct + editorial_inference | 基于 ev-002 | 视频 00:17–01:46]

### 2. 复制后继删除法

设局部结构为：

```text
… → A → node(x) → successor(y) → B → …
```

核心方法并不物理释放 `node(x)`。它执行：

1. 把 `successor` 的值 `y` 复制到 `node`；
2. 保存 `successor` 的地址；
3. 让 `node->next` 指向 `successor->next`；
4. 释放原 `successor`。

[course_direct + visual_direct | ev-003, ev-004 | 视频 01:46–05:38]

结果是：

```text
… → A → node(y) → B → …
```

从值序列看，`x` 消失，后续值保持原顺序，因此逻辑效果等同于删除原来位于 `node` 位置的元素。[course_direct + visual_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 01:46–05:38]

### 3. 逻辑节点与物理对象

这道题最容易混淆两个层面：

- **逻辑位置**：调用者希望链表中原 `node` 位置对应的值不再出现；
- **物理对象**：参数 `node` 指向的内存对象仍保留，只是其 `val` 被后继值覆盖；真正被 `delete` 的是原后继对象。

[visual_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 01:46–05:38]

因此更精确的表述不是“直接释放给定节点”，而是：

> 用后继内容覆盖给定节点，再物理删除后继，从外部遍历所得的值序列上模拟删除给定位置。

[course_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 01:46–05:38]

这个技巧依赖题目的节点模型主要由 `val` 和 `next` 构成。若节点还承担不可复制的身份、外部引用或其他资源语义，就需要重新确认“复制值是否等价”；视频没有讨论这些扩展情形。[补充说明]

### 4. 方法的必要前提

核心语句第一步需要读取：

```cpp

```

所以必须同时满足：


`node->next != NULL` 不只是避免崩溃的防御检查，也是算法存在性的前提：没有后继，就没有可复制到当前节点的替身。[course_direct + editorial_inference | 基于 ev-003, ev-005 | 视频 01:46–04:04；05:38–07:09]

## 正确性解释

规范化证据把正确性方法记录为 `state_transition`。下面的充分性说明只对“当前节点存在且有后继”这一前提成立；它不覆盖屏幕中的尾节点分支。[course_direct + editorial_inference | 基于 ev-003–ev-005 | 视频 01:46–07:09]

### 有效核心路径

初始局部值序列是：

```text
prefix, x, y, suffix
```

执行复制后继删除法后：

1. `x` 被 `y` 覆盖；
2. 原来承载 `y` 的后继节点被旁路并释放；
3. `prefix` 与 `suffix` 的相对顺序和连接保持；
4. 最终值序列为 `prefix, y, suffix`。

[course_direct + visual_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 01:46–05:38]

这正是从原值序列中删除 `x` 后的结果。整个过程没有遍历前驱，也不需要修改 `P`，因为 `P` 仍然指向同一个物理 `node`，只是该节点现在承载后继值 `y`。[editorial_inference | 基于 ev-002–ev-004 | 视频 00:17–05:38]

### 删除前的链表状态

```text

          ↑
         node
```

函数没有 `P` 的地址，也没有指向 `P->next` 这个链接槽位的引用。[course_direct + editorial_inference | 基于 ev-002, ev-005 | 视频 00:17–01:46；05:38–07:09]

### `delete node` 做了什么

`delete node` 释放 `T` 所在的内存，但它不会自动搜索并改写其他对象中保存的指针。于是 `P->next` 仍保留原来的地址，只是该地址现在已经失效。[editorial_inference | 基于 ev-005 | 视频 05:38–07:09]

此时结构实际是：

```text
… → P → [已释放内存]
```

`P->next` 成为悬空指针。后续从链表头遍历到这里并解引用，会触发未定义行为风险。[editorial_inference | 基于 ev-005 | 视频 05:38–07:09]

### `node = NULL` 为什么无效

函数签名是：

```cpp
void deleteNode(ListNode* node)
```

`node` 是按值传入的局部指针变量。执行：

```cpp
node = NULL;
```

只改变该局部变量保存的地址，不会改变 `P->next`，也不会自动改变调用者或链表内部的其他指针。[visual_direct + editorial_inference | 基于 ev-002, ev-005 | 视频 00:17–01:46；05:38–07:09]

而且赋值发生在 `delete node` 之后，只能避免函数内部继续使用这份局部地址，不能修复已经存在的悬空链接。[editorial_inference | 基于 ev-005 | 视频 05:38–07:09]

### 结论

在“只给尾节点指针、不给头或前驱”的普通单链表接口下，函数缺少修改前驱链接所需的信息，无法完成正确的通用尾节点删除。[editorial_inference | 基于 ev-002, ev-005 | 视频 00:17–01:46；05:38–07:09]

可接受的处理方式必须来自明确契约，例如：

- 题目保证待删节点不是尾节点；
- 接口额外提供链表头或前驱；
- 接口提供可直接修改前驱链接槽位的其他结构。

这些是接口设计方向，不是视频给出的替代代码。[补充说明]

## 时间与空间复杂度

规范化证据中的总复杂度字段为 `null`，视频没有直接给出时间或空间复杂度。因此本节全部是对屏幕代码的编辑性推导，不能标为课程结论。[editorial_inference | 基于 ev-004, ev-005 | 视频 04:04–07:09]

### 有效核心路径

在 `node != NULL && node->next != NULL`，并按面试常用单位成本模型把一次指针读写、值赋值和 `delete` 视为常数工作时：

- 不遍历链表；
- 固定执行一次值复制；
- 固定执行若干次指针读取和写入；
- 只使用一个额外指针 `delNode`。

因此可整理为：

```text
时间复杂度：O(1)
辅助空间复杂度：O(1)
```

[editorial_inference | 基于 ev-004 | 视频 04:04–05:38]

### 复杂度不证明正确性

屏幕尾节点分支同样只执行常数次语句，但它会留下悬空指针。`O(1)` 只描述工作量，不表示结果符合链表删除契约。[editorial_inference | 基于 ev-005 | 视频 05:38–07:09]

## 边界条件、易错点与测试

### 课程直接呈现的边界检查

1. `node == NULL` 时直接返回；[course_direct + visual_direct | ev-005 | 视频 05:38–07:09]
2. 在访问 `node->next->val` 前检查 `node->next`；[course_direct + visual_direct | ev-005 | 视频 05:38–07:09]
3. 视频为 `node->next == NULL` 写出了单独分支。[visual_direct | ev-005 | 视频 05:38–07:09]

第三项只表示屏幕中存在这段代码，不代表分支实现正确。人工审查结论仍是：它不能修复前驱 `next`，会留下悬空指针。[visual_direct + editorial_inference | 基于 ev-005 | 视频 05:38–07:09]

### 常见错误

1. **未检查 `node` 就访问成员**：空指针输入会导致无效解引用。[course_direct | ev-005 | 视频 05:38–07:09]
2. **未检查后继就复制值**：尾节点上访问 `node->next->val` 无效。[course_direct | ev-005 | 视频 05:38–07:09]
3. **复制值后忘记旁路后继**：链表会暂时保留两个相同的连续值，节点数没有减少。[visual_direct + editorial_inference | 基于 ev-003, ev-004 | 视频 01:46–05:38]
4. **旁路后继后忘记释放**：在课程的手动内存管理代码模型中会遗留被移出链表的对象。[visual_direct + editorial_inference | 基于 ev-004 | 视频 04:04–05:38]
5. **先释放后继再读取其 `next`**：会从已释放对象读取指针；屏幕代码正确地先完成旁路，再 `delete delNode`。[visual_direct + editorial_inference | 基于 ev-004 | 视频 04:04–05:38]
6. **把 `node = NULL` 当作更新链表**：它只修改局部参数副本，不能改写前驱链接。[visual_direct + editorial_inference | 基于 ev-002, ev-005 | 视频 00:17–01:46；05:38–07:09]
7. **把视频代码写成已验证实现**：当前状态是 `shown_in_video/not_run`，没有运行证据。[visual_direct | ev-004, ev-005 | 视频 04:04–07:09]
