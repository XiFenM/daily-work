# 课程知识关系模型

## 设计目标

课程关系不能只靠“上一节/下一节”。同一技巧会跨越数组、查找表、链表、树、回溯和动态规划；关系模型需要同时支持：

- 按原课程顺序学习；
- 从某个知识点回溯先修；
- 横向比较同一题族的不同解法；
- 按题型簇复习；
- 追溯每条关系来自视频、文本还是编辑推断。

## 六层能力结构

1. **面试元技能**：第 1 章。
2. **分析与正确性基础**：第 2 章，以及 `03-01`、`03-02`、`05-02`。
3. **线性结构与局部模式**：第 3–5 章。
4. **非线性结构与遍历**：第 6–7 章。
5. **状态空间搜索**：第 8 章。
6. **优化问题求解**：第 9–10 章。

第 11 章作为课程闭环和复习入口，把“基础优先 → 面试向练习 → 超越 Accepted → 复盘设计、实现与优化 → 形成题型分类”连成长期训练闭环。六层结构最初来自目录分析，现已随 70 个课次逐章校准；具体关系是否进入主知识地图，仍以单条边的证据状态为准。

最终图谱包含 97 条关系：96 条 `verified` 可进入主知识地图，1 条 `provisional` 仅保留为待确认候选。概念词表包含 150 个规范节点。

## 节点

| 类型              | 用途               | 示例                                  |
| ----------------- | ------------------ | ------------------------------------- |
| `course`          | 课程根节点         | `course:algorithm-interview`          |
| `chapter`         | 章节容器           | `chapter:03`                          |
| `lesson`          | 课次               | `lesson:03-07`                        |
| `asset`           | 视频、文本、字幕   | `asset:video-03-07`                   |
| `concept`         | 概念               | `concept:sliding-window`              |
| `pattern`         | 可迁移题型模式     | `pattern:two-pointers`                |
| `data_structure`  | 数据结构           | `data-structure:priority-queue`       |
| `algorithm`       | 算法               | `algorithm:bfs`                       |
| `problem`         | 题目或题族         | `problem:two-sum`                     |
| `pitfall`         | 常见错误           | `pitfall:binary-search-boundary`      |
| `interview_skill` | 面试表达或验证技能 | `interview-skill:clarify-constraints` |

概念节点保存中文名、英文名和别名，避免“窗口法/滑动窗口”或“Top K/topK”等写法造成重复节点。

## 关系

### 结构关系

- `contains`
- `precedes`

### 学习关系

- `prerequisite_of`：没有前者会明显无法理解后者。
- `recommended_before`：先学更顺畅，但并非硬依赖。
- `extends`：增加新约束、能力或抽象。
- `revisits`：重新讨论已有概念。
- `applies`：把已有方法用于具体场景。

### 对照关系

- `contrasts_with`
- `alternative_to`
- `same_pattern_as`
- `same_problem_family_as`

### 内容关系

- `uses_data_structure`
- `implements_algorithm`
- `solves_problem`
- `addresses_pitfall`
- `evidenced_by`

仅因目录相邻不能建立 `prerequisite_of`。

## 边的证据状态

| 状态          | 含义                         | 可否进入主知识地图 |
| ------------- | ---------------------------- | ------------------ |
| `provisional` | 仅由目录或编辑分析提出       | 否                 |
| `verified`    | 有课程视频/文本证据支持      | 是                 |
| `rejected`    | 证据不足、方向错误或过度关联 | 否                 |

每条边保存：

- 起点、终点和关系类型；
- 强度与置信度；
- 具体理由；
- 两端课次的时间戳或文本定位；
- 创建 Prompt/编辑过程；
- 审核状态。

`prerequisite_of` 子图必须无环。`contrasts_with`、`alternative_to`、`same_pattern_as` 等语义对称关系在数据中只保留一条规范方向边。

## 每次处理的上下文窗口

不能把前面所有完整笔记不断塞给后续视频。单课合成最多使用：

- 全课程目录；
- 当前章短摘要；
- 直接先修课的压缩 lesson card；
- 规范概念词表；
- 根据题型簇检索出的 3–8 个候选关联课。

这样既能识别跨课联系，也能限制上下文膨胀和早期错误传播。

## 校准节奏

- 单课完成：只提出或更新与当前课直接相关的关系。
- 每章完成：合并同义概念、检查边方向、降低过强先修关系。
- 全课程完成：检查先修子图是否有环，生成多条复习路径，并把所有未验证关系单独列出。最终课程综合见 [`notes/course-synthesis.md`](notes/course-synthesis.md)。
